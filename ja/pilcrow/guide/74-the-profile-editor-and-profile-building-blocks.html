プロファイルエディタとプロファイルの構成要素

構文プロファイルは、あなたのマークアップが何を意味するのかを Pilcrow に伝えるものです。この章では、プロファイルエディタをコントロールごとに説明し、続いてプロファイルで使えるすべての構成要素を一覧にします。作業を中心にした入門は、第37章から第39章をご覧ください。

エディタは 設定 ▸ ライブラリ ▸ 構文プロファイル から開きます。新規 でプロファイルを作り、編集 でカスタムプロファイルを変更し、複製 で組み込みプロファイルをコピーして、コピーのほうを変更できます。エディタのタイトルは プロファイルを編集 で、キャンセル、保存、プロファイルのヘルプ（これらの構成要素のアプリ内リファレンスを開きます）があります。画面が狭い場合は、プロファイルのセクション スイッチで 概要、ルール、テストサンプル を切り替えます。広い画面では3つすべてが同時に表示されます。

概要#

フィールド内容
名前プロファイルの名前です。ステータスバーのメニューと設定に表示されます。
説明プロファイルについてのメモです。
ファイル拡張子（カンマ区切り）ファイルに対してこのプロファイルを選ぶ拡張子です。2つのプロファイルで同じ拡張子を共有することはできません。
継承元なし、またはこのプロファイルがルールの土台にする別のプロファイルです。
構文Markdown を拡張 または Markdown を置き換え（後述）。
概要ブロックルール、インラインルール、入れ子ルール の数です。
詳細な JSON を編集…ガイド付きエディタでは扱えないフィールドのために、プロファイルを JSON として開きます。適用 で JSON の変更を保持し、キャンセル で破棄します。

Markdown を拡張 は、あなたのルールを Markdown のルールに加えます。見出し、リスト、強調などは引き続き読み取られ、あなたのブロックルールとインラインルールがそれに追加されます。CommonMark プロファイルのルールと変更のないコピーであるルールは、Markdown がすでに行っていることを表すので、Markdown に任せられます。Markdown を置き換え は、あなたのルールを構文のすべてにします。そのため Markdown の構造は認識されなくなります。この場合、いずれかのルールが 行末 を生成する必要があります。そうしないと段落が区切られません。エディタは「Add a rule whose output node is "newline", or nothing will separate into paragraphs」（出力ノードが「newline」のルールを追加してください。そうしないと段落が区切られません）と警告し、そのようなルールができるまでプロファイルを保存できません。また、プロファイルが定義していない出力の種類があれば、それも一覧表示します。

ルール#

ルールは3つのグループに分かれます。

ブロックルール#

ブロックルールは、行全体やブロックを認識します。ルールを追加 で追加します。各ルールには パターン、一致 の種類、何を 生成するもの か、そして オプション があります。ルールは 削除 ボタンで取り除きます。ルールがないときは、エディタに「No rules yet. Add one to recognize a block construct.」（まだルールがありません。ブロックの構造を認識するには、ルールを追加してください。）と表示されます。

インラインルール#

インラインルールは、行の中のテキストを認識します。インラインルールを追加 で追加します。インラインルールで選べる一致の種類は4つ（リテラル接頭辞、完全一致、正規表現（制限付き）、区切り文字ペア）で、ブロックルールでは7つすべてを選べます。

入れ子ルール#

入れ子ルールは、どの出力がどの出力の中に入れるかを定めます。各ルールには 親ノード と 許可する子ノード（カンマ区切り） があります。空の場合は制限なしを意味し、「No restrictions. Every node type may nest inside any other.」（制限なし。どのノードの種類も、ほかのどれの中にも入れ子にできます。）と表示されます。入れ子ルールを追加 で追加します。

一致の種類#

一致の種類パターンの読み方ブロックインライン
リテラル接頭辞その構造が始まるテキスト。はいはい
完全一致その構造のテキスト全体。はいはい
行頭接頭辞# のように、行の先頭にあるテキスト。はい
インデントブロック4つのスペースやタブのように、パターンで始まる行。連続する行と、その間の空行は1つのブロックとなり、インデントなしで表示されます。はい
フェンスブロックブロックを開く行。対応する行で閉じられます。はい
正規表現（制限付き）正規表現。止まってしまうおそれのある正規表現は、保存する前に Pilcrow が「This regex could hang the editor — simplify it.」（この正規表現はエディタを停止させるおそれがあります。単純にしてください。）と警告します。はいはい
区切り文字ペア%%this%% の %% のように、1行の中でテキストの両側に付く同じ記号。記号のすぐ内側にスペースは入りません。はいはい

正規表現では、(?<name>…) で一致の一部に名前を付けます。後述の「部分」をご覧ください。

周囲の文字で決まるインライン記号#

Markdown のような言語では、太字や斜体を、隣の文字によって開いたり閉じたりする文字の連なりで書き、コード片やリンクを括弧で書きます。そのため、構造全体を1つのパターンで見つけることはできません。これらを記述するには、周囲の文字で決まる記号を読み取る をオンにします。

設定内容
エスケープ文字次の1文字を普通の文字にする文字です。
コード片の文字この文字の連なりでコード片が始まり、同じ長さの次の連なりで閉じます。
連続記号連なりとして対になる記号です。連続記号を追加 で追加します。それぞれに 記号、1つの記号で描画 するもの、2つの記号で描画 するもの、そして 単語の途中で開始・終了できる（_ ではオフ）があります。
対になる記号同じ長さの連なりと対になる記号です。対になる記号を追加 で追加します。記号、描画 するもの、そして この設定がオンのときのみ（ハイライトのように、オンになっている必要がある構文設定。または 常に）を指定します。
リンクとWebアドレス画像の接頭辞、単独のアドレスを囲む文字、装飾のないアドレスの先頭になるスキーム、ラベルを定義する行に付く文字、脚注のラベルの先頭文字（ラベルの開き括弧の次の文字で、脚注にするもの。[^note]: で始まる行があれば、[^note] は脚注の参照として描かれます）。

記号は1行の中で対になります。コード、エスケープされた文字、リンクのアドレスは、周囲の記号から見ると普通のテキストです。

スタイル付きソース#

スタイル付きソース をオンにすると、エディタは書類を、その構文の見た目で描画します。大きな見出し、太字や斜体、引用の縦線、リストのインデント、タスクのボックス、罫線、リンク、コードのカードなどです。そして、カーソルがある行を除いて、それらを作る記号を隠します（マーカーを隠す がオンのとき）。エディタは特定の構文を何も知りません。ルールが、スタイルの項目を持つことで一致が何であるかを示し、持たないルールは色が付くだけでスタイルは変わりません。

すべてのルールの オプション には スタイル付きソース グループがあります。

フィールド内容
役割一致が何であるか、または スタイルなし。行の中の1つの構造には、見出し（heading）、太字（strong）、強調（emphasis）、コード（code）、取り消し線（strike）、ハイライト（highlight）、下線（underline）、リンク（link）、下付き（subscript）、上付き（superscript）があります。行全体には、罫線（rule、主題の区切り）、リスト（list、リスト項目のマーカー。インデントとその後のスペースを含む）、タスク（task、チェックボックスが続くマーカー）、引用（quote、引用された行の > 記号）があります。全体で認識されるブロックには codeBlock、開始行と終了行が別々の一致であるブロックには quoteRegion、画像として描かれる表、数式、ダイアグラムには renderedBlock があります。
内容のグループ1から数えて、その構造の内容を保持するキャプチャグループです。*bold* の中の単語や、\section{Title} のタイトルなどです。一致のそれ以外の部分はその構造自身の記号で、マーカーを隠す で隠されます。0 は一致全体が内容で何も隠さないことを意味し、Web アドレスがそうです。見出しの == のように、一致が記号だけのときは省略します。
見出しレベル、レベルのグループ見出しのレベルで、1から6です。省略した場合は、ルールの出力名の末尾の数字（heading2）、または # の連なりを保持するキャプチャグループの長さになります。
マーカーのグループリストまたはタスクで、一致が引用された項目の > のようにほかのもので始まるとき、インデントとその後のスペースを含むマーカーであるキャプチャグループです。
行末までスタイルを適用一致から行末までスタイルを適用します。見出しのマーカーだけに一致し、タイトルをその後に続くテキストとして残すルール用です。
描画方法描画されるブロックについて、それが何であるかです。表、数式、ダイアグラム、または 画像にしない。
アドレスのグループリンクで、クリックまたはタップしたときに開くアドレスを保持するキャプチャグループを、試す順に指定します。0 は一致全体です。開くのは Web、メール、電話のアドレスだけです。

グループ番号は、パターンの括弧を1から数えたものです。0は一致全体です。Markdown を置き換えないプロファイルは、ルールが宣言していない種類について、引用の縦線や ** の対のように、Markdown 自身の読み取りも保持します。

書類の属性と条件付きセクション#

書類の属性 ルールは、name で値を定義します。属性の参照 ルール（name と original の部分を持つインラインルール）は、参照をその値に置き換えます。だれも定義していない属性への参照は、書いたままになります。条件付きセクション は、指定した属性が設定されているかどうかに応じて、その行の間のブロックを残すか除きます。属性は、定義された場所から先で有効になります。

次のブロックの設定 を生成するルールは、その後ろのブロックを設定する行全体を認識し、それ自体は何も表示しません。その部分と固定属性は、そのブロックに渡されます。title、id、nodeType、language、hardbreaks は「部分」の項に挙げた意味を持ち、ほかの部分はブロックに保持されて、表、リスト、引用が読み取ります。

プロファイルのテスト#

エディタの下部にある テストサンプル には、サンプルのテキストが入っています（最初は見出しと1行のテキストです）。サンプルをチェック を選ぶと、ルールが作るノードが、入れ子の深さに応じたインデントで表示されます。何も一致しないときは「No blocks recognized.」（認識されたブロックはありません。）と表示されます。

ベースライン#

プロファイルの ベースライン は、その復元ポイントです。プロファイルを作成、複製、または読み込んだときの状態を指します。ベースラインに戻す は、確認の後、それ以降のすべての変更を破棄します。新しいベースラインとして設定 は、プロファイルを保存し、その現在の状態を復元ポイントにします。

プロファイルが Markdown を置き換えるのに行末のルールがない場合、パターンが安全でなくエディタを止めるおそれがある場合、またはファイルを書き込めない場合は、保存が拒否され、メッセージが表示されます。

部分#

部分とは、出力が読み取る、一致の名前付きの要素です。

部分意味
allOfすべてが必要なときの、名前の間の区切りです。+ など。
alt画像を見られない読者のための、画像の説明です。
anyOfどれか1つで足りるときの、名前の間の区切りです。, など。
attribution引用を述べた人で、引用の下に表示されます。
citetitle引用の出典となる作品で、帰属表示の後に表示されます。
columns表の列リストです。1,2,1 など。要素の数が列の数になります。
conditionセクションが依存する属性の名前です。
conditionTypedefined は属性が設定されているときにセクションを残し、undefined は設定されていないときに残します。
content一致全体ではないときの、テキストそのものです。
formatダイアグラムのエンジン（mermaid または vega-lite）。表では、セルが使う区切り形式のどれかです。
hardbreaks指定すると、次のブロックの単一の改行を保持します。
headerfalse 以外の値にすると、表の最初の行が見出しになります。
id名前です。次のブロックでは、相互参照が指すID。脚注では、自分のテキストを持たない後続の脚注が番号を共有できるようにする名前です。
keys押すキーで、カンマで区切ります。
label参照やアンカーに、対象自身のタイトルの代わりに表示されるテキストです。
languageコードブロックのプログラミング言語で、色分けに使われます。
level見出しのレベルで、1から6です。
marker用語の後の区切りです。:: など。別のマーカーを使うと、説明の中にリストが入れ子になります。
name定義や参照での、属性の名前です。
nodeType次のブロックを、ファイル内の名前で指定した別の出力にします。
noHeader指定すると、表に見出し行がありません。
notation数式の記法です。tex（デフォルト）または latex。
opentrue にすると、折りたたみセクションが開いた状態で表示されます。
orderedtrue にすると、リストに番号が付きます。
original書かれたままの参照で、属性が定義されていないときに表示されます。
presentation次の説明リストの表示方法です。sideBySide は用語と説明を2列に並べ、questions は各用語を質問として番号付けし、その下に答えを置きます。
primary索引の項目です。
secondary索引の項目の下にある副項目です。
sectionLabel次の見出しの番号が後に続く語です。Appendix など。そのような見出しは単独で数えられ、Appendix A: となります。
sectionLabelStartそれらの番号の最初です。文字（A）なら文字で数え、数字なら数字で数えます。
srcビデオまたはオーディオのファイルのアドレスです。
start番号付きリストが始まる番号です。
summary折りたたみセクションが閉じている間に表示される行です。
targetID参照が指すIDです。
term説明される用語です。
tertiary副項目の下にある副項目です。
textパターンがそれ以上を捕捉するときの、表示されるテキストです。脚注のテキストは、それがある段落、表、リストの後に番号付きで続きます。
titleタイトルです。ボックスの見出し、画像やリンクのツールチップ、または次のブロックの上のキャプション。
type注記の種類です。note、tip、warning など。
unset指定すると、ルールは属性を定義せずに削除します。
urlリンクや画像が指すアドレスです。
value属性の値です。先に定義された属性への参照は、この中で置き換えられます。
