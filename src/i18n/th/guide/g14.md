# Part XXI — รูปแบบไฟล์และขีดจำกัด

# Chapter 79: รูปแบบธีมแอปพลิเคชัน

**Application Theme** (**ธีมแอปพลิเคชัน**) กำหนดสไตล์ให้ตัว Pilcrow เอง ได้แก่ รูปลักษณ์แบบสว่างหรือมืด สีเน้น แถบด้านข้าง แถบสถานะและแถบจัดรูปแบบ และตัวแก้ไข เป็นไฟล์ JSON ส่วนเอกสารที่แสดงผล (Preview, HTML, PDF, รูปภาพ, การพิมพ์ และ Word) ถูกกำหนดสไตล์แยกต่างหากด้วย **Render Theme** (**ธีมการแสดงผล**) ซึ่งเป็น CSS (บทที่ 80) ธีมทั้งสองประเภทติดตั้ง เลือก และลบแยกกัน และไม่ตามกัน

## ตัวอย่างฉบับสมบูรณ์

```json
{
  "pilcrowAppTheme": 1,
  "name": "Nord",
  "appearance": "dark",
  "colors": {
    "accent": "#88C0D0",
    "sidebar": { "background": "#2E3440", "foreground": "#D8DEE9" },
    "bars": { "background": "#3B4252", "foreground": "#D8DEE9" },
    "editor": {
      "background": "#2E3440",
      "foreground": "#ECEFF4",
      "cursor": "#88C0D0",
      "selection": "#434C5E",
      "gutterBackground": "#2E3440",
      "gutterForeground": "#4C566A"
    },
    "syntax": {
      "heading": "#88C0D0",
      "marker": "#EBCB8B",
      "code": "#A3BE8C",
      "link": "#81A1C1",
      "muted": "#7B88A1",
      "tokens": { "strong": "#D08770" }
    }
  }
}
```

## ระดับบนสุด

| คีย์ | จำเป็นหรือไม่ | ค่า |
| --- | --- | --- |
| `pilcrowAppTheme` | จำเป็น | เวอร์ชันของรูปแบบ คือ `1` |
| `name` | จำเป็น | 1–200 ตัวอักษร แสดงใน Settings และเมนูธีม |
| `appearance` | จำเป็น | `"light"`, `"dark"` หรือ `"automatic"` |
| `colors` | ธีม `light` และ `dark` | หนึ่งชุดสี (ด้านล่าง) |
| `light`, `dark` | ธีม `automatic` | สองชุดสี: ชุดหนึ่งใช้ในรูปลักษณ์สว่างของระบบ อีกชุดใช้ในรูปลักษณ์มืด |
| `id` | ไม่จำเป็น | Pilcrow เขียนให้สำหรับคลังของตัวเอง จะถูกละเว้นเมื่อนำเข้า ซึ่งจะกำหนด id ใหม่เสมอ |

`appearance` กำหนดรูปลักษณ์ของ**ทุก**หน้าต่าง รวมถึงเมนู Settings ชีต และตัวเลือก ธีม `light` หรือ `dark` กำหนดตายตัว ส่วน `automatic` ตามระบบ

ธีมแบบ automatic ต้องกำหนดแต่ละสีทั้งใน `light` และ `dark` หรือไม่กำหนดเลยทั้งสองอย่าง มิฉะนั้นสีที่กำหนดไว้เพียงรูปลักษณ์เดียวจะถูกวาดในอีกรูปลักษณ์หนึ่งด้วย

## ชุดสี

ทุกคีย์เป็นตัวเลือก สีที่ไม่ได้กำหนดจะใช้หน้าตาในตัวของ Pilcrow ดังนั้นธีมจึงเล็กได้ถึงขนาดมีสีเน้นเพียงสีเดียว

| คีย์ | กำหนดสไตล์ให้ |
| --- | --- |
| `accent` | สีเน้นทั้งแอป: ปุ่ม ส่วนที่เลือก สวิตช์ ลิงก์ วงโฟกัส และแถวที่เลือกของแถบด้านข้าง หากไม่กำหนดจะใช้สีเน้นของระบบ |
| `sidebar.background`, `sidebar.foreground` | แถบด้านข้างของไฟล์ เค้าร่าง และค้นหา ป้ายรองได้มาจากสีพื้นหน้า |
| `bars.background`, `bars.foreground` | แถบสถานะ แถบเครื่องมือจัดรูปแบบที่ยึดติด และประกาศการนำเข้า ป้ายรองได้มาจากสีพื้นหน้า |
| `editor.background`, `editor.foreground` | พื้นที่ตัวแก้ไขและข้อความเนื้อหา |
| `editor.cursor`, `editor.selection` | จุดแทรกและไฮไลต์ส่วนที่เลือก |
| `editor.gutterBackground`, `editor.gutterForeground` | คอลัมน์หมายเลขบรรทัด พื้นหลังมีค่าเริ่มต้นเป็นพื้นหลังของตัวแก้ไข |
| `editor.currentLineRule` | เส้นบางใต้บรรทัดที่เคอร์เซอร์อยู่ เมื่อ **View ▸ Current-Line Rule** (**มุมมอง ▸ กฎบรรทัดปัจจุบัน**) เปิดอยู่ ค่าเริ่มต้นคือสีข้อความของตัวแก้ไขที่ความเข้มต่ำ |
| `syntax.<group>` | สีไวยากรณ์แบบสดตามกลุ่ม (ด้านล่าง) |
| `syntax.tokens.<raw>` | โทเค็นหนึ่งตัวตามค่าดิบ ซึ่งแทนที่สีของกลุ่ม |

### กลุ่มไวยากรณ์

| กลุ่ม | สีที่กำหนด |
| --- | --- |
| `heading` | หัวเรื่อง (เครื่องหมายและข้อความ) เครื่องหมายการแจ้งเตือน และคำนิยาม |
| `marker` | ตัวเน้น ตัวหนา ขีดทับ และตัวคั่นในบรรทัดอื่น ๆ เครื่องหมายรายการและงาน |
| `code` | โค้ดแบบแทรกในบรรทัด บล็อกโค้ดแบบรั้วและแบบเยื้อง สูตรคณิตศาสตร์ บล็อก HTML |
| `link` | ป้ายและปลายทางของลิงก์และรูปภาพ ลิงก์อัตโนมัติ |
| `muted` | เครื่องหมายข้อความอ้างอิง เส้นคั่นเชิงเนื้อหา แถวของตาราง คอมเมนต์ แอตทริบิวต์ของบล็อก |
| `codeKeyword`, `codeString`, `codeNumber`, `codeComment` | โค้ดที่ไฮไลต์ภายในรั้วโค้ด |

กลุ่มที่ไม่ได้กำหนดจะใช้สีในตัวที่เลือกให้เข้ากับพื้นหลังของตัวแก้ไข: โทนเข้มกว่าบนพื้นสว่าง โทนสว่างกว่าบนพื้นมืด ชื่อโทเค็นใน `syntax.tokens` ใช้ตัวอักษร ตัวเลข `_` และ `-` และต้องไม่ซ้ำกับชื่อกลุ่ม (`syntax.heading` ครอบคลุม `heading` อยู่แล้ว)

## สี

ทุกสีเป็นสตริงฐานสิบหก: `#RGB`, `#RGBA`, `#RRGGBB` หรือ `#RRGGBBAA` ใน sRGB Pilcrow เก็บเป็นตัวพิมพ์ใหญ่

## การตรวจสอบความถูกต้อง

Pilcrow ปฏิเสธไฟล์แทนที่จะละเว้นบางส่วน และระบุคีย์ที่ผิด เช่น `colors.editor.cursor: must be a hex colour` โดยจะปฏิเสธ:

- เวอร์ชัน `pilcrowAppTheme` ที่ขาดหายไปหรือต่างออกไป
- คีย์ที่ไม่รู้จักในระดับใดก็ตาม (มักเป็นการพิมพ์ผิด)
- คีย์ชุดสีที่ไม่ตรงกับรูปลักษณ์ (`colors` ในธีม automatic, `light` และ `dark` ในธีม light หรือ dark)
- สีที่ไม่ใช่ฐานสิบหก
- ธีม automatic ที่ชุดสี `light` และ `dark` กำหนดสีต่างกัน

## สิ่งที่ธีมแอปพลิเคชันไม่เปลี่ยน

แถบชื่อหน้าต่างและแถบเครื่องมือ (กระจกของระบบ ซึ่งรับเฉพาะสีเน้น) เมนู Settings ชีต และตัวเลือกยังคงหน้าตาดั้งเดิม นอกจากรูปลักษณ์และสีเน้น ฟอนต์ไม่ถูกกำหนดด้วยธีม: ฟอนต์และขนาดของตัวแก้ไขตั้งใน **Settings ▸ Appearance ▸ Text Size & Fonts** (**การตั้งค่า ▸ รูปลักษณ์ ▸ ขนาดข้อความและฟอนต์**)

## การติดตั้งและการแชร์

- **นำเข้า**ไฟล์ `.json` จาก **Settings ▸ Library ▸ Themes** (**การตั้งค่า ▸ คลัง ▸ ธีม**) **File ▸ Import ▸ Theme** (**ไฟล์ ▸ นำเข้า ▸ ธีม**) บน Mac หรือ **Settings ▸ Library ▸ Import** บน iPad การวางไฟล์ลงบน Pilcrow ก็ใช้ได้เช่นกัน
- แพ็กเกจธีม `.zip` อาจมีธีมแอปพลิเคชันควบคู่กับธีมการแสดงผล (บทที่ 80)
- ปุ่มแชร์ข้างธีมจะบันทึกไฟล์ `.json` ของธีม หรือทั้งแพ็กเกจหากธีมนั้นมาจากแพ็กเกจ

Pilcrow มีธีมแอปพลิเคชันสามธีม: **Automatic** (**อัตโนมัติ**), **Light** (**สว่าง**) และ **Dark** (**มืด**) ธีมเหล่านี้กำหนดสีของตัวแก้ไขและไวยากรณ์ และปล่อยส่วนโครงหน้าต่างไว้ตามหน้าตาในตัว

# Chapter 80: เอกสารอ้างอิง CSS ของธีมการแสดงผล

**Render Theme** (**ธีมการแสดงผล**) คือ CSS กำหนดสไตล์ให้ผลลัพธ์แบบ Preview, HTML, PDF, รูปภาพ และการพิมพ์ รวมถึงสไตล์ Word ที่ระบุไว้ท้ายบทนี้ ธีมการแสดงผลอาจเป็นไฟล์ `.css` ไฟล์เดียวหรือเป็นส่วนหนึ่งของแพ็กเกจ ZIP ที่มีทรัพยากรในเครื่อง โปรไฟล์ไวยากรณ์กำหนดว่าข้อความต้นฉบับกลายเป็นเอกสารได้อย่างไร ธีมการแสดงผลเพียงกำหนดสไตล์ให้ผลลัพธ์ CSS ไม่เคยกำหนดสไตล์ให้แอปหรือตัวแก้ไข นั่นคือหน้าที่ของธีมแอปพลิเคชัน (บทที่ 79)

## ลำดับการซ้อนทับ

Pilcrow ใช้สไตล์ตามลำดับนี้:

1. การรีเซ็ตโครงสร้างของ Pilcrow
2. CSS ของธีมที่เลือก
3. CSS ใช้ครั้งเดียวจากแผงส่งออก (**Advanced options ▸ Custom CSS**) (**ตัวเลือกขั้นสูง ▸ CSS กำหนดเอง**)
4. การแก้ไขที่จำเป็นสำหรับการพิมพ์และการแสดงผล

กฎที่มาทีหลังจะชนะตามลำดับการซ้อนทับของ CSS ปกติ JavaScript ในธีม ทรัพยากรระยะไกล URL แบบ `file:` และ `@import` ไม่รองรับ

## ทรัพยากร

Pilcrow อ่าน CSS ของธีมด้วยตัวแยกโทเค็น CSS มาตรฐาน ดังนั้นการหลีกอักขระจะถูกถอดรหัสก่อนตรวจสอบสิ่งใด: `u\72 l(…)` คือ `url()` และ `@im\70 ort` คือ `@import` ทุกที่ที่เบราว์เซอร์จะโหลดจะถูกตรวจสอบ: `url(…)`, `url("…")`, `src("…")` และสตริงภายใน `image-set()` แต่ละรายการต้องเป็นอย่างใดอย่างหนึ่งต่อไปนี้:

- พาธแบบสัมพันธ์กับแพ็กเกจ (`fonts/Body.woff2`, `./paper.png`) อนุญาตให้มี `?query` หรือ `#fragment` และจะถูกละเว้นเมื่อค้นหาไฟล์
- URL แบบ `data:` ประเภท PNG, JPEG, GIF, WebP, SVG (`image/svg+xml`), TTF, OTF, WOFF หรือ WOFF2
- การอ้างอิงแบบเศษส่วน เช่น `url(#shadow)` ซึ่งระบุชื่อองค์ประกอบในหน้า

สิ่งที่มี scheme อื่นนอกจาก `data:` (`https:`, `file:`, `blob:`) หรือขึ้นต้นด้วย `//` จะถูกปฏิเสธ เช่นเดียวกับพาธที่ขึ้นต้นด้วย `/` หรือมี `..`

## แพ็กเกจ ZIP

แพ็กเกจ ZIP อาจมีธีมการแสดงผล (`.css`) และธีมแอปพลิเคชัน (`.json`) ร่วมกัน แต่ละธีมจะแสดงในรายการพร้อมประเภทของตัวเองใน Settings ZIP ที่มี CSS ไม่เกินหนึ่งไฟล์และธีมแอปพลิเคชันไม่เกินหนึ่งไฟล์ไม่ต้องมีไฟล์ manifest หากมากกว่านั้นต้องมี `pilcrow-theme.json` ซึ่งแสดงทุกธีมภายใต้ `variants[].file` นามสกุลไฟล์เป็นตัวกำหนดประเภทของไฟล์:

```json
{
  "id": "com.example.paper",
  "name": "Paper",
  "version": "1.0.0",
  "author": "Example Author",
  "license": "MIT",
  "cssAPIVersion": 1,
  "variants": [
    { "id": "app", "name": "Paper", "file": "Paper.json", "appearance": "automatic" },
    { "id": "light", "name": "Paper Light", "file": "Paper-Light.css", "appearance": "light" },
    { "id": "dark", "name": "Paper Dark", "file": "Paper-Dark.css", "appearance": "dark" }
  ]
}
```

manifest อธิบายแพ็กเกจและธีมของแพ็กเกจ ไม่เคยมีค่าสไตล์: ค่าเหล่านั้นอยู่ในไฟล์ CSS และไฟล์ธีมแอปพลิเคชัน

- `id` ของแพ็กเกจกำหนดชื่อโฟลเดอร์ติดตั้ง ต้องไม่ขึ้นต้นด้วย `.` และไม่มีช่องว่างนำหน้าหรือต่อท้าย การติดตั้งแพ็กเกจที่มี `id` ติดตั้งอยู่แล้วจะแทนที่แพ็กเกจเดิม
- ZIP ที่สร้างด้วย **Compress** ของ Finder ใช้ได้ทันที Pilcrow ข้าม `__MACOSX/`, `._*`, `.DS_Store` และ `Thumbs.db` และเมื่อทุกไฟล์อยู่ในโฟลเดอร์ระดับบนสุดเดียว โฟลเดอร์นั้นจะถือเป็นรากของแพ็กเกจ
- การลบธีมหนึ่งธีมจะนำธีมนั้นออกจากแพ็กเกจและเก็บธีมอื่นไว้พร้อมกับทรัพยากรที่ใช้ร่วมกัน การลบธีมสุดท้ายจะลบแพ็กเกจ ธีมที่ถูกลบซึ่งเคยถูกเลือกไว้จะทำให้การเลือกกลับไปเป็นค่าเริ่มต้นของประเภทนั้น: Automatic สำหรับธีมแอปพลิเคชัน Light สำหรับธีมการแสดงผล
- CSS อ้างอิงไฟล์ PNG, JPEG, GIF, WebP, TTF, OTF, WOFF และ WOFF2 ที่อยู่ในแพ็กเกจได้ด้วยพาธ `url(...)` แบบสัมพัทธ์ Pilcrow ตรวจสอบลายเซ็นของไฟล์และฝังทรัพยากรที่อ้างอิงเป็น data URL เพื่อให้การแสดงผลและ HTML ที่ส่งออกยังคงทำงานแบบออฟไลน์และครบในตัว พาธใน ZIP ต้องไม่หลุดออกนอกแพ็กเกจ ไม่ซ้ำกันเมื่อไม่สนตัวพิมพ์เล็กใหญ่ และไม่ชี้ไปที่ลิงก์ ขนาดไฟล์เก็บถาวร จำนวนรายการ ขนาดแต่ละไฟล์ และอัตราส่วนการบีบอัดมีขีดจำกัด

## Word

การส่งออก Word ใช้ค่า `:root` แบบสว่าง (พื้นฐาน) และแมปคุณสมบัติเชิงความหมายเหล่านี้ไปยังสไตล์ Word ที่มีชื่อ: `--pt-foreground`, `--pt-background`, `--pt-accent`, `--pt-link-color`, `--pt-code-background`, `--pt-code-foreground`, `--pt-body-font-family`, `--pt-mono-font-family`, `--pt-base-font-size` และ `--pt-line-height` ตัวเลือกของเบราว์เซอร์และกฎเค้าโครงไม่มีสิ่งที่เทียบเท่าใน Word โดยทั่วไป ผลลัพธ์แบบ Preview, HTML, PDF และรูปภาพใช้สไตล์ชีตทั้งหมด ส่วน Word ใช้ชุดย่อยนี้ในขณะที่รักษาโครงสร้างเอกสาร แผนภาพ รูปสมการ ลิงก์ และสื่อไว้ แผงส่งออกจะแสดงข้อจำกัดนี้ทุกครั้งที่เลือก Word

Pilcrow มีธีมการแสดงผลสองธีม คือ **Light** (**สว่าง**) และ **Dark** (**มืด**) ซึ่งเป็นจุดเริ่มต้นที่สมบูรณ์
