# Chapter 24: สร้างเทมเพลตที่ใช้ซ้ำได้ด้วย Super Tab

ฟิลด์ช่วยเปลี่ยนการขยายข้อความแบบคงที่ให้เป็นแบบฟอร์มที่นำทางคุณได้ ฟิลด์หนึ่งอาจมีข้อความตัวอย่าง ค่าเริ่มต้น หรือรายการตัวเลือก

1. สร้างมาโครสำหรับโครงสร้างที่ใช้ซ้ำ
2. เพิ่มฟิลด์ในข้อความที่ขยาย หรือใช้ **แทรก ▸ ฟิลด์** ขณะสร้างต้นฉบับ
3. ขยายมาโคร
4. พิมพ์ลงในฟิลด์แรกที่ถูกเลือกไว้
5. ใช้ **ฟิลด์ถัดไป** เพื่อไปข้างหน้า และ **ฟิลด์ก่อนหน้า** เพื่อย้อนกลับ
6. สำหรับฟิลด์แบบตัวเลือก ให้เลือกจากรายการตัวเลือกของฟิลด์

ออกแบบฟิลด์ตามลำดับที่คนตอบได้อย่างเป็นธรรมชาติ วางเคอร์เซอร์สุดท้ายไว้ตรงจุดที่การเขียนอิสระควรดำเนินต่อไป ตั้งค่าเริ่มต้นให้ไม่เป็นอันตราย: ฟิลด์ที่ผู้ใช้ลืมกรอกควรเห็นได้ชัดใน ตัวอย่าง ไม่ใช่เผยแพร่เนื้อหาที่ทำให้เข้าใจผิดออกไปอย่างเงียบ ๆ

# Part VII — คณิตศาสตร์ แผนภาพ แผนภูมิ และรูปภาพ

# Chapter 25: เขียนสมการ แผนภาพ และแผนภูมิ

Pilcrow มีการแสดงผลแบบออฟไลน์สำหรับสมการ MathJax แผนภาพ Mermaid และแผนภูมิ Vega-Lite โปรไฟล์ที่ใช้งานอยู่ยังคงเป็นตัวกำหนดว่าบล็อกเริ่มและสิ้นสุดตรงไหน ส่วนไลบรารีที่มาพร้อมแอปจะวาดเฉพาะเนื้อหาข้างในเท่านั้น

## เริ่มจากเทมเพลต

1. เลือก **แทรก ▸ สมการ**, **แผนภาพ** หรือ **แผนภูมิ**
2. เลือกเทมเพลต
3. แทนที่ต้นฉบับตัวอย่าง
4. สลับไปที่ ตัวอย่าง หรือ เคียงข้างกัน
5. แก้ไขข้อผิดพลาดทางไวยากรณ์ที่รายงานในบล็อกต้นฉบับ

ใช้ MathJax สำหรับสัญกรณ์ทางคณิตศาสตร์ ใช้ Mermaid สำหรับผังงานและความสัมพันธ์ และใช้ Vega-Lite สำหรับแผนภูมิที่ขับเคลื่อนด้วยข้อมูล ควรมีคำอธิบายเป็นข้อความไว้ใกล้ภาพสำคัญทุกภาพ เพื่อให้เอกสารยังเข้าใจได้เมื่อไม่มีตัวแสดงผล และเข้าถึงได้สำหรับผู้อ่านมากขึ้น

ไลบรารีเหล่านี้มาพร้อมแอปและทำงานได้โดยไม่ต้องเชื่อมต่อเครือข่าย การตั้งค่า ▸ คลัง ▸ ไลบรารีการแสดงผล จะแสดงเวอร์ชันและประกาศต่าง ๆ หากบล็อกไม่แสดงผล ให้ตรวจสอบป้ายกำกับภาษา ตัวคั่น การตั้งค่าคุณสมบัติเสริม และไวยากรณ์ก่อนเปลี่ยนธีม

# Chapter 26: จัดการการแทรกรูปภาพและความเป็นส่วนตัวของรูปภาพออนไลน์

เปิด **การตั้งค่า ▸ การแก้ไข ▸ รูปภาพ** แล้วตัดสินใจเรื่องต่อไปนี้

- รูปภาพที่แทรกจะถูกคัดลอก ย้าย หรือปล่อยไว้ที่เดิม
- กฎนี้ใช้กับรูปภาพในเครื่องและรูปภาพออนไลน์หรือไม่
- อนุญาตให้โหลดรูปภาพออนไลน์หรือไม่
- ควรใช้พาธแบบสัมพัทธ์เมื่อเป็นไปได้หรือไม่
- พาธแบบสัมพัทธ์ขึ้นต้นด้วย `./` หรือไม่
- URL จะถูกหลีกอักขระเมื่อแทรกหรือไม่

สำหรับโปรเจกต์ที่พกพาได้ ให้เก็บรูปภาพไว้ในโฟลเดอร์ของเอกสารและใช้พาธแบบสัมพัทธ์ การคัดลอกปลอดภัยกว่าการย้ายเมื่อต้นฉบับเป็นของโปรเจกต์อื่น การย้ายช่วยหลีกเลี่ยงไฟล์ซ้ำ แต่อาจทำให้ตำแหน่งต้นทางเสียหาย

รูปภาพออนไลน์เปิดเผยที่อยู่เครือข่ายของผู้ดูให้โฮสต์ของรูปภาพทราบ และอาจเปลี่ยนแปลงหรือหายไปได้ ควรปิดการโหลดผ่านเครือข่ายไว้เมื่อตรวจทานเอกสารที่ไม่น่าไว้วางใจ สำหรับการเผยแพร่ระยะยาว ให้ดาวน์โหลดสำเนาที่ได้รับอนุญาตและอ้างอิงจากในเครื่อง

# Part VIII — เผยแพร่และแชร์

# Chapter 27: ส่งออกเป็น HTML, PDF, Word และรูปภาพ

1. บันทึกเอกสารและตรวจดู ตัวอย่าง
2. เลือก ส่งออก จากแถบเครื่องมือหรือคำสั่งของ ไฟล์
3. เลือก HTML, HTML (ไม่มีสไตล์), PDF, Word, รูปภาพ หรือ PDF Archive
4. เลือกธีมการแสดงผลใต้ **สไตล์**
5. สำหรับ PDF, PDF Archive และ Word ให้ตรวจสอบตัวเลือก **หน้า**: ขนาดกระดาษ การวางแนว และขอบกระดาษ
6. เลือก **ส่งออก** แล้วเลือกปลายทาง หรือเลือก **แชร์…** เพื่อส่งไฟล์ที่สร้างขึ้นโดยตรง

HTML สร้างหน้าเว็บแบบสแตนด์อโลนที่มีสไตล์ **HTML (ไม่มีสไตล์)** ให้โครงสร้างที่สะอาดโดยไม่ฝัง CSS ของธีม Word สร้างแพ็กเกจ `.docx` จริงที่มีโครงสร้างเอกสารเชิงความหมาย โดยสมการ แผนภาพ และแผนภูมิเสริมจะกลายเป็นรูปภาพ **รูปภาพ** สร้างไฟล์ PNG หนึ่งไฟล์จากเอกสารที่แสดงผลแล้ว **PDF Archive** สร้างไฟล์ ZIP ที่บรรจุส่วน PDF ที่เรียงลำดับแล้วพร้อมไฟล์รายการ (manifest) ซึ่งมีประโยชน์เมื่อเวิร์กโฟลว์อื่นต้องการส่วนที่มีขอบเขตและแยกจากกันได้ PDF ขนาดใหญ่ทั่วไปจะถูกประกอบผ่านเส้นทางการแสดงผลแบบแบ่งส่วนโดยอัตโนมัติ ส่วน PDF Archive จะเก็บส่วนเหล่านั้นไว้เป็นผลลัพธ์ที่ส่งมอบ

เปิด **ตัวเลือกขั้นสูง** เพื่อเพิ่ม **CSS กำหนดเอง** สำหรับการส่งออกครั้งนี้เท่านั้น CSS ต่อการส่งออกจะถูกใช้หลังธีม จึงมีผลเหนือกว่าเมื่อตัวเลือก (selector) มีน้ำหนักเท่ากัน การเปลี่ยนแปลงหน้ามีผลเฉพาะการส่งออกครั้งปัจจุบัน เว้นแต่คุณเลือก **ใช้การตั้งค่าหน้านี้เป็นค่าเริ่มต้น** สารบัญที่สร้างขึ้น การกำกับเลขหัวเรื่อง และป้ายหัวเรื่อง ตั้งค่าครั้งเดียวสำหรับทุกการส่งออกที่ **การตั้งค่า ▸ สารบัญ** (Chapter 70)

หากผลลัพธ์ไม่ถูกต้อง ให้พิจารณาว่าปัญหาอยู่ที่โครงสร้างหรือสไตล์ หัวเรื่องที่หายไปมักเป็นปัญหาของโปรไฟล์/ต้นฉบับ ส่วนหัวเรื่องที่ไม่สวยเป็นปัญหาของธีมการแสดงผล

## พิมพ์เอกสารที่แสดงผลแล้ว

เลือก **พิมพ์…** จาก ไฟล์ หรือ เพิ่มเติม การพิมพ์ใช้ไปป์ไลน์การแสดงผลและค่าเริ่มต้นของเลย์เอาต์หน้าเดียวกับ PDF ดังนั้น ตัวอย่าง และการส่งออก PDF จึงเป็นที่ที่เหมาะที่สุดในการวินิจฉัยโครงสร้างและสไตล์ก่อน บน Mac การตั้งค่าหน้ากระดาษจะแก้ไขเลย์เอาต์หน้าที่ใช้ร่วมกันเดียวกัน ตรวจสอบกระดาษ การวางแนว ขอบกระดาษ ส่วนหัว และส่วนท้ายในกล่องโต้ตอบการพิมพ์ก่อนพิมพ์ลงกระดาษจริง

# Chapter 28: ตั้งค่าเริ่มต้นการส่งออกและองค์ประกอบของหน้า

เปิด **การตั้งค่า ▸ ส่งออก ▸ ค่าเริ่มต้นการส่งออก** เลือกธีมการแสดงผลเริ่มต้นและเลย์เอาต์หน้า กำหนดข้อมูลผู้เขียน ส่วนหัว ส่วนท้าย และกำหนดว่าหัวเรื่องระดับบนสุดแต่ละอันจะขึ้นหน้าใหม่หรือไม่ (**ตัดหน้าระหว่างหัวเรื่องระดับบนสุด**)

เทมเพลตส่วนหัวและส่วนท้ายใส่ `${title}`, `${author}`, `${pageNo}`, `${pageCount}` และ `${today}` ได้ ควรให้สั้นพอที่จะพอดีกับขอบกระดาษ ทดสอบด้วย PDF หลายหน้า เพราะส่วนหัวที่ดูดีในหน้าเดียวอาจชนกับหัวเรื่องยาวหรือเลขหน้าในหน้าถัด ๆ ไป ค่าปรับแต่งเหล่านี้เก็บแยกตามรูปแบบผลลัพธ์ ส่วนเลย์เอาต์หน้าใช้ร่วมกันระหว่าง PDF, PDF Archive, Word และการพิมพ์

ตัวเลือก CommonMark ควบคุมไวยากรณ์เสริม เช่น การไฮไลต์ ตัวห้อย ตัวยก คณิตศาสตร์ในบรรทัด ลิงก์อัตโนมัติ การแจ้งเตือน front matter แผนภาพ เครื่องหมายวรรคตอนอัจฉริยะ และการแสดงผลของโค้ดแบบ fence เปิดใช้เฉพาะคุณสมบัติที่ต้นฉบับของคุณใช้จริงเท่านั้น เอกสาร CommonMark ที่พกพาได้ไม่ควรพึ่งพาส่วนขยายโดยไม่บันทึกไว้

# Chapter 29: แชร์ต้นฉบับและผลลัพธ์สำเร็จรูป

เลือก **แชร์…** สำหรับเอกสารต้นฉบับเมื่ออีกฝ่ายต้องการไฟล์ที่แก้ไขได้ เอกสารที่บันทึกแล้วและไม่มีการเปลี่ยนแปลงจะถูกแชร์โดยตรง เอกสารที่ยังไม่ได้บันทึกหรือมีการแก้ไขค้างอยู่จะถูกแชร์เป็นสำเนาชั่วคราวของข้อความปัจจุบัน เอกสารขนาดใหญ่มากอาจต้องบันทึกก่อน

เลือก **แชร์** ใน ส่งออก เมื่อผู้รับต้องการ PDF เอกสาร Word ไฟล์ HTML หรือรูปภาพที่เสร็จแล้ว วิธีนี้สร้างผลลัพธ์ให้โดยคุณไม่ต้องเก็บไฟล์ส่งออกที่บันทึกแยกไว้ก่อน

ก่อนแชร์ต้นฉบับ ให้รวมรูปภาพในเครื่อง เอกสารที่ลิงก์ โปรไฟล์ หรือธีมที่เกี่ยวข้อง เมื่อผู้รับต้องการให้ทำงานเหมือนกัน ก่อนแชร์ผลลัพธ์สำเร็จรูป ให้ตรวจสอบลิงก์ ตัวอย่าง การตัดหน้า ข้อความทดแทน และชื่อไฟล์

# Part IX — ผู้ช่วย

# Chapter 30: เชื่อมต่อผู้ให้บริการ AI อย่างปลอดภัย

ผู้ช่วยเป็นตัวเลือกเสริมและใช้การเชื่อมต่อที่คุณกำหนดค่าเอง Pilcrow ไม่เลือกผู้ให้บริการให้โดยไม่บอกคุณ

1. เปิด **การตั้งค่า ▸ ทั่วไป ▸ ผู้ช่วย**
2. เพิ่มค่าที่ตั้งไว้ล่วงหน้า หรือเลือก **กำหนดเอง…**
3. ป้อนชื่อ URL ฐาน รูปแบบสาย (wire format) และโมเดล
4. หากผู้ให้บริการต้องใช้ **คีย์ API** ให้เปิดตัวเลือกนั้นและเก็บคีย์เมื่อระบบถาม คีย์จะถูกเก็บไว้ใน Keychain ของระบบ
5. เลือก **ทดสอบการเชื่อมต่อ**
6. บันทึกและตั้งการเชื่อมต่อให้เป็นอันที่ใช้งาน

ใช้ **เลือกโมเดล…** ในผู้ช่วยเมื่อผู้ให้บริการมีการค้นหาโมเดล หากโมเดลหายไป ให้เลือกโมเดลปัจจุบันแทนที่จะลองตัวระบุที่ล้าสมัยซ้ำ ๆ

ก่อนใช้การเชื่อมต่อครั้งแรก Pilcrow จะแสดงว่าข้อความจะถูกส่งไปที่ใดและขอความยินยอม ให้อ่านชื่อโฮสต์ เซิร์ฟเวอร์ในเครื่องกับผู้ให้บริการคลาวด์สาธารณะมีผลต่อความเป็นส่วนตัวต่างกัน แม้จะมีรูปแบบ API เดียวกัน

# Chapter 31: ถามคำถามด้วยบริบทที่เลือกอย่างตั้งใจ

เปิดแถบด้านข้างของผู้ช่วยและเลือกโหมดสนทนา ชิปบริบทเริ่มต้นด้วยขอบเขตที่เล็กที่สุดที่มีประโยชน์ ซึ่งโดยปกติคือส่วนที่เลือก เลือกขอบเขตอื่นเฉพาะเมื่อคำถามต้องการ

1. เลือกย่อหน้าที่ต้องการความช่วยเหลือ
2. ยืนยันว่าชิปแสดง ส่วนที่เลือก และตรวจดูสรุปของมัน
3. ถามคำถามที่เฉพาะเจาะจง เช่น “ประโยคไหนทำให้ลำดับเหตุการณ์ไม่ชัดเจน”
4. อ่านคำตอบเป็นคำแนะนำ ไม่ใช่การแก้ไขอัตโนมัติ
5. ใช้การเปลี่ยนแปลงด้วยตัวเอง หรือผ่านการดำเนินการที่ผ่านการตรวจทานซึ่งผู้ช่วยเสนอ

Pilcrow ไม่นำรูปแบบและโฟลเดอร์ที่กำหนดให้ยกเว้นเข้าไปในบริบทของผู้ช่วย จัดการได้ในการตั้งค่าผู้ช่วย ใช้ตัวควบคุมโฟลเดอร์เพื่อปิดการเข้าถึงของผู้ช่วยสำหรับพื้นที่ทำงานที่ละเอียดอ่อน ล้างการสนทนาด้วยปุ่มถังขยะเมื่อไม่เกี่ยวกับงานปัจจุบันอีกต่อไป

อย่าแชร์ทั้งโฟลเดอร์เพียงเพราะคำถามพูดถึงไฟล์เดียว บริบทเท่าที่จำเป็นขั้นต่ำช่วยให้เป็นส่วนตัวมากขึ้นและมักทำให้คำตอบดีขึ้นด้วย

# Chapter 32: ขอความช่วยเหลือในการสร้างทรัพยากรของ Pilcrow

สลับผู้ช่วยไปที่ **วิธีใช้** แล้วเลือก โปรไฟล์ มาโคร หรือคู่มือสไตล์ Pilcrow จะแนบเอกสารอ้างอิงรูปแบบที่เกี่ยวข้องไปกับการสนทนา เพื่อให้คำสั่งต่อเนื่องอ้างอิงได้ถูกต้อง

อธิบายพฤติกรรมที่ต้องการและให้ตัวอย่างเล็ก ๆ ขอให้ร่างให้ ใช้ ตัวอย่าง เพื่อตรวจข้อความทรัพยากรที่สร้างขึ้น แล้วตรวจสอบความถูกต้องในตัวแก้ไขการตั้งค่าที่เกี่ยวข้อง อย่านำเข้าหรือบันทึก JSON ที่สร้างขึ้นโดยไม่รู้เนื้อหา โดยไม่อ่านชื่อ ตัวกระตุ้นหรือรูปแบบ และผลลัพธ์ของมันก่อน

ลำดับที่ได้ผลคือ

1. ระบุพฤติกรรมหนึ่งอย่างและตัวอย่างสองตัวอย่าง
2. ขอทรัพยากรที่ถูกต้องและเล็กที่สุด
3. ตรวจสอบความถูกต้องใน Pilcrow
4. ทดสอบกรณีที่สำเร็จหนึ่งกรณีและกรณีที่ไม่ตรงหนึ่งกรณี
5. ส่งข้อผิดพลาดจากการตรวจสอบกลับไปเพื่อแก้ไขอย่างตรงจุด

# Chapter 33: ตรวจทานสไตล์ด้วย AI ช่วย

ขั้นตอนนี้ต่อยอดจาก Chapter 21

1. เลือกข้อความตอนหนึ่งสำหรับการทดลองครั้งแรก
2. เลือก ตรวจทานสไตล์ คู่มือ ตัวแปร และด้านที่ต้องการตรวจทาน
3. ยืนยันผู้ให้บริการและโมเดลที่ใช้งานอยู่
4. เริ่มการตรวจทาน
5. จัดเรียงผลการตรวจพบตามความรุนแรงหรือด้านตามที่มีให้

7. ใช้ ปฏิเสธ หรือปล่อยไว้โดยยังไม่แก้

สำหรับทั้งเอกสาร Pilcrow จะประมาณจำนวนไบต์และจำนวนคำขอ และถามอีกครั้งก่อนส่ง คุณหยุดระหว่างช่วงได้ ตรวจทานเอกสารที่ละเอียดอ่อนในเครื่อง หรือกับผู้ให้บริการที่เงื่อนไขการจัดการข้อมูลเป็นที่ยอมรับได้ ลบข้อมูลและคีย์ AI จากการตั้งค่า ผู้ช่วย หรือ พื้นที่จัดเก็บและความเป็นส่วนตัว เมื่อเลิกใช้การเชื่อมต่อ

# Part X — โปรเจกต์หนังสือ

# Chapter 34: เปลี่ยนโฟลเดอร์ให้เป็นโปรเจกต์หนังสือ

สำหรับโปรเจกต์ใหม่ ให้เลือก **ไฟล์ ▸ หนังสือใหม่…** ป้อนชื่อเรื่องและปลายทาง แล้วให้ Pilcrow สร้างโฟลเดอร์เริ่มต้นและไฟล์รายการ (manifest) หากต้องการนำต้นฉบับที่มีอยู่แล้วมาใช้ ให้เปิดโฟลเดอร์ของมัน เลือก **ไฟล์ ▸ ทำให้โฟลเดอร์เป็นโปรเจกต์หนังสือ** หรือ **ทำให้เป็นโปรเจกต์** ในแถบด้านข้างโปรเจกต์ แล้วกรอกข้อมูลเมทาดาตาให้ครบ Pilcrow สร้างไฟล์ `manifest.pilcrow` ที่อธิบายลำดับและเมทาดาตา แต่ไม่จัดเรียงไฟล์ต้นฉบับใหม่

เปิดการตั้งค่าโปรเจกต์และป้อนชื่อเรื่อง ผู้เขียน จำนวนคำเป้าหมาย ตัวแปร พฤติกรรมการนับคำ และไวยากรณ์ เพิ่มไฟล์ที่มีอยู่ซึ่งแสดงเป็น **ไม่อยู่ในต้นฉบับ** หรือสร้างส่วนหน้า บท ฉาก และส่วนท้ายใหม่จากเมนูเครื่องหมายบวก

คอมมิตหรือสำรองข้อมูล `manifest.pilcrow` ไปพร้อมกับต้นฉบับ มันคือสารบัญสำหรับการจัดระเบียบโปรเจกต์ แม้ไฟล์ต้นฉบับจะยังเป็นข้อความธรรมดา

# Chapter 35: วางแผนฉากและติดตามความคืบหน้าของต้นฉบับ

เลือกระหว่าง **รายการ**, **เรื่องย่อ** และ **การ์ด**

- รายการเน้นลำดับของต้นฉบับและจำนวนคำ
- เรื่องย่อเพิ่มบทสรุป มุมมองการเล่าเรื่อง ตำแหน่ง สถานะ และความคืบหน้า
- การ์ดเป็นกระดานวางแผนแบบภาพโดยไม่เปลี่ยนลำดับไฟล์

เปิดรายละเอียดของรายการเพื่อกำหนดบทบาท สถานะ เรื่องย่อ มุมมองการเล่าเรื่อง ตำแหน่ง และจำนวนคำเป้าหมาย กรองตามสถานะเพื่อโฟกัสงานที่เป็นฉบับร่าง การแก้ไข หรือเสร็จสมบูรณ์ ลบรายการออกจากต้นฉบับโดยไม่ลบไฟล์ของมันเมื่อเป็นงานค้นคว้าหรือฉากที่ตัดออก

จัดลำดับใหม่เฉพาะเมื่อไม่มีตัวกรองสถานะที่ใช้งานอยู่ เพราะชุดย่อยที่กรองแล้วไม่สามารถแทนลำดับต้นฉบับทั้งหมดได้อย่างปลอดภัย บน iPad ให้เลือก **จัดลำดับใหม่** ลาก แล้วเลือก **เสร็จสิ้น** ยุบบทเพื่อลดความรกของรายการ

หาก Pilcrow แจ้งว่าไฟล์โปรเจกต์มีการเปลี่ยนแปลงบนดิสก์ ให้โหลดซ้ำแล้วทำการดำเนินการที่ตั้งใจไว้อีกครั้ง การป้องกันความขัดแย้งนี้ช่วยไม่ให้อุปกรณ์หรือผู้ร่วมงานคนหนึ่งเขียนทับ manifest ที่ใหม่กว่า

# Chapter 36: คอมไพล์ต้นฉบับ

1. เปิดแถบด้านข้างโปรเจกต์
2. ยืนยันลำดับ ไฟล์ที่รวมอยู่ และเมทาดาตาของโปรเจกต์
3. เลือก **คอมไพล์…**
4. เลือกรูปแบบผลลัพธ์ ธีมการแสดงผล และตัวเลือกการคอมไพล์
5. ตรวจทานส่วนหน้า การแบ่งบท การกำกับเลข และบทบาทที่รวมอยู่
6. คอมไพล์และตรวจดูผลลัพธ์

การคอมไพล์สร้าง HTML, PDF หรือ Word ได้ เลือกว่าส่วนหน้า ภาค บท และส่วนท้ายใดจะขึ้นหน้าใหม่ กำหนดตัวคั่นระหว่างฉาก รวมสารบัญ กำกับเลขหัวเรื่อง และเลือกได้ว่าจะเก็บสแนปชอตประวัติเวอร์ชันของทุกไฟล์ที่รวมอยู่ไว้ก่อนหรือไม่ สรุป ต้นฉบับ แสดงไฟล์ที่รวมอยู่ ไบต์ ไฟล์ที่ถูกละไว้ พาธที่ไม่พบ และลำดับสุดท้าย ต้องแก้ไฟล์ที่ไม่พบให้เรียบร้อยก่อนจึงจะใช้ คอมไพล์ ได้

บันทึกกลุ่มตัวเลือกการคอมไพล์เป็นค่าที่ตั้งไว้ล่วงหน้าที่มีชื่อ เมื่อคุณเผยแพร่ต้นฉบับเดียวกันหลายรูปแบบ เช่น “Editor DOCX” และ “Print PDF” ลบค่าที่ตั้งไว้ล่วงหน้าที่ไม่ใช้แล้วจากชีตเดียวกัน ขณะคอมไพล์ ความคืบหน้าจะแสดงจำนวนไฟล์ และ **หยุด** ยกเลิกการดำเนินการ `{{variables}}` ที่ยังไม่ถูกแก้จะถูกรายงานและปล่อยไว้ไม่เปลี่ยนแปลงให้เห็นได้ชัด

การคอมไพล์อ่านลำดับจาก manifest และรวมต้นฉบับในเชิงตรรกะ ไม่ได้ต่อไฟล์แล้วเขียนทับไฟล์ของคุณ แก้ฉากในไฟล์ต้นฉบับของมัน แล้วคอมไพล์อีกครั้ง ใช้ตัวแปรโปรเจกต์สำหรับเมทาดาตาที่ซ้ำ แทนการคัดลอกข้อความชื่อเรื่องหรือผู้เขียนด้วยมือ

# Part XI — โปรไฟล์ไวยากรณ์

# Chapter 37: เลือกและทำความเข้าใจโปรไฟล์ไวยากรณ์

โปรไฟล์บอก Pilcrow ว่าเครื่องหมายในต้นฉบับกลายเป็นบทบาทเชิงโครงสร้างได้อย่างไร CommonMark มาพร้อมแอป แต่เป็นเพียงโปรไฟล์หนึ่ง ไม่ใช่นิยามของแอป

ใช้ตัวควบคุมโปรไฟล์ในแถบสถานะหรือตัวควบคุมเอกสารที่เหมาะสมเพื่อเลือกโปรไฟล์ Pilcrow อนุมานโปรไฟล์จากนามสกุลไฟล์ได้ และจำตัวเลือกรายไฟล์ไว้ โปรไฟล์ที่ใช้งานอยู่ควบคุมการไฮไลต์ เค้าร่าง ความพร้อมใช้งานของการจัดรูปแบบ ตัวอย่าง โครงสร้างการส่งออก พฤติกรรมการต่อเนื่อง และสิ่งที่แทรกเฉพาะโปรไฟล์

เลือกโปรไฟล์ตามภาษาต้นฉบับที่มีอยู่แล้ว การเปลี่ยนโปรไฟล์ไม่ได้แปลงข้อความ แต่ตีความใหม่ หากต้องการแปลง ให้สร้างสำเนาและแปลงต้นฉบับอย่างชัดเจน

# Chapter 38: สร้างและทดสอบโปรไฟล์

1. เปิด **การตั้งค่า ▸ คลัง ▸ โปรไฟล์ไวยากรณ์**
2. ทำสำเนาโปรไฟล์ในตัวที่ใกล้เคียง หรือสร้างโปรไฟล์ใหม่
3. ใน **ภาพรวม** กำหนดชื่อ ตัวระบุ นามสกุล และการสืบทอดที่ไม่บังคับ
4. ใน **กฎ** เพิ่มโครงสร้างที่เล็กที่สุดที่คุณต้องการ
5. เปิด **ตัวอย่างทดสอบ** วางต้นฉบับที่เป็นตัวแทน แล้วเลือก **ตัวอย่างการตรวจสอบ**
6. บันทึก เปิดใช้โปรไฟล์ในเอกสารทดลอง แล้วเปรียบเทียบ แก้ไข เค้าร่าง ตัวอย่าง และการส่งออก

ทดสอบขอบเขต: ต้นและท้ายไฟล์ บรรทัดว่าง โครงสร้างซ้อน Unicode ตัวคั่นที่ไม่ปิด และข้อความที่ไม่ควรตรง โปรไฟล์น่าเชื่อถือเมื่อปฏิเสธกรณีเกือบตรงได้เช่นเดียวกับที่รู้จักตัวอย่างได้

ใช้ **ตั้งเป็นค่าพื้นฐานใหม่** หลังการแก้ไขที่ทราบว่าใช้ได้ดี **รีเซ็ตเป็นค่าพื้นฐาน** จะทิ้งการทดลองที่ทำภายหลัง ทำสำเนาก่อนการออกแบบใหม่ที่เสี่ยง

# Chapter 39: แก้ไขกฎของโปรไฟล์และ JSON ขั้นสูง

ตัวแก้ไขกฎแสดงประเภทรูปแบบ ข้อกำหนดการขึ้นต้นบรรทัด บทบาทที่สร้าง การจับกลุ่ม การต่อเนื่องหลังกด Return พฤติกรรมของบล็อกที่มีตัวคั่น เลย์เอาต์ การรันและคู่ในบรรทัด คำบรรยาย และบทบาทด้านสไตล์

ใช้ตัวจดจำแบบตรงตัวหรือมีโครงสร้างทุกครั้งที่แสดงไวยากรณ์ได้ ทำให้รูปแบบมีขอบเขตและยึดตำแหน่ง Pilcrow ปฏิเสธรูปแบบที่ทราบว่าไม่ปลอดภัย แต่นิพจน์ที่ผ่านทางเทคนิคก็ยังอาจกว้างหรือสับสนเกินไปได้

เลือก **แก้ไข JSON ขั้นสูง…** เฉพาะเมื่อตัวแก้ไขแบบภาพไม่แสดงคุณสมบัติที่ต้องการ **นำไปใช้** จะตรวจสอบ JSON และป้องกันการเปลี่ยนตัวตนของโปรไฟล์ผ่านชีตนั้น เก็บตัวอย่างทดสอบที่ถูกต้องไว้คู่กับงานขั้นสูง

การสืบทอดมีประโยชน์สำหรับภาษาถิ่นเล็ก ๆ: สืบทอดจากแม่ที่เสถียรแล้วแทนที่เฉพาะไวยากรณ์ที่ระบุชื่อ หลีกเลี่ยงสายโซ่ยาวที่ทำให้อธิบายพฤติกรรมได้ยาก หากการนำเข้าโปรไฟล์รายงานความขัดแย้ง ให้เปรียบเทียบชื่อและ ID ก่อนแทนที่สิ่งใด
