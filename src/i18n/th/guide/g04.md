# Part XII — ธีมและรูปลักษณ์

# Chapter 40: ทำความเข้าใจธีมแอปพลิเคชันและธีมการแสดงผล

Pilcrow มีระบบธีมสองระบบที่แยกจากกัน

- **ธีมแอปพลิเคชัน** เป็น JSON และกำหนดสไตล์ให้แอป แถบต่าง ๆ แถบด้านข้าง สีเน้น สีของตัวแก้ไข และรูปลักษณ์สว่างหรือมืด
- **ธีมการแสดงผล** เป็น CSS และกำหนดสไตล์ให้ ตัวอย่าง, HTML, PDF และส่วนย่อยเชิงความหมายที่ใช้กับ Word

เลือกทั้งสองอย่างได้ที่ **มุมมอง ▸ ธีม** หรือการตั้งค่า ไม่มีตัวสลับโหมดแยกต่างหากที่จะขัดกับธีมแอปพลิเคชัน เพราะธีมเป็นผู้ประกาศรูปลักษณ์เอง CSS ไม่กำหนดสไตล์ให้แอปหรือตัวแก้ไขต้นฉบับ

เมื่อตัวแก้ไขดูไม่ถูกต้อง ให้เปลี่ยนธีมแอปพลิเคชัน เมื่อ ตัวอย่าง หรือผลการส่งออกดูไม่ถูกต้อง ให้เปลี่ยนธีมการแสดงผล ความแตกต่างข้อนี้ช่วยแก้ความสับสนเรื่องธีมได้เกือบทั้งหมด

# Chapter 41: สร้างและจัดการธีม

เปิด **การตั้งค่า ▸ คลัง ▸ ธีม** เลือกชุดแอปพลิเคชันหรือชุดการแสดงผล แล้วทำสำเนา นำเข้า ส่งออก แก้ไข หรือลบธีมของผู้ใช้

สำหรับธีมแอปพลิเคชัน ใช้ตัวแก้ไขเพื่อกำหนดรูปลักษณ์ สีเน้น โครม แถบด้านข้าง แถบต่าง ๆ และสีของตัวแก้ไข ตรวจสอบคอนทราสต์ของส่วนที่เลือก ความเห็นได้ชัดของบรรทัดปัจจุบัน ลิงก์ คำเตือน และตัวควบคุมทั้งที่ใช้งานและไม่ได้ใช้งาน

สำหรับธีมการแสดงผล ให้แก้ CSS ตาม API คลาสของ Pilcrow เริ่มจากเปลี่ยนตัวอักษรและระยะห่าง จากนั้นเป็นหัวเรื่อง รายการ โค้ด ตาราง คอลเลาต์ ลิงก์ เชิงอรรถ และบล็อกเสริม ทดสอบตัวอย่างภาพใน `Examples/Themes/VisualTestPack` หากคุณทำงานจากเช็กเอาต์ของโปรเจกต์

ธีมในตัวเป็นจุดเริ่มต้นที่เสถียร ให้ทำสำเนาแทนการพยายามเขียนทับ แพ็กเกจ ZIP อาจมีธีมทั้งสองชนิด นามสกุลไฟล์เป็นตัวกำหนดว่าแต่ละรายการอยู่ที่ใด

# Chapter 42: เลือกฟอนต์ ขนาด ระยะห่าง และฉากหลัง

ใช้ **การตั้งค่า ▸ รูปลักษณ์ ▸ ขนาดข้อความและฟอนต์** สำหรับฟอนต์ของตัวแก้ไขและขอบ (gutter) ขนาดพอยต์ ระยะห่างระหว่างบรรทัด และความกว้างแท็บ การตั้งค่าเหล่านี้มีผลกับพื้นที่เขียน ไม่ใช่ตัวอักษรที่ส่งออก

ใช้ **ธีมและฉากหลัง** สำหรับธีมแอปพลิเคชัน ซูม ความเร็วในการอ่าน และรูปภาพเสริมด้านหลังพื้นที่ข้อความหรือแถบด้านข้าง เลือก แทนที่ หรือลบฉากหลังแต่ละอย่างแยกกัน ฉากหลังควรรักษาคอนทราสต์และสมาธิ รูปภาพสวยที่ทำให้อ่านยากเป็นการตั้งค่าตัวแก้ไขที่ไม่ดี

ใช้ธีมการแสดงผลและค่าเริ่มต้นการส่งออกสำหรับฟอนต์ที่เผยแพร่และเลย์เอาต์หน้า การแยกนี้ช่วยให้คุณเขียนในตัวแก้ไขแบบโมโนสเปซที่อ่านง่ายมาก ขณะที่เผยแพร่ด้วยตัวอักษรแบบสัดส่วนสำหรับหนังสือ

# Part XIII — นำเข้า ส่งออก และจัดการคลังของคุณ

# Chapter 43: นำเข้าและแชร์ทรัพยากรของ Pilcrow

Pilcrow นำเข้าโปรไฟล์ไวยากรณ์ ธีมแอปพลิเคชัน ธีมการแสดงผล ชุดมาโคร คู่มือสไตล์ และแพ็กเกจ ZIP ที่มีทรัพยากรที่รองรับได้

1. เปิดหน้าการตั้งค่าคลังที่ตรงกัน หรือหน้านำเข้าบน iOS
2. เลือกนำเข้าและเลือกไฟล์
3. ตรวจดูประเภททรัพยากร ชื่อ และความขัดแย้งใด ๆ
4. นำเข้า เปลี่ยนชื่อ หรือแทนที่ก็ต่อเมื่อเข้าใจผลที่ตามมา
5. เปิดใช้งานและทดสอบในเอกสารทดลอง

ส่งออกทรัพยากรของผู้ใช้จากหน้าคลังของมันเพื่อแชร์หรือสำรองข้อมูล เก็บทรัพยากรที่เกี่ยวข้องไว้ใน ZIP เดียวเมื่อโปรเจกต์ต้องการโปรไฟล์ ธีม มาโคร และคู่มือไปด้วยกัน

ปฏิบัติต่อโปรไฟล์ มาโคร CSS และคู่มือสไตล์ที่นำเข้าเหมือนการกำหนดค่าที่คล้ายโค้ด อ่านตัวกระตุ้น รูปแบบ CSS ดิบ และคำสั่งของผู้ช่วยก่อนไว้วางใจ

# Chapter 44: ย้ายหรือกู้คืนคลังของคุณ

เปิด **การตั้งค่า ▸ คลัง ▸ ตำแหน่ง** เลือกโฟลเดอร์หรือ **ใช้อุปกรณ์นี้** หากปลายทางมีคลังอยู่แล้ว ให้เลือกระหว่าง

- **ใช้ที่มีอยู่** เพื่อสลับไปใช้โดยไม่คัดลอก
- **ย้ายคลังของฉันมาที่นี่** เพื่อถ่ายโอนและลบสำเนาที่จัดการไว้เดิมหลังสำเร็จ
- **คัดลอกคลังของฉันมาที่นี่** เพื่อเก็บไว้ทั้งสองที่

ใช้โฟลเดอร์ที่ซิงก์เฉพาะเมื่อผู้ให้บริการรักษาไฟล์ธรรมดาได้อย่างเชื่อถือได้ และคุณเข้าใจเรื่องการแก้ไขพร้อมกัน ปล่อยให้การถ่ายโอนเสร็จก่อนออกจากแอป หากตำแหน่งใช้งานไม่ได้ ให้เชื่อมต่อไดรฟ์หรือบัญชีอีกครั้ง หรือเลือกตำแหน่งอื่น อย่าสร้างทรัพยากรทดแทนที่ขัดแย้งกันโดยไม่ตรวจสอบ

บน iOS หน้านำเข้ากู้คืนเนื้อหาคลังจากแพ็กเกจได้ ตรวจสอบธีมและโปรไฟล์ที่ใช้งานอยู่หลังการกู้คืน เพราะ ID ของทรัพยากร ไม่ใช่แค่ชื่อที่แสดง เป็นตัวกำหนดการอ้างอิง

# Part XIV — การตั้งค่า ความเป็นส่วนตัว และการสนับสนุน

# Chapter 45: กำหนดค่า ทั่วไป ไฟล์ และการแก้ไข

การตั้งค่าถูกจัดกลุ่มและค้นหาได้ ใช้ช่องค้นหาด้วยป้ายชื่อ เช่น “line numbers” “image” หรือ “header”

## ทั่วไป

กำหนดค่าพฤติกรรมของหน้าต่างและการเปิดแอป ภาษา การแปล การเชื่อมต่อผู้ช่วย การวินิจฉัย และพื้นที่จัดเก็บและความเป็นส่วนตัว

## ไฟล์

เลือกพฤติกรรมของโฟลเดอร์ตอนเปิดแอป ชนิดไฟล์เริ่มต้น การบันทึกอัตโนมัติและการกู้คืน จำนวนเวอร์ชันที่เก็บไว้ พฤติกรรมของแผนผังไฟล์ และสิ่งที่เกิดขึ้นเมื่อลากรายการที่นำเข้าได้มาวางบนแอป

## การแก้ไข — การแสดงผลและการพิมพ์

กำหนดค่าเลขบรรทัด แถบสถานะ แถบเครื่องมือจัดรูปแบบ การตัดบรรทัด เส้นบรรทัดปัจจุบัน ต้นฉบับที่มีสไตล์ เครื่องหมาย บล็อกที่แสดงผล การพับหัวเรื่อง การขยายอัตโนมัติ การจับคู่วงเล็บและเครื่องหมายคำพูด การจับคู่ Markdown รหัสย่ออีโมจิ การต่อเนื่องของรายการและคำพูดอ้างอิง การเยื้องเมื่อกด Return ช่องว่างแทนแท็บ การสะกดคำ และคำเตือนการแยกวิเคราะห์

## การแก้ไข — เสียงการพิมพ์

เปิด **เล่นเสียงขณะพิมพ์** เพื่อให้ได้ยินเสียงขณะคุณพิมพ์ เลือกชุดเสียง (เครื่องพิมพ์ดีด เป็ด หรือลูกแมว) ตั้งระดับเสียง และใช้ **ตัวอย่าง** เพื่อฟังเสียง แต่ละชนิดของแป้นมีเสียงของตัวเอง: ตัวอักษรพิมพ์เล็ก ตัวอักษรพิมพ์ใหญ่ ตัวเลข สัญลักษณ์ ช่องว่าง แท็บ Return และ Delete การวางและการแก้ไขหลายอักขระจะไม่มีเสียง

ใต้ **เสียงของคุณเอง** เลือก **เลือก…** ถัดจากชนิดของแป้นเพื่อใช้ไฟล์เสียงของคุณเองกับแป้นนั้น (WAV, AIFF, MP3, M4A หรือ CAF) คลิปยาวได้ไม่เกิน 2 วินาทีและขนาดไม่เกิน 3 MB Pilcrow แปลงเป็นคลิปโมโนขนาดเล็ก ดังนั้นไฟล์ที่ยาวหรือดังจะไม่ทำให้การพิมพ์ช้าหรือเกิดเสียงคลิก ใช้ **เล่น** เพื่อฟัง และ **ลบออก** เพื่อกลับไปใช้เสียงของชุดเสียง หากไฟล์ถูกปฏิเสธ ข้อความจะบอกเหตุผล บน iPad สวิตช์ปิดเสียงจะปิดเสียงการพิมพ์ และเสียงจะผสมกับเสียงอื่น

## การแก้ไข — รูปภาพ

กำหนดค่าการแทรก การคัดลอกหรือการย้าย การโหลดออนไลน์ รูปแบบพาธ และการหลีก URL

## รูปลักษณ์

เลือกธีมแอปพลิเคชัน ซูม ฉากหลัง ขนาดตัวแก้ไข ฟอนต์ ระยะห่างระหว่างบรรทัด และความกว้างแท็บ

## ส่งออก

เลือกธีมการแสดงผล เลย์เอาต์ ส่วนหัว ส่วนท้าย เมทาดาตา และการตัดหน้าตามหัวเรื่อง

## คลัง

จัดการโปรไฟล์ ตัวเลือก CommonMark ธีม มาโคร คู่มือสไตล์ ไลบรารีการแสดงผล ตำแหน่ง และการนำเข้า

## แป้นพิมพ์

ค้นหา กำหนดใหม่ ยกเลิกการกำหนด และรีเซ็ตทางลัด รวมถึงพฤติกรรมการนำทางระหว่างฟิลด์

เปลี่ยนทีละกลุ่ม เมื่อประเมินตัวอักษร ให้คงธีมไว้ไม่เปลี่ยน เมื่อประเมินการแยกวิเคราะห์ ให้คงโปรไฟล์ไว้ไม่เปลี่ยน การเปลี่ยนแปลงที่ควบคุมได้ทำให้เห็นเหตุและผลชัดเจน

# Chapter 46: ควบคุมความเป็นส่วนตัวและข้อมูลที่จัดเก็บ

เปิด **การตั้งค่า ▸ ทั่วไป ▸ พื้นที่จัดเก็บและความเป็นส่วนตัว** Pilcrow แยกการลบตามหมวดหมู่ เพื่อไม่ให้การล้างแคชลบเอกสารโดยไม่ได้ตั้งใจ

- **ตรวจสอบข้อมูลการกู้คืน…** แสดงรายการเนื้อหาที่กู้คืนได้ บันทึกหรือปิดเอกสารที่ยังมีการแก้ไขค้างอยู่ก่อนลบ
- **ตรวจสอบประวัติเวอร์ชัน…** แสดงเวอร์ชันและพื้นที่โดยประมาณก่อนลบ
- **ล้างสิทธิ์เข้าถึงไฟล์ล่าสุด…** ลบไฟล์ล่าสุด โฟลเดอร์ที่จำไว้ บุ๊กมาร์กของเซสชัน และตัวเลือกไวยากรณ์รายไฟล์
- **ลบข้อมูลและคีย์ AI…** ลบการเชื่อมต่อ คีย์ใน Keychain การสนทนา และตัวเลือกความเป็นส่วนตัวของ AI
- **ลบข้อมูลวินิจฉัย…** ลบบันทึกที่ถูกบันทึกไว้และข้อมูลสนับสนุนการขัดข้อง
- **ล้างแคช…** ลบแคชที่สร้างใหม่ได้และการตอบกลับจากเครือข่าย

โปรไฟล์ ธีม มาโคร คู่มือสไตล์ และฉากหลังที่กำหนดเองยังคงอยู่ในหน้าคลังที่มองเห็นได้ และต้องตรวจสอบที่นั่น การควบคุมเหล่านี้ไม่ลบเอกสารของคุณ

การตั้งค่าผู้ช่วยยังจัดการรูปแบบไฟล์ที่ยกเว้น โฟลเดอร์ที่ปิดผู้ช่วย และการลบข้อมูล AI การโหลดรูปภาพออนไลน์เป็นตัวเลือกความเป็นส่วนตัวแยกต่างหาก การตรวจสอบลิงก์ไม่เคยเข้าถึงเครือข่าย

# Chapter 47: บันทึกและส่งข้อมูลวินิจฉัย

เปิด **การตั้งค่า ▸ ทั่วไป ▸ การวินิจฉัย** สำหรับปัญหาที่เกิดเป็นช่วง ๆ ให้เลือก **สร้างปัญหาซ้ำ** เลือกส่วนที่เกี่ยวข้อง ระดับ ระยะเวลาเก็บ และข้อมูลสนับสนุนที่รวมไว้ ตัวเลือกประกอบด้วยข้อมูลอุปกรณ์/ระบบ การตั้งค่า Pilcrow ความเร็วและหน่วยความจำ รอยการกระทำล่าสุด และรายละเอียดการขัดข้อง

สร้างปัญหาซ้ำทันที แล้วเลือก **ดูบันทึก…** กรองตามระบบย่อยและความรุนแรง ก่อนส่ง ให้ตรวจดูรายงาน เลือก **วิธีใช้ ▸ รายงานข้อบกพร่อง…** เพื่อเปิดแบบฟอร์มรายงานข้อบกพร่องบน GitHub โดยกรอกเวอร์ชันของคุณให้แล้ว และให้ Pilcrow คัดลอกบันทึกไปไว้ในคลิปบอร์ดเพื่อวางลงไป คุณยังบันทึกรายงานเป็นไฟล์เพื่อแนบ แชร์ หรือเลือก **รายงานบน GitHub…** จากตัวดูบันทึกได้ด้วย รายงานบน GitHub เป็นสาธารณะ

การวินิจฉัยควรบันทึกความยาว ตัวระบุ สถานะ และข้อผิดพลาด ไม่ใช่เนื้อหาเอกสาร แต่ควรตรวจดูรายงานก่อนแชร์เสมอ ตั้งการบันทึกกลับเป็น **เฉพาะปัญหา** หรือปิดการเก็บรายละเอียดหลังจากจับปัญหาได้แล้ว การบันทึกแบบละเอียดอาจใช้พื้นที่จัดเก็บและส่งผลต่อประสิทธิภาพ

# Chapter 48: ใช้ Pilcrow ในภาษาอื่น

เปิดการตั้งค่าและเลือก ภาษา อาจต้องรีสตาร์ต Pilcrow มีภาษาอังกฤษ รวมถึงสเปน ฝรั่งเศส เยอรมัน อิตาลี โปรตุเกสบราซิล ดัตช์ รัสเซีย ญี่ปุ่น เกาหลี และจีนตัวย่อ

การแปลอินเทอร์เฟซที่ไม่ใช่ภาษาอังกฤษสร้างโดย AI จนกว่าจะมีเครื่องหมายว่าผ่านการตรวจทานโดยมนุษย์ Pilcrow แสดงประกาศตอนเริ่มต้นในภาษาเหล่านั้น เลือก **ไม่ต้องแสดงอีก** เพื่อปิดถาวร หรือเปิดประกาศอีกครั้งในการตั้งค่าภาษา ป้ายกำกับ “Machine-translated — may contain errors” ระบุเนื้อหาที่ยังไม่ได้ตรวจทาน

การเปลี่ยนภาษาของอินเทอร์เฟซไม่ได้แปลเอกสาร ใช้คำสั่งการแปลสำหรับข้อความในเอกสาร หากคำสั่งใดกำกวมในคำแปล ให้สลับไปใช้ภาษาอังกฤษชั่วคราวเพื่อดูถ้อยคำต้นฉบับที่เป็นทางการ

# Chapter 50: แก้ไขปัญหาที่พบบ่อย

## ไฟล์แสดงเป็นตัวอักษรเพี้ยน

ตรวจสอบการเข้ารหัสในแถบสถานะ เปิดใหม่หรือแปลงด้วยการเข้ารหัสที่ถูกต้องก่อนแก้ไข

## การจัดรูปแบบหรือตัวอย่างไม่ถูกต้อง

ยืนยันโปรไฟล์ที่ใช้งานอยู่ ตรวจสอบตัวคั่นในต้นฉบับ เปิดไวยากรณ์เสริมที่ต้องใช้ แล้วจึงยืนยันธีมการแสดงผล ใช้ แก้ไข โดยแสดงเครื่องหมายเพื่อตรวจข้อความตามตัวอักษร

## คำสั่งจัดรูปแบบหรือแทรกถูกปิดใช้งาน

สลับจาก ตัวอย่าง ไปที่ แก้ไข จากนั้นยืนยันว่ามีเอกสารและโปรไฟล์ไวยากรณ์ที่ใช้งานอยู่ และโปรไฟล์รองรับโครงสร้างที่ขอ

## แผนภาพ แผนภูมิ หรือสมการไม่แสดงผล

ตรวจสอบป้ายกำกับภาษาของ fence ขอบเขตของบล็อก ไวยากรณ์ต้นฉบับ และตัวเลือกแผนภาพ/คณิตศาสตร์ เริ่มจากเทมเพลตที่มาพร้อมแอปเพื่อแยกข้อผิดพลาด

## ค้นหาไม่พบข้อความที่เห็นใน ตัวอย่าง

ค้นหาใน แก้ไข สำหรับข้อความที่ถูกแบ่งด้วยการจัดรูปแบบหรืออยู่ในโค้ด สมการ แผนภาพ หรือแผนภูมิ การค้นหาใน ตัวอย่าง ครอบคลุมเฉพาะข้อความที่แสดงผลและอ่านได้ ไม่ใช่ทุกโหนดของต้นฉบับ โดยตั้งใจ

## รูปภาพหรือลิงก์แบบสัมพัทธ์เสีย

บันทึกเอกสารเพื่อให้มีโฟลเดอร์ ตรวจสอบชื่อไฟล์และตัวพิมพ์ใหญ่เล็กให้ตรงทุกตัว ใช้พาธแบบสัมพัทธ์ภายในโปรเจกต์เป็นหลัก และเรียกใช้ ตรวจสอบลิงก์

## การแทนที่ในโฟลเดอร์ข้ามบางไฟล์

ปิดไฟล์เหล่านั้นใน Pilcrow ตรวจสอบว่าเป็นข้อความ UTF-8 เรียกใช้ตัวอย่างอีกครั้ง และตรวจว่าไฟล์ไม่ได้ถูกเปลี่ยนจากภายนอกระหว่างตัวอย่างกับการคอมมิต

## มาโครไม่ทำงาน หรือทำงานบ่อยเกินไป

ยืนยันว่าชุดและมาโครเปิดใช้งานอยู่ ตรวจสอบประเภทการจับคู่และขอบเขตตัวกระตุ้น ทดสอบนอกโค้ด และทำให้รูปแบบที่กว้างเกินไปแคบลง

## การแปลใช้งานไม่ได้

ยืนยันว่าเป็น macOS 15 หรือ iOS 18 ขึ้นไป ติดตั้งการรองรับภาษาแล้ว และมีคู่ภาษาต้นทาง/ปลายทางที่รองรับ การแปลเอกสารต่างจากภาษาของอินเทอร์เฟซ

## ผู้ช่วยใช้งานไม่ได้

เพิ่มและทดสอบการเชื่อมต่อ ตั้งให้ใช้งานอยู่ เลือกโมเดลที่เสนอให้ รับทราบผู้ให้บริการ และตรวจว่าโฟลเดอร์หรือไฟล์ไม่ได้ถูกยกเว้น

## การดำเนินการกับไฟล์ขนาดมหึมาช้า

รอให้การทำดัชนีบรรทัดเบื้องหลังเสร็จ ใช้การค้นหาแบบเจาะจง และหลีกเลี่ยง PDF หรือการแปลงทั้งเอกสารเมื่อเวิร์กโฟลว์ HTML/Word แบบสตรีมตอบโจทย์ได้

## Pilcrow รายงานว่าปิดตัวโดยไม่คาดคิดหรือตัวแก้ไขไม่ซิงก์

หยุดแก้ไข บันทึกสำเนาหากทำได้ ใช้การกู้คืนเมื่อมีให้ และบันทึกข้อมูลวินิจฉัยก่อนเปิดแอปใหม่ อย่าทิ้งชุดการกู้คืนจนกว่าจะตรวจสอบเอกสารที่บันทึกแล้ว

## แผงโปรเจกต์รายงานความขัดแย้งของ manifest

โหลดซ้ำ ตรวจสอบสถานะโปรเจกต์ล่าสุด แล้วทำการเปลี่ยนแปลงซ้ำ อย่าเขียนทับ `manifest.pilcrow` จากสองอุปกรณ์พร้อมกัน

## ทรัพยากรที่กำหนดเองนำเข้าไม่ได้

ยืนยันนามสกุลและรูปแบบ JSON/CSS ที่คาดไว้ ตรวจสอบรูปแบบที่ไม่ปลอดภัยหรือความขัดแย้งที่รายงาน และนำเข้าไปยังส่วนธีมแอปพลิเคชัน ธีมการแสดงผล โปรไฟล์ มาโคร หรือคู่มือสไตล์ที่ถูกต้อง

# Chapter 51: สร้างกิจวัตรการทำงานที่พึ่งพาได้

ใช้กิจวัตรนี้สำหรับงานทั่วไป

1. เปิดโฟลเดอร์ ไม่ใช่แค่ไฟล์เดี่ยว เมื่อเอกสารมีทรัพยากรที่เกี่ยวข้อง
2. ยืนยันโปรไฟล์และการเข้ารหัสก่อนแก้ไขมาก ๆ
3. บันทึกจุดตรวจสอบเริ่มต้น
4. เขียนใน แก้ไข ใช้ เคียงข้างกัน เมื่อโครงสร้างสำคัญ
5. ใช้มาโครและฟิลด์สำหรับงานซ้ำ ไม่ใช่การคัดลอกด้วยมือ
6. บันทึกก่อนการแทนที่จำนวนมาก การยอมรับการเปรียบเทียบ การแทนที่ด้วยคำแปล หรือการทดลองกับโปรไฟล์
7. ตรวจการสะกด ตรวจทานสไตล์ และตรวจสอบลิงก์ในขั้นตอนที่เหมาะสม
8. คลี่ทุกส่วนออกและตรวจดู ตัวอย่าง ตั้งแต่ต้นจนจบ
9. ส่งออกด้วยธีมการแสดงผลที่ตั้งใจไว้ และตรวจดูรูปแบบปลายทางจริง
10. แชร์ต้นฉบับเมื่อผู้รับต้องแก้ไขเท่านั้น มิฉะนั้นให้แชร์ผลลัพธ์สำเร็จรูป
11. เก็บโปรไฟล์ ธีม มาโคร คู่มือสไตล์ manifest ของโปรเจกต์ และทรัพยากรในเครื่องไว้กับข้อมูลสำรองของโปรเจกต์
12. ตรวจสอบการกู้คืน เวอร์ชัน ข้อมูล AI การวินิจฉัย และแคชเป็นระยะที่ พื้นที่จัดเก็บและความเป็นส่วนตัว

เหตุผลนั้นเรียบง่าย: ทำให้ความหมายชัดเจนในต้นฉบับ เก็บการนำเสนอไว้ในธีม ตั้งจุดตรวจก่อนการดำเนินการที่เปลี่ยนแปลง แชร์ข้อมูลเท่าที่จำเป็นน้อยที่สุด และตรวจสอบสิ่งที่อีกฝ่ายจะได้รับจริง นั่นคือวิถีของ Pilcrow ที่ทำให้ข้อความธรรมดาทั้งทรงพลังและพึ่งพาได้
