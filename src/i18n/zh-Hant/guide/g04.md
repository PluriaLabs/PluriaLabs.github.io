# Part XII — 佈景主題與外觀

# Chapter 40: 了解應用程式佈景主題與渲染佈景主題

Pilcrow 有兩套各自獨立的佈景主題系統：

- **應用程式佈景主題** 為 JSON，用來設定 App、列、側邊欄、強調色、編輯器色彩，以及淺色或深色外觀的樣式。
- **渲染佈景主題** 為 CSS，用來設定預覽、HTML、PDF，以及 Word 所用的語意子集的樣式。

請在 **檢視 ▸ 佈景主題** 或「設定」中選擇這兩者。沒有獨立的模式切換會與應用程式佈景主題相抵觸；佈景主題自己就會宣告其外觀。CSS 不會設定 App 或原始碼編輯器的樣式。

當編輯器看起來不對時，請更換應用程式佈景主題。當預覽或匯出結果看起來不對時，請更換渲染佈景主題。光是這個區別，就能解決大部分佈景主題的困惑。

# Chapter 41: 建立與管理佈景主題

開啟 **設定 ▸ 資料庫 ▸ 佈景主題**。選擇應用程式或渲染集合，然後可以複製、匯入、匯出、編輯或刪除使用者佈景主題。

對於應用程式佈景主題，請使用編輯器設定外觀、強調色、外框、側邊欄、列與編輯器色彩。請檢查選取範圍的對比、目前行的可見度、連結、警告，以及使用中與非使用中的控制項。

對於渲染佈景主題，請依據 Pilcrow 的類別 API 編輯 CSS。先從字體排印與間距開始修改，再處理標題、清單、程式碼、表格、提示框、連結、註腳與補充區塊。若你是從專案原始碼簽出內容進行作業，請測試 `Examples/Themes/VisualTestPack` 中的視覺樣本。

內建項目是穩定的起點。請複製，不要嘗試覆寫它們。一個 ZIP 套件可以同時包含兩種佈景主題；檔案副檔名會決定各項目歸屬的位置。

# Chapter 42: 選擇字體、大小、間距與背景圖

請使用 **設定 ▸ 外觀 ▸ 文字大小與字體** 設定編輯器與邊欄的字體、點數大小、行距與定位字元寬度。這些設定影響的是書寫介面，不影響匯出的字體排印。

請使用 **佈景主題與背景圖** 設定應用程式佈景主題、縮放、閱讀速度，以及文字區域或側邊欄後方的選用圖片。每個背景圖都可以分別選擇、替換或移除。背景圖應保有對比與專注感；一張美麗卻降低可讀性的圖片，並不是好的編輯器設定。

請使用渲染佈景主題與匯出預設值來設定發布用的字體與頁面版面。這樣的分離讓你能在高度易讀的等寬編輯器中寫作，同時以比例字型的書籍字體發布。

# Part XIII — 匯入、匯出與管理你的資料庫

# Chapter 43: 匯入與分享 Pilcrow 資源

Pilcrow 可以匯入語法設定檔、應用程式佈景主題、渲染佈景主題、巨集集合、風格指南，以及包含受支援資源的 ZIP 套件。

1. 開啟對應的「資料庫」設定頁面，或在 iOS 上開啟「匯入」頁面。
2. 選擇「匯入」並選取檔案。
3. 檢視資源類型、名稱與任何衝突。
4. 只有在了解後果時，才進行匯入、重新命名或取代。
5. 在用完即丟的文件中啟用並測試它。

請從「資料庫」頁面匯出使用者資源，以便分享或備份。若專案需要同時包含設定檔、佈景主題、巨集與指南，請將相關資源放在同一個 ZIP 中。

請把匯入的設定檔、巨集、CSS 與風格指南視為類似程式碼的設定。在信任它們之前，請先閱讀觸發條件、模式、原始 CSS 與助理指示。

# Chapter 44: 移動或還原你的資料庫

開啟 **設定 ▸ 資料庫 ▸ 位置**。選擇資料夾或 **使用此裝置**。若目的地已包含資料庫，請在下列選項中選擇：

- **使用現有的**：不拷貝，直接切換。
- **將我的資料庫移到此處**：成功後轉移並移除舊的受管理副本。
- **將我的資料庫拷貝到此處**：兩份都保留。

只有在其供應商能可靠地保存一般檔案，且你了解同時編輯的情況時，才使用同步資料夾。請讓轉移完成後再結束。若位置變得無法使用，請重新連接磁碟機或帳號，或選擇其他位置；請勿在不明就裡的情況下建立相衝突的取代資源。

在 iOS 上，「匯入」頁面可以從套件還原資料庫內容。還原後，請驗證使用中的佈景主題與設定檔，因為定義參照的是資源 ID，而不只是顯示名稱。

# Part XIV — 設定、隱私與支援

# Chapter 45: 設定「一般」、「檔案」與「編輯」

設定已分組且可搜尋。請使用搜尋欄位輸入「行號」、「圖片」或「頁首」之類的標籤。

## 一般

設定視窗與啟動行為、語言、翻譯、助理連線、診斷，以及「儲存空間與隱私」。

## 檔案

選擇啟動資料夾行為、預設檔案類型、自動儲存與復原、保留的版本數、檔案樹行為，以及把可匯入的項目拖放到 App 上時的處理方式。

## 編輯中 — 顯示與輸入

設定行號、狀態列、格式工具列、換行、目前行標線、套用樣式的原始碼、標記、渲染區塊、標題摺疊、自動展開、括號與引號配對、Markdown 配對、表情符號簡碼、清單與引用的延續、按下換行時的縮排、以空格取代定位字元、拼字檢查與解析警告。

## 編輯中 — 鍵入聲音

開啟 **輸入時播放聲音**，即可在輸入時聽到聲音。選擇一個音效包（打字機、鴨子或小貓），設定音量，並使用 **預覽** 試聽。每種按鍵類型都有自己的聲音：小寫字母、大寫字母、數字、符號、間距、定位字元、換行與刪除。貼上與多字元編輯則是靜音的。

在 **自訂聲音** 下，選擇某種按鍵類型旁的 **選擇…**，即可為它使用你自己的音訊檔案（WAV、AIFF、MP3、M4A 或 CAF）。音訊片段最長可為 2 秒、最大 3 MB。Pilcrow 會把它轉換成小型的單聲道片段，因此過長或過大聲的檔案不會拖慢輸入或發出爆音。使用 **播放** 試聽，使用 **移除** 則可回到音效包的聲音。若檔案遭拒，訊息會說明原因。在 iPad 上，靜音開關會讓鍵入聲音靜音，而且這些聲音會與其他音訊混合播放。

## 編輯中 — 圖片

設定插入、拷貝或移動、線上載入、路徑樣式與 URL 跳脫。

## 外觀

選擇應用程式佈景主題、縮放、背景圖、編輯器大小、字體、行距與定位字元寬度。

## 匯出

選擇渲染佈景主題、版面、頁首、頁尾、中繼資料與標題分頁。

## 資料庫

管理設定檔、CommonMark 選項、佈景主題、巨集、風格指南、渲染函式庫、位置與匯入。

## 鍵盤

搜尋、重新綁定、取消綁定與重置快速鍵，包括欄位導覽的行為。

一次只變更一組設定。評估字體排印時，請固定佈景主題；評估解析時，請固定設定檔。受控的變更能讓因果關係清楚可見。

# Chapter 46: 控制隱私與儲存的資料

開啟 **設定 ▸ 一般 ▸ 儲存空間與隱私**。Pilcrow 依類別分開刪除，因此清除快取不會意外刪除文件。

- **檢視復原資料…** 會列出可復原的內容清單。刪除之前，請先儲存或關閉已修改的文件。
- **檢視版本記錄…** 會在刪除之前顯示版本與預估的空間。
- **清除最近檔案的存取權限…** 會移除最近使用的檔案、記住的資料夾、工作階段書籤，以及每個檔案的語法選擇。
- **刪除 AI 資料與金鑰…** 會移除連線、鑰匙圈中的金鑰、對話，以及 AI 隱私選擇。
- **刪除診斷資訊…** 會移除已記錄的記錄檔與當機支援資料。
- **清除快取…** 會移除可重新建立的快取與網路回應。

自訂的設定檔、佈景主題、巨集、風格指南與背景圖仍保留在其可見的「資料庫」頁面上，必須在那裡檢視。這些控制項不會刪除你的文件。

助理設定也管理被排除的檔案模式、已關閉助理的資料夾，以及 AI 資料的刪除。線上圖片的載入是另一項獨立的隱私選擇。檢查連結絕不會連上網路。

# Chapter 47: 記錄並傳送診斷資訊

開啟 **設定 ▸ 一般 ▸ 診斷**。對於時有時無的問題，請選擇 **重現問題**，並選取相關部分、層級、保留期限與要包含的支援資訊。選項包括裝置與系統資訊、Pilcrow 設定、速度與記憶體、最近動作的軌跡，以及當機詳細資料。

請儘快重現問題，然後選擇 **檢視記錄…**。依子系統與嚴重程度篩選。傳送之前，請檢查報告。選擇 **說明 ▸ 回報錯誤…**，即可在 GitHub 上開啟已填入你的版本資訊的錯誤回報表單，並讓 Pilcrow 把記錄拷貝到剪貼簿，供你貼入。你也可以把報告儲存成檔案以便附上、分享它，或從記錄檢視器中選擇 **在 GitHub 上回報…**。GitHub 上的回報是公開的。

診斷應記錄長度、識別碼、狀態與錯誤，而不是文件內容，但分享報告之前仍請務必檢查。問題擷取完成後，請將記錄恢復為 **僅問題**，或關閉詳細保留；詳盡的記錄可能占用儲存空間並影響效能。

# Chapter 48: 以其他語言使用 Pilcrow

開啟「設定」並選擇「語言」。可能需要重新啟動。Pilcrow 提供英文，以及西班牙文、法文、德文、義大利文、巴西葡萄牙文、荷蘭文、俄文、日文、韓文與簡體中文。

非英文的介面翻譯在標示為經人工審閱之前，皆為 AI 產生。Pilcrow 會在這些語言中顯示啟動通知。選擇 **不要再顯示** 即可永久關閉，或在「語言」設定中重新啟用通知。「Machine-translated — may contain errors」這個標籤用來標示尚未審閱的內容。

變更介面語言並不會翻譯文件。請使用「翻譯」指令處理文件文字。若某個指令在翻譯中有歧義，請暫時切換為英文，以查看具權威性的原始用語。

# Chapter 50: 疑難排解常見問題

## 檔案出現亂碼

請檢查狀態列中的編碼。編輯之前，請以正確的編碼重新開啟或轉換。

## 格式或預覽不正確

請確認使用中的設定檔、驗證原始碼的分隔符號、啟用所需的選用語法，然後確認渲染佈景主題。請在顯示標記的情況下使用「編輯」來檢查字面文字。

## 格式或插入指令已停用

請從「預覽」切換到「編輯」。然後確認已有文件與語法設定檔處於使用中，且該設定檔支援所要求的結構。

## 圖解、圖表或方程式無法渲染

請檢查圍欄的語言標籤、區塊邊界、原始碼語法，以及圖解／數學選項。請從內建範本開始，以找出錯誤。

## 尋找找不到預覽中可見的文字

請在「編輯」中搜尋被格式切開，或包含在程式碼、方程式、圖解或圖表中的文字。預覽搜尋刻意只涵蓋可閱讀的渲染文字，而不是每個原始節點。

## 相對路徑的圖片或連結已損壞

請儲存文件，使其有所屬資料夾，確認檔名與大小寫完全正確，優先使用專案內的相對路徑，並執行「檢查連結」。

## 資料夾取代略過了檔案

請在 Pilcrow 中關閉那些檔案，確保它們是 UTF-8 文字，重新執行預覽，並確認它們在預覽與提交之間沒有被外部變更。

## 巨集沒有觸發，或觸發太頻繁

請確認其集合與巨集已啟用、檢查比對類型與觸發邊界、在程式碼之外測試，並縮小過於寬泛的模式。

## 無法使用翻譯

請確認是 macOS 15 或 iOS 18 以上、已安裝語言支援，以及來源／目標語言組合受到支援。文件翻譯與介面語言是兩回事。

## 無法使用助理

請加入並測試連線、將它設為使用中、選擇所提供的模型、確認供應商，並確保資料夾或檔案沒有被排除。

## 大型檔案的動作很慢

請等待背景的行索引完成、使用針對性的搜尋，並在串流式 HTML／Word 工作流程能滿足需求時，避免使用 PDF 或整份文件轉換。

## Pilcrow 回報意外結束或編輯器不同步

請停止編輯，盡可能儲存一份副本，在提供時使用復原功能，並在重新啟動之前記錄診斷資訊。在確認已儲存的文件無誤之前，請勿捨棄復原資料。

## 專案面板回報清單衝突

請重新載入、檢查最新的專案狀態，然後重做變更。請勿在兩台裝置上同時覆寫 `manifest.pilcrow`。

## 自訂資源無法匯入

請確認預期的副檔名與 JSON／CSS 格式、檢查所回報的不安全模式或衝突，並匯入到正確的應用程式佈景主題、渲染佈景主題、設定檔、巨集或風格指南區段。

# Chapter 51: 養成可靠的工作習慣

一般工作請使用這個流程：

1. 當文件有相關資產時，開啟資料夾，而不只是單一檔案。
2. 在大量編輯之前，確認設定檔與編碼。
3. 儲存一個初始檢查點。
4. 在「編輯」中寫作；結構重要時使用「並排」。
5. 重複的內容請使用巨集與欄位，不要手動複製。
6. 在批次取代、接受比較結果、取代翻譯或進行設定檔實驗之前先儲存。
7. 在適當的階段執行拼字檢查、風格審閱與「檢查連結」。
8. 展開所有區段，並從頭到尾檢查預覽。
9. 以預定的渲染佈景主題匯出，並檢查實際的目標格式。
10. 只有在收件者需要編輯時才分享原始碼；否則請分享完成的輸出。
11. 將設定檔、佈景主題、巨集、風格指南、專案清單與本機資產，與專案備份放在一起。
12. 定期在「儲存空間與隱私」下檢視復原資料、版本、AI 資料、診斷資訊與快取。

道理很簡單：在原始碼中明確表達意義，把呈現交給佈景主題，在交易之前建立檢查點，分享最少必要的資料，並驗證他人將實際收到的成品。這就是讓純文字既強大又可靠的 Pilcrow 之道。
