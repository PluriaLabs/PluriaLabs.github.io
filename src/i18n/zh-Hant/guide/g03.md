# Chapter 24: 使用 Super Tab 建立可重複使用的範本

欄位能把靜態展開變成引導式表單。欄位可以有預留文字、預設值或選項清單。

1. 為重複出現的結構建立巨集。
2. 在展開內容中加入欄位，或在撰寫原始碼時使用 **插入 ▸ 欄位**。
3. 展開巨集。
4. 在已選取的第一個欄位中輸入內容。
5. 使用 **下一個欄位** 前進，使用 **上一個欄位** 返回。
6. 若是選項欄位，請從欄位選項清單中選取。

請依照人們自然回答的順序來設計欄位。把最後的插入點放在應該繼續自由書寫的地方。預設值要無害：使用者漏填的欄位應該在「預覽」中一目了然，而不是悄悄地發布具誤導性的內容。

# Part VII — 數學、圖解、圖表與圖片

# Chapter 25: 撰寫方程式、圖解與圖表

Pilcrow 內建離線渲染功能，可處理 MathJax 方程式、Mermaid 圖解與 Vega-Lite 圖表。區塊從哪裡開始、到哪裡結束，仍由目前使用的設定檔決定；內建的函式庫只負責繪製區塊的內容。

## 從範本開始

1. 選擇 **插入 ▸ 方程式**、**圖解** 或 **圖表**。
2. 挑選一個範本。
3. 替換範例原始碼。
4. 切換到「預覽」或「並排」。
5. 在原始碼區塊中修正所回報的語法錯誤。

數學符號請用 MathJax，流程與關係請用 Mermaid，以資料驅動的圖表請用 Vega-Lite。在任何重要的視覺內容附近，請保留文字說明，這樣即使無法使用渲染器，文件仍然看得懂，也能讓更多讀者無障礙地閱讀。

這些函式庫都已內建，無需網路即可執行。設定 ▸ 資料庫 ▸ 渲染函式庫會顯示版本與聲明。若區塊無法渲染，請在更換佈景主題之前，先確認它的語言標籤、分隔符號、選用功能設定與語法。

# Chapter 26: 管理圖片插入與線上圖片隱私

開啟 **設定 ▸ 編輯中 ▸ 圖片**，並決定：

- 插入的圖片要拷貝、移動，還是留在原處。
- 此規則是否適用於本機圖片與線上圖片。
- 是否允許載入線上圖片。
- 是否盡可能使用相對路徑。
- 相對路徑是否以 `./` 開頭。
- 插入時是否對 URL 進行跳脫。

若要讓專案方便攜帶，請把圖片放在文件資料夾內，並使用相對路徑。當原始檔案屬於其他專案時，拷貝比移動更安全。移動可避免重複，但可能破壞原本的來源位置。

線上圖片會向其主機洩漏檢視者的網路位址，而且可能變更或消失。審閱不受信任的文件時，請保持關閉網路載入。若要長期發布，請下載一份已獲授權的副本，並在本機引用。

# Part VIII — 發布與分享

# Chapter 27: 匯出 HTML、PDF、Word 與圖片

1. 儲存文件並檢查「預覽」。
2. 從工具列或「檔案」指令中選擇「匯出」。
3. 選擇 HTML、HTML（不含樣式）、PDF、Word、圖片或 PDF 封存。
4. 在 **樣式** 下選擇渲染佈景主題。
5. 若是 PDF、PDF 封存與 Word，請檢視 **頁面** 選項：紙張大小、方向與邊界。
6. 選擇 **匯出** 並選取目的地，或選擇 **分享** 直接傳送產生的檔案。

HTML 會建立獨立且帶有樣式的頁面。**HTML（不含樣式）** 會輸出乾淨的結構，不含內嵌的佈景主題 CSS。Word 會產生具備語意化文件結構的真正 `.docx` 套件；補充的方程式、圖解與圖表會變成圖片。**圖片** 會把渲染後的文件製作成單一 PNG。**PDF 封存** 會建立一個 ZIP，內含依序排列的 PDF 分段與一份清單，當其他工作流程需要有界限、可分開的分段時很有用。一般的大型 PDF 會自動透過分段渲染的路徑組合而成，而 PDF 封存則把這些分段保留為最終成品。

開啟 **進階選項**，可加入僅用於本次匯出的 **自訂 CSS**。每次匯出專用的 CSS 會在佈景主題之後套用，因此在選擇器權重相同時會優先生效。頁面的變更只會影響目前這次匯出，除非你選擇 **將這些頁面設定作為預設值**。產生的目錄、標題編號與標題標籤，則是在 **設定 ▸ 目錄** 中為所有匯出一次設定好（第 70 章）。

若輸出結果不對，請先判斷問題出在結構還是樣式。標題遺失通常是設定檔或原始碼的問題；標題不好看則是渲染佈景主題的問題。

## 列印渲染後的文件

從「檔案」或「更多」中選擇 **列印…**。列印使用與 PDF 相同的渲染流程與頁面版面預設值，因此要診斷結構與樣式，最適合的地方是「預覽」與 PDF 匯出。在 Mac 上，頁面設定編輯的是同一份共用的頁面版面。在實際印出紙本之前，請先在列印對話框中檢查紙張、方向、邊界、頁首與頁尾。

# Chapter 28: 設定匯出預設值與頁面裝飾

開啟 **設定 ▸ 匯出 ▸ 匯出預設值**。選擇預設的渲染佈景主題與頁面版面。設定作者中繼資料、頁首、頁尾，以及每個頂層標題是否從新的一頁開始（**在頂層標題之間分頁**）。

頁首與頁尾範本可以包含 `${title}`、`${author}`、`${pageNo}`、`${pageCount}` 與 `${today}`。請保持簡短，以符合頁面邊界。請測試多頁 PDF，因為在單頁看起來正常的頁首，之後可能會和較長的標題或頁碼相衝突。這些修飾用的值是依輸出格式分別儲存的；頁面版面則由 PDF、PDF 封存、Word 與列印共用。

CommonMark 選項控制各種選用語法，例如螢光標示、下標、上標、行內數學、自動連結、提示框、前置資料、圖解、智慧標點與程式碼區塊的呈現方式。請只啟用原始碼實際用到的功能。可攜式的 CommonMark 文件若使用擴充語法，應該附上說明，不要隱含依賴。

# Chapter 29: 分享原始碼與完成的輸出

當他人需要可編輯的檔案時，請為原始文件選擇 **分享…**。已儲存且未修改的文件會直接分享。尚未儲存或已修改的文件，則會以目前文字的暫存副本進行分享；非常大的文件可能需要先儲存。

當收件者需要完成的 PDF、Word 文件、HTML 檔案或圖片時，請在「匯出」中選擇 **分享**。這會直接產生輸出，不需要你先另外保留一份已儲存的匯出檔。

分享原始碼之前，若收件者需要相同的行為，請一併附上相依的本機圖片、連結的文件、設定檔或佈景主題。分享完成的輸出之前，請檢查連結、預覽、分頁、替代文字與檔名。

# Part IX — 助理

# Chapter 30: 安全地連接 AI 供應商

助理是選用功能，使用的是你自行設定的連線。Pilcrow 不會在背後擅自選擇供應商。

1. 開啟 **設定 ▸ 一般 ▸ 助理**。
2. 加入預設組合，或選擇 **自訂…**。
3. 輸入名稱、基本 URL、通訊格式與模型。
4. 若供應商需要 API 金鑰，請啟用該選項，並在提示時儲存金鑰。金鑰會保存在系統鑰匙圈中。
5. 選擇 **測試連線**。
6. 儲存並將該連線設為使用中。

當供應商提供模型探索功能時，請在助理中使用 **選擇模型…**。若某個模型已消失，請改選目前可用的模型，不要反覆重試已過時的識別碼。

第一次使用某個連線之前，Pilcrow 會顯示文字將傳送到哪裡，並徵求你的同意。請閱讀主機名稱。即使本機伺服器與公開的雲端供應商提供相同的 API 格式，兩者對隱私的影響也不相同。

# Chapter 31: 以經過考量的上下文提問

開啟助理側邊欄並選擇對話模式。上下文標籤一開始是最小的實用範圍，通常是選取範圍。只有在問題需要時，才選擇其他範圍。

1. 選取你想獲得協助的段落。
2. 確認標籤顯示的是「選取範圍」，並檢視其摘要。
3. 提出具體的問題，例如「哪個句子讓時間順序變得不清楚？」
4. 把回覆當作建議來閱讀，而不是自動修改。
5. 自行套用變更，或透過所提供的、經過審閱的動作來套用。

Pilcrow 會把已設定的模式與資料夾排除在助理的上下文之外。請在助理設定中管理這些項目。使用資料夾控制項可針對敏感的工作區關閉助理存取。當對話不再屬於目前的任務時，請用垃圾桶按鈕清除對話。

切勿只因為一個問題提到某個檔案，就分享整個資料夾。提供必要的最少上下文，能提升隱私，通常也能提升回答品質。

# Chapter 32: 取得撰寫 Pilcrow 資源的協助

將助理切換為 **說明**，並選擇設定檔、巨集或風格指南。Pilcrow 會把相關的格式參考資料連同對話一起帶入，讓後續的指示保持有所依據。

請描述想要的行為，並提供一個小範例。請求一份草稿，使用「預覽」檢視所產生的資源文字，然後在相關的「設定」編輯器中驗證。若沒有先讀過名稱、觸發條件或模式與輸出，請勿匯入或儲存來源不明的產生式 JSON。

有效率的順序如下：

1. 說明一種行為與兩個範例。
2. 要求最小的有效資源。
3. 在 Pilcrow 中驗證。
4. 測試一個成功的案例與一個不相符的案例。
5. 把驗證錯誤回傳，請對方針對性地修正。

# Chapter 33: 執行 AI 輔助的風格審閱

此工作流程延伸自第 21 章：

1. 先選取一段文字做第一次試用。
2. 選擇風格審閱、一份指南、變體與審閱範圍。
3. 確認使用中的供應商與模型。
4. 開始審閱。
5. 依提供的選項，依嚴重程度或範圍排序發現的問題。
6. 開啟一項發現，閱讀其引用的證據，並檢查原始碼位置。
7. 套用、駁回，或保持未解決。

若是整份文件，Pilcrow 會估算位元組數與請求次數，並在傳送之前再次詢問。你可以在區塊之間停止。請在本機審閱敏感文件，或交給你接受其處理條款的供應商。停用某個連線時，請從助理或「儲存空間與隱私」設定中刪除 AI 資料與金鑰。

# Part X — 書籍專案

# Chapter 34: 將資料夾變成書籍專案

若要建立全新的專案，請選擇 **檔案 ▸ 新增書籍…**，輸入書名與目的地，讓 Pilcrow 建立初始資料夾與清單。若要接管現有書稿，請開啟其資料夾，選擇 **檔案 ▸ 將資料夾設為書籍專案**，或使用專案側邊欄的 **設為專案**，並完成中繼資料。Pilcrow 會建立一個 `manifest.pilcrow` 檔案來描述順序與中繼資料；它不會重新整理書稿檔案。

開啟專案設定，輸入書名、作者、目標字數、變數、字數計算行為與語法。加入列為 **不在書稿中** 的現有檔案，或從加號選單建立新的前言、章節、場景與後記。

請將 `manifest.pilcrow` 與書稿一起提交或備份。它是專案組織的目錄，即使原始檔案仍是一般的文字檔。

# Chapter 35: 規劃場景並追蹤書稿進度

在 **清單**、**概要** 與 **卡片** 之間選擇：

- 清單著重書稿順序與字數。
- 概要會加入摘要、視角、地點、狀態與進度。
- 卡片提供視覺化的規劃板，不會更動檔案順序。

開啟項目的詳細資料，可設定其角色、狀態、概要、視角、地點與目標字數。依狀態篩選，可專注於草稿、修訂或已完成的工作。若項目是研究資料或刪除的場景，可將它從書稿中移除，而不刪除其檔案。

僅在沒有套用狀態篩選時才重新排序；經過篩選的子集無法安全地代表完整的書稿順序。在 iPad 上，請選擇 **重新排序**、拖曳，然後選擇 **完成**。收合章節可減少清單的雜亂。

若 Pilcrow 表示專案檔案在磁碟上已變更，請重新載入並重做原本想做的動作。這項衝突保護可避免某個裝置或共同作者覆寫較新的清單。

# Chapter 36: 編譯書稿

1. 開啟專案側邊欄。
2. 確認順序、包含的檔案與專案中繼資料。
3. 選擇 **編譯…**。
4. 選擇輸出格式、渲染佈景主題與編譯選項。
5. 檢視前言、章節分隔、編號與包含的角色。
6. 編譯並檢查結果。

編譯可以產生 HTML、PDF 或 Word。你可以選擇哪些前言、部分、章節與後記要從新的一頁開始；設定場景之間的分隔符號；加入目錄；為標題編號；也可以選擇先為每個包含的檔案保留一份版本記錄快照。書稿摘要會顯示包含的檔案、位元組數、省略的檔案、遺失的路徑與最終順序。必須先解決遺失的檔案，才能使用「編譯」。

當你以多種方式發布同一份書稿時，例如「編輯用 DOCX」與「印刷用 PDF」，可將一組編譯選擇儲存為具名的預設組合。在同一個面板中刪除已過時的預設組合。編譯進行時，進度會顯示檔案數量，而 **停止** 會取消操作。未解析的 `{{variables}}` 會被回報，並以明顯不變的形式保留。

編譯會讀取清單順序，並以邏輯方式合併原始內容；它不會串接並覆寫你的檔案。請在原始檔案中修正場景，然後再次編譯。重複出現的中繼資料請使用專案變數，不要手動重複輸入書名或作者文字。

# Part XI — 語法設定檔

# Chapter 37: 選擇並了解語法設定檔

設定檔告訴 Pilcrow 原始碼標記如何轉變為結構角色。CommonMark 是內建的，但它只是其中一個設定檔，並不是這個 App 的定義。

請使用狀態列中的設定檔控制項或適當的文件控制項來選擇設定檔。Pilcrow 可從副檔名推斷設定檔，並記住每個檔案的選擇。使用中的設定檔會控制醒目提示、大綱、格式化功能的可用性、預覽、匯出結構、延續行為，以及該設定檔專屬的插入項目。

請依據原始碼已使用的語言來選擇設定檔。更換設定檔並不會轉換文字，而是重新詮釋文字。若需要轉換，請建立一份副本，並明確地轉換原始碼。

# Chapter 38: 建立並測試設定檔

1. 開啟 **設定 ▸ 資料庫 ▸ 語法設定檔**。
2. 複製一個相近的內建設定檔，或建立新的設定檔。
3. 在 **總覽** 中設定名稱、識別碼、副檔名與選用的繼承。
4. 在 **規則** 中加入你需要的最小結構。
5. 開啟 **測試範例**，貼上具代表性的原始碼，並選擇 **檢查範例**。
6. 儲存、在用完即丟的文件中啟用該設定檔，並比較編輯、大綱、預覽與匯出。

請測試各種邊界：檔案的開頭與結尾、空白行、巢狀結構、Unicode、未閉合的分隔符號，以及不該相符的文字。設定檔不僅能辨識範例，也能拒絕差一點相符的內容，才值得信賴。

在確認良好的修訂版本之後，請使用 **設為新基準**。**重置為基準** 會捨棄之後的各種嘗試。進行冒險的大幅改版之前，請先複製。

# Chapter 39: 編輯設定檔規則與進階 JSON

規則編輯器提供模式類型、行首要求、產生的角色、擷取、按下換行後的延續、分隔區塊行為、版面、行內連續片段與成對標記、標題說明，以及樣式角色。

只要字面或結構化辨識器能表達該語法，就使用它們。請讓模式保持有界且有錨點。Pilcrow 會拒絕已知不安全的模式，但技術上被接受的運算式仍可能過於寬泛或令人困惑。

只有在視覺化編輯器沒有提供所需的屬性時，才選擇 **編輯進階 JSON…**。套用時會驗證 JSON，並防止透過該面板更改設定檔的身分。進行進階操作時，請一併保留一份有效的測試範例。

繼承適合用於小型方言：繼承一個穩定的父層，只取代指定的語法。避免過長的鏈結，以免行為難以說明。若匯入設定檔時回報衝突，請在取代任何內容之前，先比較名稱與 ID。
