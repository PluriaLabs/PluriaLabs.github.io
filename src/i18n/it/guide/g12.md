# Part XIX — Editor per gli elementi della libreria

# Chapter 74: L’editor di profili e i blocchi costitutivi dei profili

Un profilo di sintassi dice a Pilcrow cosa significa il tuo markup. Questo capitolo descrive l’editor di profili controllo per controllo, poi elenca ogni blocco costitutivo che un profilo può usare. Per un’introduzione basata sulle attività, vedi dal Chapter 37 al Chapter 39.

Apri l’editor da **Impostazioni ▸ Libreria ▸ Profili di sintassi**: **Nuovo** crea un profilo, **Modifica** cambia un profilo personalizzato e **Duplica** copia un profilo integrato così puoi modificare la copia. Il titolo dell’editor è **Modifica profilo**, con **Annulla**, **Salva** e **Aiuto sui profili** (che apre il riferimento in-app a questi blocchi costitutivi). Su uno schermo stretto, un selettore **Sezione del profilo** permette di scegliere tra **Panoramica**, **Regole** e **Campione di prova**; su uno schermo largo vengono mostrate tutte e tre insieme.

## Panoramica

| Campo | Cosa fa |
| --- | --- |
| **Nome** | Il nome del profilo, mostrato nel menu della barra di stato e in Impostazioni. |
| **Descrizione** | Una nota sul profilo. |
| **Estensioni file (separate da virgole)** | Le estensioni che scelgono questo profilo per un file. Due profili non possono condividere un’estensione. |
| **Eredita da** | **Nessuno**, oppure un altro profilo sulle cui regole si basa questo. |
| **Sintassi** | **Estende Markdown** o **Sostituisce Markdown** (vedi sotto). |
| **In sintesi** | Il numero di **Regole di blocco**, **Regole inline** e **Regole di annidamento**. |
| **Modifica JSON avanzato…** | Apre il profilo come JSON per i campi che l’editor guidato non mostra. **Applica** mantiene le tue modifiche al JSON; **Annulla** le scarta. |

**Estende Markdown** aggiunge le tue regole a quelle di Markdown: titoli, elenchi, enfasi e il resto vengono ancora letti, e le tue regole di blocco e inline si aggiungono a essi. Una regola che è una copia invariata di una del profilo CommonMark descrive ciò che Markdown già fa, e viene lasciata a lui. **Sostituisce Markdown** rende le tue regole l’intera sintassi, così i costrutti di Markdown non vengono più riconosciuti. In questo caso una regola deve produrre **Fine riga**, altrimenti nulla separa i paragrafi. L’editor avvisa «Add a rule whose output node is "newline", or nothing will separate into paragraphs», e il profilo non può essere salvato finché non ne esiste una. Elenca anche i tipi di output che il profilo non definisce.

## Regole

Le regole sono di tre gruppi.

### Regole di blocco

Una regola di blocco riconosce righe e blocchi interi. **Aggiungi regola** ne aggiunge una. Ogni regola ha un **Pattern**, un tipo di **Corrispondenza**, ciò che **Produce** e le **Opzioni**. Una regola si rimuove con il suo pulsante **Elimina**. Se non ce ne sono, l’editor dice «No rules yet. Add one to recognize a block construct.»

### Regole inline

Una regola inline riconosce il testo all’interno di una riga. **Aggiungi regola inline** ne aggiunge una. Le regole inline offrono quattro tipi di corrispondenza (**Prefisso letterale**, **Letterale esatto**, **Regex (limitata)** e **Coppia di delimitatori**); le regole di blocco li offrono tutti e sette.

### Regole di annidamento

Le regole di annidamento dicono quali output possono stare dentro quali altri. Ognuna ha un **Nodo padre** e dei **Nodi figli consentiti (separati da virgole)**. Vuoto significa nessuna restrizione: «No restrictions. Every node type may nest inside any other.» **Aggiungi regola di annidamento** ne aggiunge una.

### Tipi di corrispondenza

| Tipo di corrispondenza | Legge il pattern come | Blocco | Inline |
| --- | --- | --- | --- |
| **Prefisso letterale** | Il testo con cui inizia il costrutto. | sì | sì |
| **Letterale esatto** | L’intero testo del costrutto. | sì | sì |
| **Prefisso a inizio riga** | Il testo all’inizio di una riga, come `# `. | sì | |
| **Blocco indentato** | Righe che iniziano con il pattern, come quattro spazi o una tabulazione. Quelle consecutive, e le righe vuote tra di esse, formano un unico blocco, mostrato senza il rientro. | sì | |
| **Blocco delimitato** | Una riga che apre un blocco, chiuso da una riga corrispondente. | sì | |
| **Regex (limitata)** | Un’espressione regolare. Pilcrow avvisa prima di salvarne una che potrebbe bloccarsi: «This regex could hang the editor — simplify it.» | sì | sì |
| **Coppia di delimitatori** | Lo stesso segno ai due lati di un testo su una sola riga, come `%%` in `%%this%%`. Non c’è spazio subito all’interno dei segni. | sì | sì |

In un’espressione regolare, `(?<name>…)` dà un nome a una parte della corrispondenza. Vedi Parti con nome più avanti.

## Opzioni delle regole

Il gruppo **Opzioni** di ogni regola offre:

| Opzione | Cosa fa |
| --- | --- |
| **Priorità** | Le regole con priorità più alta vengono provate per prime. |
| **Solo all’inizio di una riga** | Impedisce a una regola di corrispondere a metà riga. |
| **Le parti con nome diventano attributi** | Ogni parte con nome di un’espressione regolare diventa un attributo dell’output. L’editor elenca «Parts in this pattern» e «Parts this output reads». Per un output che contiene testo, come il grassetto o un link, il testo mostrato è la parte chiamata `text` se esiste, altrimenti l’ultima parte che ha trovato corrispondenza. |
| **Produce** | Ciò che la regola crea: un output tra gli elenchi qui sotto, oppure un nome **Personalizzato**. |
| **Nome nodo personalizzato** | Il nome di un output **Personalizzato**. |
| **Attributi fissi** | Parti che hanno ogni volta lo stesso valore, aggiunte con **Aggiungi attributo** (un **Nome** e un **Valore**). Un valore può includere una parte con nome, scritta `{name}`: una regola per gli indirizzi e-mail il cui pattern nomina `address` può dare al proprio link l’`url` `mailto:{address}`. |
| **Testo di inserimento** | Ciò che il menu **Inserisci** scrive per questa regola, esattamente come deve apparire, con `$0` dove deve andare il cursore. Una regola individuata da un’espressione regolare, da un blocco o da un rientro ne ha bisogno, altrimenti il menu Inserisci la omette. |
| **Solo dopo una riga vuota** | Per un blocco indentato: una riga rientrata subito dopo del testo resta parte di quel testo, come la riga successiva di una voce di elenco. |
| **Dopo Invio a fine riga** | Per elenchi e citazioni: **Automatico** (ripete i punti elenco e le citazioni, incrementa le voci numerate e inizia le voci di attività non spuntate), **Ripeti il marcatore**, **Incrementa**, **Ricomincia dal marcatore** o **Non aggiungere nulla**. |

### Blocchi delimitati

Per una regola **Blocco delimitato**, **Il blocco contiene** dice cosa c’è dentro:

| Scelta | Significato |
| --- | --- |
| **Ancora niente** | Non impostato. |
| **Testo, mostrato così com’è** | Codice o testo preformattato. |
| **Niente — nascosto** | Un commento, escluso dal documento. |
| **Altri blocchi, in un riquadro** | Una citazione, una barra laterale o un avviso che contiene paragrafi, elenchi e altro. |
| **Altri blocchi, senza riquadro** | I blocchi si uniscono al testo circostante; le righe servono solo a raggrupparli. |
| **Una tabella** | Vedi Tabelle, più avanti. |
| **Una tabella disegnata con il testo** | Una griglia o colonne allineate di testo che va dalla riga di apertura alla successiva riga vuota, come quella di reStructuredText. |
| **Testo rientrato sotto una riga che termina con un indicatore** | La riga di apertura è prosa che termina con l’indicatore, come fa `::` in reStructuredText; la prosa resta un paragrafo, e il testo rientrato sotto di essa dopo una riga vuota viene mostrato così com’è. |
| **Testo rientrato sotto una riga di apertura** | Una direttiva come `.. code-block::`, che contiene le righe rientrate sotto di sé e non ha riga di chiusura. |

La **Riga di chiusura** è la riga che termina il blocco; vuota significa la stessa riga di quella di apertura («Same as the opening line»). Un delimitatore che non è un’espressione regolare, come `+++`, viene confrontato come testo semplice. **La riga di chiusura ripete il segno di apertura, almeno altrettante volte** serve per i recinti in stile Markdown: la riga di chiusura è il primo carattere della riga di apertura ripetuto almeno altrettante volte, così un recinto più lungo contiene come testo uno più corto. Il linguaggio di un blocco di testo, quando la riga di apertura ne nomina uno noto, viene colorato nell’editor.

### Tabelle

Le opzioni di un blocco tabella:

| Opzione | Cosa fa |
| --- | --- |
| **Disposizione** | **Griglia con righe di separazione** (celle tra `|` con una riga di separazione tra le righe) o **Colonne allineate** (colonne incolonnate sotto una prima riga di separazione). |
| **Separatore di celle** | Il testo con cui inizia ogni cella. |
| **Modello della riga di separazione**, **Modello della riga di separazione dell’intestazione** | Righe che disegnano solo una linea di separazione, e quella che termina l’intestazione. |
| **La riga termina con** | Un segno che termina ogni riga, come fa un `tabular` di LaTeX. |
| **Modello della cella unita** | Una cella che si estende su più colonne. |
| **Modello delle opzioni di cella** | Un’espressione regolare per ciò che può stare subito prima del separatore di una cella; una parte chiamata `colspan` fa estendere la cella su quel numero di colonne. |
| **Separatore dell’elenco colonne**, **Indicatore di ripetizione** | Come si scrive un elenco `columns`: con `,` e `*`, `3*` conta tre colonne. |
| **La prima riga prima di una riga vuota è l’intestazione** | La riga di intestazione è implicita nella disposizione. |
| **Formati** | Altri modi di scrivere le celle, ciascuno con un nome e un separatore (come `csv` e `,`), aggiunti con **Aggiungi formato** e scelti con la parte `format` della tabella. |

## Impostazioni valide per tutto il profilo

| Impostazione | Cosa fa |
| --- | --- |
| **Annida gli elenchi per marcatore** | Ogni nuovo marcatore, come `**` dopo `*`, avvia un livello più profondo, qualunque sia il rientro. |
| **Riga di continuazione dell’elenco** | Una riga, da sola dopo una voce di elenco, che collega il blocco successivo alla voce. |
| **Mantieni le interruzioni di riga singole** | Un’interruzione di riga all’interno di un paragrafo resta un’interruzione di riga. |
| **Assegna ID ai titoli** | Un titolo senza un ID proprio ne riceve uno dal suo testo: minuscolo, con le parole unite dal **separatore di parole**, dopo il **prefisso** (**Prefisso dell’ID**, **Separatore di parole dell’ID**). Con `_` e `_`, «Getting Started» diventa `_getting_started`, così un riferimento incrociato ad esso mostra il titolo. Un titolo ripetuto aggiunge il separatore e un numero. |
| **Numera i titoli** | Una volta che il documento definisce l’attributo indicato in **Quando il documento definisce**, come `:sectnums:` di AsciiDoc, i titoli dal **Dal livello di titolo** in giù vengono numerati: `1.`, `1.1.`, `2.`. I titoli prima della definizione no. |
| **Didascalie numerate** | Un blocco con titolo di un output elencato qui, come `image`, `table` o `example`, riceve l’**Etichetta** e un proprio numero prima del titolo (ad esempio «Figura 1.»), nella **Posizione della didascalia**, **Sopra** o **Sotto** il blocco. Si aggiunge con **Aggiungi didascalia**. |

## Segni inline che si accoppiano in base a ciò che li circonda

Un linguaggio come Markdown scrive grassetto e corsivo con una sequenza di caratteri che apre o chiude a seconda dei caratteri accanto, e un frammento di codice o un link con le parentesi, perciò un solo pattern per l’intero costrutto non può trovarli. Attiva **Leggi i segni in base a ciò che li circonda** per descriverli.

| Impostazione | Cosa fa |
| --- | --- |
| **Carattere di escape** | Un carattere che rende normale quello successivo. |
| **Carattere del frammento di codice** | Una sequenza di questo carattere apre un frammento che viene chiuso dalla successiva sequenza della stessa lunghezza. |
| **Segni a sequenza** | Segni che si accoppiano come sequenze, aggiunti con **Aggiungi segno a sequenza**. Ognuno ha un **Segno**, ciò che **Un segno disegna** e ciò che **Due segni disegnano**, e **Può aprire o chiudere dentro una parola** (disattivato per `_`). |
| **Segni a coppia** | Segni che si accoppiano con una sequenza della stessa lunghezza, aggiunti con **Aggiungi segno a coppia**: il **Segno**, ciò che **Disegna**, e **Solo se questa impostazione è attiva**, un’impostazione di sintassi come l’evidenziazione che deve essere attiva (oppure **Sempre**). |
| **Link e indirizzi web** | **Prefisso immagine**, **Un indirizzo scritto da solo è racchiuso da**, **Schemi con cui inizia un indirizzo semplice**, **Una riga che definisce un’etichetta ha** e **L’etichetta di una nota a piè di pagina inizia con** (il carattere dopo la parentesi di apertura di un’etichetta che ne fa una nota a piè di pagina: `[^note]` viene disegnato come riferimento a una nota a piè di pagina quando una riga inizia con `[^note]:`). |

I segni si accoppiano all’interno di una riga. Il codice, i caratteri preceduti da escape e l’indirizzo di un link sono testo normale per i segni che li circondano.

## Sorgente con stile

Con **Sorgente con stile** attivo, l’editor disegna un documento con l’aspetto della sua sintassi: titoli più grandi, sequenze in grassetto e corsivo, barre di citazione, rientri degli elenchi, caselle delle attività, linee, link e riquadri di codice, e nasconde i segni che li producono (con **Nascondi i marcatori** attivo) tranne che sulla riga in cui si trova il cursore. L’editor non sa nulla di alcuna sintassi in particolare: una regola dice cos’è la sua corrispondenza portando una voce di stile, e una regola senza di essa viene colorata ma non ristilizzata.

Le **Opzioni** di ogni regola hanno un gruppo **Sorgente con stile**:

| Campo | Cosa fa |
| --- | --- |
| **Ruolo** | Cos’è la corrispondenza, oppure **Senza stile**. Per un costrutto all’interno di una riga: heading, strong, emphasis, code, strike, highlight, underline, link, subscript, superscript. Per una riga intera: rule (un’interruzione tematica), list (il marcatore di una voce di elenco, compreso il rientro e lo spazio dopo di esso), task (un marcatore seguito da una casella) e quote (i segni `>` di una riga citata). Per un blocco riconosciuto per intero: codeBlock. Per un blocco le cui righe di apertura e di chiusura sono corrispondenze separate: quoteRegion. Per una tabella, un’equazione o un diagramma disegnati come immagine: renderedBlock. |
| **Gruppo del contenuto** | Il gruppo di cattura, contando da 1, che contiene ciò di cui parla il costrutto: la parola dentro `*bold*`, il titolo in `\section{Title}`. Ciò che la corrispondenza ha in più sono i segni propri del costrutto, che Nascondi i marcatori nasconde. `0` significa che l’intera corrispondenza è contenuto e nulla si nasconde, come per un indirizzo web. Omettilo quando la corrispondenza è fatta solo di segni, come il `== ` di un titolo. |
| **Livello del titolo**, **Gruppo del livello** | Il livello di un titolo, da 1 a 6. Se omesso, è il numero alla fine del nome dell’output della regola (`heading2`), oppure la lunghezza del gruppo di cattura che contiene una sequenza di `#`. |
| **Gruppo del indicatore** | Per un elenco o un’attività, il gruppo di cattura che è il marcatore con il suo rientro e gli spazi dopo di esso, quando la corrispondenza inizia con qualcos’altro, come il `> ` di una voce citata. |
| **Applica lo stile fino a fine riga** | Applica lo stile dalla corrispondenza fino alla fine della riga, per una regola che corrisponde solo al marcatore di un titolo e lascia il suo testo come il testo che segue. |
| **Viene disegnato come** | Per un blocco disegnato, cos’è: una tabella, una formula o un diagramma, oppure **Non è un’immagine**. |
| **Gruppi dell’indirizzo** | Per un link, i gruppi di cattura, provati in ordine, che contengono l’indirizzo che si apre con un clic o un tocco; `0` è l’intera corrispondenza. Si aprono solo indirizzi web, e-mail e telefonici. |

I numeri dei gruppi contano le parentesi del pattern da 1; 0 è l’intera corrispondenza. Un profilo che non sostituisce Markdown mantiene anche la lettura propria di Markdown dei tipi che le sue regole non dichiarano, come le sue barre di citazione e le coppie di `**`.

## Attributi del documento e sezioni condizionali

Una regola **Attributo del documento** definisce un valore tramite `name`, e una regola **Riferimento ad attributo** (una regola inline con le parti `name` e `original`) sostituisce un riferimento con esso. Un riferimento a un attributo che nessuno ha definito resta com’è scritto. Una **Sezione condizionale** mantiene o scarta i blocchi tra le sue righe, a seconda che gli attributi che nomina siano impostati o meno. Gli attributi valgono dal punto in cui sono definiti in poi.

Una regola che produce **Impostazioni del blocco successivo** riconosce un’intera riga che configura il blocco dopo di essa e non mostra nulla di per sé. Le sue parti e i suoi attributi fissi vengono dati a quel blocco: `title`, `id`, `nodeType`, `language` e `hardbreaks` hanno i significati elencati in Parti, e ogni altra parte viene conservata sul blocco, dove una tabella, un elenco o una citazione la legge.

## Provare un profilo

In fondo all’editor, **Campione di prova** contiene un testo di esempio (inizialmente un titolo e una riga di testo). Scegli **Controlla esempio** per vedere i nodi creati dalle tue regole, rientrati secondo l’annidamento. Dice «No blocks recognized.» quando nulla corrisponde.

## Base di partenza

La **base di partenza** di un profilo è il suo punto di ripristino: com’era quando lo hai creato, duplicato o importato. **Ripristina la base di partenza** scarta ogni modifica da allora, dopo la tua conferma. **Imposta come nuova base di partenza** salva il profilo e rende il suo stato attuale il punto di ripristino.

Il salvataggio viene rifiutato, con un messaggio, se il profilo sostituisce Markdown ma non ha una regola di fine riga, se un pattern non è sicuro e potrebbe bloccare l’editor, o se il file non può essere scritto.

## Parti

Le parti sono i pezzi con nome di una corrispondenza che un output legge.

| Parte | Significato |
| --- | --- |
| `allOf` | Il separatore tra i nomi quando servono tutti, come `+`. |
| `alt` | La descrizione di un’immagine, per i lettori che non possono vederla. |
| `anyOf` | Il separatore tra i nomi quando ne basta uno qualsiasi, come `,`. |
| `attribution` | Chi ha detto una citazione, mostrato sotto di essa. |
| `citetitle` | L’opera da cui proviene una citazione, mostrata dopo l’attribuzione. |
| `columns` | L’elenco colonne di una tabella, come `1,2,1`; le sue voci contano le colonne. |
| `condition` | I nomi degli attributi da cui dipende la sezione. |
| `conditionType` | `defined` mantiene la sezione quando gli attributi sono impostati, `undefined` quando non lo sono. |
| `content` | Il testo stesso, quando non è l’intera corrispondenza. |
| `format` | Il motore di un diagramma (`mermaid` o `vega-lite`); per una tabella, quale dei suoi formati delimitati usano le celle. |
| `hardbreaks` | Quando presente, mantiene le interruzioni di riga singole del blocco successivo. |
| `header` | Qualsiasi valore diverso da `false` fa della prima riga di una tabella la sua intestazione. |
| `id` | Un nome: per il blocco successivo, l’ID a cui puntano i riferimenti incrociati; per una nota a piè di pagina, un nome che permette alle note successive prive di testo proprio di condividerne il numero. |
| `keys` | I tasti da premere, separati da virgole. |
| `label` | Il testo mostrato per un riferimento o un’ancora, al posto del titolo del bersaglio. |
| `language` | Il linguaggio di programmazione di un blocco di codice, usato per la colorazione. |
| `level` | Il livello del titolo, da 1 a 6. |
| `marker` | Il separatore dopo il termine, come `::`. Un marcatore diverso annida un elenco dentro la descrizione. |
| `name` | Il nome dell’attributo, in una definizione o in un riferimento. |
| `nodeType` | Trasforma il blocco successivo in un altro output, tramite il suo nome nel file. |
| `noHeader` | Quando presente, una tabella non ha riga di intestazione. |
| `notation` | La notazione matematica: `tex` (predefinita) o `latex`. |
| `open` | `true` mostra aperta una sezione comprimibile. |
| `ordered` | `true` rende numerato l’elenco. |
| `original` | Il riferimento com’è scritto, mostrato quando l’attributo non è definito. |
| `presentation` | Come viene mostrato il prossimo elenco descrittivo: `sideBySide` mette termini e descrizioni in due colonne; `questions` numera ogni termine come una domanda, con la risposta sotto di esso. |
| `primary` | La voce di indice. |
| `secondary` | Una sottovoce sotto la voce di indice. |
| `sectionLabel` | Una parola che il numero del titolo successivo segue, come `Appendix`: questi titoli sono contati a parte, `Appendix A:`. |
| `sectionLabelStart` | Il primo di quei numeri: una lettera (`A`) conta in lettere, un numero in numeri. |
| `src` | L’indirizzo del file video o audio. |
| `start` | Il numero da cui parte un elenco numerato. |
| `summary` | La riga mostrata su una sezione comprimibile mentre è chiusa. |
| `targetID` | L’ID a cui punta il riferimento. |
| `term` | Il termine che viene descritto. |
| `tertiary` | Una sottovoce sotto quella secondaria. |
| `text` | Il testo mostrato, quando il pattern cattura più di quello. Il testo di una nota a piè di pagina segue il paragrafo, la tabella o l’elenco in cui si trova, numerato. |
| `title` | Un titolo: l’intestazione di un riquadro, il suggerimento di un’immagine o di un link, oppure una didascalia sopra il blocco successivo. |
| `type` | Il tipo di avviso, come `note`, `tip` o `warning`. |
| `unset` | Quando presente, la regola rimuove l’attributo invece di definirlo. |
| `url` | L’indirizzo a cui punta un link o un’immagine. |
| `value` | Il valore dell’attributo; i riferimenti ad attributi definiti prima vengono sostituiti al suo interno. |
