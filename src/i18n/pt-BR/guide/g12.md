# Part XIX — Editores de itens da biblioteca

# Chapter 74: O editor de perfis e os blocos de construção de perfis

Um perfil de sintaxe diz ao Pilcrow o que a sua marcação significa. Este capítulo descreve o editor de perfis controle por controle e depois lista todos os blocos de construção que um perfil pode usar. Para uma introdução baseada em tarefas, veja o Chapter 37 ao Chapter 39.

Abra o editor em **Ajustes ▸ Biblioteca ▸ Perfis de sintaxe**: **Novo** inicia um perfil, **Editar** altera um perfil personalizado e **Duplicar** copia um perfil integrado para que você possa alterar a cópia. O título do editor é **Editar perfil**, com **Cancelar**, **Salvar** e **Ajuda de perfis** (que abre a referência no app a esses blocos de construção). Em uma tela estreita, um seletor **Seção do perfil** alterna entre **Visão geral**, **Regras** e **Amostra de teste**; em uma tela larga, as três aparecem ao mesmo tempo.

## Visão geral

| Campo | O que faz |
| --- | --- |
| **Nome** | O nome do perfil, exibido no menu da barra de status e nos Ajustes. |
| **Descrição** | Uma observação sobre o perfil. |
| **Extensões de arquivo (separadas por vírgula)** | As extensões que escolhem este perfil para um arquivo. Dois perfis não podem compartilhar uma extensão. |
| **Herda de** | **Nenhum**, ou outro perfil em cujas regras este se baseia. |
| **Sintaxe** | **Estende o Markdown** ou **Substitui o Markdown** (abaixo). |
| **Resumo** | Contagens de **Regras de bloco**, **Regras em linha** e **Regras de aninhamento**. |
| **Editar JSON avançado…** | Abre o perfil como JSON para campos que o editor guiado não expõe. **Aplicar** mantém as alterações no JSON; **Cancelar** as descarta. |

**Estende o Markdown** adiciona as suas regras às do Markdown: seus títulos, listas, ênfase e o restante continuam sendo lidos, e as suas regras de bloco e em linha se somam a eles. Uma regra que seja uma cópia inalterada de uma das regras do perfil CommonMark descreve o que o Markdown já faz e fica a cargo dele. **Substitui o Markdown** faz das suas regras a sintaxe inteira, de modo que as construções do Markdown deixam de ser reconhecidas. Com ele, uma regra precisa produzir **Fim de linha**, ou nada separa os parágrafos. O editor avisa “Adicione uma regra cujo nó de saída seja “newline”, ou nada separará os parágrafos”, e o perfil não pode ser salvo até que exista uma. Ele também lista os tipos de saída que o perfil não define.

## Regras

As regras vêm em três grupos.

### Regras de bloco

Uma regra de bloco reconhece linhas e blocos inteiros. **Adicionar regra** adiciona uma. Cada regra tem um **Padrão**, um tipo de **Correspondência**, o que ela **Produz** e **Opções**. Uma regra é removida com o botão **Excluir**. Sem nenhuma, o editor diz “Nenhuma regra ainda. Adicione uma para reconhecer uma construção de bloco.”

### Regras em linha

Uma regra em linha reconhece texto dentro de uma linha. **Adicionar regra em linha** adiciona uma. As regras em linha oferecem quatro tipos de correspondência (**Prefixo literal**, **Literal exato**, **Regex (limitada)** e **Par de delimitadores**); as regras de bloco oferecem os sete.

### Regras de aninhamento

As regras de aninhamento dizem quais saídas podem ficar dentro de quais. Cada uma tem um **Nó pai** e **Nós filhos permitidos (separados por vírgulas)**. Vazio significa sem restrição: “Sem restrições. Qualquer tipo de nó pode ser aninhado dentro de qualquer outro.” **Adicionar regra de aninhamento** adiciona uma.

### Tipos de correspondência

| Tipo de correspondência | Lê o padrão como | Bloco | Em linha |
| --- | --- | --- | --- |
| **Prefixo literal** | O texto com que a construção começa. | sim | sim |
| **Literal exato** | O texto inteiro da construção. | sim | sim |
| **Prefixo no início da linha** | O texto no início de uma linha, como `# `. | sim | |
| **Bloco recuado** | Linhas que começam com o padrão, como quatro espaços ou uma tabulação. As consecutivas, e as linhas em branco entre elas, formam um só bloco, exibido sem o recuo. | sim | |
| **Bloco cercado** | Uma linha que abre um bloco, fechado por uma linha correspondente. | sim | |
| **Regex (limitada)** | Uma expressão regular. O Pilcrow avisa antes de salvar uma que possa travar: “Esta regex pode travar o editor — simplifique-a.” | sim | sim |
| **Par de delimitadores** | A mesma marca nos dois lados de um texto em uma linha, como `%%` em `%%this%%`. Não há espaço logo dentro das marcas. | sim | sim |

Em uma expressão regular, `(?<name>…)` dá nome a uma parte da correspondência. Veja Partes nomeadas abaixo.

## Opções de regra

O grupo **Opções** de cada regra oferece:

| Opção | O que faz |
| --- | --- |
| **Prioridade** | As regras com maior prioridade são tentadas primeiro. |
| **Apenas no início de uma linha** | Impede que uma regra corresponda no meio de uma linha. |
| **Partes nomeadas viram atributos** | Cada parte nomeada de uma expressão regular vira um atributo da saída. O editor lista “Partes neste padrão” e “Partes que esta saída lê”. Para uma saída que contém texto, como negrito ou um link, o texto exibido é a parte chamada `text`, se houver, ou então a última parte que correspondeu. |
| **Produz** | O que a regra cria: uma saída das listas abaixo, ou um nome **Personalizado**. |
| **Nome de nó personalizado** | O nome de uma saída **Personalizado**. |
| **Atributos fixos** | Partes que têm o mesmo valor sempre, adicionadas com **Adicionar atributo** (um **Nome** e um **Valor**). Um valor pode incluir uma parte nomeada, escrita `{name}`: uma regra de e-mail cujo padrão nomeia o `address` pode dar ao seu link o `url` `mailto:{address}`. |
| **Texto de inserção** | O que o menu **Inserir** escreve para esta regra, exatamente como deve aparecer, com `$0` onde o cursor deve ficar. Uma regra correspondida por uma expressão regular, um bloco ou um recuo precisa disso, ou o menu Inserir a deixa de fora. |
| **Somente após uma linha em branco** | Para um bloco recuado: uma linha recuada logo após um texto continua fazendo parte desse texto, como a linha seguinte de um item de lista. |
| **Após Return no fim de uma linha** | Para listas e citações: **Automático** (repete marcadores e citações, conta para cima nos itens numerados e inicia itens de tarefa desmarcados), **Repetir o marcador**, **Contar para cima**, **Recomeçar a partir do marcador** ou **Não adicionar nada**. |

### Blocos cercados e delimitados

Para uma regra de **Bloco cercado**, **O bloco contém** diz o que há dentro:

| Escolha | Significado |
| --- | --- |
| **Nada ainda** | Não definido. |
| **Texto, exibido como escrito** | Código ou texto pré-formatado. |
| **Nada — oculto** | Um comentário, deixado fora do documento. |
| **Outros blocos, em uma caixa** | Uma citação, barra lateral ou aviso que contém parágrafos, listas e mais. |
| **Outros blocos, sem caixa** | Os blocos se juntam ao texto ao redor; as linhas apenas os agrupam. |
| **Uma tabela** | Veja Tabelas, abaixo. |
| **Uma tabela desenhada com texto** | Uma grade ou colunas alinhadas de texto que vai da sua linha de abertura até a próxima linha em branco, como a do reStructuredText. |
| **Texto recuado sob uma linha que termina com um marcador** | A linha de abertura é prosa que termina com o marcador, como faz o `::` do reStructuredText; a prosa continua sendo um parágrafo, e o texto recuado sob ela, após uma linha em branco, é exibido como escrito. |
| **Texto recuado sob uma linha de abertura** | Uma diretiva como `.. code-block::`, que contém as linhas recuadas sob ela e não tem linha de fechamento. |

**Linha de fechamento** é a linha que encerra o bloco; vazio significa a mesma linha da abertura (“Igual à linha de abertura”). Um delimitador que não seja uma expressão regular, como `+++`, é comparado como texto simples. **A linha de fechamento repete a marca de abertura, pelo menos o mesmo número de vezes** serve para cercas no estilo Markdown: a linha de fechamento é o primeiro caractere da linha de abertura repetido pelo menos o mesmo número de vezes, de modo que uma cerca mais longa contém uma mais curta como texto. A linguagem de um bloco de texto, quando a linha de abertura nomeia uma conhecida, é colorida no editor.

### Tabelas

As opções de um bloco de tabela:

| Opção | O que faz |
| --- | --- |
| **Disposição** | **Grade com linhas de separação** (células entre `|` com uma linha de separação entre as linhas) ou **Colunas alinhadas** (colunas alinhadas sob uma primeira linha de separação). |
| **Separador de células** | O texto que inicia cada célula. |
| **Padrão da linha de separação**, **Padrão da linha de separação do cabeçalho** | Linhas que desenham apenas uma linha de separação, e a que encerra o cabeçalho. |
| **A linha termina com** | Uma marca que encerra cada linha, como faz um `tabular` do LaTeX. |
| **Padrão de célula mesclada** | Uma célula que ocupa várias colunas. |
| **Padrão de opções de célula** | Uma expressão regular para o que pode vir logo antes do separador de uma célula; uma parte chamada `colspan` faz a célula ocupar essa quantidade de colunas. |
| **Separador da lista de colunas**, **Marcador de repetição** | Como se escreve uma lista de `columns`: com `,` e `*`, `3*` conta três colunas. |
| **A primeira linha antes de uma linha em branco é o cabeçalho** | A linha de cabeçalho é implícita pela disposição. |
| **Formatos** | Outras maneiras de escrever as células, cada uma com um nome e um separador (como `csv` e `,`), adicionadas com **Adicionar formato** e escolhidas com a parte `format` da tabela. |

## Ajustes do perfil inteiro

| Ajuste | O que faz |
| --- | --- |
| **Aninhar listas pelo marcador** | Cada novo marcador, como `**` após `*`, inicia um nível mais profundo, seja qual for o recuo. |
| **Linha de continuação da lista** | Uma linha, sozinha após um item de lista, que anexa o próximo bloco ao item. |
| **Manter quebras de linha simples** | Uma quebra de linha dentro de um parágrafo continua sendo uma quebra de linha. |
| **Dar IDs aos títulos** | Um título sem ID próprio recebe um a partir do seu texto: minúsculas, palavras unidas pelo **separador de palavras**, depois do **prefixo** (**Prefixo do ID**, **Separador de palavras do ID**). Com `_` e `_`, “Getting Started” vira `_getting_started`, de modo que uma referência cruzada a ele mostra o título. Um título repetido acrescenta o separador e um número. |
| **Numerar títulos** | Depois que o documento define o atributo nomeado em **Quando o documento define**, como o `:sectnums:` do AsciiDoc, os títulos a partir de **A partir do nível de título** são numerados: `1.`, `1.1.`, `2.`. Os títulos anteriores à definição não são. |
| **Legendas numeradas** | Um bloco com título de uma saída listada aqui, como `image`, `table` ou `example`, recebe o **Rótulo** e o seu próprio número antes do título (por exemplo “Figura 1.”), na **Posição da legenda**, **Acima** ou **Abaixo** do bloco. Adicionadas com **Adicionar legenda**. |

## Marcas em linha que formam pares conforme o que as cerca

Uma linguagem como o Markdown escreve negrito e itálico com uma sequência de caracteres que abre ou fecha dependendo dos caracteres ao lado, e um trecho de código ou link com colchetes, de modo que um único padrão para a construção inteira não consegue encontrá-los. Ative **Ler marcas conforme o que as cerca** para descrevê-los.

| Ajuste | O que faz |
| --- | --- |
| **Caractere de escape** | Um caractere que torna o seguinte comum. |
| **Caractere do trecho de código** | Uma sequência desse caractere abre um trecho que a próxima sequência do mesmo comprimento fecha. |
| **Marcas em sequência** | Marcas que formam pares como sequências, adicionadas com **Adicionar marca em sequência**. Cada uma tem uma **Marca**, o que **Uma marca desenha** e o que **Duas marcas desenham**, e **Pode abrir ou fechar dentro de uma palavra** (desativado para `_`). |
| **Marcas em pares** | Marcas que formam par com uma sequência do mesmo comprimento, adicionadas com **Adicionar marca em par**: a **Marca**, o que ela **Desenha** e **Somente se este ajuste estiver ativado**, um ajuste de sintaxe como destaque que precisa estar ativado (ou **Sempre**). |
| **Links e endereços da web** | **Prefixo de imagem**, **Um endereço escrito sozinho fica entre**, **Esquemas que iniciam um endereço simples**, **Uma linha que define um rótulo tem** e **O rótulo de uma nota de rodapé começa com** (o caractere após o colchete de abertura de um rótulo que o torna uma nota de rodapé: `[^note]` é desenhado como uma referência de nota de rodapé quando uma linha começa com `[^note]:`). |

As marcas formam pares dentro de uma linha. Código, caracteres escapados e o endereço de um link são texto simples para as marcas ao redor.

## Código-fonte estilizado

Com **Código com estilo** ativado, o editor desenha um documento com a aparência da sua sintaxe: títulos maiores, trechos em negrito e itálico, barras de citação, recuos de lista, caixas de tarefa, linhas, links e cartões de código, e oculta as marcas que os formam (com **Ocultar marcadores** ativado), exceto na linha em que está o cursor. O editor não conhece nenhuma sintaxe em particular: uma regra diz o que a sua correspondência é ao trazer uma entrada de estilo, e uma regra sem ela é colorida, mas não reestilizada.

As **Opções** de cada regra têm um grupo **Código-fonte estilizado**:

| Campo | O que faz |
| --- | --- |
| **Função** | O que a correspondência é, ou **Sem estilo**. Para uma construção dentro de uma linha: heading, strong, emphasis, code, strike, highlight, underline, link, subscript, superscript. Para uma linha inteira: rule (uma quebra temática), list (o marcador de um item de lista, incluindo o recuo e o espaço depois dele), task (um marcador seguido de uma caixa de seleção) e quote (as marcas `>` de uma linha citada). Para um bloco reconhecido por inteiro: codeBlock. Para um bloco cujas linhas de abertura e de fechamento são correspondências separadas: quoteRegion. Para uma tabela, equação ou diagrama desenhado como imagem: renderedBlock. |
| **Grupo do conteúdo** | O grupo de captura, contado a partir de 1, que contém aquilo de que a construção trata: a palavra dentro de `*bold*`, o título em `\section{Title}`. O que a correspondência tem além disso são as marcas da própria construção, que **Ocultar marcadores** oculta. `0` significa que a correspondência inteira é conteúdo e nada é ocultado, como em um endereço da web. Deixe de fora quando a correspondência for apenas marcas, como o `== ` de um título. |
| **Nível do título**, **Grupo do nível** | O nível de um título, de 1 a 6. Se omitido, é o número no fim do nome de saída da regra (`heading2`), ou o comprimento do grupo de captura que contém uma sequência de `#`. |
| **Grupo do marcador** | Para uma lista ou tarefa, o grupo de captura que é o marcador com o seu recuo e os espaços depois dele, quando a correspondência começa com outra coisa, como o `> ` de um item citado. |
| **Aplica o estilo até o fim da linha** | Aplica o estilo da correspondência até o fim da linha, para uma regra que corresponde apenas ao marcador de um título e deixa o título como o texto que vem a seguir. |
| **É desenhado como** | Para um bloco renderizado, o que ele é: uma tabela, fórmula ou diagrama, ou **Não é uma imagem**. |
| **Grupos do endereço** | Para um link, os grupos de captura, tentados em ordem, que contêm o endereço que ele abre ao ser clicado ou tocado; `0` é a correspondência inteira. Somente endereços da web, de e-mail e de telefone são abertos. |

Os números de grupo contam os parênteses do padrão a partir de 1; 0 é a correspondência inteira. Um perfil que não substitui o Markdown também mantém a leitura própria do Markdown dos tipos que as suas regras não declaram, como as suas barras de citação e os pares de `**`.

## Atributos do documento e seções condicionais

Uma regra de **Atributo do documento** define um valor por `name`, e uma regra de **Referência a atributo** (uma regra em linha com as partes `name` e `original`) substitui uma referência por ele. Uma referência a um atributo que ninguém definiu permanece como foi escrita. Uma **Seção condicional** mantém ou descarta os blocos entre as suas linhas, dependendo de os atributos que ela nomeia estarem definidos. Os atributos valem a partir de onde são definidos.

Uma regra que produz **Ajustes do próximo bloco** reconhece uma linha inteira que configura o bloco seguinte e não mostra nada por si só. As suas partes e atributos fixos são dados a esse bloco: `title`, `id`, `nodeType`, `language` e `hardbreaks` têm os significados listados em Partes, e qualquer outra parte é mantida no bloco, onde uma tabela, lista ou citação a lê.

## Testando um perfil

Na parte de baixo do editor, **Amostra de teste** contém um texto de exemplo (que começa como um título e uma linha de texto). Escolha **Verificar amostra** para ver os nós que as suas regras criam, recuados conforme se aninham. Ele diz “Nenhum bloco reconhecido.” quando nada corresponde.

## Linha de base

A **linha de base** de um perfil é o seu ponto de restauração: como ele estava quando você o criou, duplicou ou importou. **Redefinir para a linha de base** descarta todas as alterações desde então, após você confirmar. **Definir como nova linha de base** salva o perfil e faz do seu estado atual o ponto de restauração.

Salvar é recusado, com uma mensagem, se o perfil substitui o Markdown mas não tem uma regra de fim de linha, se um padrão é inseguro e poderia travar o editor, ou se o arquivo não pode ser gravado.

## Partes

Partes são os pedaços nomeados de uma correspondência que uma saída lê.

| Parte | Significado |
| --- | --- |
| `allOf` | O separador entre nomes quando todos são necessários, como `+`. |
| `alt` | A descrição de uma imagem, para leitores que não conseguem vê-la. |
| `anyOf` | O separador entre nomes quando qualquer um basta, como `,`. |
| `attribution` | Quem disse uma citação, exibido sob ela. |
| `citetitle` | A obra de onde vem uma citação, exibida após a atribuição. |
| `columns` | A lista de colunas de uma tabela, como `1,2,1`; as suas entradas contam as colunas. |
| `condition` | Os nomes de atributos dos quais a seção depende. |
| `conditionType` | `defined` mantém a seção quando os atributos estão definidos, `undefined` quando não estão. |
| `content` | O próprio texto, quando não é a correspondência inteira. |
| `format` | O mecanismo de um diagrama (`mermaid` ou `vega-lite`); em uma tabela, qual dos seus formatos delimitados as células usam. |
| `hardbreaks` | Quando presente, mantém as quebras de linha simples do próximo bloco. |
| `header` | Qualquer valor diferente de `false` faz da primeira linha de uma tabela o seu cabeçalho. |
| `id` | Um nome: para o próximo bloco, o ID para o qual as referências cruzadas apontam; para uma nota de rodapé, um nome que permite que notas de rodapé posteriores sem texto próprio compartilhem o seu número. |
| `keys` | As teclas a pressionar, separadas por vírgulas. |
| `label` | O texto exibido para uma referência ou âncora, no lugar do título do próprio destino. |
| `language` | A linguagem de programação de um bloco de código, usada para a sua coloração. |
| `level` | O nível do título, de 1 a 6. |
| `marker` | O separador após o termo, como `::`. Um marcador diferente aninha uma lista dentro da descrição. |
| `name` | O nome do atributo, em uma definição ou em uma referência. |
| `nodeType` | Transforma o próximo bloco em outra saída, pelo seu nome no arquivo. |
| `noHeader` | Quando presente, uma tabela não tem linha de cabeçalho. |
| `notation` | A notação matemática: `tex` (o padrão) ou `latex`. |
| `open` | `true` exibe uma seção recolhível aberta. |
| `ordered` | `true` torna a lista numerada. |
| `original` | A referência como foi escrita, exibida quando o atributo não está definido. |
| `presentation` | Como a próxima lista de descrição é exibida: `sideBySide` põe termos e descrições em duas colunas; `questions` numera cada termo como uma pergunta, com a resposta sob ele. |
| `primary` | A entrada do índice. |
| `secondary` | Uma subentrada sob a entrada do índice. |
| `sectionLabel` | Uma palavra que o número do próximo título segue, como `Appendix`: esses títulos são contados à parte, `Appendix A:`. |
| `sectionLabelStart` | O primeiro desses números: uma letra (`A`) conta em letras, um número conta em números. |
| `src` | O endereço do arquivo de vídeo ou áudio. |
| `start` | O número em que uma lista numerada começa. |
| `summary` | A linha exibida em uma seção recolhível enquanto ela está fechada. |
| `targetID` | O ID para o qual a referência aponta. |
| `term` | O termo que está sendo descrito. |
| `tertiary` | Uma subentrada sob a secundária. |
| `text` | O texto exibido, quando o padrão captura mais do que isso. O texto de uma nota de rodapé segue o parágrafo, tabela ou lista em que ela está, numerado. |
| `title` | Um título: o cabeçalho de uma caixa, a dica de uma imagem ou de um link, ou uma legenda acima do próximo bloco. |
| `type` | O tipo de aviso, como `note`, `tip` ou `warning`. |
| `unset` | Quando presente, a regra remove o atributo em vez de defini-lo. |
| `url` | O endereço para o qual um link ou imagem aponta. |
| `value` | O valor do atributo; referências a atributos definidos antes são substituídas nele. |
