# Chapter 24: Crie modelos reutilizáveis com o Super Tab

Os campos transformam uma expansão estática em um formulário guiado. Um campo pode ter um texto de exemplo, um valor padrão ou uma lista de opções.

1. Crie uma macro para uma estrutura repetida.
2. Adicione campos na expansão ou use **Inserir ▸ Campo** ao montar o código-fonte.
3. Expanda a macro.
4. Digite no primeiro campo selecionado.
5. Use **Próximo campo** para avançar e **Campo anterior** para voltar.
6. Em um campo de escolha, selecione um item na lista de opções do campo.

Projete os campos na ordem em que uma pessoa naturalmente responderia a eles. Coloque o cursor final no ponto em que a escrita livre deve continuar. Mantenha os valores padrão inofensivos: um campo esquecido pelo usuário deve ficar evidente na Pré-visualização, em vez de publicar silenciosamente um conteúdo enganoso.

# Part VII — Matemática, diagramas, gráficos e imagens

# Chapter 25: Escreva equações, diagramas e gráficos

O Pilcrow inclui renderização offline para equações MathJax, diagramas Mermaid e gráficos Vega-Lite. O perfil ativo continua determinando onde o bloco começa e termina; a biblioteca integrada apenas desenha o conteúdo.

## Comece por um modelo

1. Escolha **Inserir ▸ Equações**, **Diagramas** ou **Gráficos**.
2. Escolha um modelo.
3. Substitua o código de exemplo.
4. Mude para Pré-visualização ou Lado a lado.
5. Corrija qualquer erro de sintaxe informado no bloco de código-fonte.

Use MathJax para notação matemática, Mermaid para fluxos e relações e Vega-Lite para gráficos baseados em dados. Mantenha uma explicação em texto perto de qualquer elemento visual importante, para que o documento continue compreensível quando um renderizador não estiver disponível e seja acessível a mais leitores.

As bibliotecas são integradas e funcionam sem acesso à rede. Ajustes ▸ Biblioteca ▸ Bibliotecas de renderização mostra as versões e os avisos. Se um bloco não for renderizado, confirme o rótulo de idioma, os delimitadores, os ajustes dos recursos opcionais e a sintaxe antes de mudar de tema.

# Chapter 26: Gerencie a inserção de imagens e a privacidade das imagens online

Abra **Ajustes ▸ Edição ▸ Imagens** e decida:

- Se uma imagem inserida é copiada, movida ou deixada onde está.
- Se a regra vale para imagens locais e online.
- Se as imagens online podem ser carregadas.
- Se os caminhos devem ser relativos sempre que possível.
- Se os caminhos relativos começam com `./`.
- Se as URLs recebem escape na inserção.

Para um projeto portátil, mantenha as imagens dentro da pasta do documento e use caminhos relativos. Copiar é mais seguro do que mover quando o original pertence a outro projeto. Mover evita duplicatas, mas pode quebrar o local de origem.

As imagens online revelam o endereço de rede do leitor aos servidores que as hospedam e podem mudar ou desaparecer. Deixe o carregamento pela rede desativado ao revisar documentos não confiáveis. Para uma publicação duradoura, baixe uma cópia autorizada e referencie-a localmente.

# Part VIII — Publique e compartilhe

# Chapter 27: Exporte HTML, PDF, Word e imagens

1. Salve o documento e inspecione a Pré-visualização.
2. Escolha Exportar na barra de ferramentas ou nos comandos de Arquivo.
3. Escolha HTML, HTML (sem estilos), PDF, Word, Imagem ou Arquivo PDF.
4. Escolha o Tema de renderização em **Estilo**.
5. Para PDF, Arquivo PDF e Word, revise as opções de **Página**: tamanho do papel, orientação e margens.
6. Escolha **Exportar** e selecione um destino, ou **Compartilhar** para enviar diretamente o arquivo gerado.

HTML cria uma página independente com estilos. **HTML (sem estilos)** gera uma estrutura limpa, sem o CSS do tema incorporado. Word produz um pacote `.docx` real com estrutura semântica de documento; equações, diagramas e gráficos complementares viram imagens. **Imagem** cria um único PNG do documento renderizado. **Arquivo PDF** cria um ZIP contendo segmentos de PDF em ordem, além de um manifesto, o que é útil quando outro fluxo de trabalho quer segmentos limitados e separáveis. Um PDF grande normal é montado automaticamente por um caminho de renderização segmentada, enquanto o Arquivo PDF preserva os segmentos como o produto final.

Abra **Opções avançadas** para adicionar **CSS personalizado** somente para esta exportação. O CSS por exportação é aplicado depois do tema e, por isso, prevalece quando os seletores têm o mesmo peso. As mudanças de página afetam apenas a exportação atual, a menos que você escolha **Usar estes ajustes de página como padrão**. Um sumário gerado, a numeração dos títulos e os rótulos dos títulos são definidos uma única vez para todas as exportações em **Ajustes ▸ Sumário** (Chapter 70).

Se o resultado estiver errado, determine se o problema é de estrutura ou de estilo. Um título ausente costuma ser um problema de perfil ou de código-fonte; um título pouco atraente é um problema do Tema de renderização.

## Imprima o documento renderizado

Escolha **Imprimir…** em Arquivo ou Mais. A impressão usa o mesmo processo de renderização e os mesmos padrões de layout de página do PDF; portanto, a Pré-visualização e a exportação em PDF são os melhores lugares para diagnosticar primeiro a estrutura e o estilo. No Mac, a Configuração de Página edita esse mesmo layout de página compartilhado. Confira papel, orientação, margens, cabeçalhos e rodapés na caixa de diálogo de impressão antes de gastar páginas físicas.

# Chapter 28: Defina os padrões de exportação e os elementos de página

Abra **Ajustes ▸ Exportar ▸ Padrões de exportação**. Escolha o Tema de renderização e o layout de página padrão. Configure os metadados do autor, os cabeçalhos, os rodapés e se cada título de nível superior começa em uma nova página (**Quebra de página entre títulos de nível superior**).

Os modelos de cabeçalho e rodapé podem incluir `${title}`, `${author}`, `${pageNo}`, `${pageCount}` e `${today}`. Mantenha-os curtos o bastante para caber nas margens da página. Teste um PDF de várias páginas, porque um cabeçalho que parece bom em uma página pode colidir com títulos longos ou números de página mais adiante. Esses valores de acabamento são armazenados por formato de saída; o layout de página é compartilhado por PDF, Arquivo PDF, Word e impressão.

As opções do CommonMark controlam sintaxes opcionais como destaque, subscrito, sobrescrito, matemática em linha, links automáticos, alertas, front matter, diagramas, pontuação inteligente e a apresentação de blocos de código. Ative apenas os recursos que o seu código-fonte realmente usa. Documentos CommonMark portáteis não devem depender de extensões sem documentá-las.

# Chapter 29: Compartilhe o código-fonte e a saída final

Escolha **Compartilhar…** para o documento-fonte quando outra pessoa precisar do arquivo editável. Um documento salvo e sem alterações é compartilhado diretamente. Um documento não salvo ou modificado é compartilhado como uma cópia temporária do texto atual; documentos muito grandes podem precisar ser salvos antes.

Escolha **Compartilhar** em Exportar quando o destinatário precisar de um PDF, documento Word, arquivo HTML ou imagem finalizados. Isso gera a saída sem exigir que você mantenha antes uma exportação salva separada.

Antes de compartilhar o código-fonte, inclua as imagens locais, os documentos vinculados, os perfis ou os temas de que ele depende, quando o destinatário precisar do mesmo comportamento. Antes de compartilhar a saída final, confira os links, a Pré-visualização, as quebras de página, o texto alternativo e o nome do arquivo.

# Part IX — O assistente

# Chapter 30: Conecte um provedor de IA com segurança

O Assistente é opcional e usa uma conexão que você configura. O Pilcrow não escolhe um provedor silenciosamente.

1. Abra **Ajustes ▸ Geral ▸ Assistente**.
2. Adicione uma predefinição ou escolha **Personalizada…**.
3. Informe um nome, a URL base, o formato de comunicação e o modelo.
4. Se o provedor exigir uma chave de API, ative essa opção e armazene a chave quando solicitado. As chaves ficam guardadas no Chaveiro do sistema.
5. Escolha **Testar conexão**.
6. Salve e torne a conexão ativa.

Use **Escolher modelo…** no Assistente quando o provedor oferecer descoberta de modelos. Se um modelo desaparecer, escolha um atual em vez de tentar repetidamente um identificador obsoleto.

Antes do primeiro uso de uma conexão, o Pilcrow mostra para onde o texto será enviado e pede consentimento. Leia o nome do host. Um servidor local e um provedor de nuvem público têm consequências de privacidade diferentes, mesmo que exponham o mesmo formato de API.

# Chapter 31: Faça perguntas com contexto deliberado

Abra a barra lateral do Assistente e escolha o modo de conversa. O indicador de contexto começa com o menor escopo útil, normalmente a seleção. Escolha outro escopo apenas quando a pergunta exigir.

1. Selecione o parágrafo com o qual você quer ajuda.
2. Confirme que o indicador diz Seleção e revise o resumo dele.
3. Faça uma pergunta específica, como “Qual frase deixa a cronologia confusa?”
4. Leia a resposta como um conselho, não como uma edição automática.
5. Aplique as mudanças você mesmo ou por meio de uma ação revisada oferecida.

O Pilcrow exclui padrões e pastas configurados do contexto do assistente. Gerencie-os nos ajustes do Assistente. Use o controle de pasta para desativar o acesso do assistente em um espaço de trabalho sensível. Limpe a conversa com o botão da lixeira quando ela não pertencer mais à tarefa atual.

Nunca compartilhe uma pasta inteira só porque uma pergunta menciona um arquivo. O mínimo de contexto necessário melhora a privacidade e, muitas vezes, a qualidade da resposta.

# Chapter 32: Receba ajuda para criar recursos do Pilcrow

Mude o Assistente para **Ajuda** e escolha Perfil, Macro ou Guia de estilo. O Pilcrow inclui a referência de formato relevante na conversa, para que as instruções seguintes permaneçam bem fundamentadas.

Descreva o comportamento desejado e forneça um pequeno exemplo. Peça um rascunho, use a Pré-visualização para inspecionar o texto do recurso gerado e depois valide-o no editor de Ajustes correspondente. Não importe nem salve um JSON gerado e opaco sem ler o nome, os gatilhos ou padrões e as saídas.

Uma sequência produtiva é:

1. Descreva um comportamento e dois exemplos.
2. Peça o menor recurso válido.
3. Valide-o no Pilcrow.
4. Teste um caso de sucesso e um que não corresponda.
5. Devolva o erro de validação para uma correção focada.

# Chapter 33: Execute uma revisão de estilo assistida por IA

Este fluxo de trabalho amplia o Chapter 21:

1. Selecione uma passagem para o primeiro teste.
2. Escolha Revisão de estilo, um guia, uma variante e as áreas de revisão.
3. Confirme o provedor e o modelo ativos.
4. Inicie a revisão.
5. Ordene os resultados por gravidade ou área, conforme oferecido.
6. Abra um resultado, leia a evidência citada e inspecione o local no código-fonte.
7. Aplique, descarte ou deixe sem resolução.

Para um documento inteiro, o Pilcrow estima os bytes e o número de solicitações e pergunta novamente antes de enviar. Você pode parar entre os trechos. Revise documentos sensíveis localmente ou com um provedor cujos termos de tratamento de dados você aceite. Exclua os dados e as chaves de IA nos ajustes do Assistente ou de Armazenamento e privacidade ao desativar uma conexão.

# Part X — Projetos de livro

# Chapter 34: Transforme uma pasta em um projeto de livro

Para um projeto novo, escolha **Arquivo ▸ Novo livro…**, informe o título e o destino e deixe o Pilcrow criar a pasta inicial e o manifesto. Para adotar um manuscrito existente, abra a pasta dele, escolha **Arquivo ▸ Transformar a pasta em projeto de livro** ou **Transformar em projeto** na barra lateral Projeto e complete os metadados. O Pilcrow cria um arquivo `manifest.pilcrow` que descreve a ordem e os metadados; ele não reorganiza os arquivos do manuscrito.

Abra os Ajustes do projeto e informe título, autor, meta de palavras, variáveis, comportamento da contagem de palavras e sintaxe. Adicione arquivos existentes listados como **Fora do manuscrito** ou crie novos elementos pré-textuais, capítulos, cenas e pós-textuais no menu de adição.

Faça commit ou backup do `manifest.pilcrow` junto com o manuscrito. Ele é o sumário da organização do projeto, embora os arquivos-fonte continuem sendo texto comum.

# Chapter 35: Planeje cenas e acompanhe o progresso do manuscrito

Escolha entre **Lista**, **Sinopses** e **Cartões**:

- Lista enfatiza a ordem do manuscrito e as contagens de palavras.
- Sinopses acrescenta resumo, ponto de vista, local, status e progresso.
- Cartões oferece um quadro visual de planejamento sem alterar a ordem dos arquivos.

Abra os detalhes de um item para definir o papel, o status, a sinopse, o ponto de vista, o local e a meta de palavras. Filtre por status para se concentrar em trabalho em rascunho, em revisão ou concluído. Remova um item do manuscrito sem excluir o arquivo dele quando for pesquisa ou uma cena cortada.

Reordene somente quando nenhum filtro de status estiver ativo; um subconjunto filtrado não consegue representar com segurança a ordem completa do manuscrito. No iPad, escolha **Reordenar**, arraste e depois escolha **Concluído**. Recolha os capítulos para reduzir o ruído da lista.

Se o Pilcrow disser que o arquivo do projeto mudou no disco, recarregue e repita a ação pretendida. Essa proteção contra conflitos impede que um dispositivo ou colaborador sobrescreva um manifesto mais recente.

# Chapter 36: Compile um manuscrito

1. Abra a barra lateral Projeto.
2. Confirme a ordem, os arquivos incluídos e os metadados do projeto.
3. Escolha **Compilar…**.
4. Escolha o formato de saída, o Tema de renderização e as opções de compilação.
5. Revise os elementos pré-textuais, as quebras de capítulo, a numeração e os papéis incluídos.
6. Compile e inspecione o resultado.

A compilação pode produzir HTML, PDF ou Word. Escolha quais elementos pré-textuais, partes, capítulos e pós-textuais começam em uma nova página; defina o separador entre cenas; inclua um sumário; numere os títulos; e, se quiser, mantenha antes um instantâneo do Histórico de versões de cada arquivo incluído. O resumo do Manuscrito mostra os arquivos incluídos, os bytes, os arquivos omitidos, os caminhos ausentes e a ordem final. Os arquivos ausentes precisam ser resolvidos antes que Compilar fique disponível.

Salve um grupo de escolhas de compilação como uma predefinição nomeada quando você publicar o mesmo manuscrito de várias formas, por exemplo “DOCX para o editor” e “PDF para impressão”. Exclua uma predefinição obsoleta na mesma folha. Enquanto a compilação roda, o progresso mostra o número de arquivos e **Parar** cancela a operação. As `{{variables}}` não resolvidas são informadas e deixadas visivelmente inalteradas.

A compilação lê a ordem do manifesto e combina o código-fonte de forma lógica; ela não concatena nem sobrescreve os seus arquivos. Corrija uma cena no arquivo-fonte dela e compile novamente. Use variáveis do projeto para metadados repetidos, em vez de duplicar manualmente o texto do título ou do autor.

# Part XI — Perfis de sintaxe

# Chapter 37: Escolha e entenda um perfil de sintaxe

Um perfil diz ao Pilcrow como as marcas do código-fonte se tornam papéis estruturais. O CommonMark é integrado, mas é apenas um perfil, não a definição do app.

Use o controle de perfil na barra de status ou no controle de documento apropriado para escolher um perfil. O Pilcrow pode inferir um a partir da extensão e lembrar uma escolha por arquivo. O perfil ativo controla o realce, a Estrutura, a disponibilidade de formatação, a Pré-visualização, a estrutura de exportação, o comportamento de continuação e as inserções específicas do perfil.

Escolha um perfil com base na linguagem de código-fonte que já está presente. Trocar de perfil não converte o texto; ele o reinterpreta. Se você precisar de conversão, crie uma cópia e transforme o código-fonte explicitamente.

# Chapter 38: Crie e teste um perfil

1. Abra **Ajustes ▸ Biblioteca ▸ Perfis de sintaxe**.
2. Duplique um perfil integrado parecido ou crie um novo perfil.
3. Em **Visão geral**, defina nome, identificadores, extensões e herança opcional.
4. Em **Regras**, adicione a menor construção de que você precisa.
5. Abra **Amostra de teste**, cole um código-fonte representativo e escolha **Verificar amostra**.
6. Salve, ative o perfil em um documento descartável e compare Editar, Estrutura, Pré-visualização e exportação.

Teste os limites: início e fim do arquivo, linhas em branco, construções aninhadas, Unicode, um delimitador sem fechamento e texto que não deve corresponder. Um perfil é confiável quando rejeita os quase acertos, além de reconhecer os exemplos.

Use **Definir como nova linha de base** depois de uma revisão sabidamente boa. **Redefinir para a linha de base** descarta os experimentos posteriores. Duplique antes de uma reformulação arriscada.

# Chapter 39: Edite as regras do perfil e o JSON avançado

O editor de regras expõe o tipo de padrão, os requisitos de início de linha, o papel produzido, as capturas, a continuação após Return, o comportamento de blocos delimitados, o layout, os trechos e pares em linha, as legendas e os papéis de estilo.

Use reconhecedores literais ou estruturados sempre que eles expressarem a sintaxe. Mantenha os padrões limitados e ancorados. O Pilcrow rejeita padrões sabidamente inseguros, mas uma expressão tecnicamente aceita ainda pode ser ampla ou confusa demais.

Escolha **Editar JSON avançado…** somente quando o editor visual não expuser a propriedade necessária. Aplicar valida o JSON e impede a alteração da identidade do perfil por essa folha. Mantenha uma amostra de teste válida junto com o trabalho avançado.

A herança é útil para um dialeto pequeno: herde de um pai estável e substitua apenas a sintaxe nomeada. Evite uma cadeia longa que dificulte explicar o comportamento. Se a importação de um perfil informar um conflito, compare nomes e IDs antes de substituir qualquer coisa.
