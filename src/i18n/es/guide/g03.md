# Chapter 24: Crea plantillas reutilizables con Super Tab

Los campos convierten una expansión estática en un formulario guiado. Un campo puede tener un marcador de posición, un valor predeterminado o una lista de opciones.

1. Crea una macro para una estructura repetida.
2. Añade campos en la expansión, o usa **Insertar ▸ Campo** mientras construyes el código fuente.
3. Expande la macro.
4. Escribe en el primer campo seleccionado.
5. Usa **Campo siguiente** para avanzar y **Campo anterior** para retroceder.
6. En un campo de opciones, elige de la lista de opciones del campo.

Diseña los campos en el orden en que una persona los responde de forma natural. Coloca el cursor final en el punto donde debe continuar la escritura libre. Mantén los valores predeterminados inofensivos: un campo que el usuario olvide debe ser evidente en la vista previa, no publicar en silencio contenido engañoso.

# Part VII — Matemáticas, diagramas, gráficos e imágenes

# Chapter 25: Escribe ecuaciones, diagramas y gráficos

Pilcrow incluye renderizado sin conexión para ecuaciones MathJax, diagramas Mermaid y gráficos Vega-Lite. El perfil activo sigue determinando dónde empieza y termina el bloque; la biblioteca incluida solo dibuja su contenido.

## Empieza desde una plantilla

1. Elige **Insertar ▸ Ecuaciones**, **Diagramas** o **Gráficos**.
2. Elige una plantilla.
3. Reemplaza el código fuente de ejemplo.
4. Cambia a Vista previa o En paralelo.
5. Corrige cualquier error de sintaxis indicado en el bloque de código fuente.

Usa MathJax para notación matemática, Mermaid para flujos y relaciones, y Vega-Lite para gráficos basados en datos. Mantén una explicación textual cerca de cualquier elemento visual importante para que el documento siga siendo comprensible cuando no haya un renderizador disponible y sea accesible para más lectores.

Las bibliotecas están incluidas y funcionan sin acceso a la red. Configuración ▸ Biblioteca ▸ Rendering Libraries muestra las versiones y los avisos. Si un bloque no se renderiza, confirma su etiqueta de lenguaje, los delimitadores, los ajustes de funciones opcionales y la sintaxis antes de cambiar de tema.

# Chapter 26: Gestiona la inserción de imágenes y la privacidad de las imágenes en línea

Abre **Configuración ▸ Edición ▸ Imágenes** y decide:

- Si una imagen insertada se copia, se mueve o se deja donde está.
- Si la regla se aplica a las imágenes locales y a las imágenes en línea.
- Si pueden cargarse las imágenes en línea.
- Si las rutas deben ser relativas cuando sea posible.
- Si las rutas relativas empiezan por `./`.
- Si las URL se escapan al insertarlas.

Para un proyecto portátil, mantén las imágenes dentro de la carpeta del documento y usa rutas relativas. Copiar es más seguro que mover cuando el original pertenece a otro proyecto. Mover evita duplicados, pero puede romper la ubicación original.

Las imágenes en línea revelan la dirección de red del espectador a sus servidores y pueden cambiar o desaparecer. Deja desactivada la carga desde la red al revisar documentos que no son de confianza. Para una publicación duradera, descarga una copia autorizada y haz referencia a ella de forma local.

# Part VIII — Publica y comparte

# Chapter 27: Exporta HTML, PDF, Word e imágenes

1. Guarda el documento e inspecciona la Vista previa.
2. Elige Exportar en la barra de herramientas o en los comandos de Archivo.
3. Elige HTML, HTML (sin estilos), PDF, Word, Imagen o PDF Archive.
4. Elige el Tema de renderizado en **Estilo**.
5. Para PDF, PDF Archive y Word, revisa las opciones de **Página**: tamaño de papel, orientación y márgenes.
6. Elige **Exportar** y selecciona un destino, o **Compartir** para enviar directamente el archivo generado.

HTML crea una página independiente con estilos. **HTML (sin estilos)** genera una estructura limpia sin el CSS del tema incrustado. Word produce un paquete `.docx` real con estructura semántica del documento; las ecuaciones, los diagramas y los gráficos complementarios se convierten en imágenes. **Imagen** crea un único PNG del documento renderizado. **PDF Archive** crea un ZIP que contiene segmentos PDF ordenados más un manifiesto, lo cual es útil cuando otro flujo de trabajo necesita segmentos acotados y separables. Un PDF grande normal se ensambla automáticamente mediante una ruta de renderizado segmentada, mientras que PDF Archive conserva los segmentos como producto final.

Abre **Opciones avanzadas** para añadir **CSS personalizado** solo para esta exportación. El CSS de cada exportación se aplica después del tema y, por tanto, prevalece cuando los selectores tienen el mismo peso. Los cambios de página afectan solo a la exportación actual, a menos que elijas **Usar estos ajustes de página como predeterminados**. La tabla de contenido generada, la numeración de los encabezados y las etiquetas de los encabezados se establecen una sola vez para todas las exportaciones en **Configuración ▸ Tabla de contenido** (capítulo 70).

Si el resultado es incorrecto, determina si el problema es de estructura o de estilo. Un encabezado que falta suele ser un problema del perfil o del código fuente; un encabezado poco atractivo es un problema del Tema de renderizado.

## Imprime el documento renderizado

Elige **Imprimir…** en Archivo o en Más. La impresión usa la misma canalización de renderizado y los mismos valores predeterminados de diseño de página que el PDF, por lo que la Vista previa y la exportación a PDF son los lugares adecuados para diagnosticar primero la estructura y el estilo. En Mac, Ajustar página edita el mismo diseño de página compartido. Comprueba el papel, la orientación, los márgenes, los encabezados y los pies de página en el cuadro de diálogo de impresión antes de imprimir páginas físicas.

# Chapter 28: Establece los valores de exportación predeterminados y los elementos de página

Abre **Configuración ▸ Exportar ▸ Valores de exportación predeterminados**. Elige el Tema de renderizado y el diseño de página predeterminados. Configura los metadatos del autor, los encabezados, los pies de página y si cada encabezado de nivel superior empieza en una página nueva (**Salto de página entre encabezados de nivel superior**).

Las plantillas de encabezado y pie de página pueden incluir `${title}`, `${author}`, `${pageNo}`, `${pageCount}` y `${today}`. Mantenlas lo bastante cortas para los márgenes de la página. Prueba un PDF de varias páginas, porque un encabezado que se ve bien en una página puede chocar más adelante con encabezados largos o números de página. Estos valores de acabado se almacenan por formato de salida; el diseño de página es compartido por PDF, PDF Archive, Word e impresión.

Las opciones de CommonMark controlan la sintaxis opcional, como resaltado, subíndice, superíndice, matemáticas en línea, enlaces automáticos, alertas, front matter, diagramas, puntuación tipográfica y presentación de los bloques de código. Activa solo las funciones que tu código fuente realmente usa. Los documentos CommonMark portátiles no deberían depender de extensiones sin documentarlas.

# Chapter 29: Comparte el código fuente y el resultado final

Elige **Compartir…** para el documento fuente cuando otra persona necesite el archivo editable. Un documento guardado y sin cambios se comparte directamente. Un documento sin guardar o con cambios se comparte como una copia temporal de su texto actual; los documentos muy grandes pueden requerir guardarse primero.

Elige **Compartir** en Exportar cuando el destinatario necesite un PDF, un documento de Word, un archivo HTML o una imagen terminados. Esto genera la salida sin que tengas que conservar antes una exportación guardada aparte.

Antes de compartir el código fuente, incluye las imágenes locales, los documentos enlazados, los perfiles o los temas de los que dependa, cuando el destinatario necesite el mismo comportamiento. Antes de compartir el resultado final, comprueba los enlaces, la Vista previa, los saltos de página, el texto alternativo y el nombre de archivo.

# Part IX — El asistente

# Chapter 30: Conecta un proveedor de IA de forma segura

El Asistente es opcional y usa una conexión que tú configuras. Pilcrow no elige un proveedor en silencio.

1. Abre **Configuración ▸ General ▸ Asistente**.
2. Añade un ajuste preestablecido o elige **Personalizada…**.
3. Introduce un nombre, la URL base, el formato de comunicación y el modelo.
4. Si el proveedor requiere una clave de API, activa esa opción y guarda la clave cuando se te pida. Las claves se conservan en el llavero del sistema.
5. Elige **Probar conexión**.
6. Guarda y activa la conexión.

Usa **Elegir modelo…** en el Asistente cuando el proveedor ofrezca detección de modelos. Si un modelo desaparece, elige uno actual en lugar de reintentar repetidamente un identificador obsoleto.

Antes del primer uso de una conexión, Pilcrow muestra adónde irá el texto y pide tu consentimiento. Lee el nombre del host. Un servidor local y un proveedor público en la nube tienen consecuencias de privacidad distintas, aunque expongan el mismo formato de API.

# Chapter 31: Haz preguntas con un contexto deliberado

Abre la barra lateral del Asistente y elige el modo conversacional. La etiqueta de contexto empieza con el alcance útil más pequeño, normalmente la selección. Elige otro alcance solo cuando la pregunta lo requiera.

1. Selecciona el párrafo con el que quieres ayuda.
2. Confirma que la etiqueta dice Selección y revisa su resumen.
3. Haz una pregunta concreta, como «¿Qué frase hace confusa la cronología?»
4. Lee la respuesta como un consejo, no como una edición automática.
5. Aplica los cambios tú mismo o mediante una acción revisada que se te ofrezca.

Pilcrow excluye del contexto del asistente los patrones y las carpetas configurados. Adminístralos en los ajustes del Asistente. Usa el control de carpetas para desactivar el acceso del asistente en un espacio de trabajo sensible. Borra la conversación con el botón de la papelera cuando ya no pertenezca a la tarea actual.

Nunca compartas una carpeta entera solo porque una pregunta mencione un archivo. El contexto mínimo necesario mejora la privacidad y, a menudo, la calidad de las respuestas.

# Chapter 32: Obtén ayuda para crear recursos de Pilcrow

Cambia el Asistente a **Ayuda** y elige Perfil, Macro o Guía de estilo. Pilcrow incluye la referencia de formato correspondiente junto con la conversación para que las instrucciones posteriores sigan fundamentadas.

Describe el comportamiento deseado y proporciona un ejemplo pequeño. Pide un borrador, usa la Vista previa para inspeccionar el texto del recurso generado y luego valídalo en el editor de Configuración correspondiente. No importes ni guardes JSON generado y opaco sin leer su nombre, sus disparadores o patrones y sus salidas.

Una secuencia productiva es:

1. Indica un comportamiento y dos ejemplos.
2. Pide el recurso válido más pequeño.
3. Valídalo en Pilcrow.
4. Prueba un caso que funcione y uno que no coincida.
5. Devuelve el error de validación para obtener una corrección concreta.

# Chapter 33: Ejecuta una revisión de estilo asistida por IA

Este flujo de trabajo amplía el capítulo 21:

1. Selecciona un pasaje para la primera prueba.
2. Elige Revisión de estilo, una guía, una variante y las áreas de revisión.
3. Confirma el proveedor y el modelo activos.
4. Inicia la revisión.
5. Ordena los hallazgos por gravedad o área, según se ofrezca.
6. Abre un hallazgo, lee la evidencia citada e inspecciona la ubicación en el código fuente.
7. Aplícalo, descártalo o déjalo sin resolver.

Para un documento completo, Pilcrow estima los bytes y el número de solicitudes y vuelve a preguntar antes de enviar. Puedes detener el proceso entre fragmentos. Revisa los documentos sensibles de forma local o con un proveedor cuyas condiciones de tratamiento de datos aceptes. Elimina los datos y las claves de IA desde los ajustes del Asistente o de Almacenamiento y privacidad al dar de baja una conexión.

# Part X — Proyectos de libro

# Chapter 34: Convierte una carpeta en un proyecto de libro

Para un proyecto nuevo, elige **Archivo ▸ Nuevo libro…**, introduce el título y el destino, y deja que Pilcrow cree la carpeta inicial y el manifiesto. Para adoptar un manuscrito existente, abre su carpeta, elige **Archivo ▸ Convertir la carpeta en proyecto de libro** o **Convertir en proyecto** en la barra lateral del Proyecto, y completa los metadatos. Pilcrow crea un archivo `manifest.pilcrow` que describe el orden y los metadatos; no reorganiza los archivos del manuscrito.

Abre Ajustes del proyecto e introduce el título, el autor, el recuento de palabras objetivo, las variables, el comportamiento del recuento de palabras y la sintaxis. Añade los archivos existentes que aparecen como **No está en el manuscrito**, o crea nuevo material preliminar, capítulos, escenas y material final desde el menú de más (+).

Confirma o respalda `manifest.pilcrow` junto con el manuscrito. Es la tabla de contenido para la organización del proyecto, aunque los archivos fuente sigan siendo texto normal.

# Chapter 35: Planifica escenas y sigue el progreso del manuscrito

Elige entre **Lista**, **Sinopsis** y **Tarjetas**:

- Lista destaca el orden del manuscrito y los recuentos de palabras.
- Sinopsis añade resumen, punto de vista, ubicación, estado y progreso.
- Tarjetas ofrece un tablero visual de planificación sin cambiar el orden de los archivos.

Abre los detalles de un elemento para establecer su función, estado, sinopsis, punto de vista, ubicación y palabras objetivo. Filtra por estado para centrarte en el trabajo en borrador, en revisión o terminado. Quita un elemento del manuscrito sin eliminar su archivo cuando sea material de investigación o una escena eliminada.

Reordena solo mientras no haya ningún filtro de estado activo; un subconjunto filtrado no puede representar con seguridad el orden completo del manuscrito. En iPad, elige **Reordenar**, arrastra y luego elige **Listo**. Contrae los capítulos para reducir el ruido de la lista.

Si Pilcrow dice que el archivo del proyecto cambió en el disco, recarga y repite la acción prevista. Esta protección frente a conflictos evita que un dispositivo o un colaborador sobrescriba un manifiesto más reciente.

# Chapter 36: Compila un manuscrito

1. Abre la barra lateral del Proyecto.
2. Confirma el orden, los archivos incluidos y los metadatos del proyecto.
3. Elige **Compilar…**.
4. Elige el formato de salida, el Tema de renderizado y las opciones de compilación.
5. Revisa el material preliminar, los saltos de capítulo, la numeración y las funciones incluidas.
6. Compila e inspecciona el resultado.

La compilación puede producir HTML, PDF o Word. Elige qué material preliminar, partes, capítulos y material final empiezan en una página nueva; establece el separador entre escenas; incluye una tabla de contenido; numera los encabezados; y, opcionalmente, conserva primero una instantánea del Historial de versiones de cada archivo incluido. El resumen del Manuscrito muestra los archivos incluidos, los bytes, los archivos omitidos, las rutas que faltan y el orden final. Los archivos que faltan deben resolverse antes de que Compilar esté disponible.

Guarda un grupo de opciones de compilación como ajuste preestablecido con nombre cuando publiques el mismo manuscrito de varias formas, por ejemplo, «DOCX para el editor» y «PDF para imprenta». Elimina un ajuste preestablecido obsoleto desde la misma hoja. Mientras se ejecuta la compilación, el progreso muestra el número de archivos y **Detener** cancela la operación. Las `{{variables}}` sin resolver se notifican y se dejan visiblemente sin cambios.

La compilación lee el orden del manifiesto y combina el código fuente de forma lógica; no concatena ni sobrescribe tus archivos. Corrige una escena en su archivo fuente y vuelve a compilar. Usa variables del proyecto para los metadatos repetidos en lugar de duplicar manualmente el texto del título o del autor.

# Part XI — Perfiles de sintaxis

# Chapter 37: Elige y comprende un perfil de sintaxis

Un perfil le indica a Pilcrow cómo las marcas del código fuente se convierten en funciones estructurales. CommonMark viene incluido, pero es un perfil más, no la definición de la aplicación.

Usa el control de perfil de la barra de estado o el control adecuado del documento para elegir un perfil. Pilcrow puede deducir uno a partir de una extensión y recordar una elección por archivo. El perfil activo controla el resaltado, el Esquema, la disponibilidad del formato, la Vista previa, la estructura de exportación, el comportamiento de continuación y las inserciones específicas del perfil.

Elige un perfil según el lenguaje de código fuente que ya esté presente. Cambiar de perfil no convierte el texto; lo reinterpreta. Si necesitas una conversión, crea una copia y transforma el código fuente de forma explícita.

# Chapter 38: Crea y prueba un perfil

1. Abre **Configuración ▸ Biblioteca ▸ Perfiles de sintaxis**.
2. Duplica un perfil integrado parecido o crea un perfil nuevo.
3. En **Overview**, establece el nombre, los identificadores, las extensiones y la herencia opcional.
4. En **Rules**, añade la construcción más pequeña que necesites.
5. Abre **Test Sample**, pega código fuente representativo y elige **Comprobar muestra**.
6. Guarda, activa el perfil en un documento desechable y compara Edición, Esquema, Vista previa y la exportación.

Prueba los límites: inicio y final del archivo, líneas en blanco, construcciones anidadas, Unicode, un delimitador sin cerrar y texto que no debería coincidir. Un perfil es fiable cuando rechaza los casi aciertos además de reconocer los ejemplos.

Usa **Establecer como nueva línea base** después de una revisión que sepas que funciona. **Restablecer a la línea base** descarta los experimentos posteriores. Duplica antes de un rediseño arriesgado.

# Chapter 39: Edita las reglas del perfil y el JSON avanzado

El editor de reglas expone el tipo de patrón, los requisitos de inicio de línea, la función producida, las capturas, la continuación después de Retorno, el comportamiento de bloques delimitados, el diseño, las series y pares en línea, los pies de figura y las funciones de estilo.

Usa reconocedores literales o estructurados siempre que expresen la sintaxis. Mantén los patrones acotados y anclados. Pilcrow rechaza los patrones inseguros conocidos, pero una expresión aceptada técnicamente puede seguir siendo demasiado amplia o confusa.

Elige **Editar JSON avanzado…** solo cuando el editor visual no exponga la propiedad necesaria. Aplicar valida el JSON e impide cambiar la identidad del perfil mediante esa hoja. Conserva una muestra de prueba válida junto con el trabajo avanzado.

La herencia es útil para un dialecto pequeño: hereda de un perfil base estable y reemplaza solo la sintaxis indicada. Evita una cadena larga que dificulte explicar el comportamiento. Si al importar un perfil se informa de un conflicto, compara los nombres y los ID antes de reemplazar nada.
