# Part XIX — Editores de elementos de la biblioteca

# Chapter 74: El editor de perfiles y los bloques de construcción de un perfil

Un perfil de sintaxis le dice a Pilcrow qué significa tu marcado. Este capítulo describe el editor de perfiles control por control y luego enumera todos los bloques de construcción que puede usar un perfil. Para una introducción basada en tareas, consulta del Capítulo 37 al Capítulo 39.

Abre el editor desde **Configuración ▸ Biblioteca ▸ Perfiles de sintaxis**: **Nuevo** crea un perfil, **Editar** modifica uno personalizado y **Duplicar** copia un perfil integrado para que puedas modificar la copia. El título del editor es **Editar perfil**, con **Cancelar**, **Guardar** y **Ayuda de perfiles** (que abre la referencia de la app sobre estos bloques de construcción). En una pantalla estrecha, un selector **Sección del perfil** permite elegir entre **Resumen**, **Reglas** y **Muestra de prueba**; en una ancha se ven las tres a la vez.

## Overview

| Campo | Qué hace |
| --- | --- |
| **Nombre** | El nombre del perfil, que se muestra en el menú de la barra de estado y en Configuración. |
| **Descripción** | Una nota sobre el perfil. |
| **Extensiones de archivo (separadas por comas)** | Las extensiones que hacen que se elija este perfil para un archivo. Dos perfiles no pueden compartir una extensión. |
| **Hereda de** | **Ninguno**, u otro perfil en cuyas reglas se basa este. |
| **Sintaxis** | **Amplía Markdown** o **Sustituye Markdown** (más abajo). |
| **De un vistazo** | Recuentos de **Reglas de bloque**, **Reglas en línea** y **Reglas de anidamiento**. |
| **Editar JSON avanzado…** | Abre el perfil como JSON para los campos que el editor guiado no muestra. **Aplicar** conserva tus cambios en el JSON; **Cancelar** los descarta. |

**Amplía Markdown** suma tus reglas a las de Markdown: sus encabezados, listas, énfasis y el resto se siguen leyendo, y tus reglas de bloque y en línea se añaden a ellos. Una regla que es una copia sin cambios de una del perfil CommonMark describe lo que Markdown ya hace, y se deja en manos de este. **Sustituye Markdown** hace que tus reglas sean toda la sintaxis, de modo que las construcciones de Markdown dejan de reconocerse. Con esta opción, una regla debe producir **Fin de línea**, o nada separa los párrafos. El editor avisa «Add a rule whose output node is "newline", or nothing will separate into paragraphs» y el perfil no se puede guardar hasta que exista una. También enumera los tipos de salida que el perfil no define.

## Rules

Las reglas se dividen en tres grupos.

### Block rules

Una regla de bloque reconoce líneas y bloques completos. **Añadir regla** añade una. Cada regla tiene un **Patrón**, un tipo de **Coincidencia**, lo que **Produce** y **Opciones**. Una regla se quita con su botón **Eliminar**. Si no hay ninguna, el editor dice «No rules yet. Add one to recognize a block construct.»

### Inline rules

Una regla en línea reconoce texto dentro de una línea. **Añadir regla en línea** añade una. Las reglas en línea ofrecen cuatro tipos de coincidencia (**Prefijo literal**, **Literal exacto**, **Regex (acotada)** y **Par de delimitadores**); las reglas de bloque ofrecen los siete.

### Nesting rules

Las reglas de anidamiento indican qué salidas pueden ir dentro de cuáles. Cada una tiene un **Nodo padre** y **Nodos hijos permitidos (separados por comas)**. Vacío significa sin restricciones: «No restrictions. Every node type may nest inside any other.» **Añadir regla de anidamiento** añade una.

### Match types

| Tipo de coincidencia | Lee el patrón como | Bloque | En línea |
| --- | --- | --- | --- |
| **Prefijo literal** | Texto con el que empieza la construcción. | sí | sí |
| **Literal exacto** | El texto completo de la construcción. | sí | sí |
| **Prefijo al inicio de línea** | Texto al principio de una línea, como `# `. | sí | |
| **Bloque con sangría** | Líneas que empiezan con el patrón, como cuatro espacios o un tabulador. Las consecutivas, y las líneas en blanco entre ellas, forman un solo bloque, que se muestra sin la sangría. | sí | |
| **Bloque delimitado** | Una línea que abre un bloque, cerrado por una línea correspondiente. | sí | |
| **Regex (acotada)** | Una expresión regular. Pilcrow avisa antes de guardar una que podría quedarse bloqueada: «This regex could hang the editor — simplify it.» | sí | sí |
| **Par de delimitadores** | La misma marca a ambos lados de un texto en una línea, como `%%` en `%%this%%`. No hay ningún espacio justo dentro de las marcas. | sí | sí |

En una expresión regular, `(?<name>…)` da nombre a una parte de la coincidencia. Consulta Partes con nombre más abajo.

## Rule options

Cada grupo **Opciones** de una regla ofrece:

| Opción | Qué hace |
| --- | --- |
| **Prioridad** | Las reglas con mayor prioridad se prueban primero. |
| **Solo al principio de una línea** | Impide que una regla coincida a mitad de línea. |
| **Las partes con nombre se vuelven atributos** | Cada parte con nombre de una expresión regular se convierte en un atributo de la salida. El editor enumera «Parts in this pattern» y «Parts this output reads». Para una salida que contiene texto, como una negrita o un enlace, el texto mostrado es la parte llamada `text` si existe; si no, la última parte que coincidió. |
| **Produce** | Lo que crea la regla: una salida de las listas de abajo, o un nombre **Personalizado**. |
| **Nombre de nodo personalizado** | El nombre de una salida **Personalizado**. |
| **Atributos fijos** | Partes que tienen el mismo valor siempre, añadidas con **Añadir atributo** (un **Nombre** y un **Valor**). Un valor puede incluir una parte con nombre, escrita `{name}`: una regla de correo electrónico cuyo patrón nombra `address` puede dar a su enlace el `url` `mailto:{address}`. |
| **Texto de inserción** | Lo que escribe el menú **Insertar** para esta regla, exactamente como debe aparecer, con `$0` donde debe ir el cursor. Una regla que coincide mediante una expresión regular, un bloque o una sangría necesita esto, o el menú Insertar la omite. |
| **Solo después de una línea en blanco** | Para un bloque con sangría: una línea con sangría justo después de un texto sigue formando parte de ese texto, como la línea siguiente de un elemento de lista. |
| **Tras Intro al final de una línea** | Para listas y citas: **Automático** (repite las viñetas y las citas, cuenta hacia arriba los elementos numerados y empieza los elementos de tarea sin marcar), **Repetir el marcador**, **Contar hacia arriba**, **Empezar de nuevo desde el marcador** o **No añadir nada**. |

### Fenced and delimited blocks

Para una regla de **Bloque delimitado**, **El bloque contiene** indica qué hay dentro:

| Opción | Significado |
| --- | --- |
| **Nada todavía** | Sin definir. |
| **Texto, mostrado tal cual** | Código o texto preformateado. |
| **Nada: oculto** | Un comentario, que se deja fuera del documento. |
| **Otros bloques, en un recuadro** | Una cita, una barra lateral o una advertencia que contiene párrafos, listas y más. |
| **Otros bloques, sin recuadro** | Los bloques se unen al texto circundante; las líneas solo los agrupan. |
| **Una tabla** | Consulta Tablas, más abajo. |
| **Una tabla dibujada con texto** | Una cuadrícula o columnas alineadas de texto que va desde su línea de apertura hasta la siguiente línea en blanco, como las de reStructuredText. |
| **Texto con sangría bajo una línea que termina en una marca** | La línea de apertura es prosa que termina en la marca, como hace `::` en reStructuredText; la prosa sigue siendo un párrafo, y el texto con sangría que viene debajo tras una línea en blanco se muestra tal cual. |
| **Texto con sangría bajo una línea de apertura** | Una directiva como `.. code-block::`, que contiene las líneas con sangría que hay debajo y no tiene línea de cierre. |

**Línea de cierre** es la línea que termina el bloque; vacío significa la misma línea que la de apertura («Same as the opening line»). Un delimitador que no es una expresión regular, como `+++`, se busca como texto simple. **La línea de cierre repite la marca de apertura, al menos las mismas veces** es para las vallas al estilo de Markdown: la línea de cierre es el primer carácter de la línea de apertura repetido al menos tantas veces, de modo que una valla más larga contiene una más corta como texto. El lenguaje de un bloque de texto, cuando la línea de apertura nombra uno conocido, se colorea en el editor.

### Tables

Las opciones de un bloque de tabla:

| Opción | Qué hace |
| --- | --- |
| **Disposición** | **Cuadrícula con líneas de separación** (celdas entre `|` con una línea de separación entre filas) o **Columnas alineadas** (columnas alineadas bajo una primera línea de separación). |
| **Separador de celdas** | El texto con el que empieza cada celda. |
| **Patrón de línea de separación**, **Patrón de línea de separación del encabezado** | Líneas que solo dibujan una separación, y la que termina el encabezado. |
| **La fila termina con** | Una marca que termina cada fila, como hace un `tabular` de LaTeX. |
| **Patrón de celda combinada** | Una celda que abarca varias columnas. |
| **Patrón de opciones de celda** | Una expresión regular para lo que puede ir justo antes del separador de una celda; una parte llamada `colspan` hace que la celda abarque esa cantidad de columnas. |
| **Separador de la lista de columnas**, **Marcador de repetición** | Cómo se escribe una lista `columns`: con `,` y `*`, `3*` cuenta tres columnas. |
| **La primera línea antes de una línea en blanco es la cabecera** | La fila de cabecera se deduce de la disposición. |
| **Formatos** | Otras formas de escribir las celdas, cada una con un nombre y un separador (como `csv` y `,`), añadidas con **Añadir formato** y elegidas con la parte `format` de la tabla. |

| Ajuste | Qué hace |
| --- | --- |
| **Anidar listas por marcador** | Cada marcador nuevo, como `**` después de `*`, inicia un nivel más profundo, sea cual sea la sangría. |
| **Línea de continuación de lista** | Una línea, sola tras un elemento de lista, que une el bloque siguiente al elemento. |
| **Conservar los saltos de línea simples** | Un salto de línea dentro de un párrafo sigue siendo un salto de línea. |
| **Dar identificadores a los encabezados** | Un encabezado sin identificador propio recibe uno a partir de su título: en minúsculas, con las palabras unidas por el **separador de palabras**, tras el **prefijo** (**Prefijo del identificador**, **Separador de palabras del identificador**). Con `_` y `_`, «Getting Started» es `_getting_started`, de modo que una referencia cruzada a él muestra el título. Un título repetido añade el separador y un número. |
| **Numerar encabezados** | Una vez que el documento define el atributo indicado en **Cuando el documento define**, como `:sectnums:` de AsciiDoc, los encabezados desde **Desde el nivel de encabezado** hacia abajo se numeran: `1.`, `1.1.`, `2.`. Los encabezados anteriores a la definición no. |
| **Leyendas numeradas** | Un bloque con título de una salida enumerada aquí, como `image`, `table` o `example`, recibe la **Etiqueta** y su propio número antes del título (por ejemplo «Figura 1.»), en la **Posición de la leyenda**, **Encima** o **Debajo** del bloque. ## Inline marks that pair by what stands around them

Un lenguaje como Markdown escribe la negrita y la cursiva con una serie de caracteres que abre o cierra según los caracteres que tiene al lado, y un fragmento de código o un enlace con corchetes, de modo que un solo patrón para toda la construcción no puede encontrarlos. Activa **Leer marcas según lo que las rodea** para describirlos.

| Ajuste | Qué hace |
| --- | --- |
| **Carácter de escape** | Un carácter que hace que el siguiente sea texto normal. |
| **Carácter del fragmento de código** | Una serie de este carácter abre un fragmento que cierra la siguiente serie de la misma longitud. |
| **Marcas de serie** | Marcas que se emparejan como series, añadidas con **Añadir marca de serie**. Cada una tiene una **Marca**, lo que **Una marca dibuja** y lo que **Dos marcas dibujan**, y **Puede abrir o cerrar dentro de una palabra** (desactivado para `_`). |
| **Marcas por pares** | Marcas que se emparejan con una serie de la misma longitud, añadidas con **Añadir marca por pares**: la **Marca**, lo que **Dibuja** y **Solo si este ajuste está activado**, un ajuste de sintaxis como el resaltado que debe estar activado (o **Siempre**). |
| **Enlaces y direcciones web** | **Prefijo de imagen**, **Una dirección escrita sola va entre**, **Esquemas que inician una dirección sin marcar**, **Una línea que define una etiqueta tiene** y **La etiqueta de una nota al pie empieza por** (el carácter tras el corchete de apertura de una etiqueta que la convierte en nota al pie: `[^note]` se dibuja como referencia a una nota al pie cuando una línea empieza por `[^note]:`). |

Las marcas se emparejan dentro de una línea. El código, los caracteres escapados y la dirección de un enlace son texto normal para las marcas que los rodean.

## Styled source

Con **Código con estilo** activado, el editor dibuja un documento con el aspecto de su sintaxis: encabezados más grandes, series en negrita y cursiva, barras de cita, sangrías de lista, casillas de tarea, líneas, enlaces y tarjetas de código, y oculta las marcas que los forman (con **Ocultar marcadores** activado) excepto en la línea donde está el cursor. El editor no sabe nada de ninguna sintaxis concreta: una regla indica qué es su coincidencia llevando una entrada de estilo, y una regla sin ella se colorea pero no se le cambia el estilo.

Las **Opciones** de cada regla tienen un grupo **Código con estilo**:

| Campo | Qué hace |
| --- | --- |
| **Función** | Qué es la coincidencia, o **Sin estilo**. Para una construcción dentro de una línea: heading, strong, emphasis, code, strike, highlight, underline, link, subscript, superscript. Para una línea completa: rule (una separación temática), list (la marca de un elemento de lista, con su sangría y el espacio que la sigue), task (una marca seguida de una casilla) y quote (las marcas `>` de una línea citada). Para un bloque reconocido entero: codeBlock. Para un bloque cuyas líneas de apertura y cierre son coincidencias distintas: quoteRegion. Para una tabla, ecuación o diagrama dibujado como imagen: renderedBlock. |
| **Grupo del contenido** | El grupo de captura, contando desde 1, que contiene de qué trata la construcción: la palabra dentro de `*bold*`, el título en `\section{Title}`. Lo que la coincidencia tiene además son las marcas propias de la construcción, que Ocultar marcadores oculta. `0` significa que toda la coincidencia es contenido y no se oculta nada, como en una dirección web. Omítelo cuando la coincidencia sean solo marcas, como el `== ` de un encabezado. |
| **Nivel del título**, **Grupo del nivel** | El nivel de un encabezado, de 1 a 6. Si se omite, es el número al final del nombre de salida de la regla (`heading2`), o la longitud del grupo de captura que contiene una serie de `#`. |
| **Grupo del marcador** | Para una lista o una tarea, el grupo de captura que es la marca con su sangría y los espacios que la siguen, cuando la coincidencia empieza con otra cosa, como el `> ` de un elemento citado. |
| **Aplica el estilo hasta el final de la línea** | Aplica el estilo desde la coincidencia hasta el final de la línea, para una regla que solo coincide con la marca de un encabezado y deja su título como el texto que sigue. |
| **Se dibuja como** | Para un bloque dibujado, qué es: una tabla, una fórmula o un diagrama, o **No es una imagen**. |
| **Grupos de la dirección** | Para un enlace, los grupos de captura, probados por orden, que contienen la dirección que abre al hacer clic o tocar; `0` es toda la coincidencia. Solo se abren direcciones web, de correo y de teléfono. |

Los números de grupo cuentan los paréntesis del patrón desde 1; 0 es toda la coincidencia. Un perfil que no sustituye Markdown también conserva la lectura propia de Markdown de los tipos que sus reglas no declaran, como sus barras de cita y los pares de `**`.

## Document attributes and conditional sections

Una regla de **Atributo del documento** define un valor mediante `name`, y una regla de **Referencia a atributo** (una regla en línea con las partes `name` y `original`) sustituye una referencia por él. Una referencia a un atributo que nadie ha definido se queda como está escrita. Una **Sección condicional** conserva o descarta los bloques entre sus líneas, según estén o no establecidos los atributos que nombra. Los atributos se aplican desde donde se definen en adelante.

Una regla que produce **Ajustes del bloque siguiente** reconoce una línea completa que configura el bloque que viene después y no muestra nada por sí misma. Sus partes y atributos fijos se pasan a ese bloque: `title`, `id`, `nodeType`, `language` y `hardbreaks` tienen los significados indicados en Partes, y cualquier otra parte se conserva en el bloque, donde la lee una tabla, lista o cita.

## Testing a profile

En la parte inferior del editor, **Muestra de prueba** contiene texto de ejemplo (empieza como un encabezado y una línea de texto). Elige **Comprobar muestra** para ver los nodos que crean tus reglas, con sangría según su anidamiento. Dice «No blocks recognized.» cuando nada coincide.

## Baseline

La **línea base** de un perfil es su punto de restauración: cómo estaba cuando lo creaste, duplicaste o importaste. **Restablecer a la línea base** descarta todos los cambios desde entonces, tras pedirte confirmación. **Establecer como nueva línea base** guarda el perfil y convierte su estado actual en el punto de restauración.

Se rechaza guardar, con un mensaje, si el perfil sustituye Markdown pero no tiene regla de fin de línea, si un patrón es inseguro y podría bloquear el editor, o si no se puede escribir el archivo.

## Parts

Las partes son las piezas con nombre de una coincidencia que lee una salida.

| Parte | Significado |
| --- | --- |
| `allOf` | El separador entre nombres cuando se necesitan todos, como `+`. |
| `alt` | La descripción de una imagen, para lectores que no pueden verla. |
| `anyOf` | El separador entre nombres cuando basta con uno cualquiera, como `,`. |
| `attribution` | Quién dijo una cita, que se muestra debajo de ella. |
| `citetitle` | La obra de la que procede una cita, que se muestra después de la atribución. |
| `columns` | La lista de columnas de una tabla, como `1,2,1`; sus entradas cuentan las columnas. |
| `condition` | Los nombres de atributo de los que depende la sección. |
| `conditionType` | `defined` conserva la sección cuando los atributos están establecidos, `undefined` cuando no lo están. |
| `content` | El texto en sí, cuando no es toda la coincidencia. |
| `format` | El motor de un diagrama (`mermaid` o `vega-lite`); en una tabla, cuál de sus formatos delimitados usan las celdas. |
| `hardbreaks` | Si está presente, conserva los saltos de línea simples del bloque siguiente. |
| `header` | Cualquier valor excepto `false` hace que la primera fila de una tabla sea su cabecera. |
| `id` | Un nombre: para el bloque siguiente, el identificador al que apuntan las referencias cruzadas; para una nota al pie, un nombre que permite que las notas posteriores sin texto propio compartan su número. |
| `keys` | Las teclas que pulsar, separadas por comas. |
| `label` | El texto mostrado para una referencia o un ancla, en lugar del título propio del destino. |
| `language` | El lenguaje de programación de un bloque de código, usado para su coloreado. |
| `level` | El nivel del encabezado, de 1 a 6. |
| `marker` | El separador tras el término, como `::`. Un marcador distinto anida una lista dentro de la descripción. |
| `name` | El nombre del atributo, en una definición o en una referencia. |
| `nodeType` | Convierte el bloque siguiente en otra salida, por su nombre en el archivo. |
| `noHeader` | Si está presente, una tabla no tiene fila de cabecera. |
| `notation` | La notación matemática: `tex` (la predeterminada) o `latex`. |
| `open` | `true` muestra abierta una sección plegable. |
| `ordered` | `true` hace que la lista sea numerada. |
| `original` | La referencia tal como está escrita, que se muestra cuando el atributo no está definido. |
| `presentation` | Cómo se muestra la siguiente lista de descripciones: `sideBySide` pone los términos y las descripciones en dos columnas; `questions` numera cada término como una pregunta, con su respuesta debajo. |
| `primary` | La entrada del índice. |
| `secondary` | Una subentrada bajo la entrada del índice. |
| `sectionLabel` | Una palabra a la que sigue el número del encabezado siguiente, como `Appendix`: esos encabezados se cuentan por separado, `Appendix A:`. |
| `sectionLabelStart` | El primero de esos números: una letra (`A`) cuenta en letras, un número en números. |
| `src` | La dirección del archivo de vídeo o audio. |
| `start` | El número con el que empieza una lista numerada. |
| `summary` | La línea que se muestra en una sección plegable mientras está cerrada. |
| `targetID` | El identificador al que apunta la referencia. |
| `term` | El término que se describe. |
| `tertiary` | Una subentrada bajo la secundaria. |
| `text` | El texto mostrado, cuando el patrón captura más que eso. El texto de una nota al pie sigue al párrafo, tabla o lista en que está, numerado. |
| `title` | Un título: el encabezado de un recuadro, la información emergente de una imagen o un enlace, o una leyenda sobre el bloque siguiente. |
| `type` | El tipo de advertencia, como `note`, `tip` o `warning`. |
| `unset` | Si está presente, la regla quita el atributo en lugar de definirlo. |
| `url` | La dirección a la que apunta un enlace o una imagen. |
| `value` | El valor del atributo; las referencias a atributos definidos antes se sustituyen en él. |
