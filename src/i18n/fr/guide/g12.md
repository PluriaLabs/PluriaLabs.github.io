# Part XIX — Éditeurs des éléments de la bibliothèque

# Chapter 74: L’éditeur de profil et les blocs de construction d’un profil

Un profil de syntaxe indique à Pilcrow ce que signifie votre balisage. Ce chapitre décrit l’éditeur de profil contrôle par contrôle, puis liste tous les blocs de construction qu’un profil peut utiliser. Pour une introduction par tâches, voir le Chapter 37 au Chapter 39.

Ouvrez l’éditeur depuis **Réglages ▸ Bibliothèque ▸ Profils de syntaxe** : **Nouveau** crée un profil, **Modifier** change un profil personnalisé et **Dupliquer** copie un profil intégré pour que vous puissiez modifier la copie. Le titre de l’éditeur est **Modifier le profil**, avec **Annuler**, **Enregistrer** et **Aide sur les profils** (qui ouvre la référence intégrée à l’app sur ces blocs de construction). Sur un écran étroit, un sélecteur **Section du profil** permet de choisir entre **Aperçu**, **Règles** et **Échantillon de test** ; sur un écran large, les trois s’affichent en même temps.

## Aperçu

| Champ | Ce qu’il fait |
| --- | --- |
| **Nom** | Le nom du profil, affiché dans le menu de la barre d’état et dans les Réglages. |
| **Description** | Une note sur le profil. |
| **Extensions de fichier (séparées par des virgules)** | Les extensions qui font choisir ce profil pour un fichier. Deux profils ne peuvent pas partager une extension. |
| **Hérite de** | **Aucun**, ou un autre profil sur les règles duquel celui-ci s’appuie. |
| **Syntaxe** | **Étend Markdown** ou **Remplace Markdown** (voir ci-dessous). |
| **En un coup d’œil** | Le nombre de **Règles de bloc**, de **Règles en ligne** et de **Règles d’imbrication**. |
| **Modifier le JSON avancé…** | Ouvre le profil en JSON pour les champs que l’éditeur guidé n’expose pas. **Appliquer** conserve vos modifications JSON ; **Annuler** les abandonne. |

**Étend Markdown** ajoute vos règles à celles de Markdown : ses titres, ses listes, son emphase et le reste sont toujours lus, et vos règles de bloc et en ligne s’y ajoutent. Une règle qui est une copie inchangée d’une de celles du profil CommonMark décrit ce que Markdown fait déjà, et lui est laissée. **Remplace Markdown** fait de vos règles la syntaxe tout entière, si bien que les constructions Markdown ne sont plus reconnues. Dans ce cas, une règle doit produire **Fin de ligne**, sinon rien ne sépare les paragraphes. L’éditeur avertit « Add a rule whose output node is "newline", or nothing will separate into paragraphs », et le profil ne peut pas être enregistré tant qu’il n’en existe pas une. Il liste aussi les types de sortie que le profil ne définit pas.

## Règles

Les règles se répartissent en trois groupes.

### Règles de bloc

Une règle de bloc reconnaît des lignes et des blocs entiers. **Ajouter une règle** en ajoute une. Chaque règle a un **Motif**, un type de **Correspondance**, ce qu’elle **Produit**, et des **Options**. Une règle se supprime avec son bouton **Supprimer**. S’il n’y en a aucune, l’éditeur indique « No rules yet. Add one to recognize a block construct. »

### Règles en ligne

Une règle en ligne reconnaît du texte à l’intérieur d’une ligne. **Ajouter une règle en ligne** en ajoute une. Les règles en ligne proposent quatre types de correspondance (**Préfixe littéral**, **Littéral exact**, **Regex (bornée)** et **Paire de délimiteurs**) ; les règles de bloc proposent les sept.

### Règles d’imbrication

Les règles d’imbrication disent quelles sorties peuvent se trouver dans lesquelles. Chacune a un **Nœud parent** et des **Nœuds enfants autorisés (séparés par des virgules)**. Vide signifie sans restriction : « No restrictions. Every node type may nest inside any other. » **Ajouter une règle d’imbrication** en ajoute une.

### Types de correspondance

| Type de correspondance | Lit le motif comme | Bloc | En ligne |
| --- | --- | --- | --- |
| **Préfixe littéral** | Le texte par lequel la construction commence. | oui | oui |
| **Littéral exact** | Le texte entier de la construction. | oui | oui |
| **Préfixe en début de ligne** | Le texte au début d’une ligne, comme `# `. | oui | |
| **Bloc indenté** | Des lignes qui commencent par le motif, comme quatre espaces ou une tabulation. Les lignes consécutives, et les lignes vides entre elles, forment un seul bloc, affiché sans le retrait. | oui | |
| **Bloc délimité** | Une ligne qui ouvre un bloc, fermé par une ligne correspondante. | oui | |
| **Regex (bornée)** | Une expression régulière. Pilcrow avertit avant d’enregistrer une expression qui pourrait se bloquer : « This regex could hang the editor — simplify it. » | oui | oui |
| **Paire de délimiteurs** | La même marque des deux côtés d’un texte sur une seule ligne, comme `%%` dans `%%this%%`. Il n’y a pas d’espace juste à l’intérieur des marques. | oui | oui |

Dans une expression régulière, `(?<name>…)` nomme une partie de la correspondance. Voir Parties nommées plus bas.

## Options des règles

Le groupe **Options** de chaque règle propose :

| Option | Ce qu’elle fait |
| --- | --- |
| **Priorité** | Les règles de priorité plus élevée sont essayées en premier. |
| **Uniquement en début de ligne** | Empêche une règle de correspondre au milieu d’une ligne. |
| **Les parties nommées deviennent des attributs** | Chaque partie nommée d’une expression régulière devient un attribut de la sortie. L’éditeur liste « Parts in this pattern » et « Parts this output reads ». Pour une sortie qui contient du texte, comme le gras ou un lien, le texte affiché est la partie nommée `text` s’il y en a une, sinon la dernière partie qui a correspondu. |
| **Produit** | Ce que la règle fabrique : une sortie des listes ci-dessous, ou un nom **Personnalisé**. |
| **Nom de nœud personnalisé** | Le nom d’une sortie **Personnalisé**. |
| **Attributs fixes** | Des parties qui ont la même valeur à chaque fois, ajoutées avec **Ajouter un attribut** (un **Nom** et une **Valeur**). Une valeur peut inclure une partie nommée, écrite `{name}` : une règle d’e-mail dont le motif nomme l’`address` peut donner à son lien l’`url` `mailto:{address}`. |
| **Texte d’insertion** | Ce que le menu **Insérer** écrit pour cette règle, exactement comme cela doit apparaître, avec `$0` à l’endroit où le curseur doit se placer. Une règle reconnue par une expression régulière, un bloc ou un retrait en a besoin, sinon le menu Insérer l’omet. |
| **Seulement après une ligne vide** | Pour un bloc indenté : une ligne indentée placée juste après du texte reste une partie de ce texte, comme la ligne suivante d’un élément de liste. |
| **Après Retour en fin de ligne** | Pour les listes et les citations : **Automatique** (répète les puces et les citations, incrémente les éléments numérotés et démarre les éléments de tâche non cochés), **Répéter le marqueur**, **Incrémenter**, **Repartir du marqueur d’origine**, ou **Ne rien ajouter**. |

### Blocs délimités

Pour une règle de **Bloc délimité**, **Le bloc contient** indique ce qu’il y a à l’intérieur :

| Choix | Signification |
| --- | --- |
| **Rien pour l’instant** | Non défini. |
| **Texte, affiché tel quel** | Du code ou du texte préformaté. |
| **Rien — masqué** | Un commentaire, exclu du document. |
| **D’autres blocs, dans un encadré** | Une citation, un encadré latéral ou un encadré d’avertissement contenant des paragraphes, des listes et plus. |
| **D’autres blocs, sans encadré** | Les blocs se joignent au texte environnant ; les lignes ne servent qu’à les regrouper. |
| **Un tableau** | Voir Tableaux, ci-dessous. |
| **Un tableau dessiné en texte** | Une grille ou des colonnes alignées de texte qui va de sa ligne d’ouverture à la ligne vide suivante, comme celui de reStructuredText. |
| **Texte en retrait sous une ligne se terminant par un marqueur** | La ligne d’ouverture est de la prose qui se termine par le marqueur, comme le fait `::` en reStructuredText ; la prose reste un paragraphe, et le texte mis en retrait en dessous après une ligne vide est affiché tel quel. |
| **Texte en retrait sous une ligne d’ouverture** | Une directive comme `.. code-block::`, qui contient les lignes en retrait situées en dessous et n’a pas de ligne de fermeture. |

**Ligne de fermeture** est la ligne qui termine le bloc ; vide, elle signifie la même ligne que celle d’ouverture (« Same as the opening line »). Un délimiteur qui n’est pas une expression régulière, comme `+++`, est reconnu comme du texte simple. **La ligne de fermeture répète le repère d’ouverture, au moins autant de fois** est pour les délimiteurs de style Markdown : la ligne de fermeture est le premier caractère de la ligne d’ouverture répété au moins autant de fois, de sorte qu’un délimiteur plus long contient un plus court comme texte. Le langage d’un bloc de texte, lorsque la ligne d’ouverture en nomme un connu, est coloré dans l’éditeur.

### Tableaux

Les options d’un bloc de tableau :

| Option | Ce qu’elle fait |
| --- | --- |
| **Disposition** | **Grille avec lignes de séparation** (des cellules entre `|` avec une ligne de séparation entre les rangées) ou **Colonnes alignées** (des colonnes alignées sous une première ligne de séparation). |
| **Séparateur de cellules** | Le texte qui commence chaque cellule. |
| **Motif de ligne de séparation**, **Motif de ligne de séparation de l’en-tête** | Les lignes qui ne dessinent qu’une séparation, et celle qui termine l’en-tête. |
| **La ligne se termine par** | Une marque qui termine chaque rangée, comme le fait un `tabular` de LaTeX. |
| **Motif de cellule fusionnée** | Une cellule qui s’étend sur plusieurs colonnes. |
| **Motif des options de cellule** | Une expression régulière pour ce qui peut venir juste avant le séparateur d’une cellule ; une partie nommée `colspan` fait que la cellule s’étend sur ce nombre de colonnes. |
| **Séparateur de la liste des colonnes**, **Marqueur de répétition** | La façon d’écrire une liste `columns` : avec `,` et `*`, `3*` compte trois colonnes. |
| **La première ligne avant une ligne vide est l’en-tête** | La rangée d’en-tête est déduite de la disposition. |
| **Formats** | D’autres façons d’écrire les cellules, chacune avec un nom et un séparateur (comme `csv` et `,`), ajoutées avec **Ajouter un format** et choisies avec la partie `format` du tableau. |

## Réglages applicables à tout le profil

| Réglage | Ce qu’il fait |
| --- | --- |
| **Imbriquer les listes selon le marqueur** | Chaque nouveau marqueur, comme `**` après `*`, ouvre un niveau plus profond, quelle que soit l’indentation. |
| **Ligne de continuation de liste** | Une ligne, seule après un élément de liste, qui rattache le bloc suivant à cet élément. |
| **Conserver les sauts de ligne simples** | Un saut de ligne à l’intérieur d’un paragraphe reste un saut de ligne. |
| **Donner des identifiants aux titres** | Un titre sans identifiant propre en reçoit un tiré de son titre : en minuscules, avec les mots joints par le **séparateur de mots**, après le **préfixe** (**Préfixe de l’identifiant**, **Séparateur de mots de l’identifiant**). Avec `_` et `_`, « Getting Started » devient `_getting_started`, si bien qu’un renvoi vers lui affiche le titre. Un titre répété ajoute le séparateur et un numéro. |
| **Numéroter les titres** | Une fois que le document définit l’attribut nommé dans **Quand le document définit**, comme `:sectnums:` d’AsciiDoc, les titres à partir de **À partir du niveau de titre** sont numérotés : `1.`, `1.1.`, `2.`. Les titres placés avant la définition ne le sont pas. |
| **Légendes numérotées** | Un bloc titré d’une sortie listée ici, comme `image`, `table` ou `example`, reçoit le **Libellé** et son propre numéro avant son titre (par exemple « Figure 1. »), à la **Position de la légende**, **Au-dessus** ou **En dessous** du bloc. Ajoutées avec **Ajouter une légende**. |

## Marques en ligne qui s’appairent selon ce qui les entoure

Un langage comme Markdown écrit le gras et l’italique avec une suite de caractères qui ouvre ou ferme selon les caractères voisins, et un extrait de code ou un lien avec des crochets, si bien qu’un seul motif pour toute la construction ne peut pas les trouver. Activez **Lire les marques selon ce qui les entoure** pour les décrire.

| Réglage | Ce qu’il fait |
| --- | --- |
| **Caractère d’échappement** | Un caractère qui rend le suivant ordinaire. |
| **Caractère de l’extrait de code** | Une suite de ce caractère ouvre un extrait que la suite suivante de même longueur ferme. |
| **Marques en série** | Des marques qui s’appairent en suites, ajoutées avec **Ajouter une marque en série**. Chacune a une **Marque**, ce que **Une marque dessine** et ce que **Deux marques dessinent**, et **Peut ouvrir ou fermer au milieu d’un mot** (désactivé pour `_`). |
| **Marques par paires** | Des marques qui s’appairent avec une suite de même longueur, ajoutées avec **Ajouter une marque par paire** : la **Marque**, ce qu’elle **Dessine**, et **Seulement si ce réglage est activé**, un réglage de syntaxe comme le surlignage qui doit être activé (ou **Toujours**). |
| **Liens et adresses web** | **Préfixe d’image**, **Une adresse écrite seule est entourée de**, **Schémas qui commencent une adresse nue**, **Une ligne qui définit une étiquette porte**, et **L’étiquette d’une note de bas de page commence par** (le caractère après le crochet ouvrant d’une étiquette qui en fait une note de bas de page : `[^note]` est dessiné comme une référence de note de bas de page lorsqu’une ligne commence par `[^note]:`). |

Les marques s’appairent à l’intérieur d’une ligne. Le code, les caractères échappés et l’adresse d’un lien sont du texte simple pour les marques qui les entourent.

## Source stylisée

Avec **Source stylisée** activée, l’éditeur dessine un document selon l’aspect de sa syntaxe : titres plus grands, suites en gras et en italique, barres de citation, retraits de liste, cases de tâche, lignes, liens et cartes de code, et masque les marques qui les produisent (avec **Masquer les marqueurs** activé) sauf sur la ligne où se trouve le curseur. L’éditeur ne connaît aucune syntaxe en particulier : une règle dit ce qu’est sa correspondance en portant une entrée de style, et une règle qui n’en a pas est colorée mais pas restylée.

Les **Options** de chaque règle contiennent un groupe **Source stylée** :

| Champ | Ce qu’il fait |
| --- | --- |
| **Rôle** | Ce qu’est la correspondance, ou **Sans style**. Pour une construction à l’intérieur d’une ligne : heading, strong, emphasis, code, strike, highlight, underline, link, subscript, superscript. Pour une ligne entière : rule (une rupture thématique), list (le marqueur d’un élément de liste, avec son retrait et l’espace qui le suit), task (un marqueur suivi d’une case à cocher) et quote (les marques `>` d’une ligne citée). Pour un bloc reconnu en entier : codeBlock. Pour un bloc dont les lignes d’ouverture et de fermeture sont des correspondances distinctes : quoteRegion. Pour un tableau, une équation ou un diagramme dessiné comme une image : renderedBlock. |
| **Groupe du contenu** | Le groupe de capture, compté à partir de 1, qui contient ce dont parle la construction : le mot à l’intérieur de `*bold*`, le titre dans `\section{Title}`. Ce que la correspondance contient en plus, ce sont les marques propres à la construction, que Masquer les marqueurs masque. `0` signifie que toute la correspondance est du contenu et que rien n’est masqué, comme pour une adresse web. Omettez-le quand la correspondance n’est faite que de marques, comme le `== ` d’un titre. |
| **Niveau du titre**, **Groupe du niveau** | Le niveau d’un titre, de 1 à 6. S’il est omis, c’est le nombre à la fin du nom de sortie de la règle (`heading2`), ou la longueur du groupe de capture qui contient une suite de `#`. |
| **Groupe du marqueur** | Pour une liste ou une tâche, le groupe de capture qui est le marqueur avec son retrait et les espaces qui le suivent, lorsque la correspondance commence par autre chose, comme le `> ` d’un élément cité. |
| **Applique le style jusqu’à la fin de la ligne** | Applique le style de la correspondance jusqu’à la fin de la ligne, pour une règle qui ne reconnaît que le marqueur d’un titre et laisse son titre comme le texte qui suit. |
| **Dessiné comme** | Pour un bloc rendu, ce qu’il est : un tableau, une formule ou un diagramme, ou **Pas une image**. |
| **Groupes de l’adresse** | Pour un lien, les groupes de capture, essayés dans l’ordre, qui contiennent l’adresse qu’il ouvre lorsqu’on clique ou touche ; `0` est la correspondance entière. Seules les adresses web, de messagerie et de téléphone s’ouvrent. |

Les numéros de groupe comptent les parenthèses du motif à partir de 1 ; 0 est la correspondance entière. Un profil qui ne remplace pas Markdown conserve aussi la lecture propre à Markdown des types que ses règles ne déclarent pas, comme ses barres de citation et les paires de `**`.

## Attributs du document et sections conditionnelles

Une règle **Attribut du document** définit une valeur par `name`, et une règle **Référence d’attribut** (une règle en ligne avec les parties `name` et `original`) remplace une référence par cette valeur. Une référence à un attribut que personne n’a défini reste telle qu’écrite. Une **Section conditionnelle** conserve ou supprime les blocs entre ses lignes, selon que les attributs qu’elle nomme sont définis ou non. Les attributs s’appliquent à partir de l’endroit où ils sont définis.

Une règle qui produit **Réglages du bloc suivant** reconnaît une ligne entière qui configure le bloc suivant et n’affiche rien elle-même. Ses parties et ses attributs fixes sont transmis à ce bloc : `title`, `id`, `nodeType`, `language` et `hardbreaks` ont les sens listés sous Parties, et toute autre partie est conservée sur le bloc, où un tableau, une liste ou une citation la lit.

## Tester un profil

En bas de l’éditeur, **Échantillon de test** contient un texte d’exemple (au départ un titre et une ligne de texte). Choisissez **Vérifier l’échantillon** pour voir les nœuds que vos règles produisent, indentés selon leur imbrication. Il affiche « No blocks recognized. » quand rien ne correspond.

## Référence

La **référence** d’un profil est son point de restauration : son état au moment où vous l’avez créé, dupliqué ou importé. **Revenir à la référence** abandonne toutes les modifications depuis, après confirmation. **Définir comme nouvelle référence** enregistre le profil et fait de son état actuel le point de restauration.

L’enregistrement est refusé, avec un message, si le profil remplace Markdown mais n’a pas de règle de fin de ligne, si un motif n’est pas sûr et pourrait bloquer l’éditeur, ou si le fichier ne peut pas être écrit.

## Parties

Les parties sont les morceaux nommés d’une correspondance qu’une sortie lit.

| Partie | Signification |
| --- | --- |
| `allOf` | Le séparateur entre les noms lorsqu’il les faut tous, comme `+`. |
| `alt` | La description d’une image, pour les lecteurs qui ne peuvent pas la voir. |
| `anyOf` | Le séparateur entre les noms lorsqu’un seul suffit, comme `,`. |
| `attribution` | Qui a dit une citation, affiché en dessous. |
| `citetitle` | L’œuvre d’où vient une citation, affichée après l’attribution. |
| `columns` | La liste des colonnes d’un tableau, comme `1,2,1` ; ses entrées comptent les colonnes. |
| `condition` | Les noms d’attributs dont dépend la section. |
| `conditionType` | `defined` conserve la section lorsque les attributs sont définis, `undefined` lorsqu’ils ne le sont pas. |
| `content` | Le texte lui-même, lorsqu’il n’est pas toute la correspondance. |
| `format` | Le moteur d’un diagramme (`mermaid` ou `vega-lite`) ; pour un tableau, lequel de ses formats délimités les cellules utilisent. |
| `hardbreaks` | Lorsqu’elle est présente, conserve les sauts de ligne simples du bloc suivant. |
| `header` | Toute valeur autre que `false` fait de la première rangée d’un tableau son en-tête. |
| `id` | Un nom : pour le bloc suivant, l’identifiant vers lequel pointent les renvois ; pour une note de bas de page, un nom qui permet aux notes suivantes sans texte propre de partager son numéro. |
| `keys` | Les touches à presser, séparées par des virgules. |
| `label` | Le texte affiché pour une référence ou une ancre, à la place du titre propre de la cible. |
| `language` | Le langage de programmation d’un bloc de code, utilisé pour sa coloration. |
| `level` | Le niveau du titre, de 1 à 6. |
| `marker` | Le séparateur après le terme, comme `::`. Un marqueur différent imbrique une liste à l’intérieur de la description. |
| `name` | Le nom de l’attribut, dans une définition ou une référence. |
| `nodeType` | Transforme le bloc suivant en une autre sortie, par son nom dans le fichier. |
| `noHeader` | Lorsqu’elle est présente, un tableau n’a pas de rangée d’en-tête. |
| `notation` | La notation mathématique : `tex` (par défaut) ou `latex`. |
| `open` | `true` affiche une section repliable ouverte. |
| `ordered` | `true` rend la liste numérotée. |
| `original` | La référence telle qu’écrite, affichée lorsque l’attribut n’est pas défini. |
| `presentation` | La façon dont la prochaine liste de définitions est affichée : `sideBySide` met les termes et les descriptions sur deux colonnes ; `questions` numérote chaque terme comme une question, avec sa réponse en dessous. |
| `primary` | L’entrée d’index. |
| `secondary` | Une sous-entrée sous l’entrée d’index. |
| `sectionLabel` | Un mot que le numéro du titre suivant accompagne, comme `Appendix` : ces titres sont comptés à part, `Appendix A:`. |
| `sectionLabelStart` | Le premier de ces numéros : une lettre (`A`) compte en lettres, un nombre en nombres. |
| `src` | L’adresse du fichier vidéo ou audio. |
| `start` | Le numéro par lequel commence une liste numérotée. |
| `summary` | La ligne affichée sur une section repliable tant qu’elle est fermée. |
| `targetID` | L’identifiant vers lequel pointe la référence. |
| `term` | Le terme décrit. |
| `tertiary` | Une sous-entrée sous la secondaire. |
| `text` | Le texte affiché, lorsque le motif capture plus que cela. Le texte d’une note de bas de page suit le paragraphe, le tableau ou la liste où elle se trouve, numéroté. |
| `title` | Un titre : l’intitulé d’un encadré, l’infobulle d’une image ou d’un lien, ou une légende au-dessus du bloc suivant. |
| `type` | Le genre d’avertissement, comme `note`, `tip` ou `warning`. |
| `unset` | Lorsqu’elle est présente, la règle supprime l’attribut au lieu de le définir. |
| `url` | L’adresse vers laquelle pointe un lien ou une image. |
| `value` | La valeur de l’attribut ; les références à des attributs définis plus tôt y sont remplacées. |
