# Part XII — 테마와 화면 모드

# Chapter 40: 앱 테마와 렌더링 테마 이해하기

Pilcrow에는 서로 별개인 두 가지 테마 시스템이 있습니다.

- **앱 테마**는 JSON이며 앱, 막대, 사이드바, 강조 색, 편집기 색상, 라이트 또는 다크 화면 모드를 스타일링합니다.
- **렌더링 테마**는 CSS이며 미리보기, HTML, PDF, 그리고 Word에 쓰이는 의미 구조 부분 집합을 스타일링합니다.

**보기 ▸ 테마** 또는 설정에서 둘 다 선택하세요. 앱 테마와 충돌할 만한 별도의 모드 전환 스위치는 없으며, 테마가 스스로 화면 모드를 정의합니다. CSS는 앱이나 소스 편집기를 스타일링하지 않습니다.

편집기가 이상해 보이면 앱 테마를 바꾸세요. 미리보기나 내보내기가 이상해 보이면 렌더링 테마를 바꾸세요. 이 구분 하나로 테마와 관련된 대부분의 혼란이 해결됩니다.

# Chapter 41: 테마 만들고 관리하기

**설정 ▸ 라이브러리 ▸ 테마**를 엽니다. 앱 또는 렌더링 컬렉션을 선택한 다음 사용자 테마를 복제, 가져오기, 내보내기, 편집 또는 삭제하세요.

앱 테마는 편집기에서 화면 모드, 강조 색, 크롬, 사이드바, 막대, 편집기 색상을 설정합니다. 선택 영역의 대비, 현재 줄이 보이는지, 링크, 경고, 활성 및 비활성 컨트롤을 모두 확인하세요.

렌더링 테마는 Pilcrow 클래스 API에 맞춰 CSS를 편집합니다. 먼저 타이포그래피와 간격을 바꾸고, 그다음 제목, 목록, 코드, 표, 콜아웃, 링크, 각주, 보조 블록 순으로 진행하세요. 프로젝트 체크아웃에서 작업한다면 `Examples/Themes/VisualTestPack`의 시각 샘플로 테스트하세요.

기본 제공 테마는 안정적인 출발점입니다. 덮어쓰려 하지 말고 복제하세요. ZIP 패키지에는 두 종류의 테마가 함께 들어 있을 수 있으며, 파일 확장자가 각 항목이 속할 곳을 결정합니다.

# Chapter 42: 서체, 크기, 간격, 배경 선택하기

편집기 및 거터 서체, 포인트 크기, 줄 간격, 탭 너비는 **설정 ▸ 화면 모드 ▸ 텍스트 크기 및 글꼴**에서 설정하세요. 이 설정은 작성 화면에 영향을 주며 내보낸 결과물의 타이포그래피에는 영향을 주지 않습니다.

앱 테마, 확대/축소, 읽기 속도, 텍스트 영역이나 사이드바 뒤의 선택적 이미지는 **테마 및 배경**에서 설정하세요. 배경은 각각 따로 선택, 교체 또는 제거할 수 있습니다. 배경은 대비와 집중력을 해치지 않아야 합니다. 아무리 아름다워도 가독성을 떨어뜨리는 이미지는 편집기 설정으로 좋지 않습니다.

게시용 서체와 페이지 레이아웃은 렌더링 테마와 내보내기 기본값을 사용하세요. 이렇게 분리하면 가독성이 높은 고정폭 편집기에서 글을 쓰면서도 가변폭 책 서체로 게시할 수 있습니다.

# Part XIII — 라이브러리 가져오기, 내보내기, 관리하기

# Chapter 43: Pilcrow 리소스 가져오기와 공유하기

Pilcrow는 구문 프로파일, 앱 테마, 렌더링 테마, 매크로 컬렉션, 스타일 가이드, 그리고 지원되는 리소스가 담긴 ZIP 패키지를 가져올 수 있습니다.

1. 해당 라이브러리 설정 페이지를 열거나, iOS에서는 가져오기 페이지를 엽니다.
2. 가져오기를 선택하고 파일을 고릅니다.
3. 리소스 유형, 이름, 충돌 여부를 검토합니다.
4. 결과를 이해한 경우에만 가져오기, 이름 변경 또는 교체를 합니다.
5. 연습용 문서에서 활성화하고 테스트합니다.

공유하거나 백업하려면 라이브러리 페이지에서 사용자 리소스를 내보내세요. 프로젝트에 프로파일, 테마, 매크로, 가이드가 함께 필요하다면 관련 리소스를 하나의 ZIP에 모아 두세요.

가져온 프로파일, 매크로, CSS, 스타일 가이드는 코드에 가까운 구성으로 취급하세요. 신뢰하기 전에 트리거, 패턴, 원본 CSS, 어시스턴트 지침을 읽어 보세요.

# Chapter 44: 라이브러리 이동 또는 복원하기

**설정 ▸ 라이브러리 ▸ 위치**를 엽니다. 폴더 또는 **이 기기 사용**을 선택하세요. 대상에 이미 라이브러리가 있다면 다음 중에서 선택합니다.

- **있는 것 사용**은 복사 없이 전환합니다.
- **내 라이브러리를 여기로 이동**은 전송한 뒤 성공하면 이전의 관리되는 사본을 제거합니다.
- **내 라이브러리를 여기로 복사**는 양쪽을 모두 유지합니다.

동기화 폴더는 제공자가 일반 파일을 안정적으로 보존하고 동시 편집의 영향을 이해하고 있을 때만 사용하세요. 전송이 끝날 때까지 기다린 뒤 종료하세요. 위치를 사용할 수 없게 되면 드라이브나 계정을 다시 연결하거나 다른 위치를 선택하세요. 충돌하는 대체 리소스를 무심코 만들지 마세요.

iOS에서는 가져오기 페이지에서 패키지로부터 라이브러리 콘텐츠를 복원할 수 있습니다. 참조는 표시 이름만이 아니라 리소스 ID로 정의되므로, 복원한 뒤에는 활성 테마와 프로파일을 확인하세요.

# Part XIV — 설정, 개인정보 보호, 지원

# Chapter 45: 일반, 파일, 편집 설정 구성하기

설정은 그룹으로 나뉘어 있으며 검색할 수 있습니다. “줄 번호”, “이미지”, “머리글” 같은 레이블은 검색 필드로 찾으세요.

## 일반

창과 실행 동작, 언어, 번역, 어시스턴트 연결, 진단, 저장 공간 및 개인정보를 구성합니다.

## 파일

실행 시 폴더 동작, 기본 파일 유형, 자동 저장과 복구, 보관할 버전 수, 파일 트리 동작, 가져올 수 있는 항목을 앱에 끌어다 놓았을 때의 동작을 선택합니다.

## 편집 — 표시 및 입력

줄 번호, 상태 막대, 서식 도구 막대, 줄 바꿈, 현재 줄 구분선, 스타일 적용 소스, 마커, 렌더링된 블록, 제목 접기, 자동 확장, 괄호와 따옴표 짝 맞추기, Markdown 짝 맞추기, 이모지 단축 코드, 목록 및 인용 연속 입력, Return 시 들여쓰기, Tab 대신 공백 사용, 맞춤법, 구문 분석 경고를 구성합니다.

## 편집 — 입력 소리

**입력할 때 소리 재생**을 켜면 입력하는 동안 소리가 납니다. 팩(타자기, 오리 또는 새끼 고양이)을 선택하고 음량을 설정한 뒤 **미리보기**로 들어 보세요. 키 종류마다 고유한 소리가 납니다. 소문자, 대문자, 숫자, 기호, 스페이스, 탭, Return, 삭제가 해당됩니다. 붙여넣기와 여러 글자를 한 번에 바꾸는 편집은 소리가 나지 않습니다.

**내 소리**에서 키 종류 옆의 **선택…**을 선택하면 해당 키에 직접 만든 오디오 파일(WAV, AIFF, MP3, M4A 또는 CAF)을 사용할 수 있습니다. 클립은 최대 2초, 3MB까지 가능합니다. Pilcrow는 이를 작은 모노 클립으로 변환하므로 길거나 큰 파일이 입력을 느리게 하거나 잡음을 내지 않습니다. **재생**으로 들어 보고 **제거**로 팩의 소리로 되돌리세요. 파일이 거부되면 메시지에 이유가 표시됩니다. iPad에서는 무음 스위치가 입력 소리를 끄며, 입력 소리는 다른 오디오와 함께 재생됩니다.

## 편집 — 이미지

삽입, 복사 또는 이동, 온라인 불러오기, 경로 스타일, URL 이스케이프를 구성합니다.

## 화면 모드

앱 테마, 확대/축소, 배경, 편집기 크기, 서체, 줄 간격, 탭 너비를 선택합니다.

## 내보내기

렌더링 테마, 레이아웃, 머리글, 바닥글, 메타데이터, 제목 페이지 나누기를 선택합니다.

## 라이브러리

프로파일, CommonMark 옵션, 테마, 매크로, 스타일 가이드, 렌더링 라이브러리, 위치, 가져오기를 관리합니다.

## 키보드

필드 탐색 동작을 포함해 단축키를 검색, 재할당, 할당 해제, 재설정합니다.

한 번에 한 묶음씩만 바꾸세요. 타이포그래피를 평가할 때는 테마를 고정하고, 구문 분석을 평가할 때는 프로파일을 고정하세요. 변경을 통제하면 원인과 결과가 분명해집니다.

# Chapter 46: 개인정보 보호와 저장된 데이터 관리하기

**설정 ▸ 일반 ▸ 저장 공간 및 개인정보**를 엽니다. Pilcrow는 삭제를 범주별로 나누어, 캐시를 지우다가 실수로 문서가 삭제되는 일이 없도록 합니다.

- **복구 데이터 검토…**는 복구할 수 있는 콘텐츠의 목록을 보여 줍니다. 삭제하기 전에 변경된 문서를 저장하거나 닫으세요.
- **버전 기록 검토…**는 삭제하기 전에 버전과 예상 용량을 보여 줍니다.
- **최근 파일 접근 권한 지우기…**는 최근 파일, 기억된 폴더, 세션 북마크, 파일별 구문 선택을 제거합니다.
- **AI 데이터 및 키 삭제…**는 연결, 키체인 키, 대화, AI 개인정보 선택을 제거합니다.
- **진단 정보 삭제…**는 기록된 로그와 충돌 지원 데이터를 제거합니다.
- **캐시 비우기…**는 다시 만들 수 있는 캐시와 네트워크 응답을 제거합니다.

사용자 프로파일, 테마, 매크로, 스타일 가이드, 배경은 눈에 보이는 라이브러리 페이지에 그대로 남아 있으므로 그곳에서 검토해야 합니다. 이 컨트롤은 문서를 삭제하지 않습니다.

어시스턴트 설정에서도 제외할 파일 패턴, 어시스턴트가 꺼진 폴더, AI 데이터 삭제를 관리합니다. 온라인 이미지 불러오기는 별도의 개인정보 선택입니다. 링크 확인은 네트워크에 접속하지 않습니다.

# Chapter 47: 진단 정보 기록하고 보내기

**설정 ▸ 일반 ▸ 진단**을 엽니다. 간헐적으로 발생하는 문제라면 **문제 재현**을 선택하고 관련 부분, 수준, 보관 기간, 포함할 지원 정보를 선택하세요. 옵션에는 기기/시스템 정보, Pilcrow 설정, 속도와 메모리, 최근 동작 이력, 충돌 세부 정보가 있습니다.

문제를 바로 재현한 다음 **로그 보기…**를 선택하세요. 하위 시스템과 심각도로 필터링합니다. 보내기 전에 보고서를 확인하세요. **도움말 ▸ 버그 보고…**를 선택하면 버전이 채워진 GitHub의 버그 보고 양식이 열리며, Pilcrow가 로그를 클립보드에 복사하므로 붙여 넣으면 됩니다. 보고서를 파일로 저장해 첨부하거나 공유할 수도 있고, 로그 뷰어에서 **GitHub에 보고…**를 선택할 수도 있습니다. GitHub의 보고서는 공개됩니다.

진단은 문서 내용이 아니라 길이, 식별자, 상태, 오류를 기록해야 하지만, 공유하기 전에는 항상 보고서를 검토하세요. 문제를 기록한 뒤에는 기록을 **문제만**으로 되돌리거나 상세 보관을 끄세요. 자세한 로깅은 저장 공간을 차지하고 성능에 영향을 줄 수 있습니다.

# Chapter 48: 다른 언어로 Pilcrow 사용하기

설정을 열고 언어를 선택하세요. 다시 시작해야 할 수도 있습니다. Pilcrow는 영어와 함께 스페인어, 프랑스어, 독일어, 이탈리아어, 브라질 포르투갈어, 네덜란드어, 러시아어, 일본어, 한국어, 중국어 간체를 제공합니다.

영어가 아닌 인터페이스 번역은 사람이 검토했다고 표시되기 전까지는 AI가 생성한 것입니다. Pilcrow는 해당 언어에서 시작 시 안내를 표시합니다. **다시 표시하지 않음**을 선택하면 영구적으로 닫히며, 언어 설정에서 안내를 다시 켤 수 있습니다. “Machine-translated — may contain errors”라는 레이블은 검토되지 않은 콘텐츠임을 나타냅니다.

인터페이스 언어를 바꿔도 문서는 번역되지 않습니다. 문서 텍스트에는 번역 명령을 사용하세요. 번역된 명령이 모호하다면 잠시 영어로 전환해 기준이 되는 원래 표현을 확인하세요.

# Chapter 50: 흔한 문제 해결하기

## 파일이 깨져 보입니다

상태 막대에서 인코딩을 확인하세요. 편집하기 전에 올바른 인코딩으로 다시 열거나 변환하세요.

## 서식이나 미리보기가 잘못되었습니다

활성 프로파일을 확인하고, 소스 구분자를 검증하고, 필요한 선택적 구문을 켠 다음, 렌더링 테마를 확인하세요. 마커가 보이는 편집 모드에서 리터럴 텍스트를 살펴보세요.

## 서식 또는 삽입 명령이 비활성화되어 있습니다

미리보기에서 편집 모드로 전환하세요. 그런 다음 문서와 구문 프로파일이 활성 상태인지, 프로파일이 요청한 구성 요소를 지원하는지 확인하세요.

## 다이어그램, 차트 또는 수식이 렌더링되지 않습니다

펜스 언어 레이블, 블록 경계, 소스 구문, 다이어그램/수식 옵션을 확인하세요. 오류를 분리하려면 내장 템플릿에서 시작하세요.

## 찾기가 미리보기에 보이는 텍스트를 놓칩니다

서식으로 나뉘었거나 코드, 수식, 다이어그램, 차트 안에 있는 텍스트는 편집 모드에서 검색하세요. 미리보기 검색은 모든 소스 노드가 아니라 읽을 수 있는 렌더링된 텍스트만 대상으로 합니다.

## 상대 경로 이미지나 링크가 깨졌습니다

문서가 폴더를 갖도록 저장하고, 파일 이름과 대소문자가 정확한지 확인하고, 프로젝트 안의 상대 경로를 우선 사용한 다음, 링크 확인을 실행하세요.

## 폴더 바꾸기에서 일부 파일을 건너뛰었습니다

Pilcrow에서 해당 파일을 닫고, UTF-8 텍스트인지 확인하고, 미리보기를 다시 실행하고, 미리보기와 확정 사이에 외부에서 변경되지 않았는지 확인하세요.

## 매크로가 작동하지 않거나 너무 자주 작동합니다

해당 컬렉션과 매크로가 켜져 있는지 확인하고, 일치 유형과 트리거 경계를 점검하고, 코드 밖에서 테스트하고, 지나치게 넓은 패턴은 좁히세요.

## 번역을 사용할 수 없습니다

macOS 15 또는 iOS 18 이상인지, 언어 지원이 설치되어 있는지, 지원되는 원본/대상 언어 쌍인지 확인하세요. 문서 번역은 인터페이스 언어와 별개입니다.

## 어시스턴트를 사용할 수 없습니다

연결을 추가하고 테스트하고, 활성으로 지정하고, 제안된 모델을 선택하고, 제공자를 확인하고, 폴더나 파일이 제외되어 있지 않은지 확인하세요.

## 대용량 파일 작업이 느립니다

백그라운드 줄 색인이 끝나기를 기다리고, 대상을 좁힌 검색을 사용하고, 스트리밍 HTML/Word 워크플로로 충분하다면 PDF나 문서 전체 변환은 피하세요.

## Pilcrow가 예기치 않게 종료되었거나 편집기가 동기화되지 않았다고 알립니다

편집을 멈추고, 가능하면 사본을 저장하고, 복구가 제안되면 복구를 사용하고, 다시 실행하기 전에 진단 정보를 기록하세요. 저장된 문서를 확인하기 전에는 복구 세트를 삭제하지 마세요.

## 프로젝트 패널이 매니페스트 충돌을 알립니다

다시 불러오고, 최신 프로젝트 상태를 확인한 다음, 변경을 반복하세요. 두 기기에서 동시에 `manifest.pilcrow`를 덮어쓰지 마세요.

## 사용자 리소스를 가져올 수 없습니다

예상되는 확장자와 JSON/CSS 포맷을 확인하고, 보고된 안전하지 않은 패턴이나 충돌을 살펴보고, 올바른 앱 테마, 렌더링 테마, 프로파일, 매크로 또는 스타일 가이드 섹션으로 가져오세요.

# Chapter 51: 믿을 수 있는 작업 루틴 만들기

일반적인 작업에는 다음 루틴을 사용하세요.

1. 문서에 관련 자산이 있다면 개별 파일만이 아니라 폴더를 엽니다.
2. 본격적으로 편집하기 전에 프로파일과 인코딩을 확인합니다.
3. 처음 체크포인트를 저장합니다.
4. 편집 모드에서 작성하고, 구조가 중요할 때는 나란히 보기를 사용합니다.
5. 반복에는 직접 복제하지 말고 매크로와 필드를 사용합니다.
6. 일괄 바꾸기, 비교 결과 수락, 번역 바꾸기, 프로파일 실험 전에 저장합니다.
7. 적절한 단계마다 맞춤법, 스타일 검토, 링크 확인을 실행합니다.
8. 모든 섹션을 펼치고 미리보기를 처음부터 끝까지 확인합니다.
9. 의도한 렌더링 테마로 내보내고 실제 대상 포맷을 확인합니다.
10. 받는 사람이 편집해야 할 때만 소스를 공유하고, 그렇지 않으면 완성된 출력을 공유합니다.
11. 프로파일, 테마, 매크로, 스타일 가이드, 프로젝트 매니페스트, 로컬 자산을 프로젝트 백업에 함께 보관합니다.
12. 저장 공간 및 개인정보에서 복구, 버전, AI 데이터, 진단, 캐시를 주기적으로 검토합니다.

이유는 단순합니다. 소스에서는 의미를 명시적으로 드러내고, 표현은 테마에 맡기고, 변경이 큰 작업 전에는 체크포인트를 남기고, 꼭 필요한 최소한의 데이터만 공유하고, 다른 사람이 실제로 받게 될 결과물을 그대로 검증하세요. 이것이 일반 텍스트를 강력하면서도 믿을 수 있게 유지하는 Pilcrow의 방식입니다.
