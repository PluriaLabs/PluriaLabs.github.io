# Chapter 24: Super Tab으로 재사용 가능한 템플릿 만들기

필드는 고정된 확장 결과를 안내형 양식으로 바꿔 줍니다. 필드에는 자리 표시자, 기본값 또는 선택 목록을 둘 수 있습니다.

1. 반복되는 구조를 위한 매크로를 만듭니다.
2. 확장 내용에 필드를 추가하거나, 소스를 작성하는 동안 **삽입 ▸ 필드**를 사용합니다.
3. 매크로를 확장합니다.
4. 선택된 첫 번째 필드에 입력합니다.
5. **다음 필드**로 넘어가고 **이전 필드**로 돌아갑니다.
6. 선택 필드에서는 필드 선택 목록에서 항목을 고릅니다.

사람이 자연스럽게 답하는 순서대로 필드를 설계하세요. 마지막 캐럿은 자유로운 글쓰기를 이어 가야 할 위치에 두세요. 기본값은 무해하게 유지하세요. 사용자가 깜박한 필드는 미리보기에서 눈에 띄어야 하며, 오해를 부르는 내용이 조용히 게시되어서는 안 됩니다.

# Part VII — 수식, 다이어그램, 차트, 이미지

# Chapter 25: 수식, 다이어그램, 차트 작성하기

Pilcrow에는 MathJax 수식, Mermaid 다이어그램, Vega-Lite 차트를 위한 오프라인 렌더링이 포함되어 있습니다. 블록이 어디서 시작하고 끝나는지는 여전히 활성 프로파일이 결정하며, 내장 라이브러리는 그 내용만 그립니다.

## 템플릿에서 시작하기

1. **삽입 ▸ 수식**, **다이어그램** 또는 **차트**를 선택합니다.
2. 템플릿을 고릅니다.
3. 샘플 소스를 바꿉니다.
4. 미리보기 또는 나란히 보기로 전환합니다.
5. 보고된 구문 오류를 소스 블록에서 수정합니다.

수학 표기에는 MathJax를, 흐름과 관계에는 Mermaid를, 데이터 기반 차트에는 Vega-Lite를 사용하세요. 중요한 시각 자료 근처에는 텍스트 설명을 함께 두어, 렌더러를 쓸 수 없을 때도 문서를 이해할 수 있고 더 많은 독자가 접근할 수 있게 하세요.

라이브러리는 내장되어 있어 네트워크 없이 실행됩니다. 설정 ▸ 라이브러리 ▸ 렌더링 라이브러리에서 버전과 고지 사항을 볼 수 있습니다. 블록이 렌더링되지 않으면 테마를 바꾸기 전에 언어 레이블, 구분자, 선택 기능 설정, 구문을 먼저 확인하세요.

# Chapter 26: 이미지 삽입과 온라인 이미지 개인정보 관리하기

**설정 ▸ 편집 ▸ 이미지**를 열고 다음을 결정하세요.

- 삽입한 이미지를 복사할지, 이동할지, 그 자리에 둘지.
- 규칙을 로컬 이미지와 온라인 이미지 모두에 적용할지.
- 온라인 이미지를 불러오도록 허용할지.
- 가능하면 상대 경로를 사용할지.
- 상대 경로를 `./`로 시작할지.
- 삽입할 때 URL을 이스케이프할지.

이식 가능한 프로젝트라면 이미지를 문서 폴더 안에 두고 상대 경로를 사용하세요. 원본이 다른 프로젝트에 속해 있다면 이동보다 복사가 더 안전합니다. 이동하면 중복은 피할 수 있지만 원래 위치가 깨질 수 있습니다.

온라인 이미지는 보는 사람의 네트워크 주소를 호스트에 드러내며, 바뀌거나 사라질 수 있습니다. 신뢰할 수 없는 문서를 검토할 때는 네트워크 불러오기를 끄세요. 오래 보존할 게시물이라면 사용 허가를 받은 사본을 내려받아 로컬로 참조하세요.

# Part VIII — 게시와 공유

# Chapter 27: HTML, PDF, Word, 이미지로 내보내기

1. 문서를 저장하고 미리보기를 확인합니다.
2. 도구 막대 또는 파일 명령에서 내보내기를 선택합니다.
3. HTML, HTML(스타일 없음), PDF, Word, 이미지 또는 PDF 보관본을 선택합니다.
4. **스타일**에서 렌더링 테마를 선택합니다.
5. PDF, PDF 보관본, Word의 경우 **페이지** 옵션(용지 크기, 방향, 여백)을 검토합니다.
6. **내보내기**를 선택해 저장 위치를 고르거나, **공유**를 선택해 생성된 파일을 바로 보냅니다.

HTML은 스타일이 포함된 독립형 페이지를 만듭니다. **HTML(스타일 없음)**은 내장된 테마 CSS 없이 깔끔한 구조만 출력합니다. Word는 의미 구조를 갖춘 실제 `.docx` 패키지를 만들며, 보조 수식, 다이어그램, 차트는 그림이 됩니다. **이미지**는 렌더링된 문서를 하나의 PNG로 만듭니다. **PDF 보관본**은 순서대로 정렬된 PDF 조각과 매니페스트를 담은 ZIP을 만들며, 다른 워크플로가 크기가 제한된 분리 가능한 조각을 원할 때 유용합니다. 일반적인 대용량 PDF는 분할 렌더링 경로를 통해 자동으로 조립되지만, PDF 보관본은 그 조각들을 최종 결과물로 보존합니다.

**고급 옵션**을 열어 이번 내보내기에만 적용할 **사용자 CSS**를 추가하세요. 내보내기별 CSS는 테마 뒤에 적용되므로 선택자의 우선순위가 같으면 이쪽이 우선합니다. 페이지 변경은 **이 페이지 설정을 기본값으로 사용**을 선택하지 않는 한 현재 내보내기에만 영향을 줍니다. 생성되는 목차, 제목 번호, 제목 레이블은 **설정 ▸ 목차**(Chapter 70)에서 모든 내보내기에 한 번에 설정합니다.

출력이 잘못되었다면 문제가 구조에 있는지 스타일에 있는지 먼저 가려내세요. 제목이 빠졌다면 대개 프로파일이나 소스의 문제이고, 제목이 보기 좋지 않다면 렌더링 테마의 문제입니다.

## 렌더링된 문서 프린트하기

파일 또는 더 보기에서 **프린트…**를 선택하세요. 프린트는 PDF와 동일한 렌더링 파이프라인과 페이지 레이아웃 기본값을 사용하므로, 구조와 스타일은 미리보기와 PDF 내보내기에서 먼저 진단하는 것이 좋습니다. Mac에서는 페이지 설정이 같은 공유 페이지 레이아웃을 편집합니다. 실제 종이에 인쇄하기 전에 프린트 대화상자에서 용지, 방향, 여백, 머리글, 바닥글을 확인하세요.

# Chapter 28: 내보내기 기본값과 페이지 장식 설정하기

**설정 ▸ 내보내기 ▸ 내보내기 기본값**을 엽니다. 기본 렌더링 테마와 페이지 레이아웃을 선택하세요. 작성자 메타데이터, 머리글, 바닥글을 구성하고, 최상위 제목마다 새 페이지에서 시작할지(**최상위 제목 사이 페이지 나누기**)도 정하세요.

머리글과 바닥글 템플릿에는 `${title}`, `${author}`, `${pageNo}`, `${pageCount}`, `${today}`를 넣을 수 있습니다. 페이지 여백에 들어갈 만큼 짧게 유지하세요. 한 페이지에서는 괜찮아 보이던 머리글이 뒤쪽의 긴 제목이나 페이지 번호와 겹칠 수 있으므로 여러 페이지짜리 PDF로 테스트하세요. 이러한 다듬기 값은 출력 포맷별로 저장되며, 페이지 레이아웃은 PDF, PDF 보관본, Word, 프린트가 공유합니다.

CommonMark 옵션은 강조 표시, 아래 첨자, 위 첨자, 인라인 수식, 자동 링크, 경고 상자, 머리말 데이터, 다이어그램, 스마트 문장 부호, 코드 펜스 표시 방식 같은 선택적 구문을 제어합니다. 소스가 실제로 사용하는 기능만 켜세요. 이식 가능한 CommonMark 문서는 문서화하지 않은 확장 기능에 의존해서는 안 됩니다.

# Chapter 29: 소스와 완성된 출력 공유하기

다른 사람에게 편집 가능한 파일이 필요하면 소스 문서에 대해 **공유…**를 선택하세요. 깨끗하게 저장된 문서는 그대로 공유됩니다. 저장하지 않았거나 변경된 문서는 현재 텍스트의 임시 사본으로 공유되며, 매우 큰 문서는 먼저 저장해야 할 수도 있습니다.

받는 사람에게 완성된 PDF, Word 문서, HTML 파일 또는 이미지가 필요하면 내보내기에서 **공유**를 선택하세요. 따로 저장된 내보내기 파일을 미리 보관해 두지 않아도 출력을 생성해 줍니다.

소스를 공유하기 전에, 받는 사람이 같은 동작을 필요로 한다면 의존하는 로컬 이미지, 연결된 문서, 프로파일, 테마를 함께 포함하세요. 완성된 출력을 공유하기 전에는 링크, 미리보기, 페이지 나누기, 대체 텍스트, 파일 이름을 확인하세요.

# Part IX — 어시스턴트

# Chapter 30: AI 제공자를 안전하게 연결하기

어시스턴트는 선택 사항이며 사용자가 구성한 연결을 사용합니다. Pilcrow는 제공자를 임의로 선택하지 않습니다.

1. **설정 ▸ 일반 ▸ 어시스턴트**를 엽니다.
2. 프리셋을 추가하거나 **사용자 지정…**을 선택합니다.
3. 이름, 기본 URL, 와이어 포맷, 모델을 입력합니다.
4. 제공자가 API 키를 요구하면 해당 옵션을 켜고 메시지가 나올 때 키를 저장합니다. 키는 시스템 키체인에 보관됩니다.
5. **연결 테스트**를 선택합니다.
6. 저장하고 해당 연결을 활성으로 지정합니다.

제공자가 모델 탐색을 지원하면 어시스턴트에서 **모델 선택…**을 사용하세요. 모델이 사라졌다면 오래된 식별자를 계속 재시도하지 말고 최신 모델을 선택하세요.

연결을 처음 사용하기 전에 Pilcrow는 텍스트가 어디로 전송되는지 보여 주고 동의를 요청합니다. 호스트 이름을 읽어 보세요. 로컬 서버와 공용 클라우드 제공자는 같은 API 포맷을 제공하더라도 개인정보 보호 측면의 결과가 다릅니다.

# Chapter 31: 의도적인 맥락으로 질문하기

어시스턴트 사이드바를 열고 대화 모드를 선택하세요. 맥락 칩은 쓸모 있는 가장 작은 범위, 보통은 선택 영역으로 시작합니다. 질문에 꼭 필요할 때만 다른 범위를 선택하세요.

1. 도움을 받고 싶은 단락을 선택합니다.
2. 칩에 선택 영역이라고 표시되는지 확인하고 요약을 검토합니다.
3. “어느 문장 때문에 시간 순서가 불분명한가요?”처럼 구체적인 질문을 합니다.
4. 답변은 자동 편집이 아니라 조언으로 읽습니다.
5. 변경 사항은 직접 적용하거나, 제안되는 검토된 동작을 통해 적용합니다.

Pilcrow는 구성된 패턴과 폴더를 어시스턴트 맥락에서 제외합니다. 어시스턴트 설정에서 관리하세요. 민감한 작업 공간에서는 폴더 컨트롤로 어시스턴트 접근을 끄세요. 대화가 더 이상 현재 작업과 관련이 없으면 휴지통 버튼으로 대화를 지우세요.

질문에서 파일 하나가 언급된다고 해서 폴더 전체를 공유하지 마세요. 필요한 최소한의 맥락만 제공하면 개인정보가 보호되고 답변의 품질도 대개 좋아집니다.

# Chapter 32: Pilcrow 리소스 작성 도움받기

어시스턴트를 **도움말**로 전환하고 프로파일, 매크로 또는 스타일 가이드를 선택하세요. Pilcrow는 관련 포맷 참조를 대화와 함께 포함하므로 후속 지시도 그 내용에 근거해 이어집니다.

원하는 동작을 설명하고 작은 예시를 제공하세요. 초안을 요청하고, 미리보기로 생성된 리소스 텍스트를 확인한 다음, 해당 설정 편집기에서 검증하세요. 이름, 트리거 또는 패턴, 출력을 읽어 보지 않은 채 불투명한 생성 JSON을 가져오거나 저장하지 마세요.

효과적인 순서는 다음과 같습니다.

1. 하나의 동작과 두 가지 예시를 설명합니다.
2. 유효한 가장 작은 리소스를 요청합니다.
3. Pilcrow에서 검증합니다.
4. 성공 사례 하나와 일치하지 않는 사례 하나를 테스트합니다.
5. 검증 오류를 돌려주어 집중적으로 수정하게 합니다.

# Chapter 33: AI 지원 스타일 검토 실행하기

이 워크플로는 Chapter 21의 내용을 확장합니다.

1. 첫 시도를 위해 구절 하나를 선택합니다.
2. 스타일 검토, 가이드, 변형, 검토 영역을 선택합니다.
3. 활성 제공자와 모델을 확인합니다.
4. 검토를 시작합니다.
5. 제공되는 대로 심각도 또는 영역별로 결과를 정렬합니다.
6. 결과를 열어 인용된 근거를 읽고 소스 위치를 확인합니다.
7. 적용하거나, 무시하거나, 미해결로 둡니다.

문서 전체를 검토할 때 Pilcrow는 바이트 수와 요청 횟수를 추정하고 전송하기 전에 다시 확인합니다. 조각 사이에서 중단할 수 있습니다. 민감한 문서는 로컬에서 검토하거나, 처리 약관을 받아들일 수 있는 제공자와 검토하세요. 연결을 폐기할 때는 어시스턴트 또는 저장 공간 및 개인정보 설정에서 AI 데이터와 키를 삭제하세요.

# Part X — 책 프로젝트

# Chapter 34: 폴더를 책 프로젝트로 바꾸기

새 프로젝트라면 **파일 ▸ 새 책…**을 선택하고 제목과 저장 위치를 입력하면 Pilcrow가 초기 폴더와 매니페스트를 만들어 줍니다. 기존 원고를 가져오려면 해당 폴더를 열고 **파일 ▸ 폴더를 책 프로젝트로 만들기** 또는 프로젝트 사이드바의 **프로젝트로 만들기**를 선택한 뒤 메타데이터를 입력하세요. Pilcrow는 순서와 메타데이터를 기술하는 `manifest.pilcrow` 파일을 만들며, 원고 파일을 재배치하지는 않습니다.

프로젝트 설정을 열어 제목, 작성자, 목표 단어 수, 변수, 단어 수 계산 방식, 구문을 입력하세요. **원고에 없음**으로 표시된 기존 파일을 추가하거나, 더하기 메뉴에서 새 머리말, 장, 장면, 맺음말을 만드세요.

`manifest.pilcrow`는 원고와 함께 커밋하거나 백업하세요. 소스 파일은 평범한 텍스트로 남지만, 이 파일은 프로젝트 구성을 위한 목차 역할을 합니다.

# Chapter 35: 장면 계획과 원고 진행 상황 추적하기

**목록**, **줄거리**, **카드** 중에서 선택하세요.

- 목록은 원고 순서와 단어 수를 강조합니다.
- 줄거리는 요약, 시점, 위치, 상태, 진행률을 추가합니다.
- 카드는 파일 순서를 바꾸지 않고 시각적인 계획 보드를 제공합니다.

항목의 세부 정보를 열어 역할, 상태, 줄거리, 시점, 위치, 목표 단어 수를 설정하세요. 상태로 필터링하면 초안, 수정 또는 완료된 작업에 집중할 수 있습니다. 자료 조사나 잘라 낸 장면이라면 파일을 삭제하지 않고 원고에서 항목만 제거하세요.

순서 변경은 상태 필터가 켜져 있지 않을 때만 하세요. 필터링된 일부만으로는 원고 전체의 순서를 안전하게 나타낼 수 없습니다. iPad에서는 **순서 변경**을 선택하고 끌어다 놓은 뒤 **완료**를 선택하세요. 장을 접으면 목록이 덜 복잡해집니다.

Pilcrow가 프로젝트 파일이 디스크에서 변경되었다고 알려 주면 다시 불러온 뒤 하려던 동작을 반복하세요. 이 충돌 보호는 한 기기나 공동 작업자가 더 최신 매니페스트를 덮어쓰는 것을 막아 줍니다.

# Chapter 36: 원고 컴파일하기

1. 프로젝트 사이드바를 엽니다.
2. 순서, 포함된 파일, 프로젝트 메타데이터를 확인합니다.
3. **컴파일…**을 선택합니다.
4. 출력 포맷, 렌더링 테마, 컴파일 옵션을 선택합니다.
5. 머리말, 장 나누기, 번호 매기기, 포함된 역할을 검토합니다.
6. 컴파일한 뒤 결과를 확인합니다.

컴파일은 HTML, PDF 또는 Word를 생성할 수 있습니다. 머리말, 부분, 장, 맺음말 중 무엇을 새 페이지에서 시작할지 선택하고, 장면 사이의 구분선을 설정하며, 목차를 포함하고, 제목에 번호를 매기고, 원한다면 포함된 모든 파일의 버전 기록 스냅샷을 먼저 남길 수 있습니다. 원고 요약에는 포함된 파일, 바이트 수, 제외된 파일, 누락된 경로, 최종 순서가 표시됩니다. 누락된 파일은 해결해야 컴파일을 사용할 수 있습니다.

같은 원고를 여러 방식으로 게시한다면 컴파일 선택 항목 묶음을 이름 있는 프리셋으로 저장하세요. 예를 들어 “편집자용 DOCX”와 “인쇄용 PDF”처럼 말입니다. 더 이상 필요 없는 프리셋은 같은 시트에서 삭제하세요. 컴파일이 진행되는 동안 진행 상황에 파일 수가 표시되며 **중지**를 선택하면 작업이 취소됩니다. 해결되지 않은 `{{variables}}`는 보고되고 눈에 띄게 변경 없이 남습니다.

컴파일은 매니페스트의 순서를 읽어 소스를 논리적으로 결합하며, 파일을 이어 붙여 덮어쓰지 않습니다. 장면을 고치려면 해당 소스 파일에서 수정한 다음 다시 컴파일하세요. 반복되는 메타데이터는 제목이나 작성자 텍스트를 직접 복제하지 말고 프로젝트 변수를 사용하세요.

# Part XI — 구문 프로파일

# Chapter 37: 구문 프로파일 선택하고 이해하기

프로파일은 소스 표시가 어떻게 구조적 역할이 되는지를 Pilcrow에 알려 줍니다. CommonMark는 내장되어 있지만 하나의 프로파일일 뿐이며 앱의 정의가 아닙니다.

상태 막대의 프로파일 컨트롤이나 적절한 문서 컨트롤로 프로파일을 선택하세요. Pilcrow는 확장자에서 프로파일을 추론하고 파일별 선택을 기억할 수 있습니다. 활성 프로파일은 하이라이트, 개요, 서식 사용 가능 여부, 미리보기, 내보내기 구조, 연속 입력 동작, 프로파일 고유의 삽입 항목을 제어합니다.

이미 들어 있는 소스 언어에 맞춰 프로파일을 선택하세요. 프로파일을 바꿔도 텍스트가 변환되지 않고 다르게 해석될 뿐입니다. 변환이 필요하면 사본을 만들어 소스를 명시적으로 변환하세요.

# Chapter 38: 프로파일 만들고 테스트하기

1. **설정 ▸ 라이브러리 ▸ 구문 프로파일**을 엽니다.
2. 비슷한 기본 제공 프로파일을 복제하거나 새 프로파일을 만듭니다.
3. **개요**에서 이름, 식별자, 확장자, 선택적 상속을 설정합니다.
4. **규칙**에서 필요한 가장 작은 구성 요소를 추가합니다.
5. **테스트 샘플**을 열고 대표적인 소스를 붙여 넣은 뒤 **샘플 검사**를 선택합니다.
6. 저장하고, 연습용 문서에서 프로파일을 활성화한 다음 편집, 개요, 미리보기, 내보내기를 비교합니다.

경계 조건을 테스트하세요. 파일의 시작과 끝, 빈 줄, 중첩된 구성 요소, 유니코드, 닫히지 않은 구분자, 일치하면 안 되는 텍스트가 대상입니다. 프로파일은 예시를 인식할 뿐 아니라 아슬아슬하게 어긋난 입력도 거부할 때 신뢰할 수 있습니다.

정상 동작이 확인된 수정본에서 **새 기준본으로 설정**을 사용하세요. **기준본으로 되돌리기**는 이후의 실험을 버립니다. 위험한 재설계를 하기 전에는 복제부터 하세요.

# Chapter 39: 프로파일 규칙과 고급 JSON 편집하기

규칙 편집기에서는 패턴 유형, 줄 시작 요구 사항, 생성되는 역할, 캡처, Return 이후의 연속 입력, 구분된 블록 동작, 레이아웃, 인라인 구간과 쌍, 캡션, 스타일 역할을 다룰 수 있습니다.

구문을 표현할 수 있다면 항상 리터럴 또는 구조화된 인식기를 사용하세요. 패턴은 범위를 제한하고 앵커로 고정하세요. Pilcrow는 알려진 위험한 패턴을 거부하지만, 기술적으로 받아들여진 표현식도 지나치게 넓거나 혼란스러울 수 있습니다.

시각적 편집기가 필요한 속성을 제공하지 않을 때만 **고급 JSON 편집…**을 선택하세요. 적용하면 JSON을 검증하며, 이 시트를 통해 프로파일 정체성을 바꾸는 것은 막습니다. 고급 작업을 하는 동안에는 유효한 테스트 샘플을 곁에 두세요.

상속은 작은 방언을 만들 때 유용합니다. 안정적인 부모를 상속하고 이름이 지정된 구문만 교체하세요. 동작을 설명하기 어렵게 만드는 긴 상속 체인은 피하세요. 프로파일을 가져올 때 충돌이 보고되면 무엇이든 교체하기 전에 이름과 ID를 비교하세요.
