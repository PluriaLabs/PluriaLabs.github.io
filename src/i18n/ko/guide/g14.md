# Part XXI — 파일 형식과 제한

# Chapter 79: 앱 테마 형식

**앱 테마**는 Pilcrow 자체의 모양, 즉 라이트 또는 다크 화면 모드, 강조색, 사이드바, 상태 및 서식 막대, 편집기의 스타일을 지정합니다. JSON 파일입니다. 렌더링된 문서(미리보기, HTML, PDF, 이미지, 프린트, Word)는 CSS로 된 **렌더링 테마**가 따로 스타일을 지정합니다(Chapter 80). 두 종류는 각각 따로 설치, 선택, 삭제되며 서로 영향을 주지 않습니다.

## 전체 예시

```json
{
  "pilcrowAppTheme": 1,
  "name": "Nord",
  "appearance": "dark",
  "colors": {
    "accent": "#88C0D0",
    "sidebar": { "background": "#2E3440", "foreground": "#D8DEE9" },
    "bars": { "background": "#3B4252", "foreground": "#D8DEE9" },
    "editor": {
      "background": "#2E3440",
      "foreground": "#ECEFF4",
      "cursor": "#88C0D0",
      "selection": "#434C5E",
      "gutterBackground": "#2E3440",
      "gutterForeground": "#4C566A"
    },
    "syntax": {
      "heading": "#88C0D0",
      "marker": "#EBCB8B",
      "code": "#A3BE8C",
      "link": "#81A1C1",
      "muted": "#7B88A1",
      "tokens": { "strong": "#D08770" }
    }
  }
}
```

## 최상위 수준

| 키 | 필수 여부 | 값 |
| --- | --- | --- |
| `pilcrowAppTheme` | 예 | 형식 버전, `1`. |
| `name` | 예 | 1~200자. 설정과 테마 메뉴에 표시됩니다. |
| `appearance` | 예 | `"light"`, `"dark"` 또는 `"automatic"`. |
| `colors` | `light` 및 `dark` 테마 | 팔레트 하나(아래 참고). |
| `light`, `dark` | `automatic` 테마 | 팔레트 두 개: 하나는 시스템이 라이트 모드일 때, 하나는 다크 모드일 때 사용합니다. |
| `id` | 아니요 | Pilcrow가 자체 라이브러리용으로 기록합니다. 가져올 때는 무시되며 항상 새 id가 지정됩니다. |

`appearance`는 메뉴, 설정, 시트, 선택기를 포함한 **모든** 창의 화면 모드를 결정합니다. `light` 또는 `dark` 테마는 화면 모드를 고정하고, `automatic`은 시스템을 따릅니다.

automatic 테마는 각 색상을 `light`와 `dark` 모두에서 지정하거나 둘 다 지정하지 않아야 합니다. 한쪽 화면 모드에만 지정한 색상은 다른 쪽에도 그대로 그려지기 때문입니다.

## 팔레트

모든 키는 선택 사항입니다. 생략한 색상은 Pilcrow의 기본 모양을 유지하므로 테마는 강조색 하나만으로도 만들 수 있습니다.

| 키 | 스타일 대상 |
| --- | --- |
| `accent` | 앱 전체의 색조: 버튼, 선택된 세그먼트, 토글, 링크, 포커스 링, 사이드바의 선택된 행. 지정하지 않으면 시스템 강조색을 사용합니다. |
| `sidebar.background`, `sidebar.foreground` | 파일, 개요, 찾기 사이드바. 보조 레이블은 전경색에서 파생됩니다. |
| `bars.background`, `bars.foreground` | 상태 막대, 고정된 서식 도구 막대, 가져오기 알림. 보조 레이블은 전경색에서 파생됩니다. |
| `editor.background`, `editor.foreground` | 편집기 캔버스와 본문 텍스트. |
| `editor.cursor`, `editor.selection` | 삽입 지점과 선택 영역 강조 표시. |
| `editor.gutterBackground`, `editor.gutterForeground` | 줄 번호 거터. 배경의 기본값은 편집기 배경입니다. |
| `editor.currentLineRule` | **보기 ▸ 현재 줄 밑줄**이 켜져 있을 때 캐럿이 있는 줄 아래의 가는 선. 기본값은 약한 강도의 편집기 텍스트 색상입니다. |
| `syntax.<group>` | 그룹별 실시간 구문 색상(아래 참고). |
| `syntax.tokens.<raw>` | 원시 값으로 지정하는 토큰 하나. 해당 그룹의 색상보다 우선합니다. |

### 구문 그룹

| 그룹 | 색상 대상 |
| --- | --- |
| `heading` | 제목(마커와 텍스트), 알림 마커, 정의 용어 |
| `marker` | 강조, 굵게, 취소선 및 기타 인라인 구분 기호, 목록 및 작업 마커 |
| `code` | 인라인 코드, 펜스 및 들여쓰기 코드 블록, 수식, HTML 블록 |
| `link` | 링크와 이미지의 레이블 및 대상, 자동 링크 |
| `muted` | 인용 마커, 주제 구분선, 표 행, 주석, 블록 속성 |
| `codeKeyword`, `codeString`, `codeNumber`, `codeComment` | 펜스 안의 강조된 코드 |

지정하지 않은 그룹은 편집기 배경에 맞춰 선택된 기본 제공 색상을 사용합니다. 밝은 캔버스에서는 더 어두운 톤, 어두운 캔버스에서는 더 밝은 톤입니다. `syntax.tokens`의 토큰 이름에는 영문자, 숫자, `_`, `-`를 사용할 수 있으며 그룹 이름과 같을 수 없습니다(`syntax.heading`이 이미 `heading`을 포함합니다).

## 색상

모든 색상은 sRGB의 16진수 문자열(`#RGB`, `#RGBA`, `#RRGGBB` 또는 `#RRGGBBAA`)입니다. Pilcrow는 이를 대문자로 저장합니다.

## 유효성 검사

Pilcrow는 파일의 일부를 무시하는 대신 파일 전체를 거부하며, 문제가 있는 키를 알려 줍니다. 예: `colors.editor.cursor: must be a hex colour`. 다음의 경우 거부합니다.

- `pilcrowAppTheme` 버전이 없거나 다른 경우
- 어느 수준에서든 알 수 없는 키가 있는 경우(대개 오타)
- 화면 모드와 맞지 않는 팔레트 키(automatic 테마의 `colors`, light 또는 dark 테마의 `light`와 `dark`)
- 16진수가 아닌 색상
- `light`와 `dark` 팔레트가 서로 다른 색상을 지정한 automatic 테마

## 앱 테마가 바꾸지 않는 것

창 제목 막대와 도구 막대(강조색만 적용되는 시스템 글라스), 메뉴, 설정, 시트, 선택기는 화면 모드와 강조색을 제외하면 기본 모양을 유지합니다. 서체는 테마로 지정하지 않으며, 편집기 글꼴과 크기는 **설정 ▸ 화면 모드 ▸ 텍스트 크기 및 글꼴**에서 정합니다.

## 설치와 공유

- `.json` 파일은 **설정 ▸ 라이브러리 ▸ 테마**에서 **가져오기**하거나, Mac에서는 **파일 ▸ 가져오기 ▸ 테마**, iPad에서는 **설정 ▸ 라이브러리 ▸ 가져오기**를 사용합니다. 파일을 Pilcrow 위로 끌어다 놓아도 됩니다.
- `.zip` 테마 패키지에는 렌더링 테마와 함께 앱 테마를 담을 수 있습니다(Chapter 80).
- 테마 옆의 공유 버튼은 해당 테마의 `.json` 파일을 저장하며, 패키지에서 온 테마라면 패키지 전체를 저장합니다.

Pilcrow에는 **자동**, **라이트**, **다크**의 앱 테마 세 가지가 포함되어 있습니다. 이 테마들은 편집기와 구문 색상을 지정하고 크롬은 기본 모양 그대로 둡니다.

# Chapter 80: 렌더링 테마 CSS 참조

**렌더링 테마**는 CSS입니다. 미리보기, HTML, PDF, 이미지, 프린트 출력과 이 장 끝에 나열된 Word 스타일의 모양을 지정합니다. 렌더링 테마는 `.css` 파일 하나일 수도 있고 로컬 에셋이 들어 있는 ZIP 패키지의 일부일 수도 있습니다. 구문 프로필은 소스 텍스트가 문서가 되는 방식을 정의하고, 렌더링 테마는 그 결과의 스타일만 지정합니다. CSS는 앱이나 편집기의 스타일을 지정하지 않으며, 그것은 앱 테마의 역할입니다(Chapter 79).

## 캐스케이드

Pilcrow는 다음 순서로 스타일을 적용합니다.

1. Pilcrow의 구조 재설정
2. 선택한 테마 CSS
3. 내보내기 패널의 일회성 CSS(**고급 옵션 ▸ 사용자 CSS**)
4. 필수 프린트 및 렌더링 보정

나중 규칙이 일반적인 CSS 캐스케이드에 따라 우선합니다. 테마 JavaScript, 원격 리소스, `file:` URL, `@import`는 지원되지 않습니다.

## 리소스

Pilcrow는 표준 CSS 토크나이저로 테마 CSS를 읽으므로, 검사하기 전에 이스케이프가 먼저 해석됩니다. `u\72 l(…)`은 `url()`이고 `@im\70 ort`는 `@import`입니다. 브라우저가 무언가를 불러오는 모든 위치(`url(…)`, `url("…")`, `src("…")`, `image-set()` 안의 문자열)를 검사하며, 각각은 다음 중 하나여야 합니다.

- 패키지 기준 상대 경로(`fonts/Body.woff2`, `./paper.png`). `?query`나 `#fragment`는 허용되며 파일을 찾을 때는 무시됩니다.
- PNG, JPEG, GIF, WebP, SVG(`image/svg+xml`), TTF, OTF, WOFF, WOFF2 형식의 `data:` URL
- `url(#shadow)`처럼 페이지 안의 요소를 가리키는 프래그먼트 참조

`data:`가 아닌 스킴(`https:`, `file:`, `blob:`)이 붙은 것이나 `//`로 시작하는 것, `/`로 시작하거나 `..`를 포함하는 경로는 거부됩니다.

## 렌더링 속성

기본 제공 재설정은 다음 속성을 읽고 대체값을 제공합니다.

| 간격 | `--pt-paragraph-spacing`, `--pt-blockquote-indent`, `--pt-list-indent`, `--pt-code-padding`, `--pt-heading-top`, `--pt-heading-bottom` |

## ZIP 패키지

ZIP 패키지에는 렌더링 테마(`.css`)와 앱 테마(`.json`)를 함께 담을 수 있으며, 각각 설정에서 자신의 종류와 함께 표시됩니다. CSS 파일이 최대 하나이고 앱 테마가 최대 하나인 ZIP에는 매니페스트가 필요 없습니다. 그보다 많으면 모든 테마를 `variants[].file` 아래에 나열하는 `pilcrow-theme.json`이 필요합니다. 파일의 확장자가 종류를 결정합니다.

```json
{
  "id": "com.example.paper",
  "name": "Paper",
  "version": "1.0.0",
  "author": "Example Author",
  "license": "MIT",
  "cssAPIVersion": 1,
  "variants": [
    { "id": "app", "name": "Paper", "file": "Paper.json", "appearance": "automatic" },
    { "id": "light", "name": "Paper Light", "file": "Paper-Light.css", "appearance": "light" },
    { "id": "dark", "name": "Paper Dark", "file": "Paper-Dark.css", "appearance": "dark" }
  ]
}
```

매니페스트는 패키지와 그 테마를 설명하며 스타일 값은 절대 담지 않습니다. 스타일 값은 CSS와 앱 테마 파일에 있습니다.

- 패키지 `id`는 설치 폴더의 이름이 됩니다. `.`으로 시작하거나 앞뒤에 공백이 있으면 안 됩니다. 이미 설치된 `id`의 패키지를 설치하면 기존 패키지를 대체합니다.
- Finder의 **압축**으로 만든 ZIP은 그대로 사용할 수 있습니다. Pilcrow는 `__MACOSX/`, `._*`, `.DS_Store`, `Thumbs.db`를 건너뛰며, 모든 파일이 최상위 폴더 하나 안에 있으면 그 폴더를 패키지 루트로 취급합니다.
- 테마 하나를 삭제하면 패키지에서 그 테마만 제거되고 나머지 테마와 공유 에셋은 유지됩니다. 마지막 테마를 삭제하면 패키지가 제거됩니다. 선택되어 있던 테마를 삭제하면 해당 종류의 기본값으로 선택이 돌아갑니다. 앱 테마는 자동, 렌더링 테마는 라이트입니다.
- CSS는 상대 `url(...)` 경로로 패키지 안의 PNG, JPEG, GIF, WebP, TTF, OTF, WOFF, WOFF2 파일을 참조할 수 있습니다. Pilcrow는 파일 시그니처를 확인하고, 참조된 에셋을 데이터 URL로 내장하여 렌더링과 내보낸 HTML이 오프라인에서 독립적으로 유지되게 합니다. ZIP 경로는 패키지를 벗어나거나, 대소문자로 충돌하거나, 링크를 가리킬 수 없습니다. 아카이브 크기, 항목 수, 개별 크기, 압축률에는 제한이 있습니다.

## Word

Word 내보내기는 라이트(기본) `:root` 값을 사용하며, 다음 의미 속성을 이름이 있는 Word 스타일에 대응시킵니다. `--pt-foreground`, `--pt-background`, `--pt-accent`, `--pt-link-color`, `--pt-code-background`, `--pt-code-foreground`, `--pt-body-font-family`, `--pt-mono-font-family`, `--pt-base-font-size`, `--pt-line-height`입니다. 브라우저 선택자와 레이아웃 규칙은 Word에 일반적으로 대응하는 것이 없습니다. 미리보기, HTML, PDF, 이미지 출력은 전체 스타일시트를 사용하고, Word는 문서 구조, 다이어그램, 수식 그림, 링크, 미디어를 보존하면서 이 부분 집합을 사용합니다. 내보내기 패널은 Word를 선택할 때마다 이 제한을 표시합니다.

Pilcrow에는 완전한 출발점이 되는 렌더링 테마 두 가지, **라이트**와 **다크**가 포함되어 있습니다.
