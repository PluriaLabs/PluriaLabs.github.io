# Part XII — 主题与外观

# Chapter 40: 理解应用主题和渲染主题

Pilcrow 有两套相互独立的主题系统：

- **应用主题** 是 JSON，用于设置应用、各栏、边栏、强调色、编辑器颜色以及浅色或深色外观的样式。
- **渲染主题** 是 CSS，用于设置预览、HTML、PDF 以及用于 Word 的语义子集的样式。

可在 **视图 ▸ 主题** 或设置中选择这两种主题。没有会与应用主题相冲突的独立模式开关；主题自己声明外观。CSS 不会为应用或源码编辑器设置样式。

当编辑器看起来不对时，请更改应用主题。当预览或导出看起来不对时，请更改渲染主题。这一个区别就能解决大多数主题方面的困惑。

# Chapter 41: 创建和管理主题

打开 **设置 ▸ 资源库 ▸ 主题**。选择应用集合或渲染集合，然后可以复制、导入、导出、编辑或删除用户主题。

对于应用主题，请使用编辑器设置外观、强调色、外框、边栏、各栏和编辑器颜色。检查选择内容的对比度、当前行的可见性、链接、警告，以及活动和非活动的控件。

对于渲染主题，请针对 Pilcrow 类 API 编辑 CSS。先修改字体排印和间距，然后依次是标题、列表、代码、表格、提示框、链接、脚注和补充块。如果你是在项目检出目录中工作，请使用 `Examples/Themes/VisualTestPack` 中的可视样本进行测试。

内置主题是稳定的起点。请复制，而不要试图覆盖它。一个 ZIP 包可以同时包含两种主题；文件扩展名决定每一项归属何处。

# Chapter 42: 选择字体、大小、间距和背景

使用 **设置 ▸ 外观 ▸ 文字大小和字体** 设置编辑器和行号栏的字体、磅值大小、行距和制表符宽度。这些设置影响书写界面，而不影响导出的字体排印。

使用 **主题与背景** 设置应用主题、缩放、阅读速度，以及文本区域或边栏后面的可选图像。分别选择、替换或移除每个背景。背景应当保持对比度和专注：一张漂亮却降低可读性的图像，是糟糕的编辑器设置。

发布用的字体和页面布局请使用渲染主题和导出默认设置。这种分离让你可以在清晰易读的等宽编辑器中写作，同时以比例字体的书籍字体发布。

# Part XIII — 导入、导出和管理你的资源库

# Chapter 43: 导入和共享 Pilcrow 资源

Pilcrow 可以导入语法配置、应用主题、渲染主题、宏集合、风格指南，以及包含受支持资源的 ZIP 包。

1. 打开相应的资源库设置页面，或 iOS 上的导入页面。
2. 选择导入并选取文件。
3. 检查资源类型、名称和任何冲突。
4. 只有在理解后果的情况下，才导入、重命名或替换。
5. 在一个临时文稿中启用并测试它。

从资源库页面导出用户资源，以便共享或备份。当项目需要同时具备配置、主题、宏和指南时，请把相关资源放在一个 ZIP 中。

请把导入的配置、宏、CSS 和风格指南视为类似代码的配置。在信任它们之前，请阅读触发器、模式、原始 CSS 和助手指令。

# Chapter 44: 移动或恢复你的资源库

打开 **设置 ▸ 资源库 ▸ 位置**。选择一个文件夹或 **使用此设备**。如果目的位置已经包含一个资源库，请在以下选项中选择：

- **使用现有内容**：直接切换而不拷贝。
- **将我的资源库移到此处**：传输，并在成功后移除旧的受管理副本。
- **将我的资源库拷贝到此处**：两份都保留。

只有当同步文件夹的提供商能可靠地保留普通文件，并且你了解并发编辑的风险时，才使用同步文件夹。退出之前，请让传输完成。如果位置变得不可用，请重新连接驱动器或账户，或选择另一个位置；不要盲目地创建相互冲突的替代资源。

在 iOS 上，导入页面可以从包中恢复资源库内容。恢复之后请核实当前的主题和配置，因为资源 ID，而不仅仅是显示名称，决定了引用关系。

# Part XIV — 设置、隐私和支持

# Chapter 45: 配置通用、文件和编辑设置

设置已分组且可搜索。可使用搜索栏查找诸如“行号”“图像”或“页眉”之类的标签。

## 通用

配置窗口和启动行为、语言、翻译、助手连接、诊断以及存储与隐私。

## 文件

选择启动文件夹行为、默认文件类型、自动存储和恢复、保留的版本数、文件树行为，以及将可导入项目拖放到应用上时的处理方式。

## 编辑 — 显示与输入

配置行号、状态栏、格式工具栏、换行、当前行标线、样式化源码、标记、渲染块、标题折叠、自动展开、括号和引号配对、Markdown 配对、表情符号短代码、列表和引用续行、按下换行时的缩进、用空格代替制表符、拼写以及解析警告。

## 编辑 — 键入声音

打开 **输入时播放声音**，即可在输入时听到声音。选择一个声音包（打字机、鸭子或小猫），设置音量，并使用 **预览** 试听。每种按键类型都有各自的声音：小写字母、大写字母、数字、符号、空格、制表符、换行和删除。粘贴和多字符编辑则保持静音。

在 **自定声音** 下，选择某种按键类型旁边的 **选择…**，即可为它使用你自己的音频文件（WAV、AIFF、MP3、M4A 或 CAF）。片段最长 2 秒，最大 3 MB。Pilcrow 会把它转换成小型单声道片段，因此过长或过响的文件不会拖慢输入，也不会产生咔嗒声。使用 **播放** 试听，使用 **移除** 恢复为声音包中的声音。如果文件被拒绝，提示信息会说明原因。在 iPad 上，静音开关会让键入声音静音，并且它们会与其他音频混合播放。

## 编辑 — 图像

配置插入、拷贝或移动、在线加载、路径样式和 URL 转义。

## 外观

选择应用主题、缩放、背景、编辑器大小、字体、行距和制表符宽度。

## 导出

选择渲染主题、布局、页眉、页脚、元数据和标题分页。

## 资源库

管理配置、CommonMark 选项、主题、宏、风格指南、渲染库、位置和导入。

## 键盘

搜索、重新绑定、取消绑定和重置快捷键，包括字段导航的行为。

一次只更改一组设置。评估字体排印时，请固定主题；评估解析时，请固定配置。受控的更改能让因果关系清晰可见。

# Chapter 46: 控制隐私和存储的数据

打开 **设置 ▸ 通用 ▸ 存储与隐私**。Pilcrow 按类别分别进行删除，因此清除缓存不会意外删除文稿。

- **查看恢复数据…** 列出可恢复的内容。删除之前，请保存或关闭有未存储改动的文稿。
- **查看版本历史…** 在删除之前显示版本和预估的空间。
- **清除最近文件的访问权限…** 会移除最近的文件、记住的文件夹、会话书签以及每个文件的语法选择。
- **删除 AI 数据和密钥…** 会移除连接、钥匙串中的密钥、对话以及 AI 隐私选择。
- **删除诊断信息…** 会移除已记录的日志和崩溃支持数据。
- **清除缓存…** 会移除可重新创建的缓存和网络响应。

自定义配置、主题、宏、风格指南和背景仍保留在各自可见的资源库页面上，必须在那里检查。这些控件不会删除你的文稿。

助手设置还管理被排除的文件模式、已关闭助手的文件夹以及 AI 数据的删除。在线图像的加载是另一项隐私选择。检查链接绝不会访问网络。

# Chapter 47: 记录并发送诊断信息

打开 **设置 ▸ 通用 ▸ 诊断**。对于时有时无的问题，请选择 **重现问题**，然后选择相关部分、级别、保留时间以及要包含的支持信息。选项包括设备和系统信息、Pilcrow 设置、速度和内存、最近操作的痕迹以及崩溃详情。

请及时重现问题，然后选择 **查看日志…**。按子系统和严重程度筛选。发送之前，请检查报告。选择 **帮助 ▸ 报告错误…** 可打开 GitHub 上的错误报告表单，并自动填入你的版本，同时 Pilcrow 会把日志拷贝到剪贴板，供你粘贴进去。你也可以把报告存为文件以便附上、共享它，或在日志查看器中选择 **在 GitHub 上报告…**。GitHub 上的报告是公开的。

诊断信息应当记录长度、标识符、状态和错误，而不是文稿内容，但共享报告之前请务必检查。问题捕获之后，请把记录恢复为 **仅问题**，或关闭详细保留；详尽的日志会占用存储空间并影响性能。

# Chapter 48: 以其他语言使用 Pilcrow

打开设置并选择语言。可能需要重新启动。Pilcrow 提供英语，以及西班牙语、法语、德语、意大利语、巴西葡萄牙语、荷兰语、俄语、日语、韩语和简体中文。

在被标记为经过人工审阅之前，非英语的界面翻译均由 AI 生成。Pilcrow 会在这些语言下显示启动提示。选择 **不再显示** 可永久关闭该提示，或在语言设置中重新启用该提示。标签“机器翻译 — 可能包含错误”用于标识尚未审阅的内容。

更改界面语言不会翻译文稿。请使用翻译命令处理文稿文本。如果某个命令在翻译后含义不明确，请临时切换到英语，以查看权威的原始措辞。

# Chapter 50: 排查常见问题

## 文件出现乱码

请检查状态栏中的编码。编辑之前，请用正确的编码重新打开或转换。

## 格式或预览不正确

确认当前配置，验证源码分隔符，启用所需的可选语法，然后确认渲染主题。使用显示标记的编辑模式检查字面文本。

## 格式或插入命令被禁用

从预览切换到编辑。然后确认已有当前文稿和语法配置，并且该配置支持所请求的结构。

## 图示、图表或公式无法渲染

检查围栏的语言标签、块边界、源码语法以及图示/数学选项。从内置模板开始，以隔离错误。

## 查找漏掉了预览中可见的文本

请在编辑中搜索被格式拆分的文本，或包含在代码、公式、图示或图表中的文本。预览搜索有意只覆盖可读的渲染文本，而不是每个源码节点。

## 相对路径的图像或链接已损坏

请保存文稿使其有一个文件夹，核对确切的文件名和大小写，优先使用项目内的相对路径，并运行检查链接。

## 文件夹替换跳过了一些文件

请在 Pilcrow 中关闭这些文件，确保它们是 UTF-8 文本，重新运行预览，并核实它们在预览和提交之间没有被外部更改。

## 宏没有触发，或触发过于频繁

请确认其集合和宏已启用，检查匹配类型和触发边界，在代码之外进行测试，并收窄过宽的模式。

## 翻译不可用

请确认使用的是 macOS 15 或 iOS 18 或更高版本，已安装语言支持，并且源语言/目标语言组合受支持。文稿翻译与界面语言是两回事。

## 助手不可用

添加并测试一个连接，将其设为当前连接，选择一个提供的模型，确认提供商，并确保文件夹或文件未被排除。

## 超大文件的操作很慢

请等待后台的行索引完成，使用有针对性的搜索，并在流式 HTML/Word 工作流可满足需求时，避免使用 PDF 或整篇文稿的转换。

## Pilcrow 报告意外退出或编辑器不同步

请停止编辑，尽可能存一份副本，在提供恢复时使用恢复，并在重新启动之前记录诊断信息。在核实已存储的文稿之前，不要丢弃恢复集。

## 项目面板报告清单冲突

请重新加载，检查最新的项目状态，然后重复该更改。不要同时从两台设备覆盖 `manifest.pilcrow`。

## 自定义资源无法导入

请确认预期的扩展名和 JSON/CSS 格式，检查所报告的不安全模式或冲突，并导入到正确的应用主题、渲染主题、配置、宏或风格指南部分。

# Chapter 51: 养成可靠的工作习惯

对日常工作使用以下流程：

1. 当文稿有相关资源时，打开文件夹，而不只是单个孤立的文件。
2. 在大量编辑之前确认配置和编码。
3. 存储一个初始检查点。
4. 在编辑中写作；当结构重要时使用并排。
5. 用宏和字段处理重复内容，而不是手动复制。
6. 在批量替换、接受比较结果、替换翻译或进行配置实验之前先存储。
7. 在适当的阶段运行拼写检查、风格审阅和检查链接。
8. 展开所有部分，并从头到尾检查预览。
9. 用预期的渲染主题导出，并检查实际的目标格式。
10. 只有在收件人需要编辑时才共享源文件；否则请共享成品输出。
11. 把配置、主题、宏、风格指南、项目清单和本地资源与项目备份放在一起。
12. 定期在存储与隐私下检查恢复数据、版本、AI 数据、诊断信息和缓存。

道理很简单：在源码中把含义表达清楚，把呈现交给主题，在操作之前设置检查点，只共享最少必要的数据，并验证他人将收到的确切成品。这就是让纯文本既强大又可靠的 Pilcrow 之道。
