# Chapter 24: 使用 Super Tab 构建可复用模板

字段能把静态展开变成引导式表单。字段可以带有占位符、默认值或一组选项。

1. 为重复出现的结构创建一个宏。
2. 在展开内容中添加字段，或在编写源码时使用 **插入 ▸ 字段**。
3. 展开该宏。
4. 在已选中的第一个字段中输入内容。
5. 使用 **下一个字段** 前进，使用 **上一个字段** 返回。
6. 对于选项字段，从字段选项列表中选择。

请按人们自然回答的顺序来设计字段。把最终的插入点放在应当继续自由写作的位置。默认值要无害：用户遗漏的字段应当在预览中一目了然，而不是悄无声息地发布误导性内容。

# Part VII — 数学、图示、图表和图像

# Chapter 25: 编写公式、图示和图表

Pilcrow 内置离线渲染，支持 MathJax 公式、Mermaid 图示和 Vega-Lite 图表。块从哪里开始、到哪里结束，仍由当前语法配置决定；内置的库只负责绘制其中的内容。

## 从模板开始

1. 选择 **插入 ▸ 公式**、**图示** 或 **图表**。
2. 选取一个模板。
3. 替换示例源码。
4. 切换到预览或并排。
5. 在源码块中修正所有报告的语法错误。

数学符号使用 MathJax，流程与关系使用 Mermaid，数据驱动的图表使用 Vega-Lite。请在重要的图像附近保留文字说明，这样即使渲染器不可用，文稿依然可以理解，也能让更多读者无障碍阅读。

这些库已内置，无需联网即可运行。设置 ▸ 资源库 ▸ 渲染库 会显示版本和声明。如果某个块无法渲染，请先确认它的语言标签、分隔符、可选功能设置和语法，然后再更换主题。

# Chapter 26: 管理图像插入与在线图像隐私

打开 **设置 ▸ 编辑 ▸ 图像** 并决定：

- 插入的图像是拷贝、移动，还是保留在原处。
- 该规则是否适用于本地图像和在线图像。
- 是否允许加载在线图像。
- 是否尽可能使用相对路径。
- 相对路径是否以 `./` 开头。
- 插入时是否对 URL 进行转义。

为了便于移植，请把图像放在文稿文件夹内并使用相对路径。当原件属于另一个项目时，拷贝比移动更安全。移动可避免重复，但可能破坏原来的位置。

在线图像会向其主机泄露查看者的网络地址，而且可能变化或消失。审阅不可信的文稿时，请保持网络加载关闭。若要长期发布，请下载一份已获授权的副本并在本地引用。

# Part VIII — 发布与共享

# Chapter 27: 导出 HTML、PDF、Word 和图像

1. 保存文稿并检查预览。
2. 从工具栏或文件命令中选择导出。
3. 选择 HTML、HTML（无样式）、PDF、Word、图像或 PDF 归档。
4. 在 **样式** 下选择渲染主题。
5. 对于 PDF、PDF 归档和 Word，检查 **页面** 选项：纸张大小、方向和边距。
6. 选择 **导出** 并选定目的位置，或选择 **共享** 直接发送生成的文件。

HTML 会创建一个独立的带样式页面。**HTML（无样式）** 输出干净的结构，不含内嵌的主题 CSS。Word 会生成真正的 `.docx` 包，带有语义化的文稿结构；补充的公式、图示和图表会变成图片。**图像** 会为渲染后的文稿创建一张 PNG。**PDF 归档** 会创建一个 ZIP，内含按顺序排列的 PDF 分段和一个清单，当其他工作流需要有界、可分离的分段时很有用。普通的大型 PDF 会自动通过分段渲染路径组装，而 PDF 归档则把这些分段作为最终交付物保留下来。

打开 **高级选项** 可添加仅用于本次导出的 **自定 CSS**。每次导出的 CSS 在主题之后应用，因此在选择器权重相同时优先生效。页面更改只影响当前这次导出，除非你选择 **将这些页面设置用作默认设置**。生成的目录、标题编号和标题标签在 **设置 ▸ 目录** 中为所有导出统一设置（Chapter 70）。

如果输出有误，请先判断问题出在结构还是样式。标题缺失通常是语法配置或源码问题；标题不好看则是渲染主题的问题。

## 打印渲染后的文稿

从文件或更多中选择 **打印…**。打印使用与 PDF 相同的渲染流程和页面布局默认值，因此预览和 PDF 导出是首先诊断结构与样式的好地方。在 Mac 上，页面设置编辑的是同一份共享页面布局。在正式打印实体页面之前，请在打印对话框中检查纸张、方向、边距、页眉和页脚。

# Chapter 28: 设置导出默认值和页面附加元素

打开 **设置 ▸ 导出 ▸ 导出默认设置**。选择默认的渲染主题和页面布局。配置作者元数据、页眉、页脚，以及每个顶级标题是否另起一页（**在顶级标题之间分页**）。

页眉和页脚模板可以包含 `${title}`、`${author}`、`${pageNo}`、`${pageCount}` 和 `${today}`。请让它们足够短，以适应页边距。请测试多页 PDF，因为在一页上看起来没问题的页眉，到后面可能会与长标题或页码冲突。这些润色值按输出格式分别存储；页面布局则由 PDF、PDF 归档、Word 和打印共用。

CommonMark 选项控制可选语法，例如高亮、下标、上标、行内数学、自动链接、提示块、前置元数据、图示、智能标点和代码围栏的呈现方式。只启用源码实际用到的功能。可移植的 CommonMark 文稿不应在未加说明的情况下依赖扩展。

# Chapter 29: 共享源文件和成品输出

当他人需要可编辑的文件时，请对源文稿选择 **共享…**。已保存且无改动的文稿会被直接共享。未保存或有改动的文稿会以其当前文本的临时副本形式共享；非常大的文稿可能需要先保存。

当收件人需要成品 PDF、Word 文稿、HTML 文件或图像时，请在导出中选择 **共享**。这会直接生成输出，而无需你先另外保存一份导出文件。

共享源文件之前，如果收件人需要相同的效果，请一并附上所依赖的本地图像、链接的文稿、语法配置或主题。共享成品输出之前，请检查链接、预览、分页、替代文本和文件名。

# Part IX — 助手

# Chapter 30: 安全地连接 AI 提供商

助手是可选的，使用你自行配置的连接。Pilcrow 不会悄悄替你选择提供商。

1. 打开 **设置 ▸ 通用 ▸ 助手**。
2. 添加预设或选择 **自定义…**。
3. 输入名称、基础 URL、传输格式和模型。
4. 如果提供商需要 API 密钥，请启用该选项，并在提示时存储密钥。密钥保存在系统钥匙串中。
5. 选择 **测试连接**。
6. 保存并将该连接设为当前连接。

当提供商支持模型发现时，请在助手中使用 **选择模型…**。如果某个模型消失了，请选择一个当前的模型，而不是反复重试已过时的标识符。

首次使用某个连接之前，Pilcrow 会显示文本将发送到哪里并征求同意。请阅读主机名。本地服务器和公有云提供商即使使用相同的 API 格式，对隐私的影响也不同。

# Chapter 31: 带着明确的上下文提问

打开助手边栏并选择对话模式。上下文标签从最小的有用范围开始，通常是所选内容。只有在问题确实需要时才选择其他范围。

1. 选择你想获得帮助的段落。
2. 确认标签显示“所选内容”，并查看其摘要。
3. 提出具体的问题，例如“哪一句让时间顺序变得不清楚？”
4. 把回复当作建议来阅读，而不是自动修改。
5. 自行应用更改，或通过提供的已审阅操作来应用。

Pilcrow 会把已配置的模式和文件夹排除在助手上下文之外。请在助手设置中管理它们。使用文件夹控件可为敏感的工作区关闭助手访问。当对话不再属于当前任务时，请用废纸篓按钮清除对话。

切勿仅仅因为问题提到了某个文件就共享整个文件夹。最小必要的上下文能提升隐私，也往往能提升回答质量。

# Chapter 32: 获取编写 Pilcrow 资源的帮助

将助手切换到 **帮助**，并选择配置、宏或风格指南。Pilcrow 会把相关的格式参考随对话一并提供，使后续指令保持有据可依。

描述期望的行为，并提供一个小示例。请求一份草稿，使用预览检查生成的资源文本，然后在相应的设置编辑器中验证它。在读过名称、触发器或模式以及输出之前，不要导入或保存来历不明的生成 JSON。

一个行之有效的流程是：

1. 说明一种行为和两个示例。
2. 请求最小的有效资源。
3. 在 Pilcrow 中验证。
4. 测试一次成功和一次不匹配的情况。
5. 把验证错误返回给助手，以便有针对性地修正。

# Chapter 33: 运行 AI 辅助的风格审阅

此工作流是对 Chapter 21 的扩展：

1. 选择一段文字作为第一次试用。
2. 选择风格审阅、一份指南、变体和审阅范围。
3. 确认当前的提供商和模型。
4. 开始审阅。
5. 按提供的方式按严重程度或范围对发现项排序。
6. 打开一个发现项，阅读其引用的证据，并检查源码位置。
7. 应用、忽略，或保持未解决。

对于整篇文稿，Pilcrow 会估算字节数和请求次数，并在发送前再次询问。你可以在分块之间停止。审阅敏感文稿时，请在本地进行，或使用你接受其处理条款的提供商。停用某个连接时，请在助手或存储与隐私设置中删除 AI 数据和密钥。

# Part X — 书籍项目

# Chapter 34: 把文件夹变成书籍项目

对于全新的项目，请选择 **文件 ▸ 新建书籍…**，输入标题和目的位置，让 Pilcrow 创建初始文件夹和清单。若要接管现有书稿，请打开其文件夹，选择 **文件 ▸ 将文件夹设为书籍项目**，或使用项目边栏中的 **设为项目**，并填写元数据。Pilcrow 会创建一个描述顺序和元数据的 `manifest.pilcrow` 文件；它不会重新排列书稿文件。

打开项目设置，输入标题、作者、目标字数、变量、字数统计方式和语法。添加列为 **不在书稿中** 的现有文件，或通过加号菜单创建新的前言、章节、场景和后记。

请把 `manifest.pilcrow` 与书稿一起提交或备份。尽管源文件仍是普通文本，它却是项目组织的目录。

# Chapter 35: 规划场景并跟踪书稿进度

在 **列表**、**概要** 和 **卡片** 之间选择：

- 列表强调书稿顺序和字数。
- 概要增加了摘要、视角、地点、状态和进度。
- 卡片提供可视化的规划板，不会改变文件顺序。

打开某一项的详细信息，可设置其角色、状态、概要、视角、地点和目标字数。按状态筛选，可专注于草稿、修订或已完成的工作。当某项是研究资料或被删减的场景时，可以把它从书稿中移除而不删除其文件。

只有在没有启用状态筛选时才能重新排序；筛选后的子集无法安全地代表完整的书稿顺序。在 iPad 上，选择 **重新排序**，拖动，然后选择 **完成**。折叠章节可减少列表的杂乱。

如果 Pilcrow 提示项目文件在磁盘上已更改，请重新加载并重复原先想执行的操作。这种冲突保护可防止某台设备或某位协作者覆盖较新的清单。

# Chapter 36: 编译书稿

1. 打开项目边栏。
2. 确认顺序、包含的文件和项目元数据。
3. 选择 **编译…**。
4. 选择输出格式、渲染主题和编译选项。
5. 检查前言、章节分隔、编号和包含的角色。
6. 编译并检查结果。

编译可以生成 HTML、PDF 或 Word。你可以选择哪些前言、部分、章节和后记另起一页；设置场景之间的分隔符；包含目录；为标题编号；还可以在编译前为每个包含的文件保留一份版本历史快照。书稿摘要会显示包含的文件、字节数、省略的文件、缺失的路径和最终顺序。缺失的文件必须先解决，才能使用编译。

当你以多种方式发布同一份书稿时，请把一组编译选择存为命名预设，例如“编辑用 DOCX”和“印刷用 PDF”。在同一张面板中删除过时的预设。编译运行期间，进度会显示文件数，**停止** 会取消操作。未解决的 `{{variables}}` 会被报告，并按原样明显保留。

编译读取清单顺序并在逻辑上合并源文件；它不会拼接并覆盖你的文件。请在源文件中修正某个场景，然后重新编译。对于重复出现的元数据，请使用项目变量，而不要手动重复标题或作者文本。

# Part XI — 语法配置

# Chapter 37: 选择并理解语法配置

配置告诉 Pilcrow 源码标记如何变成结构角色。CommonMark 是内置的，但它只是其中一种配置，并不是应用本身的定义。

使用状态栏中的配置控件或相应的文稿控件来选择配置。Pilcrow 可以根据扩展名推断配置，并记住每个文件的选择。当前配置控制高亮、大纲、格式可用性、预览、导出结构、续行行为以及特定于配置的插入项。

请根据源码中已有的语言来选择配置。更换配置不会转换文本，只是重新解释它。如果需要转换，请创建一个副本并明确地转换源码。

# Chapter 38: 创建并测试配置

1. 打开 **设置 ▸ 资源库 ▸ 语法配置**。
2. 复制一个相近的内置配置，或创建新配置。
3. 在 **概览** 中设置名称、标识符、扩展名和可选的继承。
4. 在 **规则** 中添加你所需的最小结构。
5. 打开 **测试示例**，粘贴有代表性的源码，然后选择 **检查示例**。
6. 保存，在一个临时文稿中启用该配置，并比较编辑、大纲、预览和导出。

测试边界情况：文件的开头和结尾、空行、嵌套结构、Unicode、未闭合的分隔符，以及不应匹配的文本。一个配置之所以可信，是因为它既能识别示例，也能拒绝近似但不符的内容。

在确认无误的修订之后，使用 **设为新基线**。**重置为基线** 会丢弃之后的试验。在冒险的重新设计之前，请先复制。

# Chapter 39: 编辑配置规则和高级 JSON

规则编辑器提供以下设置：模式类型、行首要求、产生的角色、捕获、按下换行后的续行、分隔块行为、布局、行内片段和成对符号、题注以及样式角色。

只要字面或结构化识别器能表达该语法，就请使用它们。让模式保持有界并加锚点。Pilcrow 会拒绝已知的不安全模式，但技术上被接受的表达式仍可能过于宽泛或令人困惑。

只有当可视化编辑器没有提供所需属性时，才选择 **编辑高级 JSON…**。**应用** 会验证 JSON，并阻止通过该面板更改配置的身份。进行高级操作时，请保留一份有效的测试示例。

继承适合用于小型方言：继承一个稳定的父配置，只替换指定的语法。避免过长的继承链，以免行为难以解释。如果导入配置时报告冲突，请在替换任何内容之前比较名称和 ID。
