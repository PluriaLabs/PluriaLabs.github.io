# Part XXI — Formaty plików i ograniczenia

# Chapter 79: Format motywu aplikacji

**Motyw aplikacji** stylizuje samego Pilcrow: jego jasny lub ciemny wygląd, kolor akcentu, pasek boczny, paski stanu i formatowania oraz edytor. Jest to plik JSON. Dokumenty renderowane (podgląd, HTML, PDF, obraz, druk i Word) są stylizowane osobno przez **motyw renderowania**, czyli CSS (rozdział 80). Oba rodzaje są instalowane, wybierane i usuwane oddzielnie i żaden nie podąża za drugim.

## Kompletny przykład

```json
{
  "pilcrowAppTheme": 1,
  "name": "Nord",
  "appearance": "dark",
  "colors": {
    "accent": "#88C0D0",
    "sidebar": { "background": "#2E3440", "foreground": "#D8DEE9" },
    "bars": { "background": "#3B4252", "foreground": "#D8DEE9" },
    "editor": {
      "background": "#2E3440",
      "foreground": "#ECEFF4",
      "cursor": "#88C0D0",
      "selection": "#434C5E",
      "gutterBackground": "#2E3440",
      "gutterForeground": "#4C566A"
    },
    "syntax": {
      "heading": "#88C0D0",
      "marker": "#EBCB8B",
      "code": "#A3BE8C",
      "link": "#81A1C1",
      "muted": "#7B88A1",
      "tokens": { "strong": "#D08770" }
    }
  }
}
```

## Najwyższy poziom

| Klucz | Wymagany | Wartość |
| --- | --- | --- |
| `pilcrowAppTheme` | tak | Wersja formatu, `1`. |
| `name` | tak | 1–200 znaków. Wyświetlana w Ustawieniach i w menu Motywy. |
| `appearance` | tak | `"light"`, `"dark"` lub `"automatic"`. |
| `colors` | motywy `light` i `dark` | Jedna paleta (poniżej). |
| `light`, `dark` | motywy `automatic` | Dwie palety: jedna używana w jasnym wyglądzie systemu, druga w ciemnym. |
| `id` | nie | Zapisywany przez Pilcrow na potrzeby własnej biblioteki. Ignorowany przy imporcie, który zawsze nadaje nowy identyfikator. |

`appearance` decyduje o wyglądzie **każdego** okna, także menu, Ustawień, arkuszy i selektorów. Motyw `light` lub `dark` go ustala; `automatic` podąża za systemem.

Motyw automatyczny musi ustawiać każdy kolor zarówno w `light`, jak i w `dark`, albo w żadnym z nich. Kolor ustawiony tylko dla jednego wyglądu zostałby inaczej narysowany w drugim.

## Paleta

Każdy klucz jest opcjonalny. Pominięty kolor zachowuje wbudowany wygląd Pilcrow, więc motyw może być tak mały jak jeden kolor akcentu.

| Klucz | Stylizuje |
| --- | --- |
| `accent` | Odcień w całej aplikacji: przyciski, zaznaczone segmenty, przełączniki, łącza, pierścienie fokusu i zaznaczony wiersz paska bocznego. Nieustawiony zachowuje akcent systemowy. |
| `sidebar.background`, `sidebar.foreground` | Pasek boczny Pliki, Konspekt i Znajdź. Etykiety drugorzędne są wyprowadzane z koloru pierwszego planu. |
| `bars.background`, `bars.foreground` | Pasek stanu, zadokowany pasek formatowania i powiadomienia o imporcie. Etykiety drugorzędne są wyprowadzane z koloru pierwszego planu. |
| `editor.background`, `editor.foreground` | Płótno edytora i tekst podstawowy. |
| `editor.cursor`, `editor.selection` | Punkt wstawiania i podświetlenie zaznaczenia. |
| `editor.gutterBackground`, `editor.gutterForeground` | Margines z numerami wierszy. Tło domyślnie pasuje do tła edytora. |
| `editor.currentLineRule` | Cienka linia pod wierszem, w którym znajduje się kursor, gdy włączone jest **Widok ▸ Linia bieżącego wiersza**. Domyślnie kolor tekstu edytora o niskiej intensywności. |
| `syntax.<group>` | Kolory składni na żywo według grup (poniżej). |
| `syntax.tokens.<raw>` | Jeden token według jego surowej wartości, nadpisujący jego grupę. |

### Grupy składni

| Grupa | Koloruje |
| --- | --- |
| `heading` | Nagłówki (znaczniki i tekst), znaczniki alertów, terminy definicji |
| `marker` | Wyróżnienie, pogrubienie, przekreślenie i inne ograniczniki śródwierszowe; znaczniki list i zadań |
| `code` | Kod w wierszu, bloki kodu ogrodzone i wcięte, wzory, bloki HTML |
| `link` | Etykiety i cele łączy oraz obrazów, autołącza |
| `muted` | Znaczniki cytatów blokowych, przerwy tematyczne, wiersze tabel, komentarze, atrybuty bloków |
| `codeKeyword`, `codeString`, `codeNumber`, `codeComment` | Podświetlony kod wewnątrz ogrodzenia |

Nieustawiona grupa przyjmuje wbudowany kolor dobrany do tła edytora: ciemniejsze tony na jasnym płótnie, jaśniejsze na ciemnym. Nazwy tokenów w `syntax.tokens` składają się z liter, cyfr, `_` i `-` i nie mogą powtarzać nazwy grupy (`syntax.heading` już obejmuje `heading`).

## Kolory

Każdy kolor to ciąg szesnastkowy: `#RGB`, `#RGBA`, `#RRGGBB` lub `#RRGGBBAA`, w sRGB. Pilcrow zapisuje je wielkimi literami.

## Walidacja

Pilcrow odrzuca plik zamiast ignorować jego część i wskazuje klucz z błędem, na przykład `colors.editor.cursor: must be a hex colour`. Odrzuca:

- brakującą lub inną wersję `pilcrowAppTheme`;
- nieznany klucz na dowolnym poziomie (zwykle literówkę);
- klucz palety niepasujący do wyglądu (`colors` w motywie automatycznym, `light` i `dark` w motywie jasnym lub ciemnym);
- kolor, który nie jest szesnastkowy;
- motyw automatyczny, którego palety `light` i `dark` ustawiają różne kolory.

## Czego motyw aplikacji nie zmienia

Pasek tytułu okna i pasek narzędzi (systemowe szkło, które przyjmuje tylko akcent), menu, Ustawienia, arkusze i selektory zachowują natywny wygląd, poza wyglądem i akcentem. Czcionki nie podlegają motywom: czcionkę i rozmiar edytora ustawia się w **Ustawienia ▸ Wygląd ▸ Rozmiar tekstu i czcionki**.

## Instalowanie i udostępnianie

- **Importuj** plik `.json` z **Ustawienia ▸ Biblioteka ▸ Motywy**, **Plik ▸ Importuj ▸ Motyw** na Macu lub **Ustawienia ▸ Biblioteka ▸ Importuj** na iPadzie. Przeciągnięcie pliku na Pilcrow też działa.
- Pakiet motywów `.zip` może zawierać motywy aplikacji obok motywów renderowania (rozdział 80).
- Przycisk udostępniania obok motywu zapisuje jego plik `.json` albo cały pakiet, jeśli motyw pochodzi z pakietu.

Pilcrow zawiera trzy motywy aplikacji: **Automatycznie**, **Jasny** i **Ciemny**. Ustawiają kolory edytora i składni, a elementy otoczenia zostawiają w ich wbudowanym wyglądzie.

# Chapter 80: Dokumentacja CSS motywu renderowania

**Motyw renderowania** to CSS. Stylizuje podgląd oraz wyjście HTML, PDF, obrazu i druku, a także style Worda wymienione na końcu tego rozdziału. Motyw renderowania może być pojedynczym plikiem `.css` albo częścią pakietu ZIP z lokalnymi zasobami. Profile składni określają, jak tekst źródłowy staje się dokumentem; motywy renderowania tylko stylizują wynik. CSS nigdy nie stylizuje aplikacji ani edytora; to zadanie motywu aplikacji (rozdział 79).

## Kaskada

Pilcrow stosuje style w tej kolejności:

1. strukturalny reset Pilcrow;
2. CSS wybranego motywu;
3. jednorazowy CSS z panelu eksportu (**Opcje zaawansowane ▸ Własny CSS**);
4. wymagane poprawki druku i renderowania.

Późniejsze reguły wygrywają zgodnie ze zwykłą kaskadą CSS. Skrypty JavaScript w motywach, zasoby zdalne, adresy URL `file:` i `@import` nie są obsługiwane.

## Zasoby

Pilcrow odczytuje CSS motywu standardowym tokenizerem CSS, więc sekwencje ucieczki są dekodowane przed jakimkolwiek sprawdzeniem: `u\72 l(…)` to `url()`, a `@im\70 ort` to `@import`. Sprawdzane jest każde miejsce, z którego przeglądarka mogłaby coś wczytać: `url(…)`, `url("…")`, `src("…")` oraz ciągi znaków wewnątrz `image-set()`. Każde z nich musi być jednym z:

- ścieżką względną w pakiecie (`fonts/Body.woff2`, `./paper.png`). `?query` lub `#fragment` jest dozwolone i ignorowane podczas wyszukiwania pliku;
- adresem `data:` typu PNG, JPEG, GIF, WebP, SVG (`image/svg+xml`), TTF, OTF, WOFF lub WOFF2;
- odwołaniem do fragmentu, takim jak `url(#shadow)`, które wskazuje element na stronie.

Wszystko ze schematem innym niż `data:` (`https:`, `file:`, `blob:`) lub zaczynające się od `//` jest odrzucane, podobnie jak ścieżka zaczynająca się od `/` lub zawierająca `..`.

## Właściwości renderowania

Wbudowany reset odczytuje te właściwości i dostarcza wartości zastępcze:

| Grupa | Właściwości |
| --- | --- |
| Kolor | `--pt-background`, `--pt-foreground`, `--pt-secondary-background`, `--pt-secondary-foreground`, `--pt-accent`, `--pt-link-color`, `--pt-border-color` |
| Kod | `--pt-code-background`, `--pt-code-foreground`, `--pt-code-keyword`, `--pt-code-string`, `--pt-code-number`, `--pt-code-comment` |
| Typografia | `--pt-body-font-family`, `--pt-mono-font-family`, `--pt-base-font-size`, `--pt-line-height` |
| Odstępy | `--pt-paragraph-spacing`, `--pt-blockquote-indent`, `--pt-list-indent`, `--pt-code-padding`, `--pt-heading-top`, `--pt-heading-bottom` |
| Tabele | `--pt-table-header-background`, `--pt-table-stripe-background` |
| Alerty | `--pt-admonition-note-color`, `--pt-admonition-tip-color`, `--pt-admonition-important-color`, `--pt-admonition-warning-color`, `--pt-admonition-caution-color` |

## Pakiety ZIP

Pakiet ZIP może zawierać razem motywy renderowania (`.css`) i motywy aplikacji (`.json`); każdy jest wymieniony w Ustawieniach z własnym rodzajem. ZIP z co najwyżej jednym plikiem CSS i co najwyżej jednym motywem aplikacji nie wymaga manifestu. Cokolwiek więcej wymaga `pilcrow-theme.json`, który wymienia każdy motyw w `variants[].file`. O rodzaju pliku decyduje jego rozszerzenie:

```json
{
  "id": "com.example.paper",
  "name": "Paper",
  "version": "1.0.0",
  "author": "Example Author",
  "license": "MIT",
  "cssAPIVersion": 1,
  "variants": [
    { "id": "app", "name": "Paper", "file": "Paper.json", "appearance": "automatic" },
    { "id": "light", "name": "Paper Light", "file": "Paper-Light.css", "appearance": "light" },
    { "id": "dark", "name": "Paper Dark", "file": "Paper-Dark.css", "appearance": "dark" }
  ]
}
```

Manifest opisuje pakiet i jego motywy. Nigdy nie zawiera wartości stylów: te są w plikach CSS i motywów aplikacji.

- `id` pakietu nazywa folder instalacji. Nie może zaczynać się od `.` ani mieć spacji na początku lub na końcu. Zainstalowanie pakietu, którego `id` jest już zainstalowane, zastępuje go.
- ZIP utworzony poleceniem **Kompresuj** w Finderze działa bez zmian. Pilcrow pomija `__MACOSX/`, `._*`, `.DS_Store` i `Thumbs.db`, a gdy wszystkie pliki znajdują się w jednym folderze najwyższego poziomu, ten folder jest traktowany jako katalog główny pakietu.
- Usunięcie jednego motywu usuwa go z pakietu i zachowuje pozostałe wraz ze wspólnymi zasobami. Usunięcie ostatniego motywu usuwa pakiet. Usunięty motyw, który był wybrany, przywraca wybór domyślny dla jego rodzaju: Automatycznie dla motywu aplikacji, Jasny dla motywu renderowania.
- CSS może odwoływać się do spakowanych plików PNG, JPEG, GIF, WebP, TTF, OTF, WOFF i WOFF2 za pomocą względnych ścieżek `url(...)`. Pilcrow weryfikuje ich sygnatury i osadza przywoływane zasoby jako adresy danych, dzięki czemu renderowanie i wyeksportowany HTML pozostają offline i samodzielne. Ścieżki w ZIP nie mogą wychodzić poza pakiet, kolidować wielkością liter ani wskazywać dowiązań. Rozmiar archiwum, liczba wpisów, rozmiar pojedynczego pliku i współczynnik kompresji są ograniczone.

## Word

Eksport do Worda używa wartości jasnego (bazowego) `:root` i odwzorowuje te właściwości semantyczne na nazwane style Worda: `--pt-foreground`, `--pt-background`, `--pt-accent`, `--pt-link-color`, `--pt-code-background`, `--pt-code-foreground`, `--pt-body-font-family`, `--pt-mono-font-family`, `--pt-base-font-size` i `--pt-line-height`. Selektory przeglądarki i reguły układu nie mają ogólnego odpowiednika w Wordzie. Podgląd oraz wyjście HTML, PDF i obrazu używają pełnego arkusza stylów; Word używa tego podzbioru, zachowując strukturę dokumentu, diagramy, obrazy wzorów, łącza i multimedia. Panel eksportu pokazuje to ograniczenie, ilekroć wybrany jest Word.

Pilcrow zawiera dwa motywy renderowania, **Jasny** i **Ciemny**, które są kompletnymi punktami wyjścia.
