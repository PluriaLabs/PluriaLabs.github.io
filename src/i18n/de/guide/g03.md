# Chapter 24: Wiederverwendbare Vorlagen mit Super Tab erstellen

Felder machen aus einer statischen Erweiterung ein geführtes Formular. Ein Feld kann einen Platzhalter, einen Standardwert oder eine Auswahlliste haben.

1. Erstellen Sie ein Makro für eine wiederkehrende Struktur.
2. Fügen Sie Felder in die Erweiterung ein, oder verwenden Sie **Einfügen ▸ Feld**, während Sie den Quelltext aufbauen.
3. Erweitern Sie das Makro.
4. Tippen Sie in das ausgewählte erste Feld.
5. Mit **Nächstes Feld** gehen Sie weiter und mit **Vorheriges Feld** zurück.
6. Wählen Sie bei einem Auswahlfeld einen Eintrag aus der Auswahlliste des Felds.

Gestalten Sie Felder in der Reihenfolge, in der man sie natürlicherweise beantwortet. Setzen Sie die letzte Einfügemarke dorthin, wo das freie Schreiben weitergehen soll. Halten Sie Standardwerte harmlos: Ein vergessenes Feld sollte in der Vorschau offensichtlich sein und nicht stillschweigend irreführende Inhalte veröffentlichen.

# Part VII — Mathematik, Diagramme, Datendiagramme und Bilder

# Chapter 25: Gleichungen, Diagramme und Datendiagramme schreiben

Pilcrow enthält ein Offline-Rendering für MathJax-Gleichungen, Mermaid-Diagramme und Vega-Lite-Datendiagramme. Das aktive Profil bestimmt weiterhin, wo der Block beginnt und endet; die mitgelieferte Bibliothek zeichnet nur seinen Inhalt.

## Mit einer Vorlage beginnen

1. Wählen Sie **Einfügen ▸ Gleichungen**, **Diagramme** oder **Datendiagramme**.
2. Wählen Sie eine Vorlage.
3. Ersetzen Sie den Beispielquelltext.
4. Wechseln Sie zu Vorschau oder Nebeneinander.
5. Korrigieren Sie jeden gemeldeten Syntaxfehler im Quellblock.

Verwenden Sie MathJax für mathematische Notation, Mermaid für Abläufe und Beziehungen und Vega-Lite für datengestützte Diagramme. Halten Sie in der Nähe jeder wichtigen Grafik eine textliche Erklärung bereit, damit das Dokument auch dann verständlich bleibt, wenn kein Renderer verfügbar ist, und für mehr Leserinnen und Leser zugänglich ist.

Die Bibliotheken sind mitgeliefert und laufen ohne Netzwerkzugriff. Einstellungen ▸ Bibliothek ▸ Rendering-Bibliotheken zeigt Versionen und Hinweise an. Wenn ein Block nicht dargestellt wird, prüfen Sie seine Sprachbezeichnung, die Begrenzer, die Einstellungen für optionale Funktionen und die Syntax, bevor Sie Themes ändern.

# Chapter 26: Bildeinfügung und Datenschutz bei Online-Bildern verwalten

Öffnen Sie **Einstellungen ▸ Bearbeitung ▸ Bilder** und legen Sie fest:

- Ob ein eingefügtes Bild kopiert, verschoben oder am Ort belassen wird.
- Ob die Regel für lokale und Online-Bilder gilt.
- Ob Online-Bilder geladen werden dürfen.
- Ob Pfade nach Möglichkeit relativ sein sollen.
- Ob relative Pfade mit `./` beginnen.
- Ob URLs beim Einfügen maskiert werden.

Für ein portables Projekt behalten Sie Bilder im Dokumentordner und verwenden relative Pfade. Kopieren ist sicherer als Verschieben, wenn das Original zu einem anderen Projekt gehört. Verschieben vermeidet Duplikate, kann aber den ursprünglichen Speicherort ungültig machen.

Online-Bilder geben die Netzwerkadresse der betrachtenden Person an deren Hosts preis und können sich ändern oder verschwinden. Lassen Sie das Laden aus dem Netzwerk beim Prüfen nicht vertrauenswürdiger Dokumente ausgeschaltet. Für eine dauerhafte Veröffentlichung laden Sie eine genehmigte Kopie herunter und verweisen lokal darauf.

# Part VIII — Veröffentlichen und teilen

# Chapter 27: HTML, PDF, Word und Bilder exportieren

1. Sichern Sie das Dokument und prüfen Sie die Vorschau.
2. Wählen Sie Exportieren in der Symbolleiste oder bei den Befehlen im Menü „Datei“.
3. Wählen Sie HTML, HTML (ohne Stile), PDF, Word, Bild oder PDF-Archiv.
4. Wählen Sie unter **Stil** das Render-Theme.
5. Prüfen Sie für PDF, PDF-Archiv und Word die **Seite**-Optionen: Papierformat, Ausrichtung und Ränder.
6. Wählen Sie **Exportieren** und ein Ziel, oder **Teilen**, um die erzeugte Datei direkt zu senden.

HTML erzeugt eine eigenständige formatierte Seite. **HTML (ohne Stile)** gibt eine saubere Struktur ohne eingebettetes Theme-CSS aus. Word erzeugt ein echtes `.docx`-Paket mit semantischer Dokumentstruktur; ergänzende Gleichungen, Diagramme und Datendiagramme werden zu Bildern. **Bild** erzeugt eine einzelne PNG-Datei des gerenderten Dokuments. **PDF-Archiv** erzeugt ein ZIP mit geordneten PDF-Segmenten und einem Manifest, was nützlich ist, wenn ein anderer Arbeitsablauf begrenzte, trennbare Segmente benötigt. Ein normales großes PDF wird automatisch über einen segmentierten Rendering-Pfad zusammengesetzt, während das PDF-Archiv die Segmente als Ergebnis bewahrt.

Öffnen Sie **Erweiterte Optionen**, um **Eigenes CSS** nur für diesen Export hinzuzufügen. CSS pro Export wird nach dem Theme angewendet und gewinnt daher bei gleicher Selektorgewichtung. Seitenänderungen betreffen nur den aktuellen Export, es sei denn, Sie wählen **Diese Seiteneinstellungen als Standard verwenden**. Ein erzeugtes Inhaltsverzeichnis, die Nummerierung und die Beschriftungen von Überschriften werden einmalig für alle Exporte unter **Einstellungen ▸ Inhaltsverzeichnis** festgelegt (Chapter 70).

Wenn die Ausgabe falsch ist, klären Sie, ob das Problem die Struktur oder den Stil betrifft. Eine fehlende Überschrift ist meist ein Problem von Profil oder Quelltext; eine unschöne Überschrift ist ein Problem des Render-Themes.

## Das gerenderte Dokument drucken

Wählen Sie **Drucken…** im Menü „Datei“ oder unter „Mehr“. Das Drucken nutzt dieselbe Rendering-Pipeline und dieselben Seitenlayout-Standards wie PDF; Vorschau und PDF-Export sind daher die richtigen Orte, um zuerst Struktur und Stil zu klären. Auf dem Mac bearbeitet die Seiteneinrichtung dasselbe gemeinsame Seitenlayout. Prüfen Sie Papier, Ausrichtung, Ränder, Kopf- und Fußzeilen im Druckdialog, bevor Sie physische Seiten ausgeben.

# Chapter 28: Export-Standards und Seitenelemente festlegen

Öffnen Sie **Einstellungen ▸ Export ▸ Export-Standards**. Wählen Sie das Standard-Render-Theme und das Seitenlayout. Konfigurieren Sie Autor-Metadaten, Kopf- und Fußzeilen und ob jede Überschrift der obersten Ebene auf einer neuen Seite beginnt (**Seitenumbruch zwischen Überschriften der obersten Ebene**).

Vorlagen für Kopf- und Fußzeilen können `${title}`, `${author}`, `${pageNo}`, `${pageCount}` und `${today}` enthalten. Halten Sie sie so kurz, dass sie in die Seitenränder passen. Testen Sie ein mehrseitiges PDF, denn eine Kopfzeile, die auf einer Seite gut aussieht, kann später mit langen Überschriften oder Seitenzahlen kollidieren. Diese Feinschliff-Werte werden pro Ausgabeformat gespeichert; das Seitenlayout wird von PDF, PDF-Archiv, Word und dem Drucken gemeinsam genutzt.

Die CommonMark-Optionen steuern optionale Syntax wie Hervorhebung, Tiefstellung, Hochstellung, Inline-Mathematik, automatische Links, Hinweisboxen, Front Matter, Diagramme, intelligente Zeichensetzung und die Darstellung von Codeblöcken. Aktivieren Sie nur die Funktionen, die Ihr Quelltext tatsächlich verwendet. Portable CommonMark-Dokumente sollten sich nicht auf Erweiterungen verlassen, ohne diese zu dokumentieren.

# Chapter 29: Quelltext und fertige Ausgabe teilen

Wählen Sie **Teilen …** für das Quelldokument, wenn eine andere Person die bearbeitbare Datei braucht. Ein sauberes, gesichertes Dokument wird direkt geteilt. Ein ungesichertes oder geändertes Dokument wird als temporäre Kopie seines aktuellen Texts geteilt; sehr große Dokumente müssen unter Umständen zuerst gesichert werden.

Wählen Sie **Teilen** im Export, wenn die Empfängerin oder der Empfänger ein fertiges PDF, Word-Dokument, eine HTML-Datei oder ein Bild braucht. Dabei wird die Ausgabe erzeugt, ohne dass Sie zuvor einen separaten gesicherten Export aufbewahren müssen.

Bevor Sie Quelltext teilen, legen Sie abhängige lokale Bilder, verlinkte Dokumente, Profile oder Themes bei, wenn die Empfängerin oder der Empfänger dasselbe Verhalten braucht. Bevor Sie fertige Ausgabe teilen, prüfen Sie Links, Vorschau, Seitenumbrüche, Alternativtexte und den Dateinamen.

# Part IX — Der Assistent

# Chapter 30: Einen KI-Anbieter sicher verbinden

Der Assistent ist optional und nutzt eine Verbindung, die Sie selbst einrichten. Pilcrow wählt nicht stillschweigend einen Anbieter.

1. Öffnen Sie **Einstellungen ▸ Allgemein ▸ Assistent**.
2. Fügen Sie eine Voreinstellung hinzu oder wählen Sie **Benutzerdefiniert …**.
3. Geben Sie einen Namen, die Basis-URL, das Übertragungsformat und das Modell ein.
4. Verlangt der Anbieter einen API-Schlüssel, aktivieren Sie diese Option und hinterlegen Sie den Schlüssel, wenn Sie dazu aufgefordert werden. Schlüssel werden im System-Schlüsselbund aufbewahrt.
5. Wählen Sie **Verbindung testen**.
6. Sichern Sie und machen Sie die Verbindung aktiv.

Verwenden Sie **Modell auswählen …** im Assistenten, wenn der Anbieter eine Modellerkennung bietet. Verschwindet ein Modell, wählen Sie ein aktuelles, statt wiederholt eine veraltete Kennung zu versuchen.

Vor der ersten Verwendung einer Verbindung zeigt Pilcrow, wohin Text gesendet wird, und bittet um Einwilligung. Lesen Sie den Hostnamen. Ein lokaler Server und ein öffentlicher Cloud-Anbieter haben unterschiedliche Folgen für den Datenschutz, auch wenn sie dasselbe API-Format anbieten.

# Chapter 31: Fragen mit bewusst gewähltem Kontext stellen

Öffnen Sie die Assistent-Seitenleiste und wählen Sie den Gesprächsmodus. Der Kontext-Chip beginnt mit dem kleinsten nützlichen Umfang, normalerweise der Auswahl. Wählen Sie einen anderen Umfang nur, wenn die Frage es erfordert.

1. Wählen Sie den Absatz aus, bei dem Sie Hilfe wünschen.
2. Prüfen Sie, dass im Chip „Auswahl“ steht, und sehen Sie sich die Zusammenfassung an.
3. Stellen Sie eine konkrete Frage, etwa „Welcher Satz macht die Chronologie unklar?“
4. Lesen Sie die Antwort als Rat, nicht als automatische Änderung.
5. Übernehmen Sie Änderungen selbst oder über eine angebotene, geprüfte Aktion.

Pilcrow schließt konfigurierte Muster und Ordner vom Assistentenkontext aus. Verwalten Sie sie in den Assistent-Einstellungen. Mit der Ordner-Schaltfläche schalten Sie den Assistentenzugriff für einen sensiblen Arbeitsbereich aus. Leeren Sie die Unterhaltung mit der Papierkorb-Schaltfläche, wenn sie nicht mehr zur aktuellen Aufgabe gehört.

Teilen Sie niemals einen ganzen Ordner, nur weil eine Frage eine Datei erwähnt. Der minimal nötige Kontext verbessert den Datenschutz und oft auch die Qualität der Antwort.

# Chapter 32: Hilfe beim Erstellen von Pilcrow-Ressourcen erhalten

Schalten Sie den Assistenten auf **Hilfe** und wählen Sie Profil, Makro oder Stilleitfaden. Pilcrow fügt der Unterhaltung die passende Formatreferenz bei, damit Folgeanweisungen fundiert bleiben.

Beschreiben Sie das gewünschte Verhalten und geben Sie ein kleines Beispiel an. Bitten Sie um einen Entwurf, prüfen Sie den erzeugten Ressourcentext in der Vorschau und validieren Sie ihn dann im passenden Einstellungseditor. Importieren oder sichern Sie kein undurchsichtiges, generiertes JSON, ohne seinen Namen, die Auslöser oder Muster und die Ausgaben gelesen zu haben.

Ein bewährter Ablauf ist:

1. Nennen Sie ein Verhalten und zwei Beispiele.
2. Bitten Sie um die kleinste gültige Ressource.
3. Validieren Sie sie in Pilcrow.
4. Testen Sie einen Treffer und einen Nicht-Treffer.
5. Geben Sie den Validierungsfehler für eine gezielte Korrektur zurück.

# Chapter 33: Eine KI-gestützte Stilprüfung durchführen

Dieser Ablauf erweitert Chapter 21:

1. Wählen Sie für den ersten Versuch eine Textstelle aus.
2. Wählen Sie Stilprüfung, einen Leitfaden, eine Variante und Prüfbereiche.
3. Bestätigen Sie den aktiven Anbieter und das Modell.
4. Starten Sie die Prüfung.
5. Sortieren Sie die Befunde nach Schweregrad oder Bereich, wie angeboten.
6. Öffnen Sie einen Befund, lesen Sie den zitierten Beleg und sehen Sie sich die Fundstelle im Quelltext an.
7. Übernehmen Sie ihn, verwerfen Sie ihn oder lassen Sie ihn ungelöst.

Bei einem ganzen Dokument schätzt Pilcrow die Bytes und die Anzahl der Anfragen und fragt vor dem Senden noch einmal nach. Sie können zwischen den Abschnitten anhalten. Prüfen Sie sensible Dokumente lokal oder bei einem Anbieter, dessen Bedingungen zur Datenverarbeitung Sie akzeptieren. Löschen Sie KI-Daten und Schlüssel in den Einstellungen für Assistent oder Speicher und Datenschutz, wenn Sie eine Verbindung außer Betrieb nehmen.

# Part X — Buchprojekte

# Chapter 34: Einen Ordner in ein Buchprojekt verwandeln

Für ein neues Projekt wählen Sie **Datei ▸ Neues Buch …**, geben Titel und Zielort ein und lassen Pilcrow den Anfangsordner und das Manifest erstellen. Um ein vorhandenes Manuskript zu übernehmen, öffnen Sie seinen Ordner, wählen **Datei ▸ Ordner zum Buchprojekt machen** oder in der Projekt-Seitenleiste **Zum Projekt machen** und vervollständigen die Metadaten. Pilcrow erstellt eine Datei `manifest.pilcrow`, die Reihenfolge und Metadaten beschreibt; die Manuskriptdateien werden dabei nicht umgeordnet.

Öffnen Sie die Projekteinstellungen und geben Sie Titel, Autor, Zielwortzahl, Variablen, das Verhalten der Wortzählung und die Syntax an. Fügen Sie vorhandene Dateien hinzu, die als **Nicht im Manuskript** aufgeführt sind, oder erstellen Sie über das Plus-Menü neue Vorspannteile, Kapitel, Szenen und Nachspannteile.

Committen oder sichern Sie `manifest.pilcrow` zusammen mit dem Manuskript. Es ist das Inhaltsverzeichnis für die Projektorganisation, auch wenn die Quelldateien gewöhnlicher Text bleiben.

# Chapter 35: Szenen planen und den Manuskriptfortschritt verfolgen

Wählen Sie zwischen **Liste**, **Exposés** und **Karten**:

- Liste betont die Reihenfolge im Manuskript und die Wortzahlen.
- Exposés ergänzt Zusammenfassung, Erzählperspektive, Ort, Status und Fortschritt.
- Karten bietet eine visuelle Planungstafel, ohne die Reihenfolge der Dateien zu ändern.

Öffnen Sie die Details eines Eintrags, um Rolle, Status, Exposé, Erzählperspektive, Ort und Zielwörter festzulegen. Filtern Sie nach Status, um sich auf Entwurf, Überarbeitung oder abgeschlossene Arbeit zu konzentrieren. Entfernen Sie einen Eintrag aus dem Manuskript, ohne seine Datei zu löschen, wenn es sich um Recherchematerial oder eine gestrichene Szene handelt.

Ordnen Sie nur neu an, solange kein Statusfilter aktiv ist; eine gefilterte Teilmenge kann die vollständige Manuskriptreihenfolge nicht sicher abbilden. Wählen Sie auf dem iPad **Neu anordnen**, ziehen Sie und wählen Sie dann **Fertig**. Klappen Sie Kapitel zu, um die Liste übersichtlicher zu machen.

Meldet Pilcrow, dass sich die Projektdatei auf dem Datenträger geändert hat, laden Sie neu und wiederholen Sie die beabsichtigte Aktion. Dieser Konfliktschutz verhindert, dass ein Gerät oder eine mitarbeitende Person ein neueres Manifest überschreibt.

# Chapter 36: Ein Manuskript kompilieren

1. Öffnen Sie die Projekt-Seitenleiste.
2. Prüfen Sie Reihenfolge, einbezogene Dateien und Projektmetadaten.
3. Wählen Sie **Kompilieren …**.
4. Wählen Sie Ausgabeformat, Render-Theme und Kompilierungsoptionen.
5. Prüfen Sie Vorspann, Kapitelumbrüche, Nummerierung und einbezogene Rollen.
6. Kompilieren Sie und prüfen Sie das Ergebnis.

Die Kompilierung kann HTML, PDF oder Word erzeugen. Legen Sie fest, welche Vorspannteile, Teile, Kapitel und Nachspannteile auf einer neuen Seite beginnen, stellen Sie das Trennzeichen zwischen Szenen ein, nehmen Sie ein Inhaltsverzeichnis auf, nummerieren Sie Überschriften und behalten Sie optional zuvor einen Versionsverlauf-Schnappschuss jeder einbezogenen Datei. Die Manuskript-Zusammenfassung zeigt einbezogene Dateien, Bytes, ausgelassene Dateien, fehlende Pfade und die endgültige Reihenfolge. Fehlende Dateien müssen geklärt werden, bevor Kompilieren verfügbar wird.

Sichern Sie eine Gruppe von Kompilierungsentscheidungen als benannte Voreinstellung, wenn Sie dasselbe Manuskript auf mehrere Arten veröffentlichen, zum Beispiel „Lektorat DOCX“ und „Druck-PDF“. Löschen Sie eine veraltete Voreinstellung im selben Dialog. Während die Kompilierung läuft, zeigt der Fortschritt die Dateianzahl an, und **Stopp** bricht den Vorgang ab. Nicht aufgelöste `{{variables}}` werden gemeldet und sichtbar unverändert belassen.

Die Kompilierung liest die Manifestreihenfolge und kombiniert den Quelltext logisch; sie hängt Ihre Dateien nicht aneinander und überschreibt sie nicht. Korrigieren Sie eine Szene in ihrer Quelldatei und kompilieren Sie dann erneut. Verwenden Sie Projektvariablen für wiederkehrende Metadaten, statt Titel- oder Autorentexte manuell zu duplizieren.

# Part XI — Syntaxprofile

# Chapter 37: Ein Syntaxprofil wählen und verstehen

Ein Profil sagt Pilcrow, wie Quelltextzeichen zu strukturellen Rollen werden. CommonMark ist mitgeliefert, aber nur ein Profil und nicht die Definition der App.

Verwenden Sie das Profilsteuerelement in der Statusleiste oder ein passendes Dokumentsteuerelement, um ein Profil zu wählen. Pilcrow kann eines aus einer Dateiendung ableiten und eine Auswahl pro Datei merken. Das aktive Profil steuert Hervorhebung, Gliederung, die Verfügbarkeit der Formatierung, Vorschau, Exportstruktur, Fortsetzungsverhalten und profilspezifische Einfügungen.

Wählen Sie ein Profil anhand der Quelltextsprache, die bereits vorhanden ist. Das Wechseln des Profils konvertiert keinen Text, sondern interpretiert ihn neu. Wenn Sie eine Konvertierung brauchen, erstellen Sie eine Kopie und wandeln Sie den Quelltext ausdrücklich um.

# Chapter 38: Ein Profil erstellen und testen

1. Öffnen Sie **Einstellungen ▸ Bibliothek ▸ Syntaxprofile**.
2. Duplizieren Sie ein ähnliches integriertes Profil oder erstellen Sie ein neues.
3. Legen Sie unter **Überblick** Name, Bezeichner, Dateiendungen und optionale Vererbung fest.
4. Fügen Sie unter **Regeln** das kleinste Konstrukt hinzu, das Sie brauchen.
5. Öffnen Sie **Testbeispiel**, fügen Sie repräsentativen Quelltext ein und wählen Sie **Beispiel prüfen**.
6. Sichern Sie, aktivieren Sie das Profil in einem Wegwerfdokument und vergleichen Sie Bearbeiten, Gliederung, Vorschau und Export.

Testen Sie Grenzfälle: Anfang und Ende der Datei, Leerzeilen, verschachtelte Konstrukte, Unicode, einen nicht geschlossenen Begrenzer und Text, der nicht passen sollte. Ein Profil ist vertrauenswürdig, wenn es knappe Fehlschläge ablehnt und Beispiele erkennt.

Verwenden Sie **Als neuen Basiszustand festlegen** nach einer bewährten Fassung. **Auf Basiszustand zurücksetzen** verwirft spätere Experimente. Duplizieren Sie vor einem riskanten Umbau.

# Chapter 39: Profilregeln und erweitertes JSON bearbeiten

Der Regeleditor bietet Mustertyp, Zeilenanfang-Anforderungen, erzeugte Rolle, Erfassungen, Fortsetzung nach Return, Verhalten begrenzter Blöcke, Layout, Inline-Abschnitte und -Paare, Beschriftungen und Gestaltungsrollen.

Verwenden Sie wörtliche oder strukturierte Erkenner, wann immer sie die Syntax ausdrücken. Halten Sie Muster begrenzt und verankert. Pilcrow lehnt bekannte unsichere Muster ab, aber ein technisch akzeptierter Ausdruck kann trotzdem zu breit oder verwirrend sein.

Wählen Sie **Erweitertes JSON bearbeiten …** nur, wenn der visuelle Editor die benötigte Eigenschaft nicht anbietet. Anwenden validiert das JSON und verhindert, dass über diesen Dialog die Identität des Profils geändert wird. Behalten Sie bei fortgeschrittener Arbeit ein gültiges Testbeispiel bereit.

Vererbung ist für einen kleinen Dialekt nützlich: Erben Sie von einem stabilen Elternprofil und ersetzen Sie nur die genannte Syntax. Vermeiden Sie eine lange Kette, die das Verhalten schwer erklärbar macht. Meldet der Import eines Profils einen Konflikt, vergleichen Sie Namen und IDs, bevor Sie etwas ersetzen.
