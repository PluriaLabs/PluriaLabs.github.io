# Part XXI — ファイル形式と制限

# Chapter 79: アプリケーションテーマの形式

**アプリケーションテーマ** は、Pilcrow 自体のスタイルを設定します。ライトまたはダークの外観、アクセントカラー、サイドバー、ステータスバーと書式バー、エディタが対象です。JSON ファイルで記述します。レンダリングされた書類（プレビュー、HTML、PDF、画像、プリント、Word）のスタイルは、CSS で記述する **レンダリングテーマ** が別に設定します（Chapter 80）。2種類のテーマは、インストール、選択、削除がそれぞれ別で、どちらも他方には連動しません。

## 完全な例

```json
{
  "pilcrowAppTheme": 1,
  "name": "Nord",
  "appearance": "dark",
  "colors": {
    "accent": "#88C0D0",
    "sidebar": { "background": "#2E3440", "foreground": "#D8DEE9" },
    "bars": { "background": "#3B4252", "foreground": "#D8DEE9" },
    "editor": {
      "background": "#2E3440",
      "foreground": "#ECEFF4",
      "cursor": "#88C0D0",
      "selection": "#434C5E",
      "gutterBackground": "#2E3440",
      "gutterForeground": "#4C566A"
    },
    "syntax": {
      "heading": "#88C0D0",
      "marker": "#EBCB8B",
      "code": "#A3BE8C",
      "link": "#81A1C1",
      "muted": "#7B88A1",
      "tokens": { "strong": "#D08770" }
    }
  }
}
```

## トップレベル

| キー | 必須 | 値 |
| --- | --- | --- |
| `pilcrowAppTheme` | はい | 形式のバージョンで、`1` です。 |
| `name` | はい | 1～200文字。設定とテーマメニューに表示されます。 |
| `appearance` | はい | `"light"`、`"dark"`、`"automatic"` のいずれかです。 |
| `colors` | `light` と `dark` のテーマ | 1つのパレット（後述）。 |
| `light`、`dark` | `automatic` のテーマ | 2つのパレット：システムのライトの外観で使うものと、ダークで使うものです。 |
| `id` | いいえ | Pilcrow が自身のライブラリのために書き込みます。読み込み時は無視され、常に新しい ID が割り当てられます。 |

`appearance` は、メニュー、設定、シート、ピッカーを含む、**すべての** ウインドウの外観を決めます。`light` または `dark` のテーマは外観を固定し、`automatic` はシステムに従います。

automatic テーマでは、各配色を `light` と `dark` の両方で設定するか、どちらにも設定しないかのいずれかにする必要があります。片方の外観だけに設定した配色は、もう片方の外観でも使われてしまうためです。

## パレット

すべてのキーは省略できます。省略した配色には Pilcrow の内蔵の見た目が使われるため、テーマはアクセントカラー1色だけでも成り立ちます。

| キー | 対象 |
| --- | --- |
| `accent` | アプリ全体の色合い：ボタン、選択中のセグメント、トグル、リンク、フォーカスリング、サイドバーの選択中の行。未設定の場合はシステムのアクセントが使われます。 |
| `sidebar.background`、`sidebar.foreground` | ファイル、アウトライン、検索のサイドバー。副次的なラベルは前景色から導かれます。 |
| `bars.background`、`bars.foreground` | ステータスバー、ドッキングされた書式ツールバー、読み込みの通知。副次的なラベルは前景色から導かれます。 |
| `editor.background`、`editor.foreground` | エディタのキャンバスと本文のテキスト。 |
| `editor.cursor`、`editor.selection` | 挿入ポイントと選択範囲のハイライト。 |
| `editor.gutterBackground`、`editor.gutterForeground` | 行番号のガター。背景のデフォルトはエディタの背景です。 |
| `editor.currentLineRule` | **表示 ▸ 現在の行の罫線** がオンのときに、カーソルがある行の下に引かれる細い罫線。デフォルトは、エディタのテキスト色を薄くしたものです。 |
| `syntax.<group>` | グループ別のライブ構文カラー（後述）。 |
| `syntax.tokens.<raw>` | 生の値で指定する1つのトークン。そのグループの設定より優先されます。 |

### 構文グループ

| グループ | 色を付ける対象 |
| --- | --- |
| `heading` | 見出し（記号とテキスト）、注意の記号、定義の用語 |
| `marker` | 強調、太字、取り消し線などのインライン区切り文字、リストとタスクの記号 |
| `code` | インラインコード、フェンス付きおよびインデントのコードブロック、数式、HTML ブロック |
| `link` | リンクと画像のラベルおよび宛先、自動リンク |
| `muted` | 引用の記号、テーマの区切り、表の行、コメント、ブロック属性 |
| `codeKeyword`、`codeString`、`codeNumber`、`codeComment` | フェンス内のハイライトされたコード |

設定しなかったグループには、エディタの背景に合わせて選ばれた内蔵の色が使われます。明るいキャンバスでは暗めの色調、暗いキャンバスでは明るめの色調です。`syntax.tokens` のトークン名には、英字、数字、`_`、`-` を使えます。グループ名と同じ名前は使えません（`heading` は `syntax.heading` で既に指定できます）。

## 色

すべての色は16進文字列で、`#RGB`、`#RGBA`、`#RRGGBB`、`#RRGGBBAA` のいずれかの形式で、sRGB で指定します。Pilcrow は大文字で保存します。

## 検証

Pilcrow はファイルの一部を無視せず、ファイル全体を拒否し、問題のあるキーを示します。たとえば `colors.editor.cursor: must be a hex colour` のようになります。次のものは拒否されます。

- `pilcrowAppTheme` のバージョンがない、または異なる
- どの階層でも未知のキー（たいていは入力ミスです）
- 外観に合わないパレットキー（automatic テーマの `colors`、light または dark テーマの `light` と `dark`）
- 16進ではない色
- `light` と `dark` のパレットで設定されている色が異なる automatic テーマ

## アプリケーションテーマで変更されないもの

ウインドウのタイトルバーとツールバー（システムのガラス素材で、アクセントだけが反映されます）、メニュー、設定、シート、ピッカーは、外観とアクセントを除いて、ネイティブの見た目のままです。フォントはテーマの対象外です。エディタのフォントとサイズは、**設定 ▸ 外観 ▸ 文字サイズとフォント** で設定します。

## インストールと共有

- `.json` ファイルは、**設定 ▸ ライブラリ ▸ テーマ**、Mac では **ファイル ▸ 読み込む ▸ テーマ**、iPad では **設定 ▸ ライブラリ ▸ 読み込む** から **読み込む** ことができます。ファイルを Pilcrow にドロップしても読み込めます。
- `.zip` のテーマパッケージには、レンダリングテーマと一緒にアプリケーションテーマを含めることができます（Chapter 80）。
- テーマの横にある共有ボタンで、その `.json` ファイルを保存できます。テーマがパッケージに含まれていた場合は、パッケージ全体が保存されます。

Pilcrow には、**自動**、**ライト**、**ダーク** の3つのアプリケーションテーマが含まれています。これらはエディタと構文の配色を設定し、クロムは内蔵の見た目のままにします。

# Chapter 80: レンダリングテーマ CSS リファレンス

**レンダリングテーマ** は CSS です。プレビュー、HTML、PDF、画像、プリントの出力と、この章の最後に挙げる Word のスタイルを設定します。レンダリングテーマは、1つの `.css` ファイルでも、ローカルアセットを含む ZIP パッケージの一部でもかまいません。構文プロファイルは、ソーステキストがどのように書類になるかを定め、レンダリングテーマはその結果のスタイルだけを設定します。CSS がアプリやエディタのスタイルを設定することはありません。それはアプリケーションテーマの役割です（Chapter 79）。

## カスケード

Pilcrow は、次の順序でスタイルを適用します。

1. Pilcrow の構造的なリセット
2. 選択したテーマの CSS
3. 書き出しパネルからの一度限りの CSS（**詳細オプション ▸ カスタム CSS**）
4. 必要なプリントとレンダリングの補正

後のルールは、通常の CSS カスケードに従って優先されます。テーマの JavaScript、リモートリソース、`file:` URL、`@import` はサポートされていません。

## リソース

Pilcrow は、標準の CSS トークナイザでテーマの CSS を読み込むため、エスケープは何かを検査する前にデコードされます。`u\72 l(…)` は `url()` に、`@im\70 ort` は `@import` になります。ブラウザが読み込みを行うすべての場所が検査されます。`url(…)`、`url("…")`、`src("…")`、`image-set()` 内の文字列です。それぞれ次のいずれかでなければなりません。

- パッケージ相対パス（`fonts/Body.woff2`、`./paper.png`）。`?query` や `#fragment` は使用でき、ファイルを探すときには無視されます
- PNG、JPEG、GIF、WebP、SVG（`image/svg+xml`）、TTF、OTF、WOFF、WOFF2 のいずれかの種類の `data:` URL
- `url(#shadow)` のようなフラグメント参照。ページ内の要素を指します

`data:` 以外のスキーム（`https:`、`file:`、`blob:`）を持つもの、または `//` で始まるものは拒否されます。`/` で始まるパスや `..` を含むパスも同様です。

## レンダリングプロパティ

内蔵のリセットは、次のプロパティを読み取り、フォールバックを提供します。

| グループ | プロパティ |
| --- | --- |
| 色 | `--pt-background`、`--pt-foreground`、`--pt-secondary-background`、`--pt-secondary-foreground`、`--pt-accent`、`--pt-link-color`、`--pt-border-color` |
| コード | `--pt-code-background`、`--pt-code-foreground`、`--pt-code-keyword`、`--pt-code-string`、`--pt-code-number`、`--pt-code-comment` |
| 書体 | `--pt-body-font-family`、`--pt-mono-font-family`、`--pt-base-font-size`、`--pt-line-height` |
| 間隔 | `--pt-paragraph-spacing`、`--pt-blockquote-indent`、`--pt-list-indent`、`--pt-code-padding`、`--pt-heading-top`、`--pt-heading-bottom` |
| 表 | `--pt-table-header-background`、`--pt-table-stripe-background` |
| 注意 | `--pt-admonition-note-color`、`--pt-admonition-tip-color`、`--pt-admonition-important-color`、`--pt-admonition-warning-color`、`--pt-admonition-caution-color` |

## ZIP パッケージ

ZIP パッケージには、レンダリングテーマ（`.css`）とアプリケーションテーマ（`.json`）を一緒に含めることができ、それぞれ設定で自身の種類とともに一覧表示されます。CSS ファイルが1つ以下、アプリケーションテーマが1つ以下の ZIP には、マニフェストは不要です。それ以上ある場合は `pilcrow-theme.json` が必要で、すべてのテーマを `variants[].file` に列挙します。ファイルの拡張子で種類が決まります。

```json
{
  "id": "com.example.paper",
  "name": "Paper",
  "version": "1.0.0",
  "author": "Example Author",
  "license": "MIT",
  "cssAPIVersion": 1,
  "variants": [
    { "id": "app", "name": "Paper", "file": "Paper.json", "appearance": "automatic" },
    { "id": "light", "name": "Paper Light", "file": "Paper-Light.css", "appearance": "light" },
    { "id": "dark", "name": "Paper Dark", "file": "Paper-Dark.css", "appearance": "dark" }
  ]
}
```

マニフェストは、パッケージとそのテーマを記述するものです。スタイルの値は含みません。それらは CSS とアプリケーションテーマのファイルにあります。

- パッケージの `id` は、インストール先のフォルダ名になります。`.` で始まってはならず、先頭や末尾にスペースを入れることもできません。すでにインストールされている `id` のパッケージをインストールすると、置き換えられます。
- Finder の **圧縮** で作った ZIP は、そのまま使えます。Pilcrow は `__MACOSX/`、`._*`、`.DS_Store`、`Thumbs.db` をスキップし、すべてのファイルが1つの最上位フォルダの中にある場合は、そのフォルダをパッケージのルートとして扱います。
- テーマを1つ削除すると、そのテーマだけがパッケージから取り除かれ、ほかのテーマと共有アセットは残ります。最後のテーマを削除すると、パッケージが削除されます。選択中のテーマを削除した場合、その種類のデフォルトに戻ります。アプリケーションテーマでは自動、レンダリングテーマではライトです。
- CSS は、相対 `url(...)` パスで、パッケージ内の PNG、JPEG、GIF、WebP、TTF、OTF、WOFF、WOFF2 ファイルを参照できます。Pilcrow は署名を検証し、参照されたアセットをデータ URL として埋め込むため、レンダリングと書き出した HTML はオフラインで完結します。ZIP 内のパスは、パッケージの外に出たり、大文字と小文字の違いだけで衝突したり、リンクを指したりすることはできません。アーカイブのサイズ、エントリ数、個々のサイズ、圧縮率には上限があります。

## Word

Word への書き出しでは、ライト（ベース）の `:root` の値を使い、次の意味的なプロパティを名前付きの Word スタイルに対応させます。`--pt-foreground`、`--pt-background`、`--pt-accent`、`--pt-link-color`、`--pt-code-background`、`--pt-code-foreground`、`--pt-body-font-family`、`--pt-mono-font-family`、`--pt-base-font-size`、`--pt-line-height` です。ブラウザ向けのセレクタとレイアウトのルールには、一般的に Word での対応するものがありません。プレビュー、HTML、PDF、画像の出力ではスタイルシート全体が使われますが、Word ではこのサブセットを使い、書類の構造、ダイアグラム、数式の画像、リンク、メディアは維持されます。書き出しパネルでは、Word を選択している間、この制限が表示されます。

Pilcrow には、**ライト** と **ダーク** の2つのレンダリングテーマが含まれており、どちらも完全な出発点として使えます。
