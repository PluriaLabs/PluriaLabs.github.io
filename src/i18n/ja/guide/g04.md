# Part XII — テーマと外観

# Chapter 40: アプリケーションテーマとレンダリングテーマを理解する

Pilcrow には、2 つの独立したテーマの仕組みがあります。

- **アプリケーションテーマ** は JSON で、アプリ、バー、サイドバー、アクセント、エディタの色、ライトまたはダークの外観を設定します。
- **レンダリングテーマ** は CSS で、プレビュー、HTML、PDF、そして Word で使われる意味的なサブセットのスタイルを設定します。

どちらも **表示 ▸ テーマ** または設定で選びます。アプリケーションテーマと競合するような独立したモード切り替えはありません。外観はテーマが宣言します。CSS がアプリやソースエディタのスタイルを設定することはありません。

エディタの見た目がおかしいときは、アプリケーションテーマを変更します。プレビューや書き出しの見た目がおかしいときは、レンダリングテーマを変更します。この区別だけで、テーマに関する混乱のほとんどが解決します。

# Chapter 41: テーマを作成して管理する

**設定 ▸ ライブラリ ▸ テーマ** を開きます。アプリケーションまたはレンダリングのコレクションを選び、ユーザーテーマを複製、読み込み、書き出し、編集、削除します。

アプリケーションテーマでは、エディタを使って、外観、アクセント、クローム、サイドバー、バー、エディタの色を設定します。選択範囲のコントラスト、現在行の見やすさ、リンク、警告、そして有効なコントロールと無効なコントロールの両方を確認してください。

レンダリングテーマでは、Pilcrow のクラス API に合わせて CSS を編集します。まずタイポグラフィと間隔を変更し、続いて見出し、リスト、コード、表、コールアウト、リンク、脚注、補助的なブロックの順に進めます。プロジェクトのチェックアウトから作業している場合は、`Examples/Themes/VisualTestPack` にあるビジュアルのサンプルでテストしてください。

内蔵テーマは、安定した出発点です。上書きしようとせず、複製してください。ZIP パッケージには両方の種類のテーマを入れることができ、ファイルの拡張子によって各項目の振り分け先が決まります。

# Chapter 42: フォント、サイズ、間隔、背景を選ぶ

エディタとガターのフォント、ポイントサイズ、行間、タブ幅には、**設定 ▸ 外観 ▸ 文字サイズとフォント** を使います。これらの設定が影響するのは書き込み画面であり、書き出されるタイポグラフィではありません。

アプリケーションテーマ、ズーム、読み上げ速度、テキストエリアやサイドバーの背後に表示する画像の設定には、**テーマと背景** を使います。背景は、それぞれ別々に選択、置き換え、削除できます。背景は、コントラストと集中しやすさを損なわないものにしてください。美しくても読みにくくなる画像は、エディタの設定としては不適切です。

公開用のフォントとページレイアウトには、レンダリングテーマと書き出しの既定値を使います。この分離により、読みやすい等幅のエディタで書きながら、プロポーショナルな書籍用書体で公開できます。

# Part XIII — ライブラリの読み込み、書き出し、管理

# Chapter 43: Pilcrow のリソースを読み込んで共有する

Pilcrow は、構文プロファイル、アプリケーションテーマ、レンダリングテーマ、マクロコレクション、スタイルガイド、そして対応するリソースを含む ZIP パッケージを読み込めます。

1. 該当するライブラリの設定ページ（iOS では読み込みページ）を開きます。
2. 読み込みを選び、ファイルを選択します。
3. リソースの種類、名前、競合があればその内容を確認します。
4. 結果を理解したうえでのみ、読み込み、名前の変更、置き換えを行います。
5. 使い捨てのドキュメントで有効にして、テストします。

ユーザーリソースを共有またはバックアップするには、ライブラリのページから書き出します。プロジェクトにプロファイル、テーマ、マクロ、ガイドがまとめて必要な場合は、関連するリソースを ZIP にまとめておきます。

読み込んだプロファイル、マクロ、CSS、スタイルガイドは、コードに近い設定として扱ってください。信頼する前に、トリガ、パターン、生の CSS、アシスタントへの指示を読んでください。

# Chapter 44: ライブラリを移動または復元する

**設定 ▸ ライブラリ ▸ 場所** を開きます。フォルダを選ぶか、**このデバイスを使用** を選びます。移動先にすでにライブラリがある場合は、次の中から選びます。

- **既存のものを使用** は、コピーせずに切り替えます。
- **ライブラリをここに移動** は、転送し、成功後に古い管理対象のコピーを削除します。
- **ライブラリをここにコピー** は、両方を残します。

同期フォルダを使うのは、そのプロバイダが通常のファイルを確実に保持し、同時編集について理解している場合に限ってください。転送は、終了するまで待ってから終了してください。場所が使えなくなった場合は、ドライブまたはアカウントを再接続するか、別の場所を選びます。競合する代わりのリソースを、よく考えずに作成しないでください。

iOS では、読み込みページでパッケージからライブラリの内容を復元できます。復元後は、有効なテーマとプロファイルを確認してください。参照を決めるのは表示名だけでなく、リソース ID だからです。

# Part XIV — 設定、プライバシー、サポート

# Chapter 45: 一般、ファイル、編集の設定を行う

設定はグループ分けされており、検索もできます。「行番号」「画像」「ヘッダ」のようなラベルは、検索フィールドで探してください。

## 一般

ウインドウと起動時の動作、言語、翻訳、アシスタントの接続、診断、ストレージとプライバシーを設定します。

## ファイル

起動時のフォルダの動作、デフォルトのファイルタイプ、自動保存と復元、保持するバージョン数、ファイルツリーの動作、読み込み可能な項目をアプリにドロップしたときの動作を選びます。

## 編集 — 表示と入力

行番号、ステータスバー、書式ツールバー、折り返し、現在行の罫線、スタイル付きソース、マーカー、レンダリングされたブロック、見出しの折りたたみ、自動展開、括弧と引用符のペア入力、Markdown のペア入力、絵文字ショートコード、リストと引用の継続、Return 時のインデント、Tab でのスペース入力、スペルチェック、解析の警告を設定します。

## 編集 — 入力サウンド

**入力中にサウンドを鳴らす** をオンにすると、入力に合わせて音が鳴ります。パック（タイプライター、アヒル、子猫）を選び、音量を設定し、**プレビュー** で音を確かめます。キーの種類ごとに別々の音が鳴ります。小文字、大文字、数字、記号、スペース、Tab、Return、Delete です。ペーストや複数文字の編集では音は鳴りません。

**自分のサウンド** では、キーの種類の横にある **選択…** を選ぶと、そのキーに自分のオーディオファイル（WAV、AIFF、MP3、M4A、CAF）を使えます。クリップは最大 2 秒、3 MB までです。Pilcrow は、それを小さなモノラルのクリップに変換するため、長いファイルや音の大きいファイルが入力を遅くしたり、クリック音を出したりすることはありません。**再生** で確認し、**削除** でパックの音に戻します。ファイルが受け付けられなかった場合は、メッセージにその理由が表示されます。iPad では、消音スイッチで入力サウンドがミュートされ、ほかのオーディオとミックスされます。

## 編集 — 画像

挿入、コピーまたは移動、オンラインでの読み込み、パスのスタイル、URL のエスケープを設定します。

## 外観

アプリケーションテーマ、ズーム、背景、エディタのサイズ、フォント、行間、タブ幅を選びます。

## 書き出し

レンダリングテーマ、レイアウト、ヘッダ、フッタ、メタデータ、見出しでの改ページを選びます。

## ライブラリ

プロファイル、CommonMark のオプション、テーマ、マクロ、スタイルガイド、レンダリングライブラリ、場所、読み込みを管理します。

## キーボード

ショートカットの検索、再割り当て、割り当て解除、リセットを行います。フィールド間の移動の動作も含まれます。

変更は、一度に 1 つのまとまりずつ行ってください。タイポグラフィを評価するときはテーマを固定し、解析を評価するときはプロファイルを固定します。条件を絞って変更すれば、原因と結果が見えやすくなります。

# Chapter 46: プライバシーと保存されるデータを管理する

**設定 ▸ 一般 ▸ ストレージとプライバシー** を開きます。Pilcrow は削除をカテゴリごとに分けているため、キャッシュを消去してもドキュメントを誤って削除することはありません。

- **復元データを確認…** は、復元可能な内容の一覧を表示します。削除する前に、変更のあるドキュメントを保存するか閉じてください。
- **バージョン履歴を確認…** は、削除前にバージョンと推定の使用容量を表示します。
- **最近使ったファイルへのアクセスを消去…** は、最近使ったファイル、記憶されたフォルダ、セッションのブックマーク、ファイルごとの構文の選択を削除します。
- **AI のデータとキーを削除…** は、接続、キーチェーンのキー、会話、AI のプライバシーに関する選択を削除します。
- **診断情報を削除…** は、記録されたログとクラッシュのサポートデータを削除します。
- **キャッシュを消去…** は、再作成可能なキャッシュとネットワークの応答を削除します。

カスタムのプロファイル、テーマ、マクロ、スタイルガイド、背景は、見えているライブラリのページに残り、そこで確認する必要があります。これらのコントロールが、ドキュメントを削除することはありません。

アシスタントの設定では、除外するファイルパターン、アシスタントをオフにしたフォルダ、AI データの削除も管理します。オンライン画像の読み込みは、別のプライバシーの選択です。リンクの確認が、ネットワークにアクセスすることはありません。

# Chapter 47: 診断情報を記録して送信する

**設定 ▸ 一般 ▸ 診断** を開きます。断続的に起きる問題には、**問題を再現する** を選び、関連する部分、レベル、保持期間、含めるサポート情報を選びます。オプションには、デバイスとシステムの情報、Pilcrow の設定、速度とメモリ、最近の操作の履歴、クラッシュの詳細があります。

すぐに問題を再現し、**ログを表示…** を選びます。サブシステムと重大度で絞り込みます。送信する前に、レポートを確認してください。**ヘルプ ▸ バグを報告…** を選ぶと、バージョン情報が入力された状態で GitHub のバグ報告フォームが開きます。Pilcrow がログをクリップボードにコピーするので、フォームに貼り付けてください。レポートをファイルとして保存して添付することも、共有することも、ログビューアから **GitHubで報告…** を選ぶこともできます。GitHub 上のレポートは公開されます。

診断では、ドキュメントの内容ではなく、長さ、識別子、状態、エラーを記録するようにしていますが、共有する前には必ずレポートを確認してください。問題を記録できたら、記録を **問題のみ** に戻すか、詳細な保持を無効にしてください。詳細なログは、ストレージを消費し、パフォーマンスに影響することがあります。

# Chapter 48: 別の言語で Pilcrow を使う

設定を開き、言語を選びます。再起動が必要になる場合があります。Pilcrow は、英語に加えて、スペイン語、フランス語、ドイツ語、イタリア語、ブラジルポルトガル語、オランダ語、ロシア語、日本語、韓国語、簡体字中国語を提供しています。

英語以外のインターフェースの翻訳は、人間によるレビュー済みと表示されるまでは AI が生成したものです。Pilcrow は、これらの言語で起動時にお知らせを表示します。**今後表示しない** を選ぶと、お知らせを恒久的に閉じます。言語設定でお知らせを再び有効にすることもできます。「Machine-translated — may contain errors」というラベルは、未レビューの内容を示します。

インターフェースの言語を変更しても、ドキュメントは翻訳されません。ドキュメントのテキストには、翻訳コマンドを使います。翻訳されたコマンドの意味があいまいな場合は、一時的に英語に切り替えると、正式な原文の表現を確認できます。

# Chapter 50: よくある問題のトラブルシューティング

## ファイルが文字化けしている

ステータスバーでエンコーディングを確認します。編集する前に、正しいエンコーディングで開き直すか、変換してください。

## 書式やプレビューがおかしい

有効なプロファイルを確認し、ソースの区切り文字を検証し、必要な任意の構文を有効にしてから、レンダリングテーマを確認します。マーカーを表示した状態の編集で、文字どおりのテキストを確認します。

## 書式または挿入のコマンドが無効になっている

プレビューから編集に切り替えます。そのうえで、ドキュメントと構文プロファイルが有効であること、そしてプロファイルが目的の構成要素に対応していることを確認します。

## ダイアグラム、グラフ、数式が描画されない

フェンスの言語ラベル、ブロックの境界、ソースの構文、ダイアグラムと数式のオプションを確認します。内蔵のテンプレートから始めると、エラーの原因を切り分けられます。

## 検索でプレビューに見えているテキストが見つからない

書式で分割されているテキストや、コード、数式、ダイアグラム、グラフに含まれるテキストは、編集で検索してください。プレビューの検索は、読み取れるレンダリング後のテキストを対象としており、すべてのソースノードを対象とするわけではありません。

## 相対パスの画像やリンクが壊れている

ドキュメントを保存してフォルダを持たせ、ファイル名と大文字・小文字が正確であることを確認し、プロジェクト内の相対パスを使うようにして、リンクを確認を実行します。

## フォルダ内の置換でスキップされたファイルがある

それらのファイルを Pilcrow で閉じ、UTF-8 のテキストであることを確認してプレビューをやり直し、プレビューから確定までの間に外部で変更されていないことを確認します。

## マクロが動作しない、または動作しすぎる

コレクションとマクロが有効であることを確認し、一致の種類とトリガの境界を確認し、コードの外でテストし、広すぎるパターンは絞り込みます。

## 翻訳が利用できない

macOS 15 または iOS 18 以降であること、言語サポートがインストールされていること、対応する翻訳元と翻訳先の組み合わせであることを確認します。ドキュメントの翻訳は、インターフェースの言語とは別のものです。

## アシスタントが利用できない

接続を追加してテストし、有効にし、提示されたモデルを選び、プロバイダを承認し、フォルダまたはファイルが除外されていないことを確認します。

## 巨大ファイルの操作が遅い

バックグラウンドでの行のインデックス作成を待ち、対象を絞った検索を使い、ストリーミングされる HTML や Word のワークフローで足りる場合は、PDF やドキュメント全体の変換を避けます。

## Pilcrow が予期せず終了した、またはエディタの同期がずれたと報告された

編集を止め、可能ならコピーを保存し、提示されたら復元を使い、再起動する前に診断情報を記録します。保存したドキュメントを確認するまでは、復元セットを破棄しないでください。

## プロジェクトパネルにマニフェストの競合が表示される

再読み込みし、最新のプロジェクトの状態を確認して、変更をやり直します。2 台のデバイスから同時に `manifest.pilcrow` を上書きしないでください。

## カスタムリソースを読み込めない

想定される拡張子と JSON または CSS の形式であることを確認し、報告された安全でないパターンや競合を調べ、アプリケーションテーマ、レンダリングテーマ、プロファイル、マクロ、スタイルガイドのうち正しいセクションに読み込みます。

# Chapter 51: 信頼できる作業ルーチンを身につける

通常の作業では、次のルーチンを使います。

1. ドキュメントに関連するアセットがあるときは、単独のファイルだけでなく、フォルダを開きます。
2. 本格的に編集する前に、プロファイルとエンコーディングを確認します。
3. 最初のチェックポイントを保存します。
4. 編集で書きます。構造が重要なときは並べて表示を使います。
5. 繰り返しには、手作業で複製するのではなく、マクロとフィールドを使います。
6. 一括置換、比較結果の受け入れ、翻訳の置き換え、プロファイルの実験の前には保存します。
7. 適切な段階で、スペルチェック、スタイルレビュー、リンクを確認を実行します。
8. すべてのセクションを展開し、プレビューを最初から最後まで確認します。
9. 意図したレンダリングテーマで書き出し、実際の出力形式を確認します。
10. ソースを共有するのは、受け取る人が編集する必要があるときだけにし、それ以外は完成した出力を共有します。
11. プロファイル、テーマ、マクロ、スタイルガイド、プロジェクトのマニフェスト、ローカルのアセットを、プロジェクトのバックアップに含めます。
12. 復元、バージョン、AI データ、診断情報、キャッシュを、ストレージとプライバシーで定期的に確認します。

理由は単純です。意味はソースで明示し、見た目はテーマに任せ、トランザクションの前にチェックポイントを作り、共有するデータは必要最小限にし、他の人が受け取る実際の成果物を検証する。これが、プレーンテキストを強力で信頼できるものに保つ、Pilcrow のやり方です。
