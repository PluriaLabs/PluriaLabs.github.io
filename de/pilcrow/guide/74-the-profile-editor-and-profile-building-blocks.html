Kapitel 74

Der Profil-Editor und die Bausteine von Profilen

Ein Syntaxprofil sagt Pilcrow, was Ihre Auszeichnung bedeutet. Dieses Kapitel beschreibt den Profil-Editor Bedienelement für Bedienelement und listet dann jeden Baustein auf, den ein Profil verwenden kann. Für eine aufgabenbezogene Einführung siehe Kapitel 37 bis Kapitel 39.

Öffnen Sie den Editor über Einstellungen ▸ Bibliothek ▸ Syntaxprofile: Neu legt ein Profil an, Bearbeiten ändert ein eigenes, und Duplizieren kopiert ein eingebautes Profil, damit Sie die Kopie ändern können. Der Titel des Editors ist Profil bearbeiten, mit Abbrechen, Sichern und Profilhilfe (die die Referenz zu diesen Bausteinen in der App öffnet). Auf einem schmalen Bildschirm wählt ein Schalter Profilabschnitt zwischen Übersicht, Regeln und Testbeispiel; auf einem breiten werden alle drei gleichzeitig angezeigt.

Übersicht#

FeldWas es bewirkt
NameDer Name des Profils, angezeigt im Menü der Statusleiste und in den Einstellungen.
BeschreibungEine Notiz zum Profil.
Dateiendungen (durch Kommas getrennt)Die Endungen, die dieses Profil für eine Datei auswählen. Zwei Profile können sich keine Endung teilen.
Erbt vonKeine, oder ein anderes Profil, auf dessen Regeln dieses aufbaut.
SyntaxErweitert Markdown oder Ersetzt Markdown (siehe unten).
Auf einen BlickAnzahl der Blockregeln, Inline-Regeln und Verschachtelungsregeln.
Erweitertes JSON bearbeiten …Öffnet das Profil als JSON für Felder, die der geführte Editor nicht anbietet. Anwenden behält Ihre JSON-Änderungen; Abbrechen verwirft sie.

Erweitert Markdown fügt Ihre Regeln zu denen von Markdown hinzu: Überschriften, Listen, Betonung und der Rest werden weiterhin gelesen, und Ihre Block- und Inline-Regeln kommen hinzu. Eine Regel, die eine unveränderte Kopie einer Regel aus dem CommonMark-Profil ist, beschreibt, was Markdown bereits tut, und bleibt diesem überlassen. Ersetzt Markdown macht Ihre Regeln zur gesamten Syntax, sodass Markdown-Konstrukte nicht mehr erkannt werden. Dabei muss eine Regel Zeilenende erzeugen, sonst trennt nichts Absätze voneinander. Der Editor warnt „Fügen Sie eine Regel hinzu, deren Ausgabeknoten „newline“ ist, sonst trennt nichts die Absätze“, und das Profil kann erst gesichert werden, wenn eine existiert. Er listet auch alle Ausgabetypen auf, die das Profil nicht definiert.

Regeln#

Regeln gibt es in drei Gruppen.

Blockregeln#

Eine Blockregel erkennt ganze Zeilen und Blöcke. Regel hinzufügen fügt eine hinzu. Jede Regel hat ein Muster, einen Übereinstimmung-Typ, das, was sie Erzeugt, und Optionen. Eine Regel wird mit ihrer Schaltfläche Löschen entfernt. Ohne Regeln sagt der Editor „Noch keine Regeln. Fügen Sie eine hinzu, um ein Blockkonstrukt zu erkennen.“

Inline-Regeln#

Eine Inline-Regel erkennt Text innerhalb einer Zeile. Inline-Regel hinzufügen fügt eine hinzu. Inline-Regeln bieten vier Übereinstimmungstypen (Literales Präfix, Literal exakt, Regex (begrenzt) und Trennzeichenpaar); Blockregeln bieten alle sieben.

Verschachtelungsregeln#

Verschachtelungsregeln legen fest, welche Ausgaben in welchen stehen dürfen. Jede hat einen Übergeordneten Knoten und Zulässige untergeordnete Knoten (durch Kommas getrennt). Leer bedeutet unbeschränkt: „Keine Einschränkungen. Jeder Knotentyp darf in jedem anderen verschachtelt werden.“ Verschachtelungsregel hinzufügen fügt eine hinzu.

Übereinstimmungstypen#

ÜbereinstimmungstypLiest das Muster alsBlockInline
Literales PräfixText, mit dem das Konstrukt beginnt.jaja
Literal exaktDer gesamte Text des Konstrukts.jaja
Präfix am ZeilenanfangText am Anfang einer Zeile, etwa # .ja
Eingerückter BlockZeilen, die mit dem Muster beginnen, etwa vier Leerzeichen oder ein Tabulator. Aufeinanderfolgende Zeilen und Leerzeilen dazwischen bilden einen Block, der ohne die Einrückung angezeigt wird.ja
Umzäunter BlockEine Zeile, die einen Block öffnet und von einer passenden Zeile geschlossen wird.ja
Regex (begrenzt)Ein regulärer Ausdruck. Pilcrow warnt vor dem Sichern, wenn einer hängen bleiben könnte: „Dieser Regex könnte den Editor blockieren – vereinfachen Sie ihn.“jaja
TrennzeichenpaarDieselbe Markierung auf beiden Seiten eines Textes in einer Zeile, etwa %% in %%this%%. Direkt innerhalb der Markierungen steht kein Leerzeichen.jaja

In einem regulären Ausdruck benennt (?<name>…) einen Teil der Übereinstimmung. Siehe unten Benannte Teile.

Regeloptionen#

Die Gruppe Optionen jeder Regel bietet:

OptionWas sie bewirkt
PrioritätRegeln mit höherer Priorität werden zuerst versucht.
Nur am ZeilenanfangVerhindert, dass eine Regel mitten in einer Zeile passt.
Benannte Teile werden zu AttributenJeder benannte Teil eines regulären Ausdrucks wird zu einem Attribut der Ausgabe. Der Editor listet „Teile in diesem Muster“ und „Teile, die diese Ausgabe liest“. Bei einer Ausgabe, die Text enthält, etwa Fett oder ein Link, ist der angezeigte Text der Teil namens text, falls es einen gibt, sonst der zuletzt passende Teil.
ErzeugtWas die Regel erstellt: eine Ausgabe aus den Listen unten oder ein Eigener Name.
Eigener KnotennameDer Name für eine Eigene Ausgabe.
Feste AttributeTeile, die jedes Mal denselben Wert haben, hinzugefügt mit Attribut hinzufügen (ein Name und ein Wert). Ein Wert kann einen benannten Teil enthalten, geschrieben als {name}: Eine E-Mail-Regel, deren Muster die address benennt, kann ihrem Link die url mailto:{address} geben.
EinfügetextWas das Menü Einfügen für diese Regel schreibt, genau so, wie es erscheinen soll, mit $0 an der Stelle, an der die Einfügemarke stehen soll. Eine Regel, die durch einen regulären Ausdruck, einen Block oder eine Einrückung erkannt wird, braucht das, sonst lässt das Menü Einfügen sie aus.
Nur nach einer LeerzeileFür einen eingerückten Block: Eine eingerückte Zeile direkt nach Text bleibt Teil dieses Textes, etwa die nächste Zeile eines Listeneintrags.
Nach der Eingabetaste am ZeilenendeFür Listen und Zitate: Automatisch (wiederholt Aufzählungszeichen und Zitate, zählt nummerierte Einträge hoch und beginnt Aufgabeneinträge unmarkiert), Marker wiederholen, Hochzählen, Neu vom Marker aus beginnen oder Nichts hinzufügen.

Umzäunte und begrenzte Blöcke#

Bei einer Regel für einen Umzäunten Block sagt Der Block enthält, was darin steht:

AuswahlBedeutung
Noch nichtsNicht festgelegt.
Text, wie geschrieben angezeigtCode oder vorformatierter Text.
Nichts – ausgeblendetEin Kommentar, der im Dokument ausgelassen wird.
Andere Blöcke, in einem KastenEin Zitat, eine Randspalte oder ein Hinweis, der Absätze, Listen und mehr enthält.
Andere Blöcke, ohne KastenDie Blöcke schließen sich dem umgebenden Text an; die Zeilen gruppieren sie nur.
Eine TabelleSiehe Tabellen, unten.
Eine in Text gezeichnete TabelleEin Raster oder ausgerichtete Textspalten, das von seiner Eröffnungszeile bis zur nächsten Leerzeile reicht, wie bei reStructuredText.
Eingerückter Text unter einer Zeile, die auf eine Markierung endetDie Eröffnungszeile ist Fließtext, der auf die Markierung endet, wie es bei reStructuredText mit :: der Fall ist; der Fließtext bleibt ein Absatz, und der Text, der nach einer Leerzeile darunter eingerückt steht, wird wie geschrieben angezeigt.
Eingerückter Text unter einer EröffnungszeileEine Direktive wie .. code-block::, die die eingerückten Zeilen darunter enthält und keine Schlusszeile hat.

Die Schlusszeile ist die Zeile, die den Block beendet; leer bedeutet dieselbe Zeile wie die Eröffnungszeile („Wie die Eröffnungszeile“). Ein Trennzeichen, das kein regulärer Ausdruck ist, etwa +++, wird als einfacher Text verglichen. Die Schlusszeile wiederholt das Anfangszeichen mindestens ebenso oft ist für Zäune im Markdown-Stil: Die Schlusszeile ist das erste Zeichen der Eröffnungszeile, mindestens so oft wiederholt, sodass ein längerer Zaun einen kürzeren als Text enthält. Die Sprache eines Textblocks wird, wenn die Eröffnungszeile eine bekannte nennt, im Editor farbig dargestellt.

Hinzugefügt mit Beschriftung hinzufügen.

Inline-Markierungen, die sich nach ihrer Umgebung paaren#

Eine Sprache wie Markdown schreibt Fett und Kursiv mit einer Zeichenfolge, die je nach den Zeichen daneben öffnet oder schließt, und einen Code-Abschnitt oder Link mit Klammern, sodass ein einziges Muster für das ganze Konstrukt sie nicht finden kann. Schalten Sie Markierungen nach ihrer Umgebung lesen ein, um sie zu beschreiben.

EinstellungWas sie bewirkt
Escape-ZeichenEin Zeichen, das das nächste zu einfachem Text macht.
Zeichen für Code-AbschnitteEine Folge dieses Zeichens öffnet einen Abschnitt, den die nächste Folge gleicher Länge schließt.
ReihenmarkierungenMarkierungen, die als Folgen gepaart werden, hinzugefügt mit Reihenmarkierung hinzufügen. Jede hat eine Markierung, was Eine Markierung zeichnet und was Zwei Markierungen zeichnen, und Darf innerhalb eines Wortes öffnen oder schließen (aus bei _).
PaarmarkierungenMarkierungen, die mit einer Folge gleicher Länge gepaart werden, hinzugefügt mit Paarmarkierung hinzufügen: die Markierung, was sie Zeichnet, und Nur wenn diese Einstellung an ist, eine Syntaxeinstellung wie Hervorhebung, die an sein muss (oder Immer).
Links und WebadressenBildpräfix, Eine allein stehende Adresse steht zwischen, Schemata, mit denen eine bloße Adresse beginnt, Eine Zeile, die ein Label definiert, hat und Das Label einer Fußnote beginnt mit (das Zeichen nach der öffnenden Klammer eines Labels, das es zu einer Fußnote macht: [^note] wird als Fußnotenverweis gezeichnet, wenn eine Zeile mit [^note]: beginnt).

Markierungen werden innerhalb einer Zeile gepaart. Code, maskierte Zeichen und die Adresse eines Links sind für die Markierungen um sie herum einfacher Text.

Formatierter Quelltext#

Bei eingeschaltetem Formatierter Quelltext zeichnet der Editor ein Dokument im Aussehen seiner Syntax: größere Überschriften, fette und kursive Folgen, Zitatbalken, Listeneinrückungen, Aufgabenkästchen, Linien, Links und Codekarten, und blendet die Markierungen, die sie bilden, aus (bei eingeschaltetem Markierungen ausblenden), außer in der Zeile, in der die Einfügemarke steht. Der Editor kennt keine einzelne Syntax: Eine Regel sagt, was ihre Übereinstimmung ist, indem sie einen Formatierungseintrag trägt, und eine Regel ohne einen wird farbig dargestellt, aber nicht neu formatiert.

Die Optionen jeder Regel haben eine Gruppe Formatierter Quelltext:

FeldWas es bewirkt
RolleWas die Übereinstimmung ist, oder Ohne Stil. Für ein Konstrukt innerhalb einer Zeile: heading, strong, emphasis, code, strike, highlight, underline, link, subscript, superscript. Für eine ganze Zeile: rule (ein Themenwechsel), list (die Markierung eines Listeneintrags, einschließlich Einrückung und dem Leerzeichen danach), task (eine Markierung mit nachfolgendem Kontrollkästchen) und quote (die >-Zeichen einer zitierten Zeile). Für einen als Ganzes erkannten Block: codeBlock. Für einen Block, dessen Eröffnungs- und Schlusszeile getrennte Übereinstimmungen sind: quoteRegion. Für eine Tabelle, Gleichung oder ein Diagramm, das als Bild gezeichnet wird: renderedBlock.
Gruppe des InhaltsDie Erfassungsgruppe, ab 1 gezählt, die das enthält, worum es im Konstrukt geht: das Wort innerhalb von *bold*, den Titel in \section{Title}. Was die Übereinstimmung außerdem enthält, sind die eigenen Markierungen des Konstrukts, die Markierungen ausblenden ausblendet. 0 bedeutet, dass die ganze Übereinstimmung Inhalt ist und nichts ausgeblendet wird, wie bei einer Webadresse. Lassen Sie es weg, wenn die Übereinstimmung nur aus Markierungen besteht, etwa das == einer Überschrift.
Überschriftenebene, Gruppe der EbeneDie Ebene einer Überschrift, 1 bis 6. Wenn weggelassen, ist es die Zahl am Ende des Ausgabenamens der Regel (heading2) oder die Länge der Erfassungsgruppe, die eine Folge von # enthält.
Gruppe der MarkierungFür eine Liste oder Aufgabe die Erfassungsgruppe, die die Markierung mit ihrer Einrückung und den Leerzeichen danach ist, wenn die Übereinstimmung mit etwas anderem beginnt, etwa dem > eines zitierten Eintrags.
Formatiert bis zum ZeilenendeFormatiert von der Übereinstimmung bis zum Zeilenende, für eine Regel, die nur die Markierung einer Überschrift erkennt und ihren Titel als den folgenden Text belässt.
Wird gezeichnet alsFür einen gerenderten Block, was er ist: eine Tabelle, Mathematik oder ein Diagramm, oder Kein Bild.
Gruppen der AdresseFür einen Link die Erfassungsgruppen, in dieser Reihenfolge versucht, die die Adresse enthalten, die er beim Klicken oder Tippen öffnet; 0 ist die ganze Übereinstimmung. Nur Web-, E-Mail- und Telefonadressen werden geöffnet.

Die Gruppennummern zählen die Klammern des Musters ab 1; 0 ist die ganze Übereinstimmung. Ein Profil, das Markdown nicht ersetzt, behält auch Markdowns eigene Lesart der Arten, die seine Regeln nicht deklarieren, etwa dessen Zitatbalken und die Paare von **.

Dokumentattribute und bedingte Abschnitte#

Eine Regel Dokumentattribut definiert einen Wert über name, und eine Regel Attributverweis (eine Inline-Regel mit den Teilen name und original) ersetzt einen Verweis durch ihn. Ein Verweis auf ein Attribut, das niemand definiert hat, bleibt wie geschrieben stehen. Ein Bedingter Abschnitt behält die Blöcke zwischen seinen Zeilen oder verwirft sie, je nachdem, ob die Attribute, die er nennt, gesetzt sind. Attribute gelten ab der Stelle, an der sie definiert werden.

Eine Regel, die Einstellungen für den nächsten Block erzeugt, erkennt eine ganze Zeile, die den Block danach konfiguriert und selbst nichts anzeigt. Ihre Teile und festen Attribute werden diesem Block übergeben: title, id, nodeType, language und hardbreaks haben die unter Teile aufgeführten Bedeutungen, und jeder andere Teil bleibt am Block erhalten, wo eine Tabelle, Liste oder ein Zitat ihn liest.

Ein Profil testen#

Unten im Editor enthält Testbeispiel Beispieltext (er beginnt als Überschrift und eine Textzeile). Wählen Sie Beispiel prüfen, um die Knoten zu sehen, die Ihre Regeln erzeugen, eingerückt entsprechend ihrer Verschachtelung. Es sagt „Keine Blöcke erkannt.“, wenn nichts passt.

Basiszustand#

Der Basiszustand eines Profils ist sein Wiederherstellungspunkt: so, wie es war, als Sie es angelegt, dupliziert oder importiert haben. Auf Basiszustand zurücksetzen verwirft nach Ihrer Bestätigung jede Änderung seitdem. Als neuen Basiszustand festlegen sichert das Profil und macht seinen aktuellen Zustand zum Wiederherstellungspunkt.

Das Sichern wird mit einer Meldung abgelehnt, wenn das Profil Markdown ersetzt, aber keine Zeilenende-Regel hat, wenn ein Muster unsicher ist und den Editor blockieren könnte oder wenn die Datei nicht geschrieben werden kann.

Was eine Regel Erzeugt: ihr Name im Menü, dann der Name, den die Profildatei speichert, ob Block- oder Inline-Regeln sie erzeugen können, und die Teile, die sie liest. Eine Regel kann auch eine Ausgabe nennen, die diese Liste nicht hat; sie bleibt als Eigene erhalten.

Teile#

Teile sind die benannten Stücke einer Übereinstimmung, die eine Ausgabe liest.

TeilBedeutung
allOfDas Trennzeichen zwischen Namen, wenn alle benötigt werden, etwa +.
altDie Beschreibung eines Bildes für Leser, die es nicht sehen können.
anyOfDas Trennzeichen zwischen Namen, wenn jeder einzelne genügt, etwa ,.
attributionWer ein Zitat gesagt hat, darunter angezeigt.
citetitleDas Werk, aus dem ein Zitat stammt, nach der Quellenangabe angezeigt.
columnsDie Spaltenliste einer Tabelle, etwa 1,2,1; ihre Einträge zählen die Spalten.
conditionDie Attributnamen, von denen der Abschnitt abhängt.
conditionTypedefined behält den Abschnitt, wenn die Attribute gesetzt sind, undefined, wenn sie es nicht sind.
contentDer Text selbst, wenn er nicht die ganze Übereinstimmung ist.
formatDie Engine eines Diagramms (mermaid oder vega-lite); bei einer Tabelle, welches ihrer getrennten Formate die Zellen verwenden.
hardbreaksWenn vorhanden, bleiben die einfachen Zeilenumbrüche des nächsten Blocks erhalten.
headerJeder Wert außer false macht die erste Zeile einer Tabelle zu ihrer Kopfzeile.
idEin Name: für den nächsten Block die ID, auf die Querverweise zeigen; für eine Fußnote ein Name, der es späteren Fußnoten ohne eigenen Text erlaubt, ihre Nummer zu teilen.
keysDie zu drückenden Tasten, durch Kommas getrennt.
labelDer für einen Verweis oder Anker angezeigte Text anstelle des eigenen Titels des Ziels.
languageDie Programmiersprache eines Codeblocks, für seine Farbgebung verwendet.
levelDie Überschriftenebene, von 1 bis 6.
markerDas Trennzeichen nach dem Begriff, etwa ::. Eine andere Markierung verschachtelt eine Liste in der Beschreibung.
nameDer Name des Attributs, in einer Definition oder einem Verweis.
nodeTypeMacht den nächsten Block zu einer anderen Ausgabe, über ihren Namen in der Datei.
noHeaderWenn vorhanden, hat eine Tabelle keine Kopfzeile.
notationDie mathematische Notation: tex (Standard) oder latex.
opentrue zeigt einen einklappbaren Abschnitt geöffnet an.
orderedtrue macht die Liste nummeriert.
originalDer Verweis, wie geschrieben, angezeigt, wenn das Attribut nicht definiert ist.
presentationWie die nächste Beschreibungsliste angezeigt wird: sideBySide setzt Begriffe und Beschreibungen in zwei Spalten; questions nummeriert jeden Begriff als Frage, mit der Antwort darunter.
primaryDer Indexeintrag.
secondaryEin Untereintrag unter dem Indexeintrag.
sectionLabelEin Wort, dem die Nummer der nächsten Überschrift folgt, etwa Appendix: Solche Überschriften werden für sich gezählt, Appendix A:.
sectionLabelStartDie erste dieser Nummern: Ein Buchstabe (A) zählt in Buchstaben, eine Zahl in Zahlen.
srcDie Adresse der Video- oder Audiodatei.
startDie Zahl, bei der eine nummerierte Liste beginnt.
summaryDie Zeile, die auf einem einklappbaren Abschnitt angezeigt wird, solange er geschlossen ist.
targetIDDie ID, auf die der Verweis zeigt.
termDer Begriff, der beschrieben wird.
tertiaryEin Untereintrag unter dem sekundären.
textDer angezeigte Text, wenn das Muster mehr als das erfasst. Der Text einer Fußnote folgt dem Absatz, der Tabelle oder der Liste, in der sie steht, nummeriert.
titleEin Titel: die Überschrift eines Kastens, der Tooltip eines Bildes oder Links oder eine Beschriftung über dem nächsten Block.
typeDie Art des Hinweises, etwa note, tip oder warning.
unsetWenn vorhanden, entfernt die Regel das Attribut, statt es zu definieren.
urlDie Adresse, auf die ein Link oder Bild zeigt.
valueDer Wert des Attributs; Verweise auf früher definierte Attribute werden darin ersetzt.
